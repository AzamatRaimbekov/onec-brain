## Банки - классификатор БИК и выбор банка по БИК

**Когда использовать:** реквизиты банковских счетов (своих и контрагентов), платежные документы, проверка БИК/корр.
счета, признак «деятельность банка прекращена». Справочник `КлассификаторБанков` (БИК = Код) загружается и обновляется
из сервиса 1С - вместо самописного справочника банков и ручной загрузки bnkseek.

**Встраивание в свой объект (рецепт):**
1. Метаданные: в своём справочнике (например, `БанковскиеСчета`) реквизит `Банк` типа `СправочникСсылка.КлассификаторБанков`.
   Роль `ДобавлениеИзменениеБанков` - тем, кто загружает/правит классификатор; чтение классификатора уже в `БазовыеПраваБСП`.
   Загрузка требует подсистемы БИП `ИнтернетПоддержкаПользователей.РаботаСКлассификаторами` (иначе загрузка недоступна).
2. Переопределяемые: `РаботаСБанкамиПереопределяемый`
   - `ПриОпределенииНеобходимостиПоказаПредупрежденияОбУстаревшемКлассификатореБанков(ПоказыватьПредупреждение)` - отключить напоминание (`= Ложь`), например для не-РФ поставки.
   - `ПриОпределенииНастроекЗагрузкиКлассификатораБанков(Настройки)` - `Настройки.ОбрабатыватьОбластиДанных = Истина`, если нужен `ПриОбработкеОбластиДанных`.
   - `ПриОбработкеОбластиДанных()` - только модель сервиса: действия в каждой области после загрузки (например, обновить свои банки).
3. Модуль формы: подбор по введенному БИК.

```bsl
&НаКлиенте
Процедура БИКПриИзменении(Элемент)
	РаботаСБанкамиКлиент.ВыбратьИзСправочникаБИК(БИК, ЭтотОбъект,
		Новый ОписаниеОповещения("ПослеВыбораБанка", ЭтотОбъект));
КонецПроцедуры

&НаКлиенте
Процедура ПослеВыбораБанка(Банк, ДополнительныеПараметры) Экспорт
	Если ЗначениеЗаполнено(Банк) Тогда
		Объект.Банк = Банк;
	КонецЕсли;
КонецПроцедуры

// Сервер: поиск по БИК + корр.счету, только действующие
Сведения = РаботаСБанками.СведенияБИК("044525225", "30101810400000000225");
Если Сведения.Количество() = 0 Тогда ... // нет в классификаторе
```

**Главные методы API** (`api/Банки.md`):
- `РаботаСБанками.СведенияБИК(БИК, КоррСчет, ТолькоАктуальные)` - таблица: Ссылка, Наименование, Город, Адрес, ИНН, СВИФТБИК, РКЦ, `ДеятельностьПрекращена`.
- `РаботаСБанками.ПояснениеНедействительногоБанка(Банк)` - форматированная строка-пояснение для формы.
- `РаботаСБанкамиКлиент.ВыбратьИзСправочникаБИК(БИК, Форма, Оповещение)` - форма выбора с отбором; единственный вариант выбирается сам.

**Подводные камни:**
- Не копировать данные банка (наименование, корр.счет) в свой объект «навсегда» без причины: классификатор обновляется, банк может стать недействующим; показывайте `ПояснениеНедействительногоБанка`.
- `СведенияБИК` по умолчанию отбрасывает недействующие банки (`ТолькоАктуальные = Истина`); для старых документов передавать `Ложь`.
- Один БИК может соответствовать нескольким записям (разные корр.счета) - всегда учитывать `КоррСчет` или выбор пользователя.
- В конфигурации без БИП классификатор не загружается - заполнять вручную или вашей загрузкой.

## Валюты - справочник валют, курсы, пересчет, сумма прописью

**Когда использовать:** валютные документы и цены, пересчет сумм по курсу на дату, загрузка курсов ЦБ, зависимые валюты
(наценка/формула), сумма прописью в печатных формах. Справочник `Валюты`, регистр сведений `КурсыВалют`
(периодичность День, измерение `Валюта`, ресурсы `Курс`, `Кратность`), регламентное задание `ЗагрузкаКурсовВалют`,
общая команда `ЗагрузитьКурсыВалют`, перечисление `СпособыУстановкиКурсаВалюты` (ЗагрузкаИзИнтернета, РучнойВвод,
НаценкаНаКурсДругойВалюты, РасчетПоФормуле). Заменяет свой регистр курсов и функции пересчета.

**Встраивание в свой объект (рецепт):**
1. Метаданные:
   - реквизиты документа: `Валюта` (`СправочникСсылка.Валюты`), `Курс` (тип `ОпределяемыйТип.КурсВалюты`, Число 10.4), `Кратность` (Число);
   - суммы - `ОпределяемыйТип.ДенежнаяСуммаЛюбогоЗнака` / `ДенежнаяСуммаНеотрицательная` (Число 15.2), чтобы разрядность менялась в одном месте;
   - роли: `ЧтениеКурсовВалют` - **всем**, кто работает с валютными документами (чтение `Валюты` и `КурсыВалют` НЕ входит в `БазовыеПраваБСП`);
     `ДобавлениеИзменениеКурсовВалют` - тем, кто ведет курсы.
2. Переопределяемые:
   - `РаботаСКурсамиВалютПереопределяемый.ПриОпределенииВалютыОбъектаПоУмолчанию(ТипОбъектаПечати, ИмяПоляВалюты)` -
     какое поле объекта считать валютой для прописи в печати: `Если ТипОбъектаПечати = Тип("ДокументСсылка.Заказ") Тогда ИмяПоляВалюты = "ВалютаДокумента"; КонецЕсли;`
   - `РаботаСКурсамиВалютПереопределяемый.ПриОпределенииНеобходимостиПоказаПредупрежденияОбУстаревшихКурсахВалют(ПоказыватьПредупреждение)`.
   - Печать прописью: в `УправлениеПечатьюПереопределяемый.ПриОпределенииИсточниковДанныхПечати` вызвать
     `РаботаСКурсамиВалют.ПодключитьИсточникДанныхПечатиЧислоПрописью(ИсточникиДанныхПечати, "Документ.Заказ")`.
   - Начальное заполнение валют (обработчик первого запуска): `РаботаСКурсамиВалют.ДобавитьВалютыПоКоду(СтрРазделить("643,840,978", ","))`.
3. Модуль формы/объекта - курс при смене валюты/даты и пересчет:

```bsl
&НаСервере
Процедура ЗаполнитьКурсВалюты()
	ДанныеКурса = РаботаСКурсамиВалют.ПолучитьКурсВалюты(Объект.Валюта, Объект.Дата);
	Объект.Курс      = ДанныеКурса.Курс;
	Объект.Кратность = ДанныеКурса.Кратность;
КонецПроцедуры

// Пересчет: из валюты документа в рубли на дату (через курсы обеих валют)
СуммаРуб = РаботаСКурсамиВалют.ПересчитатьВВалюту(Сумма, Объект.Валюта, ВалютаРегл, Объект.Дата);

// На клиенте, когда параметры курсов уже есть в форме
НоваяСумма = РаботаСКурсамиВалютКлиентСервер.ПересчитатьПоКурсу(Сумма,
	Новый Структура("Валюта, Курс, Кратность", Объект.Валюта, Объект.Курс, Объект.Кратность),
	ПараметрыКурсаНовойВалюты);

// В запросе - срез последних
// ВЫБРАТЬ Курс, Кратность ИЗ РегистрСведений.КурсыВалют.СрезПоследних(&Дата, Валюта = &Валюта)
```
Сумма прописью: `РаботаСКурсамиВалют.СформироватьСуммуПрописью(Сумма, Валюта)` (параметры прописи берутся из реквизита
`ПараметрыПрописи` валюты).

**Главные методы API** (`api/Валюты.md`):
- `РаботаСКурсамиВалют.ПолучитьКурсВалюты(Валюта, Дата)` - структура Курс, Кратность, Валюта, ДатаКурса.
- `РаботаСКурсамиВалют.ПересчитатьВВалюту(Сумма, ИсходнаяВалюта, НоваяВалюта, Дата)` - пересчет через курсы на дату.
- `РаботаСКурсамиВалютКлиентСервер.ПересчитатьПоКурсу(Сумма, ПараметрыТекущегоКурса, ПараметрыНовогоКурса)` - пересчет по известным курсам, клиент+сервер.
- `РаботаСКурсамиВалют.СформироватьСуммуПрописью(Сумма, Валюта, БезДробнойЧасти, КодЯзыка)` - сумма прописью.
- `РаботаСКурсамиВалют.ОписаниеТипаДенежногоПоля(ДопустимыйЗнак)` - ОписаниеТипов для денежных колонок ТЗ/реквизитов формы.
- `РаботаСКурсамиВалют.ДобавитьВалютыПоКоду(КодыВалют)` - валюты из классификатора ОКВ.
- `РаботаСКурсамиВалют.ПодключитьИсточникДанныхПечатиЧислоПрописью` - прописи в макетах печати.
- `РаботаСКурсамиВалютКлиентЛокализация.ПоказатьЗагрузкуКурсовВалют` - интерактивная загрузка курсов.

**Подводные камни:**
- `ПересчитатьПоКурсу` (и `ПересчитатьВВалюту`) **молча возвращает 0**, если у любой валюты курс или кратность = 0, и округляет до 2 знаков. Для сумм с большей точностью и для контроля «нет курса» считать самим.
- При записи валюты БСП гарантирует курс 1/1 на 01.01.1980 (`ПроверитьКорректностьКурсаНа01_01_1980`) - «нет курса» на дату означает курс 1, а не ошибку. Проверяйте `ДатаКурса`/актуальность при необходимости.
- Пересчет «валюта -> валюта» в БСП всегда идет через курсы обеих валют на дату (`ПересчитатьВВалюту` читает две записи `КурсыВалют`); не хранить кросс-курсы отдельно.
- Права: без `ЧтениеКурсовВалют` у пользователя падает проведение/открытие формы. Либо роль в профиль, либо привилегированный режим на сервере.
- Зависимые валюты (наценка, формула) пересчитываются в модуле набора записей `КурсыВалют` при записи курса основной валюты - при `ОбменДанными.Загрузка = Истина` или `ДополнительныеСвойства.ОтключитьКонтрольПодчиненныхВалют` пересчет пропускается.
- Загрузка курсов из Интернета (ЦБ) реализована в локализации и требует Интернет-поддержки (БИП); в модели сервиса курсы поставляются как поставляемые данные.

## КалендарныеГрафики - производственные календари, рабочие дни, сроки

**Когда использовать:** «срок = дата + N рабочих дней», количество рабочих дней между датами, ближайший рабочий день,
нерабочие периоды (указы). Справочник `ПроизводственныеКалендари`, регистр `ДанныеПроизводственногоКалендаря`, ФО
`ИспользоватьНесколькоПроизводственныхКалендарей`, данные календарей загружаются из классификатора 1С. Заменяет
самописные таблицы праздников и функции «ДобавитьРабочиеДни».

**Встраивание в свой объект (рецепт):**
1. Метаданные: в своём объекте (организация, договор, подразделение) - реквизит `ПроизводственныйКалендарь`
   (`СправочникСсылка.ПроизводственныеКалендари`). Чтение календарей уже в `БазовыеПраваБСП`; роль
   `ДобавлениеИзменениеКалендарныхГрафиков` - тем, кто их правит.
2. Переопределяемые `КалендарныеГрафикиПереопределяемый` - если у вас есть данные, рассчитанные по календарю
   (сроки, нормы времени), которые надо пересчитать при обновлении календаря:
   - `ПриОбновленииПроизводственныхКалендарей(УсловияОбновления)` - неразделенный режим; `УсловияОбновления`: КодПроизводственногоКалендаря, Год;
   - `ПриОбновленииДанныхЗависимыхОтПроизводственныхКалендарей(УсловияОбновления)` - в областях данных: пересчитать свои данные;
   - `ПриЗаполненииБлокируемыхОбъектовЗависимыхОтПроизводственныхКалендарей(БлокируемыеОбъекты)` / `ПриЗаполненииИзменяемыхОбъектовЗависимыхОтПроизводственныхКалендарей(ИзменяемыеОбъекты)` -
     имена метаданных для отложенного обработчика обновления.
3. Модуль формы/объекта:

```bsl
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
	Если Объект.Ссылка.Пустая() Тогда
		// Заполнит, если в базе единственный календарь (по КПП может определить регион)
		КалендарныеГрафики.ЗаполнитьПроизводственныйКалендарьВФорме(ЭтотОбъект, "Объект.ПроизводственныйКалендарь");
	КонецЕсли;
КонецПроцедуры

// Срок оплаты = дата + 5 рабочих дней
Календарь = КалендарныеГрафики.ОсновнойПроизводственныйКалендарь();
СрокОплаты = КалендарныеГрафики.ДатаПоКалендарю(Календарь, Документ.Дата, 5);

// Перенос на ближайший рабочий день
Параметры = КалендарныеГрафики.ПараметрыПолученияБлижайшихРабочихДат(Календарь);
Даты = Новый Массив; Даты.Добавить(ПлановаяДата);
РабочаяДата = КалендарныеГрафики.БлижайшиеРабочиеДаты(Календарь, Даты, Параметры)[ПлановаяДата];
```

**Главные методы API** (`api/КалендарныеГрафики.md`):
- `КалендарныеГрафики.ДатаПоКалендарю(ГрафикИлиКалендарь, ДатаОт, КоличествоДней, ВызыватьИсключение)` - дата + N рабочих дней.
- `КалендарныеГрафики.ДатыПоКалендарю(..., МассивДней, ...)` - пакетно для нескольких сдвигов.
- `КалендарныеГрафики.РазностьДатПоКалендарю(График, Начало, Окончание)` - число рабочих дней в периоде.
- `КалендарныеГрафики.БлижайшиеРабочиеДаты` + `ПараметрыПолученияБлижайшихРабочихДат` - ближайший рабочий день (вперед/назад, с нерабочими периодами).
- `КалендарныеГрафики.ОсновнойПроизводственныйКалендарь()` - календарь по умолчанию (может быть `Неопределено`).
- `КалендарныеГрафики.ПериодыНерабочихДней(Календарь, Период)` - нерабочие периоды по указам.
- `КалендарныеГрафики.ЗаполнитьПроизводственныйКалендарьВФорме` - автозаполнение реквизита в форме.

**Подводные камни:**
- `ДатаПоКалендарю(..., 0)` возвращает `НачалоДня(ДатаОт)` даже если это выходной; для «не раньше ближайшего рабочего» используйте `БлижайшиеРабочиеДаты`.
- Результат - начало дня (время отбрасывается).
- Незаполненный календарь на год -> исключение (по умолчанию `ВызыватьИсключение = Истина`). В проведении либо проверять заранее, либо передавать `Ложь` и обрабатывать `Неопределено`.
- `ОсновнойПроизводственныйКалендарь()` возвращает `Неопределено`, если нет обработки `ЗаполнениеКалендарныхГрафиков` или календаря - проверять перед вызовом расчетов.
- Функции принимают и `СправочникСсылка.Календари` (график работы) - тогда нужна подсистема ГрафикиРаботы и права на `Календари`.
- Не кешировать праздники в своих регистрах: календарь обновляется классификатором (указы о переносах), используйте переопределяемые события для пересчета зависимых данных.

## ГрафикиРаботы - графики работы (справочник `Календари`), расписания

**Когда использовать:** у сотрудников/подразделений/ресурсов свой режим работы (сменный, 2/2, «по дням недели» с часами),
нужны даты/часы работы по графику, ближайший рабочий день по графику. Справочник `Календари` (графики, строятся по
производственному календарю), регистры `КалендарныеГрафики`, `РучныеИзмененияГрафиковРаботы`, обработка
`ЗаполнениеГрафиковРаботы`. Надстройка над КалендарнымиГрафиками.

**Встраивание в свой объект (рецепт):**
1. Метаданные:
   - реквизит `ГрафикРаботы` (`СправочникСсылка.Календари`) в своём объекте;
   - определяемый тип `ВладелецГрафикаРаботы` (в поставке заглушка `Строка`) - добавить ссылки объектов, которым принадлежат графики
     (например, `СправочникСсылка.Организации`, `СправочникСсылка.Сотрудники`) - это тип реквизита `Календари.ВладелецГрафика`;
   - роли: `ЧтениеГрафиковРаботы` всем, кто считает даты по графику (не входит в `БазовыеПраваБСП`), `ДобавлениеИзменениеГрафиковРаботы` - тем, кто их ведет.
2. Переопределяемых модулей нет.
3. Код:

```bsl
// Дата окончания задачи: + 3 рабочих дня по графику исполнителя
Окончание = ГрафикиРаботы.ДатаПоГрафику(Исполнитель.ГрафикРаботы, Начало, 3, Ложь);
Если Окончание = Неопределено Тогда // график не заполнен на период
	Окончание = КалендарныеГрафики.ДатаПоКалендарю(КалендарныеГрафики.ОсновнойПроизводственныйКалендарь(), Начало, 3);
КонецЕсли;

// Часы работы для загрузки ресурсов - сразу во временную таблицу ВТРасписанияРаботы
ГрафикиРаботы.СоздатьВТРасписанияРаботыНаПериод(МенеджерВТ, МассивГрафиков, НачалоПериода, КонецПериода);
```

**Главные методы API** (`api/ГрафикиРаботы.md`):
- `ГрафикиРаботы.ДатаПоГрафику(График, ДатаОт, КоличествоДней, ВызыватьИсключение)` / `ДатыПоГрафику(...)` - сдвиг по дням графика.
- `ГрафикиРаботы.БлижайшиеДатыВключенныеВГрафик` + `ПараметрыПолученияБлижайшихДатПоГрафику` - ближайшие рабочие по графику.
- `ГрафикиРаботы.РасписанияРаботыНаПериод(Графики, Начало, Окончание)` - ТЗ: ГрафикРаботы, ДатаГрафика, ВремяНачала, ВремяОкончания.
- `ГрафикиРаботы.СоздатьВТРасписанияРаботыНаПериод` - то же во временную таблицу для запросов.

**Подводные камни:**
- График заполняется на горизонт планирования (`Календари.ГоризонтПланирования`); за его пределами - «график не заполнен» (исключение или `Неопределено`).
- Права: регистр `КалендарныеГрафики` и справочник `Календари` читаются только с ролью `ЧтениеГрафиковРаботы`; модуль `ГрафикиРаботы` привилегированный режим не включает.
- Для предпраздничного дня без отдельного расписания берется расписание обычного рабочего дня.
- Запрос по `РегистрСведений.КалендарныеГрафики` напрямую допустим, но при ручных правках (`РучныеИзмененияГрафиковРаботы`) корректнее API.

## Организации - единый API сведений об организации для подсистем БСП

**Когда использовать:** подсистема не содержит справочника - она дает контракт `ОрганизацииСервер`, через который
БСП (ЭлектроннаяПодпись, МашиночитаемыеДоверенности, СервисМобильнойПодписи, персональные данные) получает ИНН, КПП,
ОГРН, адрес, руководителя, бухгалтера, банковский счет. Ваша задача - заполнить `ОрганизацииПереопределяемый` из своего
справочника `Организации`. Собственный прикладной код тоже может читать сведения через `ОрганизацииСервер.СведенияОбОрганизации`.

**Встраивание в свой объект (рецепт):**
1. Метаданные: определяемый тип `Организация` (подсистема БазоваяФункциональность; в поставке - `Строка`) -> `СправочникСсылка.Организации`.
   `ОрганизацииСервер.ИспользуетсяАрхив()` смотрит наличие реквизита `ВАрхиве` у первого типа - добавьте его, если нужны «неактуальные организации».
   Реквизит `ПроизводственныйКалендарь` - см. КалендарныеГрафики.
2. Переопределяемые `ОрганизацииПереопределяемый` (все с сигнатурой `(Организация, Поля, Дата, <Результат>, КодЯзыка)`):
   `ПриОпределенииРегистрационныхДанныхОрганизации`, `ПриОпределенииДополнительныхСведенийОрганизации`,
   `ПриОпределенииКонтактнойИнформацииОрганизации`, `ПриОпределенииБанковскогоСчетаОрганизации`,
   `...ОбособленногоПодразделения`, `...ОтделенияИностраннойОрганизации`, `...ИндивидуальногоПредпринимателя`,
   `...РуководителяОрганизации`, `...ГлавногоБухгалтера`, `...УполномоченногоПредставителя`. Заполнять только запрошенные `Поля`
   (пустая строка - все) и только ключи из описания возвращаемого значения соответствующей функции `ОрганизацииСервер`.

```bsl
Процедура ПриОпределенииРегистрационныхДанныхОрганизации(Организация, Поля, Дата, РегистрационныеДанные, КодЯзыка) Экспорт
	Свойства = ?(ПустаяСтрока(Поля), "ИНН,КПП,ОГРН,НаименованиеПолное,НаименованиеСокращенное", Поля);
	Значения = ОбщегоНазначения.ЗначенияРеквизитовОбъекта(Организация,
		"ИНН,КПП,ОГРН,НаименованиеПолное,НаименованиеСокращенное");
	Для Каждого Имя Из СтрРазделить(Свойства, ",", Ложь) Цикл
		Имя = СокрЛП(Имя);
		Если Значения.Свойство(Имя) Тогда
			РегистрационныеДанные.Вставить(Имя, Значения[Имя]);
		КонецЕсли;
	КонецЦикла;
КонецПроцедуры

Процедура ПриОпределенииКонтактнойИнформацииОрганизации(Организация, Поля, Дата, КонтактнаяИнформация, КодЯзыка) Экспорт
	Вид = УправлениеКонтактнойИнформацией.ВидКонтактнойИнформацииПоИмени("ЮрАдресОрганизации");
	КонтактнаяИнформация.Вставить("АдресОрганизации",
		УправлениеКонтактнойИнформацией.ПредставлениеКонтактнойИнформацииОбъекта(Организация, Вид));
КонецПроцедуры
```
Полный пример запроса со всеми полями - в комментарии к `ПриОпределенииРегистрационныхДанныхОрганизации` в исходнике.

**Главные методы API** (`api/Организации.md`):
- `ОрганизацииСервер.СведенияОбОрганизации(Организация, Поля, Дата, КодЯзыка)` - все сведения одной структурой.
- `ОрганизацииСервер.РегистрационныеДанныеОрганизации` - ИНН, КПП, ОГРН, ОКВЭД, наименования, `ВАрхиве`...
- `ОрганизацииСервер.ДополнительныеСведенияОрганизации` - руководитель, бухгалтер, телефон, эмблема для штампа ЭП.
- `ОрганизацииСервер.КонтактнаяИнформацияОрганизации` - адрес (строка/JSON/XML и поля), email, телефон.
- `ОрганизацииСервер.БанковскийСчетОрганизации` - БанковскийСчетБанк/БИК/КоррСчет/НомерСчета.
- `ОрганизацииСервер.РегистрационныеДанныеРуководителяОрганизации`, `...ГлавногоБухгалтера`, `...УполномоченногоПредставителя` - данные лиц.
- `ОрганизацииСервер.ИспользуетсяАрхив()` - есть ли у организаций признак `ВАрхиве`.

**Подводные камни:**
- Не заполнили `ОрганизацииПереопределяемый` - функции возвращают **пустые структуры** без ошибок, а МЧД/ЭП получают пустой ИНН/руководителя. Проверять после внедрения.
- `СведенияОбОрганизации` объединяет все структуры и **вызывает исключение** при совпадении ключа в двух процедурах - не дублировать поле (например, `ИНН`) в разных `ПриОпределении...`.
- Названия ключей строго из описаний возвращаемых значений `ОрганизацииСервер` - потребители БСП читают их по имени.
- Учитывать `Поля` и `Дата`: потребители запрашивают выборочно; тяжелые запросы на каждое поле - антипаттерн, читать одним запросом.
- В типовых (БП/УТ/ERP) `ОрганизацииПереопределяемый` уже заполнен прикладной частью - дорабатывать в расширении аккуратно, не перетирая.
