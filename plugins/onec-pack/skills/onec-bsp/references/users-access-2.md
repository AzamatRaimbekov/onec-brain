## ДатыЗапретаИзменения - запрет изменения данных закрытых периодов и загрузки из обмена

**Когда использовать:** «после закрытия месяца документы до даты X менять нельзя», запрет в разрезе организаций/складов/
пользователей, запрет загрузки старых данных из узлов обмена. Заменяет: самописные константы «ДатаЗапрета»,
проверки в `ПередЗаписью` каждого документа, блокировку форм по дате.

**Встраивание в свой объект (рецепт):**
1. Метаданные (в БСП подписок для прикладных объектов нет - создаёт прикладное решение):
   - Подписки на событие `ПередЗаписью` с обработчиками общего модуля `ДатыЗапретаИзменения`:
     - документы - `ДатыЗапретаИзменения.ПроверитьДатуЗапретаИзмененияПередЗаписьюДокумента`;
     - справочники/ПВХ/БП/задачи - `ДатыЗапретаИзменения.ПроверитьДатуЗапретаИзмененияПередЗаписью`;
     - регистры (наборы записей) - `...ПередЗаписьюНабораЗаписей`, `...ПередЗаписьюНабораЗаписейРегистраБухгалтерии`,
       `...ПередЗаписьюНабораЗаписейРегистраРасчета`;
     - событие `ПередУдалением` - `ДатыЗапретаИзменения.ПроверитьДатуЗапретаИзмененияПередУдалением`.
     Образец - подписки самой БСП `ПроверитьДатуЗапретаИзмененияПередЗаписьюДокументаЗащитаПерсональныхДанных` /
     `...ПередУдалениемЗащитаПерсональныхДанных` (источники - документы ЗПД).
   - Определяемый тип `АдресатЗапретаИзменения` (пользователи/группы/узлы) обычно не трогают.
   - Роли подсистемы: `ЧтениеДатЗапретаИзменения`, `ДобавлениеИзменениеДатЗапретаИзменения` (тому, кто закрывает
     период), `ЧтениеДатЗапретаЗагрузки`, `ДобавлениеИзменениеДатЗапретаЗагрузки`; включение - функц. опции
     `ИспользоватьДатыЗапретаИзменения` / `ИспользоватьДатыЗапретаЗагрузки`.
2. Переопределяемые процедуры (`ДатыЗапретаИзмененияПереопределяемый`):
   ```bsl
   Процедура ПриЗаполненииРазделовДатЗапретаИзменения(Разделы) Экспорт
       Раздел = Разделы.Добавить();
       Раздел.Имя           = "Склад";
       Раздел.Идентификатор = Новый УникальныйИдентификатор("..."); // постоянный GUID, см. комментарий в модуле
       Раздел.Представление = НСтр("ru = 'Складской учет'");
       Раздел.ТипыОбъектов.Добавить(Тип("СправочникСсылка.Организации")); // разрезы настройки дат
   КонецПроцедуры

   Процедура ЗаполнитьИсточникиДанныхДляПроверкиЗапретаИзменения(ИсточникиДанных) Экспорт
       ДатыЗапретаИзменения.ДобавитьСтроку(ИсточникиДанных,
           Метаданные.Документы.ПеремещениеТоваров.ПолноеИмя(), "Дата", "Склад", "Организация");
       ДатыЗапретаИзменения.ДобавитьСтроку(ИсточникиДанных,
           Метаданные.РегистрыНакопления.ТоварыНаСкладах.ПолноеИмя(), "Период", "Склад", "Организация");
   КонецПроцедуры
   ```
   Поле даты/объекта может быть в табличной части: `"Товары.ДатаОтгрузки"`, `"Товары.Склад"`.
   - `ПередПроверкойЗапретаИзменения(Объект, ПроверкаЗапретаИзменения, УзелПроверкиЗапретаЗагрузки, ВерсияОбъекта)` -
     пропустить проверку для отдельных случаев (например, непроведённые черновики).
   - `ПередПроверкойСтаройВерсииДанных` / `ПередПроверкойНовойВерсииДанных` - своя логика «какую дату/объект проверять»
     (пример в модуле: заказ-наряд проверяется по `ДатаОкончанияРабот`).
   - `НастройкаИнтерфейса` - `ИспользоватьВнешнихПользователей`.
3. Форма объекта - заблокировать форму, если объект в закрытом периоде (как `РегистрСведений.КурсыВалют.ФормаЗаписи`):
   ```bsl
   &НаСервере
   Процедура ПриЧтенииНаСервере(ТекущийОбъект)
       // СтандартныеПодсистемы.ДатыЗапретаИзменения
       ДатыЗапретаИзменения.ОбъектПриЧтенииНаСервере(ЭтотОбъект, ТекущийОбъект);
       // Конец СтандартныеПодсистемы.ДатыЗапретаИзменения
   КонецПроцедуры
   ```

**Главные методы API** ([api/ДатыЗапретаИзменения.md](api/ДатыЗапретаИзменения.md)):
- `ДатыЗапретаИзменения.ДобавитьСтроку(Данные, Таблица, ПолеДаты, Раздел, ПолеОбъекта)` - источник данных для проверки.
- `ДатыЗапретаИзменения.ОбъектПриЧтенииНаСервере(Форма, ТекущийОбъект)` - `ТолькоПросмотр` в форме.
- `ДатыЗапретаИзменения.ИзменениеЗапрещено(ДанныеИлиПолноеИмя, ИдентификаторДанных, ОписаниеОшибки, УзелПроверкиЗапретаЗагрузки)` -
  программная проверка (например, перед групповой обработкой).
- `ДатыЗапретаИзменения.НайденЗапретИзмененияДанных(ДанныеДляПроверки, ...)` + `ШаблонДанныхДляПроверки()` - проверка
  произвольного набора «дата-раздел-объект» без объекта.
- `ДатыЗапретаИзменения.ПроверитьДатыЗапретаЗагрузкиДанных(Данные, Узел, Отказ)` - в обработчиках обмена.
- `ДатыЗапретаИзменения.ОтключитьПроверкуДатЗапрета(Отключить)` / `ПроверкаДатЗапретаОтключена()` - служебная массовая
  перезапись (закрытие месяца, перепроведение регламентом).
- Обработчики подписок `ПроверитьДатуЗапретаИзменения*` - только для указания в подписках.

**Подводные камни:**
- Без подписки объект не проверяется, даже если описан в `ЗаполнитьИсточникиДанныхДляПроверкиЗапретаИзменения`;
  и наоборот - подписка без источника ничего не проверяет. Нужны оба шага.
- Проверяются и старая (в базе), и новая версия: перенос документа из закрытого периода в открытый тоже запрещён.
- `ОтключитьПроверкуДатЗапрета` пишет параметр сеанса: всегда восстанавливать прежнее значение
  (`ПроверкаДатЗапретаОтключена()` до вызова) в `Попытка...Исключение`, иначе запрет отключится до конца сеанса.
- При `ОбменДанными.Загрузка = Истина` обработчики подписок сразу выходят (проверки нет). Запрет **загрузки** из узлов
  проверяет подсистема обмена через `ПроверитьДатыЗапретаЗагрузкиДанных`; в своих загрузках вызывать её явно.
- Регистры, которые пишутся при проведении, проверять отдельно имеет смысл, только если их пишут и вне проведения.
- В комментарии `ДобавитьСтроку` раздел назван «предопределённым элементом ПВХ РазделыДатЗапретаИзменения», но
  разделы задаются в `ПриЗаполненииРазделовДатЗапретаИзменения` по `Имя` + постоянному `Идентификатор` - передавайте `Имя`.

## ЗапретРедактированияРеквизитовОбъектов - блокировка ключевых реквизитов в форме с разблокировкой по кнопке

**Когда использовать:** реквизиты, изменение которых после использования объекта ломает учёт (вид номенклатуры,
организация договора, тип вида КИ). Форма записанного объекта открывается с заблокированными полями, команда
«Разрешить редактирование реквизитов» проверяет ссылки на объект и предупреждает. Заменяет: ручное
`Элементы.X.ТолькоПросмотр = ЗначениеЗаполнено(Объект.Ссылка)` и самописные проверки «есть ли документы».

**Встраивание в свой объект (рецепт):**
1. Метаданные: ничего не добавлять в определяемые типы. Команда разблокировки добавляется, только если доступна роль
   `РедактированиеРеквизитовОбъектов` и право `Редактирование` на объект; у нового (незаписанного) объекта реквизиты
   открыты при наличии платформенного права `Редактирование` на реквизит.
2. Переопределяемые процедуры (`ЗапретРедактированияРеквизитовОбъектовПереопределяемый`):
   ```bsl
   Процедура ПриОпределенииОбъектовСЗаблокированнымиРеквизитами(Объекты) Экспорт
       Объекты.Вставить(Метаданные.Справочники.Номенклатура.ПолноеИмя(), "");
   КонецПроцедуры
   ```
   `ПриОпределенииЗаблокированныхРеквизитов(ИмяОбъектаМетаданных, ЗаблокированныеРеквизиты)` - поправить список
   чужого объекта без изменения его модуля менеджера.
3. Модуль менеджера + форма элемента:
   ```bsl
   // Модуль менеджера: "Реквизит" или "Реквизит; ЭлементФормы1, ЭлементФормы2" или структура
   // См. ЗапретРедактированияРеквизитовОбъектовПереопределяемый.ПриОпределенииОбъектовСЗаблокированнымиРеквизитами
   Функция ПолучитьБлокируемыеРеквизитыОбъекта() Экспорт
       Результат = Новый Массив;
       Результат.Добавить("ВидНоменклатуры");
       Реквизит = ЗапретРедактированияРеквизитовОбъектов.НовыйБлокируемыйРеквизит();
       Реквизит.Имя = "ЕдиницаИзмерения";
       Реквизит.Предупреждение = НСтр("ru = 'Изменение исказит остатки в введённых документах'");
       Результат.Добавить(Реквизит);
       Возврат Результат;
   КонецФункции
   ```
   ```bsl
   // Форма элемента
   &НаСервере
   Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
       ЗапретРедактированияРеквизитовОбъектов.ЗаблокироватьРеквизиты(ЭтотОбъект);
   КонецПроцедуры

   &НаСервере
   Процедура ПослеЗаписиНаСервере(ТекущийОбъект, ПараметрыЗаписи)
       ЗапретРедактированияРеквизитовОбъектов.ЗаблокироватьРеквизиты(ЭтотОбъект); // новый объект после записи - заблокировать
   КонецПроцедуры

   &НаКлиенте
   Процедура Подключаемый_РазрешитьРедактированиеРеквизитовОбъекта(Команда) // имя фиксировано, команду добавляет БСП
       ЗапретРедактированияРеквизитовОбъектовКлиент.РазрешитьРедактированиеРеквизитовОбъекта(ЭтотОбъект);
   КонецПроцедуры
   ```
   Своя форма вопроса о разблокировке - форма объекта `РазблокированиеРеквизитов` (возвращает Истина или массив имён).

**Главные методы API** ([api/ЗапретРедактированияРеквизитовОбъектов.md](api/ЗапретРедактированияРеквизитовОбъектов.md)):
- `ЗапретРедактированияРеквизитовОбъектов.ЗаблокироватьРеквизиты(Форма, ГруппаДляКнопкиЗапрета, ЗаголовокКнопкиЗапрета, Объект)`.
- `ЗапретРедактированияРеквизитовОбъектов.НовыйБлокируемыйРеквизит()` - `Имя`, `ЭлементыФормы`, `Предупреждение`, `Группа`, `ПредставлениеГруппы`.
- `ЗапретРедактированияРеквизитовОбъектов.БлокируемыеРеквизитыОбъекта(ИмяОбъекта)`.
- `ЗапретРедактированияРеквизитовОбъектовКлиент.РазрешитьРедактированиеРеквизитовОбъекта(Форма, ОбработкаПродолжения, ТолькоВидимые)`.
- `ЗапретРедактированияРеквизитовОбъектовКлиент.УстановитьДоступностьЭлементовФормы(Форма, Реквизиты)` - после программных
  изменений видимости/доступности.

**Подводные камни:**
- Это защита только интерфейса: программная запись, обработка `ГрупповоеИзменениеРеквизитов` (у неё своя проверка
  через `РазрешитьРедактированиеРеквизитовОбъектов`) и загрузка реквизит меняют. Инвариант учёта - проверять в `ПередЗаписью`.
- Не управлять `ТолькоПросмотр` заблокированных элементов своим кодом - после `ЗаблокироватьРеквизиты` вызывать
  `УстановитьДоступностьЭлементовФормы`, иначе разблокировка «отменится».
- Надписи, связанные с реквизитом, не блокируются - их имена указывать в `ЭлементыФормы`.
- Без процедуры `Подключаемый_РазрешитьРедактированиеРеквизитовОбъекта` в форме команда падает на клиенте.

## ЗащитаПерсональныхДанных - 152-ФЗ: согласия, журнал доступа, скрытие и уничтожение ПДн

**Когда использовать:** в конфигурации есть физлица/контактные лица/кандидаты (субъекты ПДн): регистрация доступа к
ПДн в журнале регистрации, согласия/отзывы согласий, расчёт сроков хранения, скрытие и уничтожение ПДн по акту.
Заменяет: самописные журналы «кто смотрел паспорт», ручную обезличку баз.

**Встраивание в свой объект (рецепт):**
1. Метаданные:
   - `ОпределяемыйТип.СубъектПерсональныхДанных` - ссылки субъектов (`СправочникСсылка.ФизическиеЛица`);
     `ОпределяемыйТип.СубъектПерсональныхДанныхОбъект` - их объектные типы (на нём подписки
     `СубъектПерсональныхДанныхПередЗаписью` / `СубъектПерсональныхДанныхПриЗаписи`). В поставке там заглушка `ИдентификаторыОбъектовМетаданных`.
   - `ОпределяемыйТип.Организация` - оператор ПДн (используется в согласиях); `ФизическоеЛицо` - ответственный.
   - Роли из подсистемы: `ДобавлениеИзменениеСогласийНаОбработкуПерсональныхДанных`, `ЧтениеСогласийНаОбработкуПерсональныхДанных`,
     `ДобавлениеИзменениеАктовОбУничтоженииПерсональныхДанных`, `ЧтениеАктовОбУничтоженииПерсональныхДанных`,
     `ИспользованиеОбработкиУничтожениеПерсональныхДанных` - раздать в профили.
2. Переопределяемые процедуры (`ЗащитаПерсональныхДанныхПереопределяемый`):
   ```bsl
   Процедура ЗаполнитьСведенияОПерсональныхДанных(ТаблицаСведений) Экспорт
       Сведения = ТаблицаСведений.Добавить();
       Сведения.Объект          = "Справочник.ФизическиеЛица";
       Сведения.ПоляРегистрации = "Ссылка";
       Сведения.ПоляДоступа     = "СерияДокумента,НомерДокумента,КемВыданДокумент,ДатаВыдачиДокумента";
       Сведения.ОбластьДанных   = "ПаспортныеДанные";
   КонецПроцедуры

   Процедура ЗаполнитьОбластиПерсональныхДанных(КатегорииПерсональныхДанных) Экспорт
       Область = КатегорииПерсональныхДанных.Добавить();
       Область.Имя = "ПаспортныеДанные";
       Область.Представление = НСтр("ru = 'Паспортные данные'");
   КонецПроцедуры
   ```
   Уничтожение: `ПриЗаполненииСведенийОбУничтожаемыхПерсональныхДанных(ТаблицаСведений)` - каждое место хранения ПДн
   (`Объект`, `ПолеСубъект`, `Поля`, `КатегорияДанных`; поля ТЧ - полным именем
   `"Документ.X.ТабличнаяЧасть.Состав.Реквизит.ФизическоеЛицо"`), `ПередСкрытиемПерсональныхДанныхСубъектов`,
   `ПередУничтожениемПерсональныхДанных`, `ПослеУничтоженияПерсональныхДанных`.
   Сроки хранения: `ПриРасчетеСроковХраненияПерсональныхДанных(ДанныеСубъектов, СрокиХранения)`.
   Согласие: `ДополнитьДанныеСубъектовПерсональныхДанных`, `ДополнитьДанныеОрганизацииОператораПерсональныхДанных`,
   `ЗаполнитьФИОФизическогоЛица`. Функцию `ОрганизацияПоУмолчанию` размещать в модуле менеджера справочника организаций
   (в переопределяемом модуле она устарела).
3. Модули объектов/форм:
   - События, влияющие на срок хранения (создание физлица, приём, согласие), - регистрировать:
     `ЗащитаПерсональныхДанных.ДобавитьСубъектыДляРасчетаСроковХранения(Субъекты, ДатаСобытия)`.
   - Команда печати согласия в модуле менеджера субъекта:
     ```bsl
     Процедура ДобавитьКомандыПечати(КомандыПечати) Экспорт
         ЗащитаПерсональныхДанных.ДобавитьКомандуПечатиСогласияНаОбработкуПерсональныхДанных(КомандыПечати);
     КонецПроцедуры
     ```
   - Форма списка субъектов: `ЗащитаПерсональныхДанных.ПриСозданииНаСервереФормыСписка(ЭтотОбъект, Элементы.Список)` в
     `ПриСозданииНаСервере`; `ЗащитаПерсональныхДанных.ПриПолученииДанныхНаСервере(Настройки, Строки)` в обработчике
     `СписокПриПолученииДанныхНаСервере` (`&НаСервереБезКонтекста`); у динамического списка обязательна основная таблица.
     Клиент: `ЗащитаПерсональныхДанныхКлиент.ОбработкаОповещенияФормыСписка(...)`, `ПоказыватьСоСкрытымиПДн(...)`.
   - Форма субъекта: `ЗащитаПерсональныхДанныхКлиент.ОбработкаОповещенияФормы(ЭтотОбъект, ИмяСобытия)` в `ОбработкаОповещения`.

**Главные методы API** ([api/ЗащитаПерсональныхДанных.md](api/ЗащитаПерсональныхДанных.md)):
- `ЗащитаПерсональныхДанных.ДобавитьСубъектыДляРасчетаСроковХранения(Субъекты, ДатаСобытия, ...)`.
- `ЗащитаПерсональныхДанных.ДействующееСогласиеНаОбработкуПерсональныхДанных(Субъект, Организация, Дата)`.
- `ЗащитаПерсональныхДанных.ЭтоОбъектСУничтоженнымиПерсональнымиДанными(Объект)` - не отправлять/не редактировать «пустышки».
- `ЗащитаПерсональныхДанных.ИспользоватьУничтожениеПерсональныхДанныхСубъектов()`, `ДатаУничтоженияДанныхСубъекта(Субъект)`.
- `ЗащитаПерсональныхДанных.УстановитьИспользованиеСобытияДоступ(Использование, КатегорииДанных)` - включить журналирование
  новых категорий в обработчике обновления (само не включается).
- `ЗащитаПерсональныхДанных.ДобавитьКомандуПечатиСогласияНаОбработкуПерсональныхДанных(КомандыПечати)`.
- `ЗащитаПерсональныхДанныхКлиент.ОткрытьФормуСогласиеНаОбработкуПерсональныхДанных(ПараметрыПечати)`.

**Подводные камни:**
- Новый субъект/область в `ЗаполнитьСведенияОПерсональныхДанных` не начинает журналироваться автоматически -
  администратор включает сам, либо обработчик обновления вызывает `УстановитьИспользованиеСобытияДоступ`.
- Журнал «Доступ.Доступ» срабатывает на чтение указанных полей любым запросом - не перечислять «Наименование» у
  справочников, которые массово читаются в отчётах, без необходимости: растёт журнал регистрации.
- Уничтожение пишет объекты в режиме загрузки - ваши `ПередЗаписью` не сработают; доп. действия - в
  `ПередУничтожениемПерсональныхДанных`/`ПослеУничтоженияПерсональныхДанных`.
- Неполный список в `ПриЗаполненииСведенийОбУничтожаемыхПерсональныхДанных` = ПДн остаются в базе после «уничтожения»
  (регистры ФИО, ТЧ ведомостей, присоединённые файлы).

## ПрофилиБезопасности - разрешения на внешние ресурсы и безопасный режим

Модули подсистемы: `РаботаВБезопасномРежиме`, `РаботаВБезопасномРежимеКлиент`, `РаботаВБезопасномРежимеПереопределяемый`.

**Когда использовать:** код обращается к внешним ресурсам (интернет-адрес, каталог, COM, внешняя компонента, запуск
приложения ОС) или выполняет произвольный код (`Выполнить`/`Вычислить`, внешние обработки), а ИБ может работать
с включёнными профилями безопасности кластера (облако, требования ИБ). Заменяет: молчаливые сбои «нет прав на
сетевой ресурс», голые `Выполнить()`.

**Встраивание (рецепт):**
1. Метаданные: ничего не добавлять. Для своих подсистем-библиотек - тот же переопределяемый метод.
2. Переопределяемые процедуры (`РаботаВБезопасномРежимеПереопределяемый`):
   ```bsl
   Процедура ПриЗаполненииРазрешенийНаДоступКВнешнимРесурсам(ЗапросыРазрешений) Экспорт
       Разрешения = Новый Массив;
       Разрешения.Добавить(РаботаВБезопасномРежиме.РазрешениеНаИспользованиеИнтернетРесурса(
           "HTTPS", "api.partner.ru", 443, НСтр("ru = 'Обмен заказами с партнером'")));
       ЗапросыРазрешений.Добавить(
           РаботаВБезопасномРежиме.ЗапросНаИспользованиеВнешнихРесурсов(Разрешения));
   КонецПроцедуры
   ```
   Остальные (`ПриПроверкеВозможностиИспользованияПрофилейБезопасности(Отказ)` - если конфигурация не адаптирована,
   `Отказ = Истина`; `ПриПодключенииВнешнегоМодуля`, `ПриЗапросе...`) - нужны редко.
3. Ресурс, задаваемый пользователем в форме настроек (URL, каталог тома), - запрос разрешений по владельцу и применение
   на клиенте перед записью (образец - формы настроек `Обработка.ТранспортСообщенийОбменаHTTP`, тома файлов):
   ```bsl
   // Сервер
   Владелец = ОбщегоНазначения.ИдентификаторОбъектаМетаданных(Метаданные.Справочники.НастройкиПодключения); // или ссылка объекта
   Запрос = РаботаВБезопасномРежиме.ЗапросНаИспользованиеВнешнихРесурсов(Разрешения, Владелец, Истина);
   ЗапросыВнешнихРесурсов.Добавить(Запрос);
   // Клиент
   РаботаВБезопасномРежимеКлиент.ПрименитьЗапросыНаИспользованиеВнешнихРесурсов(ЗапросыВнешнихРесурсов, ЭтотОбъект, ОповещениеОЗакрытии);
   ```
   Удалили настройку - `ЗапросНаОчисткуРазрешенийИспользованияВнешнихРесурсов(Владелец)`.

**Главные методы API** ([api/ПрофилиБезопасности.md](api/ПрофилиБезопасности.md)):
- `РаботаВБезопасномРежиме.РазрешениеНаИспользованиеИнтернетРесурса(Протокол, Адрес, Порт, Описание)`.
- `РаботаВБезопасномРежиме.РазрешениеНаИспользованиеКаталогаФайловойСистемы(Адрес, ЧтениеДанных, ЗаписьДанных, Описание)`,
  `...КаталогаВременныхФайлов`, `...КаталогаПрограммы`.
- `РаботаВБезопасномРежиме.РазрешениеНаСозданиеCOMКласса(...)`, `РазрешениеНаИспользованиеВнешнейКомпоненты(ИмяМакета)`,
  `РазрешениеНаИспользованиеПриложенияОперационнойСистемы(ШаблонСтрокиЗапуска)`, `РазрешениеНаИспользованиеПривилегированногоРежима()`.
- `РаботаВБезопасномРежиме.ЗапросНаИспользованиеВнешнихРесурсов(НовыеРазрешения, Владелец, РежимЗамещения)`,
  `ЗапросНаОтменуРазрешенийИспользованияВнешнихРесурсов`, `ЗапросНаОчисткуРазрешенийИспользованияВнешнихРесурсов`.
- `РаботаВБезопасномРежимеКлиент.ПрименитьЗапросыНаИспользованиеВнешнихРесурсов(Идентификаторы, ФормаВладелец, ОповещениеОЗакрытии)`.
- `РаботаВБезопасномРежиме.УстановленБезопасныйРежим()`.
- Выполнение произвольного кода - `ОбщегоНазначения.ВыполнитьВБезопасномРежиме(Алгоритм, Параметры)` /
  `ОбщегоНазначения.ВычислитьВБезопасномРежиме(Выражение, Параметры)` (ядро БСП).

**Подводные камни:**
- Разрешение, не объявленное в `ПриЗаполненииРазрешенийНаДоступКВнешнимРесурсам` или по владельцу, на продуктиве с
  профилями безопасности даёт отказ платформы, хотя на стенде разработчика всё работает - тестировать с включёнными профилями.
- Запросы создаются на сервере, применяются на клиенте; в фоновом/регламентном коде интерактивно запросить нельзя -
  объявлять статически.
- Код, выполняемый в безопасном режиме, не может записывать ряд служебных объектов БСП (подписка
  `ПроверитьБезопасныйРежимПередЗаписью`) и вызывать часть API (проверка `ПользователиСлужебный.ПроверитьБезопасныйРежимОтключен`,
  например в `УправлениеДоступом.ОтключитьОбновлениеКлючейДоступа`).
- SaaS: разрешения согласуются с менеджером сервиса - только через этот API, без прямой работы с профилями кластера.

## КонтрольРаботыПользователей - аудит: журнал регистрации, изменения прав

**Когда использовать:** нужен отчёт «кто входил/что менял», аудит изменений учётных записей, групп доступа, ролей профилей,
регистрация чтения чувствительных полей. Встраивания в объекты не требует - это отчёты и настройки.

**Встраивание (рецепт):**
1. Метаданные: состав подсистемы - отчёты `АнализЖурналаРегистрации`, `ИзменениеУчетныхЗаписей`,
   `ИзменениеУчастниковГруппПользователей`, `ИзменениеУчастниковГруппДоступа`, `ИзменениеРазрешенныхЗначенийГруппДоступа`,
   `ИзменениеРолейПрофилей`; константы `РегистрироватьИзмененияПравДоступа`, `НастройкиРегистрацииСобытийДоступаКДанным`;
   общая форма `НастройкиРегистрацииСобытийДоступаКДанным`. Вывести отчёты в раздел администрирования.
2. Переопределяемые: своих нет. Регистрация чтения полей своих объектов - через
   `ПользователиПереопределяемый.ПриОпределенииНастроекРегистрацииСобытийДоступаКДанным(Настройки)`
   (массив `ОписаниеИспользованияСобытияДоступЖурналаРегистрации`), для ПДн - через ЗащитаПерсональныхДанных.
3. Программно (обработчик обновления/начальное заполнение):
   ```bsl
   КонтрольРаботыПользователей.УстановитьРегистрациюДоступаКДанным(Истина);
   ```

**Главные методы API** ([api/КонтрольРаботыПользователей.md](api/КонтрольРаботыПользователей.md)):
- `КонтрольРаботыПользователей.РегистрироватьДоступКДанным()` / `УстановитьРегистрациюДоступаКДанным(Булево)`.
- `КонтрольРаботыПользователей.НастройкиРегистрацииСобытийДоступаКДанным()` / `УстановитьНастройкиРегистрацииСобытийДоступаКДанным(Настройки)`.
- `Пользователи.НастройкиРегистрацииСобытийДоступаКДанным()` / `Пользователи.ОбновитьНастройкиРегистрацииСобытийДоступаКДанным()` -
  итоговые настройки события «Доступ.Доступ» из всех источников ([api/Пользователи.md](api/Пользователи.md)).

**Подводные камни:**
- Не вызывать платформенный `УстановитьИспользованиеСобытияЖурналаРегистрации` для «Доступ.Доступ» напрямую - перезатрёт
  настройки ЗПД и администратора; добавлять свои через `ПриОпределенииНастроекРегистрацииСобытийДоступаКДанным`.
- Регистрация доступа к часто читаемым полям резко увеличивает журнал регистрации и нагрузку.
