## ТекущиеДела - панель дел пользователя с количествами и ссылками

**Когда использовать:** надо показать пользователю «что требует внимания» (неподтвержденные заказы, просроченные задачи,
непроведенные документы) с числом и переходом в список с отбором. Заменяет самописные «рабочие столы» и оповещения при запуске.

**Встраивание в свой объект (рецепт):**
1. Метаданные: ничего. Дело размещается в раздел (подсистему командного интерфейса).
2. `ТекущиеДелаПереопределяемый.ПриОпределенииОбработчиковТекущихДел(ТекущиеДела)`:
   `ТекущиеДела.Добавить(Документы.ЗаказКлиента);` (модуль менеджера или общий модуль).
   Отключить чужие дела: `ПриОтключенииТекущихДел(ОтключаемыеДела)` - идентификаторы строками.
3. Модуль менеджера - процедура обработчика (образец `ДополнительныеОтчетыИОбработки.ПриЗаполненииСпискаТекущихДел`):
   ```bsl
   // Параметры:
   //   ТекущиеДела - см. ТекущиеДелаСервер.ТекущиеДела.
   Процедура ПриЗаполненииСпискаТекущихДел(ТекущиеДела) Экспорт
       Если Не ПравоДоступа("Редактирование", Метаданные.Документы.ЗаказКлиента)
           Или ТекущиеДелаСервер.ДелоОтключено("НеподтвержденныеЗаказы") Тогда
           Возврат;
       КонецЕсли;
       Запрос = Новый Запрос("ВЫБРАТЬ РАЗРЕШЕННЫЕ КОЛИЧЕСТВО(*) КАК Количество
           |ИЗ Документ.ЗаказКлиента КАК З ГДЕ З.Проведен И НЕ З.Подтвержден");
       Количество = Запрос.Выполнить().Выгрузить()[0].Количество;
       Для Каждого Раздел Из ТекущиеДелаСервер.РазделыДляОбъекта("Документ.ЗаказКлиента") Цикл
           Дело = ТекущиеДела.Добавить();
           Дело.Идентификатор  = "НеподтвержденныеЗаказы";
           Дело.ЕстьДела       = Количество > 0;
           Дело.Количество     = Количество;
           Дело.Представление  = НСтр("ru = 'Неподтвержденные заказы'");
           Дело.Форма          = "Документ.ЗаказКлиента.ФормаСписка";
           Дело.ПараметрыФормы = Новый Структура("Отбор", Новый Структура("Подтвержден", Ложь));
           Дело.Владелец       = Раздел; // подсистема или идентификатор дела-группы
       КонецЦикла;
   КонецПроцедуры
   ```
   В БСП модули, где подсистема может отсутствовать, вызывают через `ОбщегоНазначения.ОбщийМодуль("ТекущиеДелаСервер")`.

**Главные методы API** (`api/ТекущиеДела.md`):
- `ТекущиеДелаСервер.ТекущиеДела` - описание колонок таблицы дел (`Важное`, `ВыводитьВОповещениях`, `Подсказка` ...).
- `ТекущиеДелаСервер.РазделыДляОбъекта(ИмяОбъектаМетаданных)` - в какие разделы положить дело.
- `ТекущиеДелаСервер.ДелоОтключено(ИдентификаторДела)` - уважать отключение в переопределяемом модуле.
- `ТекущиеДелаСервер.ЧисловыеПоказателиТекущихДел(Запрос)` - несколько показателей одним запросом.
- `ТекущиеДелаСервер.УстановитьПараметрыЗапросов` / `ТекущиеДелаПереопределяемый.УстановитьОбщиеПараметрыЗапросов` - общие параметры.
- `ТекущиеДелаКлиент.ОткрытьСписокТекущихДел` - открыть панель.

**Подводные камни:**
- Обработчик выполняется для каждого пользователя при открытии/обновлении панели: только агрегирующий запрос с индексами,
  без циклов по объектам. `РАЗРЕШЕННЫЕ` обязательно при RLS.
- Проверяйте права и ФО до запроса - иначе пользователь увидит дело, которое не может открыть.
- `Идентификатор` уникален в пределах конфигурации; при выводе в несколько разделов - одинаковый `Идентификатор`, разные `Владелец`.

## КонтрольВеденияУчета - правила проверки данных и индикация проблем в формах

**Когда использовать:** систематические проверки корректности учета (незаполненные реквизиты, отрицательные остатки,
нарушения сквозной нумерации) с регламентным запуском, журналом проблем и индикатором в формах. Заменяет «отчеты-проверки»
и самописные регистры ошибок.

**Встраивание в свой объект (рецепт):**
1. Метаданные: при необходимости дополнить определяемые типы `КонтекстПроверокВеденияУчета` /
   `УточнениеКонтекстаПроверокВеденияУчета` своим типом контекста (обычно достаточно строки).
2. `КонтрольВеденияУчетаПереопределяемый.ПриОпределенииПроверок(ГруппыПроверок, Проверки)` (по примеру из комментария модуля):
   ```bsl
   Группа = ГруппыПроверок.Добавить();
   Группа.Наименование        = НСтр("ru='Проверки продаж'");
   Группа.Идентификатор       = "МояКонфигурация.ПроверкиПродаж";
   Группа.ИдентификаторГруппы = "ПроверкиПродаж";
   Проверка = Проверки.Добавить();
   Проверка.ИдентификаторГруппы = "ПроверкиПродаж";
   Проверка.Идентификатор       = "МояКонфигурация.ЗаказБезМенеджера";
   Проверка.Наименование        = НСтр("ru='Заказы без менеджера'");
   Проверка.Причины             = НСтр("ru='Не заполнен менеджер.'");
   Проверка.Рекомендация        = НСтр("ru='Заполнить менеджера в заказе.'");
   Проверка.ОбработчикПроверки  = "ПроверкиПродаж.ПроверитьЗаказыБезМенеджера"; // серверный общий модуль
   Проверка.ДатаНачалаПроверки  = Дата(2024, 1, 1);
   Проверка.ЛимитПроблем        = 1000;
   Проверка.ПоддерживаетВыборочнуюПроверку = Истина;
   ```
   Обработчик (сигнатура как у `КонтрольВеденияУчетаСлужебный.ПроверитьСсылочнуюЦелостность`):
   ```bsl
   Процедура ПроверитьЗаказыБезМенеджера(Проверка, ПараметрыПроверки) Экспорт
       // при выборочной проверке: ПараметрыПроверки.ПроверяемыеОбъекты (ссылка или массив)
       Для Каждого Ссылка Из НайденныеЗаказы Цикл
           Проблема = КонтрольВеденияУчета.ОписаниеПроблемы(Ссылка, ПараметрыПроверки);
           Проблема.УточнениеПроблемы = НСтр("ru='Не заполнен менеджер'");
           КонтрольВеденияУчета.ЗаписатьПроблему(Проблема, ПараметрыПроверки);
       КонецЦикла;
   КонецПроцедуры
   ```
3. Формы:
   ```bsl
   // Форма объекта
   &НаСервере Процедура ПриЧтенииНаСервере(ТекущийОбъект)
       КонтрольВеденияУчета.ПриЧтенииНаСервере(ЭтотОбъект, ТекущийОбъект);   // важное сообщение о проблемах
   КонецПроцедуры
   &НаСервере Процедура ПослеЗаписиНаСервере(ТекущийОбъект, ПараметрыЗаписи)
       КонтрольВеденияУчета.ПослеЗаписиНаСервере(ТекущийОбъект);             // фоновая перепроверка объекта
   КонецПроцедуры
   // Форма списка: ПриСозданииНаСервере
   КонтрольВеденияУчета.ПриСозданииНаСервереФормыСписка(ЭтотОбъект, "Список"); // колонка-индикатор
   // событие списка ПриПолученииДанныхНаСервере (&НаСервереБезКонтекста)
   КонтрольВеденияУчета.ПриПолученииДанныхНаСервере(Настройки, Строки);
   // если у таблицы не было действия "Выбор", БСП ставит "Подключаемый_Выбор" - объявить в форме:
   &НаКлиенте Процедура Подключаемый_Выбор(Элемент, ВыбраннаяСтрока, Поле, СтандартнаяОбработка)
       КонтрольВеденияУчетаКлиент.ОткрытьОтчетПоПроблемамИзСписка(ЭтотОбъект, "Список", Поле, СтандартнаяОбработка);
   КонецПроцедуры
   ```

**Главные методы API** (`api/КонтрольВеденияУчета.md`):
- `КонтрольВеденияУчета.ОписаниеПроблемы` + `ЗаписатьПроблему` - регистрация проблемы из обработчика.
- `КонтрольВеденияУчета.ВыполнитьПроверку` / `ВыполнитьПроверкиВКонтексте` - запуск из кода (например, при закрытии месяца).
- `КонтрольВеденияУчета.КоличествоПроблемПоОбъекту` / `ПроблемныеОбъекты` - чтение результатов.
- `КонтрольВеденияУчета.ИгнорироватьПроблему` - пометить проблему игнорируемой.
- `КонтрольВеденияУчета.ПриЧтенииНаСервере` / `ПриСозданииНаСервереФормыСписка` / `ПриПолученииДанныхНаСервере` - формы.
- `КонтрольВеденияУчетаКлиент.ОткрытьОтчетПоПроблемам(ВидПроверок)` - отчет по проблемам.

**Подводные камни:**
- `Идентификатор` проверки - формат «<Продукт>.<Проверка>», не менять после выпуска (по нему хранятся правила и настройки важности).
- Обработчик выполняется в регламентном задании `ПроверкаВеденияУчета` порциями - учитывайте `ДатаНачалаПроверки` и
  `ЛимитПроблем`, не выбирайте всю базу.
- У динамического списка должна быть задана основная таблица, иначе индикатор не добавится.

## ОценкаПроизводительности - замеры времени ключевых операций (APDEX)

**Когда использовать:** надо измерять время проведения, открытия форм, формирования отчетов у пользователей в продуктиве
и считать APDEX. Заменяет самописные `ТекущаяУниверсальнаяДатаВМиллисекундах()` с записью в журнал.
Замеры пишутся, только если включена константа `ВыполнятьЗамерыПроизводительности`.

**Встраивание (рецепт):**
1. Метаданные: ничего; ключевые операции создаются автоматически по имени (справочник `КлючевыеОперации`).
2. Переопределяемых процедур нет.
3. Вызовы в коде:
   ```bsl
   // Сервер (как в ОбновлениеИнформационнойБазыСлужебный.ВыполнитьОбработчикОбновления)
   Если ОбщегоНазначения.ПодсистемаСуществует("СтандартныеПодсистемы.ОценкаПроизводительности") Тогда
       МодульОценкаПроизводительности = ОбщегоНазначения.ОбщийМодуль("ОценкаПроизводительности");
       НачалоЗамера = МодульОценкаПроизводительности.НачатьЗамерВремени();
   КонецЕсли;
   // ... операция ...
   Если НачалоЗамера <> Неопределено Тогда
       МодульОценкаПроизводительности.ЗакончитьЗамерВремени("Документ.ЗаказКлиента.Проведение", НачалоЗамера, КоличествоСтрок);
   КонецЕсли;

   // Клиент: замер интерактивного действия, завершается автоматически по обработчику ожидания
   ИдентификаторЗамера = ОценкаПроизводительностиКлиент.ЗамерВремени("ЗаказКлиента.ОткрытиеФормы");
   // или с явным завершением: ЗамерВремени(..., , Ложь) + ОценкаПроизводительностиКлиент.ЗавершитьЗамерВремени(ИдентификаторЗамера)
   ```
   Длительные операции с шагами: `НачатьЗамерДлительнойОперации` → `ЗафиксироватьЗамерДлительнойОперации` →
   `ЗакончитьЗамерДлительнойОперации`.

**Главные методы API** (`api/ОценкаПроизводительности.md`):
- `ОценкаПроизводительности.НачатьЗамерВремени` / `ЗакончитьЗамерВремени(КлючеваяОперация, ВремяНачала, ВесЗамера)`.
- `ОценкаПроизводительности.ЗакончитьЗамерВремениТехнологический` - технологические замеры (не в APDEX).
- `ОценкаПроизводительности.НачатьЗамерДлительнойОперации` / `ЗафиксироватьЗамерДлительнойОперации` / `ЗакончитьЗамерДлительнойОперации`.
- `ОценкаПроизводительности.СоздатьКлючевыеОперации` / `УстановитьЦелевоеВремя` - целевое время из обработчика обновления.
- `ОценкаПроизводительностиКлиент.ЗамерВремени` / `ЗавершитьЗамерВремени` / `УстановитьКомментарийЗамера` / `УстановитьВесЗамера`.

**Подводные камни:**
- Клиентские замеры буферизуются и пишутся раз в период (константа `ОценкаПроизводительностиПериодЗаписи`) - при
  закрытии сеанса часть теряется; для точных серверных операций мерьте на сервере.
- Имя ключевой операции - стабильная строка («Объект.Действие»); динамические имена плодят тысячи ключевых операций.
- `ВесЗамера` (строк в документе) нужен, иначе APDEX больших документов несопоставим с маленькими.

## ПоискИУдалениеДублей - поиск, объединение и замена дублей справочников

**Когда использовать:** дубли контрагентов/номенклатуры: обработка «Поиск и удаление дублей», команды «Объединить
выделенные», «Заменить выделенные» в списках, поиск дублей при вводе (`НайтиДублиЭлемента`). Заменяет самописные
«обработки замены ссылок» (БСП меняет ссылки во всех местах использования с контролем).

**Встраивание в свой объект (рецепт):**
1. Метаданные: ничего; команды списков выводятся подключаемыми командами (форма списка должна вызывать
   `ПодключаемыеКоманды.ПриСозданииНаСервере`).
2. Переопределяемые процедуры (`ПоискИУдалениеДублейПереопределяемый`):
   ```bsl
   Процедура ПриОпределенииОбъектовСКомандамиОбъединенияДублейЗаменыСсылок(Объекты) Экспорт
       Объекты.Добавить(Метаданные.Справочники.Контрагенты);
   КонецПроцедуры
   Процедура ПриОпределенииОбъектовСПоискомДублей(Объекты) Экспорт
       Объекты.Вставить(Метаданные.Справочники.Контрагенты.ПолноеИмя(), ""); // "" = все три процедуры в менеджере
   КонецПроцедуры
   ```
3. Модуль менеджера (образец `Справочник.ВидыКонтактнойИнформации`):
   ```bsl
   // СтандартныеПодсистемы.ПоискИУдалениеДублей
   Процедура ПараметрыПоискаДублей(ПараметрыПоиска, ДополнительныеПараметры = Неопределено) Экспорт
       Ограничение = Новый Структура("Представление, ДополнительныеПоля",
           НСтр("ru = 'Совпадает ИНН'"), "ИНН");
       ПараметрыПоиска.ОграниченияСравнения.Добавить(Ограничение);
       ПараметрыПоиска.КоличествоЭлементовДляСравнения = 100;
   КонецПроцедуры
   Процедура ПриПоискеДублей(ДублиЭлементов, ДополнительныеПараметры = Неопределено) Экспорт
       Для Каждого Дубль Из ДублиЭлементов Цикл
           Дубль.ЭтоДубли = (Дубль.Поля1.ИНН = Дубль.Поля2.ИНН);
       КонецЦикла;
   КонецПроцедуры
   Функция ВозможностьЗаменыЭлементов(Знач ПарыЗамен, Знач ПараметрыЗамены = Неопределено) Экспорт
       Результат = Новый Соответствие; // Ключ - заменяемая ссылка, Значение - причина запрета
       Возврат Результат;
   КонецФункции
   // Конец СтандартныеПодсистемы.ПоискИУдалениеДублей
   ```

**Главные методы API** (`api/ПоискИУдалениеДублей.md`):
- `ПоискИУдалениеДублей.НайтиДублиЭлемента(ОбластьПоиска, ЭталонныйОбъект, ДополнительныеПараметры)` - дубли при вводе.
- `ПоискИУдалениеДублей.НайтиПохожиеСтроки` / `ПараметрыПоискаПохожихСтрок` - нечеткое сравнение строк.
- `ПоискИУдалениеДублей.ДополнитьДублиСвязаннымиПодчиненнымиОбъектами` - учет подчиненных справочников.
- `ПоискИУдалениеДублейКлиент.ОбъединитьВыделенные` / `ЗаменитьВыделенные` / `ПоказатьМестаИспользования`.
- `ОбщегоНазначения.ЗаменитьСсылки` (базовая функциональность) - программная замена с вызовом `ВозможностьЗаменыЭлементов`.

**Подводные камни:**
- Замена ссылок переписывает документы (в т.ч. проведенные) - на больших базах долго; запускайте вне рабочего времени.
- Правила «Подобно» на больших справочниках дороги: ограничивайте `КомпоновщикОтбора` и `КоличествоЭлементовДляСравнения`.
- Бизнес-запреты (разные виды номенклатуры, разные организации) - только в `ВозможностьЗаменыЭлементов`, иначе пользователь объединит несовместимое.

## УдалениеПомеченныхОбъектов - удаление помеченных с контролем ссылок

**Когда использовать:** интерактивное/регламентное удаление помеченных (задание `УдалениеПомеченныхОбъектов`),
команды «Показать помеченные» в списках, удаление из кода с контролем ссылочной целостности. Заменяет самописные
циклы `Объект.Удалить()` и платформенное «Удаление помеченных объектов».

**Встраивание (рецепт):**
1. Метаданные: ничего.
2. `УдалениеПомеченныхОбъектовПереопределяемый.ПриОпределенииОбъектовСКомандойПоказатьПомеченные(Объекты)` -
   `Объекты.Добавить(Метаданные.Справочники.Номенклатура)` (команды - через подключаемые команды списка).
   Свои действия вокруг удаления: `ПередУдалениемГруппыОбъектов(Контекст, УдаляемыеОбъекты)` / `ПослеУдаленияГруппыОбъектов`;
   отбор кандидатов: `ПередПоискомПомеченныхНаУдаление`.
3. Форма списка, `ПриСозданииНаСервере`: `УдалениеПомеченныхОбъектов.ПриСозданииНаСервере(ЭтотОбъект, Элементы.Список);`
   Удаление из кода: `Результат = УдалениеПомеченныхОбъектов.УдалитьПомеченныеОбъекты(МассивСсылок);` → `Результат.Успешно`,
   `Результат.ПрепятствующиеУдалению`.

**Главные методы API** (`api/УдалениеПомеченныхОбъектов.md`):
- `УдалениеПомеченныхОбъектов.УдалитьПомеченныеОбъекты(УдаляемыеОбъекты, РежимУдаления)` - "Стандартный"/"Монопольный"/"Упрощенный".
- `УдалениеПомеченныхОбъектов.ПомеченныеНаУдаление` / `СсылкиНаУдаляемыеОбъекты` - кандидаты и места использования.
- `УдалениеПомеченныхОбъектов.ПриСозданииНаСервере` / `НастройкиОтображенияПомеченныхОбъектов` - видимость в списках.
- `УдалениеПомеченныхОбъектовКлиент.НачатьУдалениеПомеченных` / `ПерейтиКПомеченнымНаУдаление`.

**Подводные камни:**
- `УдалитьПомеченныеОбъекты` вызывать **вне транзакции** - функция сама управляет транзакциями и порциями.
- Режим "Упрощенный" очищает ссылки в других помеченных объектах - необратимо.
- Объект не удаляется, если на него есть ссылки, в т.ч. из регистров сведений без регистратора - результат надо показать пользователю.

## ЗавершениеРаботыПользователей - блокировка сеансов и выгон пользователей

**Когда использовать:** перед регламентными операциями (обновление, свертка, пересчет итогов) нужно запретить вход и
завершить сеансы с предупреждением пользователей. Модули подсистемы называются `СоединенияИБ*`.

**Встраивание (рецепт):**
1. Метаданные: ничего (обработки `БлокировкаРаботыПользователей`, `АктивныеПользователи` уже есть).
2. `СоединенияИБПереопределяемый.ПриОпределенииПараметровБлокировкиСеансов(ПараметрыБлокировкиСеансов)` - изменить
   сообщение/интервалы (структура - см. `СоединенияИБ.ПараметрыБлокировкиСеансов`).
3. Код:
   ```bsl
   Если СоединенияИБ.УстановитьБлокировкуСоединений(НСтр("ru = 'Пересчет итогов'"), "КодРазрешения", 5, 60) Тогда
       Попытка
           // ... работа ...
       Исключение
           СоединенияИБ.РазрешитьРаботуПользователей();
           ВызватьИсключение;
       КонецПопытки;
       СоединенияИБ.РазрешитьРаботуПользователей();
   КонецЕсли;
   ```

**Главные методы API** (`api/ЗавершениеРаботыПользователей.md`):
- `СоединенияИБ.УстановитьБлокировкуСоединений` / `РазрешитьРаботуПользователей` / `УстановленаБлокировкаСоединений`.
- `СоединенияИБ.ИнформацияОСоединениях` - есть ли активные/COM/конфигуратор-соединения.
- `СоединенияИБ.ПараметрыБлокировкиСеансов` - для клиента.
- `СоединенияИБ.УстановитьБлокировкуСеансовОбластиДанных` - то же для области (модель сервиса).
- `СоединенияИБКлиент.УстановитьРежимЗавершенияРаботыПользователей` - завершение работы с текущего клиента.

**Подводные камни:**
- Функции возвращают Ложь при недостатке прав - проверяйте результат.
- Всегда снимайте блокировку в ветке исключения, иначе база останется закрытой для всех.
- Блокировка не завершает COM-соединения и конфигуратор - проверяйте `ИнформацияОСоединениях`.

## ЦентрМониторинга - статистика использования и бизнес-операций

**Когда использовать:** собирать счетчики бизнес-операций и статистику конфигурации (с отправкой в 1С при согласии
пользователя). Внутри своей компании полезно как дешевый счетчик операций. Отправку включает администратор
(`НастройкиПрограммыКлиент.ИнтернетПоддержкаИСервисыЦентрМониторингаНастройки`).

**Встраивание (рецепт):**
1. Метаданные: ничего.
2. `ЦентрМониторингаПереопределяемый.ПриСбореПоказателейСтатистикиКонфигурации()` - вызов
   `ЦентрМониторинга.ЗаписатьСтатистикуОбъектаКонфигурации("Документ.ЗаказКлиента", КоличествоЗаказов)`;
   `ПриОпределенииНастроек(Настройки)` - `ВключитьОповещение`.
3. В коде операции: `ЦентрМониторинга.ЗаписатьОперациюБизнесСтатистики("Продажи.ЗаказКлиента.Проведение", 1);`
   (на клиенте - `ЦентрМониторингаКлиент.ЗаписатьОперациюБизнесСтатистики`).

**Главные методы API** (`api/ЦентрМониторинга.md`): `ЦентрМониторинга.ЗаписатьОперациюБизнесСтатистики` /
`ЗаписатьОперациюБизнесСтатистикиЧас` / `ЗаписатьОперациюБизнесСтатистикиСутки`, `ЗаписыватьОперацииБизнесСтатистики`,
`ЗаписатьСтатистикуОбъектаКонфигурации`, `ЦентрМониторингаВключен`, `ИдентификаторИнформационнойБазы`.

**Подводные камни:** не передавайте в имя операции или комментарий персональные данные; клиентские операции
кэшируются и при закрытии приложения не записываются.

## ОбновлениеКонфигурации - установка обновлений и исправлений (патчей)

**Когда использовать:** установка .cfu/патчей из интерфейса (Windows, толстый/тонкий клиент с конфигуратором),
программная установка патчей. Встраивать почти нечего - подсистема работает из панели «Администрирование».

**Встраивание:** метаданных и переопределяемых процедур нет. Из своего кода:
`ОбновлениеКонфигурацииКлиент.ПоказатьПоискИУстановкуОбновлений()`, проверка возможности -
`ОбновлениеКонфигурацииКлиент.ПоддерживаетсяУстановкаОбновлений()`. Пакетное обновление скриптом: перед
`ОбновлениеИнформационнойБазы.ВыполнитьОбновлениеИнформационнойБазы` вызвать `ОбновлениеКонфигурации.ИсправленияИзменены()`.

**Главные методы API** (`api/ОбновлениеКонфигурации.md`): `ОбновлениеКонфигурации.УстановкаИУдалениеИсправлений`,
`ПараметрыУстановкиИсправлений`, `УстановленныеИсправления`, `ИсправленияИзменены`, `ПредупреждатьОНаличииРасширений`,
`НастройкиОбновленияКонфигурации`.

**Подводные камни:** установка недоступна через веб-клиент/веб-сервер, вне Windows, без конфигуратора и в модели
сервиса (см. `ПоддерживаетсяУстановкаОбновлений`). Патчи - это расширения: свои расширения команды показываются
в предупреждении `ПредупреждатьОНаличииРасширений`.

## РезервноеКопированиеИБ - резервное копирование файловой базы

**Когда использовать:** файловые базы у клиентов без админа: автоматическое копирование по расписанию при выходе/запуске.
Для клиент-серверных баз копирование делается средствами СУБД, подсистема только напоминает.

**Встраивание:** метаданных нет. `РезервноеКопированиеИБКлиентПереопределяемый.ПриОпределенииНеобходимостиПоказаПредупрежденийОРезервномКопировании(ПоказыватьПредупреждение)`
- включить напоминания (по умолчанию отключены). Открыть форму: `РезервноеКопированиеИБКлиент.ОткрытьФормуРезервногоКопирования()`.

**Главные методы API** (`api/РезервноеКопированиеИБ.md`): `РезервноеКопированиеИБКлиент.ОткрытьФормуРезервногоКопирования`,
`ОбновлениеКонфигурацииКлиент.ПоказатьРезервноеКопирование`.

**Подводные камни:** копирование файловой базы требует завершения сеансов (использует ЗавершениеРаботыПользователей);
не считайте его заменой серверного бэкапа.

## УправлениеИтогамиИАгрегатами - регламентный сдвиг итогов и агрегатов

**Когда использовать:** базы с регистрами накопления/бухгалтерии - автоматическая установка периода рассчитанных итогов
(задание `УстановкаПериодаРассчитанныхИтогов`), обновление/перестроение агрегатов (`ОбновлениеАгрегатов`,
`ПерестроениеАгрегатов`), обработка `УправлениеИтогамиИАгрегатами`. Публичного API нет.

**Встраивание:** ничего - задание обходит все оборотные/остаточные регистры (`УправлениеИтогамиИАгрегатамиСлужебный.РассчитатьИтоги`):
регистры накопления - на конец прошлого месяца, бухгалтерии - на конец текущего. Минимальный период задается константой
`КоличествоМесяцевМинимальногоПериодаРассчитанныхИтогов`.

**Подводные камни:** не пишите свой регламент «УстановитьМаксимальныйПериодРассчитанныхИтогов» - будет конфликт;
документы задним числом в прошлых периодах после сдвига границы пересчитывают итоги - это нормально, но дорого.

## ПроверкаЛегальностиПолученияОбновления - подтверждение легальности обновления

**Когда использовать:** только для тиражных конфигураций 1С. Для собственных конфигураций обычно отключают.

**Встраивание:** `ПроверкаЛегальностиПолученияОбновленияПереопределяемый.ПриОпределенииНастроек(Настройки)` -
`Настройки.ТребуетсяПроверитьЛегальностьПолученияОбновления = Ложь`, если проверка не нужна (собственная/арендованная база).
Явный вызов: `ПроверкаЛегальностиПолученияОбновленияКлиент.ПоказатьПроверкуЛегальностиПолученияОбновления(Оповещение)`.

**Подводные камни:** при включенной проверке первый запуск после обновления показывает диалог; в автотестах и
пакетных обновлениях это блокирует сценарий.

## НастройкиПрограммы - панели администрирования БСП

**Когда использовать:** раздел «Администрирование» (обработка `ПанельАдминистрированияБСП`: Общие настройки,
Обслуживание, Пользователи и права, Интернет-поддержка, Органайзер, Синхронизация, Работа с файлами, Печатные формы).

**Встраивание:** формы панели не снимать с поддержки - менять через `НастройкиПрограммыПереопределяемый.<Форма>ПриСозданииНаСервере(Форма)`:
`ОбщиеНастройкиПриСозданииНаСервере`, `ОбслуживаниеПриСозданииНаСервере`, `НастройкиПользователейИПравПриСозданииНаСервере`,
`ИнтернетПоддержкаИСервисыПриСозданииНаСервере`, `ОрганайзерПриСозданииНаСервере`, `СинхронизацияДанныхПриСозданииНаСервере`,
`НастройкиРаботыСФайламиПриСозданииНаСервере`, `ПечатныеФормыОтчетыИОбработкиПриСозданииНаСервере`
(например, `Форма.Элементы.ГруппаX.Видимость = Ложь`). Свои настройки своих подсистем - в собственных панелях
по образцу формы БСП (константа + `ПриИзменении` → запись), а не в формах БСП.

**Главные методы API** (`api/НастройкиПрограммы.md`): процедуры `НастройкиПрограммы.ИнтернетПоддержкаИСервисы*` и
`НастройкиПрограммыКлиент.ИнтернетПоддержкаИСервисы*` - для переноса блоков формы «Интернет-поддержка и сервисы» в свою панель.

**Подводные камни:** элементы формы панели меняются от версии к версии БСП - обращаясь по имени, проверяйте `Элементы.Найти(...)`.

## ИнформацияПриЗапуске - стартовые информационные страницы

**Когда использовать:** показать при входе HTML-страницы (новости версии, реклама, обучение). Содержимое - двоичные
макеты-пакеты страниц в обработке `ИнформацияПриЗапуске` и табличный макет `Описатель` (колонки: имя макета, раздел,
наименование и файл стартовой страницы, даты показа, приоритет, ПоказыватьВПроф/ВБазовой/ВМоделиСервиса).

**Встраивание:** добавить макеты-пакеты и строки в `Описатель`; при необходимости
`ИнформацияПриЗапускеПереопределяемый.ОпределитьНастройки(Настройки)` → `Настройки.Показывать = Ложь` (например, для
ролей или внутренних баз). Если макетов нет, информация не показывается.

**Подводные камни:** окно не показывается, если в этом запуске выводится описание изменений после обновления или
помощник настройки подчиненного узла РИБ - не используйте подсистему для критичных уведомлений.
