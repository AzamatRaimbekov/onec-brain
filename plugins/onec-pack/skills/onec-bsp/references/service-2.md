## ВерсионированиеОбъектов - история изменений объекта

**Когда использовать:** «кто и что поменял в документе/карточке», сравнение версий, откат к версии. Заменяет самописные регистры логов изменений и разбор журнала регистрации.

**Встраивание в свой объект (рецепт):**
1. **Метаданные.**
   - Определяемый тип `ВерсионируемыеДанные` += ссылка на объект (параметр общей команды `ИсторияИзменений`, группа «Важное» командной панели формы).
   - Справочники, ПВХ, бизнес-процессы и т.п.: определяемый тип `ВерсионируемыеДанныеОбъект` += `<Вид>Объект.<Имя>` - его использует подписка `ЗаписатьВерсиюОбъекта` (ПередЗаписью, обработчик `ВерсионированиеОбъектовСобытия.ЗаписатьВерсиюОбъекта(Источник, Отказ)`).
   - **Документы в `ВерсионируемыеДанныеОбъект` не добавлять**: у ПередЗаписью документа 4 параметра, а обработчик подписки двухпараметрический («кроме документов» - комментарий в исходнике). Для документов создать свою подписку: событие `ПередЗаписью`, источник - `ДокументОбъект.<Имя>`, обработчик `ВерсионированиеОбъектовСобытия.ЗаписатьВерсиюДокумента` (`Источник, Отказ, РежимЗаписи, РежимПроведения`).
   - Роли: `ЧтениеВерсийОбъектов` (просмотр/сравнение), `ЧтениеИнформацииОВерсияхОбъектов`.
2. **Формы объекта и списка:** в `ПриСозданииНаСервере`
   ```bsl
   ВерсионированиеОбъектов.ПриСозданииНаСервере(ЭтотОбъект);
   ```
   Процедура устанавливает параметр ФО формы `ТипВерсионируемогоОбъекта`, поэтому команда «История изменений» видна только когда версионирование этого типа включено. Без вызова команда показывается всегда.
3. **Включить версионирование** - администратор в настройках (`ВерсионированиеОбъектовКлиент.ПоказатьНастройку()`), либо кодом в обработчике обновления/начального заполнения:
   ```bsl
   ВерсионированиеОбъектов.ВключитьВерсионированиеОбъекта("Документ.РасходнаяНакладная",
       Перечисления.ВариантыВерсионированияОбъектов.ВерсионироватьПриПроведении);
   ```
   Варианты: `ВерсионироватьПриЗаписи`, `ВерсионироватьПриПроведении`, `ВерсионироватьПриСтарте`, `НеВерсионировать`. Срок хранения - `ЗаписатьНастройкуВерсионированияПоОбъекту(Тип, Вариант, Перечисления.СрокиХраненияВерсий.ЗаПоследнийГод)`; очистку делает регламентное задание `ОчисткаУстаревшихВерсийОбъектов`.
4. **Переопределяемые (по необходимости):** `ВерсионированиеОбъектовПереопределяемый.ПриВыбореРеквизитовОбъекта` / `ПриОпределенииНаименованияРеквизитаОбъекта` (скрыть служебные реквизиты в отчете), `ПриПолученииТабличныхДокументовОбъекта` (показать «техногенную» ТЧ как табличный документ), `ПриПодготовкеДанныхОбъекта` / `ПриВосстановленииВерсииОбъекта` (доп. данные, например доп. сведения, сохраняемые вместе с версией).

**Главные методы API** (`api/ВерсионированиеОбъектов.md`):
- `ВерсионированиеОбъектов.ПриСозданииНаСервере(Форма)` - подключение к форме.
- `ВерсионированиеОбъектов.ВключитьВерсионированиеОбъекта` / `ВключитьВерсионированиеОбъектов` - включить кодом.
- `ВерсионированиеОбъектов.ЗаписатьНастройкуВерсионированияПоОбъекту` - вариант и срок хранения.
- `ВерсионированиеОбъектов.ВключеноВерсионированиеОбъекта(ИмяОбъекта)` - проверка.
- `ВерсионированиеОбъектовКлиент.ОткрытьОтчетПоИзменениям` / `ОткрытьОтчетПоВерсииОбъекта` - отчеты из своего кода.
- `ВерсионированиеОбъектовСобытия.ЗаписатьВерсиюОбъекта` / `ЗаписатьВерсиюДокумента` - обработчики подписок.

**Подводные камни:**
- Регистр `ВерсииОбъектов` быстро растет (полная сериализация объекта на каждую запись) - для документов с большими ТЧ выбирайте `ВерсионироватьПриПроведении` и ограниченный срок хранения.
- При загрузке в обмене (`ОбменДанными.Загрузка` и `Отправитель = Неопределено`) версия не пишется; при обмене через план обмена - пишется (так задумано, см. комментарий в `ВерсионированиеОбъектовСобытия`).
- Массовая перезапись объектов обработчиком обновления создает по версии на объект - учитывайте объем.

## ЗаметкиПользователя - личные заметки по предмету

**Когда использовать:** пользователю нужны личные пометки к документу/контрагенту («позвонить в пятницу») без изменения объекта. Заменяет реквизит «Комментарий» для личных заметок.

**Встраивание в свой объект (рецепт):**
1. **Метаданные:** определяемый тип `ПредметЗаметок` += ссылка на объект (команды `МоиЗаметкиПоПредмету` в панели навигации и `СоздатьЗаметкуПоПредмету` в группе «Органайзер»); `ПредметЗаметокОбъект` += объект (подписка `УстановитьСнятьПометкуУдаленияЗаметок`, ПриЗаписи: заметки помечаются на удаление вместе с предметом). Роль `ДобавлениеИзменениеЗаметок`. Функциональные опции `ИспользоватьЗаметки`, `ИспользоватьКомандуЗаметки`.
2. **Снятие пометки удаления** заметок при снятии пометки с предмета работает только если перед записью предмета установлен признак `ДополнительныеСвойства.СнятаПометкаУдаления`. БСП делает это подпиской лишь для `Справочник.Пользователи`. Для своих объектов создайте подписку `ПередЗаписью` с обработчиком `ЗаметкиПользователя.УстановитьСтатусИзмененияПометкиУдаленияОбъекта` (не документы) или `ЗаметкиПользователя.УстановитьСтатусИзмененияПометкиУдаленияДокумента` (документы).
3. Кода в формах не требуется.

**Главные методы API** (`api/ЗаметкиПользователя.md`): `ЗаметкиПользователя.УстановитьСтатусИзмененияПометкиУдаленияОбъекта`, `ЗаметкиПользователя.УстановитьСтатусИзмененияПометкиУдаленияДокумента` - обработчики подписок ПередЗаписью.

**Подводные камни:** заметки личные - не используйте их как «общий комментарий для отдела»; для общих обсуждений есть Обсуждения.

## НапоминанияПользователя - напоминания по объекту и по времени

**Когда использовать:** «напомнить за час до срока задачи», «напомнить о дне рождения контакта», периодические напоминания. Заменяет самописные регламентные задания и всплывающие окна через `ПодключитьОбработчикОжидания`.

**Встраивание в свой объект (рецепт):**
1. **Метаданные:** определяемый тип `ПредметНапоминания` += ссылка (общая команда `Напомнить` в группе «Органайзер»); `ПредметНапоминанияОбъект` += объект (подписка `ПроверитьИзмененияДатВПредмете`, ПриЗаписи - пересчитывает срок напоминаний при изменении даты в предмете). Роль `ДобавлениеИзменениеНапоминаний`. ФО `ИспользоватьНапоминанияПользователя`, `ИспользоватьКомандуНапоминаний`.
2. **Переопределяемый:** `НапоминанияПользователяПереопределяемый.ПриЗаполненииСпискаРеквизитовИсточникаСДатамиДляНапоминания(Источник, РеквизитыСДатами)` - убрать служебные даты (дата документа и т.п.) из выбора; `ПриОпределенииНастроек(Настройки)` - свои расписания и стандартные интервалы.
3. **Форма объекта с полем «напомнить»** (образец - `Задача.ЗадачаИсполнителя.ФормаЗадачи`):
   ```bsl
   // ПриСозданииНаСервере
   ПараметрыРазмещения = НапоминанияПользователя.ПараметрыРазмещения();
   ПараметрыРазмещения.ИмяРеквизитаСДатойСобытия = "СрокИсполнения";
   ПараметрыРазмещения.Группа = Элементы.ГруппаСрокИсполнения;
   НапоминанияПользователя.ПриСозданииНаСервере(ЭтотОбъект, ПараметрыРазмещения);
   // ПриЧтенииНаСервере
   НапоминанияПользователя.ПриЧтенииНаСервере(ЭтотОбъект, ТекущийОбъект);
   // ПриЗаписиНаСервере
   НапоминанияПользователя.ПриЗаписиНаСервере(ЭтотОбъект, Отказ, ТекущийОбъект, ПараметрыЗаписи, ТекстНапоминания);
   // ОбработкаОповещения
   НапоминанияПользователяКлиент.ОбработкаОповещения(ЭтотОбъект, ИмяСобытия, Параметр, Источник);

   &НаКлиенте
   Процедура Подключаемый_ПриИзмененииНастройкиНапоминания(Элемент)
       НапоминанияПользователяКлиент.ПриИзмененииНастройкиНапоминания(Элемент, ЭтотОбъект);
   КонецПроцедуры
   ```
4. **Из кода (сервер):**
   ```bsl
   НапоминанияПользователя.УстановитьНапоминание(НСтр("ru = 'Проверить оплату'"), ДатаСобытия, 3600, ДокументСсылка);
   // ВремяСобытия может быть Дата, РасписаниеРегламентногоЗадания или имя реквизита предмета
   ```

**Главные методы API** (`api/НапоминанияПользователя.md`):
- `НапоминанияПользователя.УстановитьНапоминание` / `УдалитьНапоминание` / `НайтиНапоминания` - сервер.
- `НапоминанияПользователя.ПриСозданииНаСервере` + `ПараметрыРазмещения` / `ПриЧтенииНаСервере` / `ПриЗаписиНаСервере` - форма.
- `НапоминанияПользователяКлиент.НапомнитьВУказанноеВремя` / `НапомнитьДоВремениПредмета` / `НапомнитьОЕжегодномСобытииПредмета` - клиент.
- `НапоминанияПользователяКлиентСервер.ЕжегодноеРасписание` - расписание «раз в год».

**Подводные камни:** напоминание создается для **текущего** пользователя (`УстановитьНапоминание` не принимает пользователя) - из регламентного задания под служебным пользователем оно уйдет не тому; напоминания показываются клиентом периодическим опросом - не используйте их для критичных к секундам событий.

## ПолнотекстовыйПоиск - поиск по всем данным

**Когда использовать:** глобальный поиск по ИБ («найти всё, где упоминается ИНН/номер»), поиск в присоединенных файлах (извлеченный текст). Заменяет самописные запросы `ПОДОБНО` по многим таблицам.

**Встраивание (рецепт):**
1. **Метаданные:** у объекта и нужных реквизитов свойство «Полнотекстовый поиск» = `Использовать` (платформенное свойство; служебные реквизиты - `Не использовать`, это уменьшает индекс). Константа/ФО `ИспользоватьПолнотекстовыйПоиск`. Регламентные задания `ОбновлениеИндексаППД`, `СлияниеИндексаППД` уже в подсистеме - включить расписание.
2. **Переопределяемый:** `ПолнотекстовыйПоискСерверПереопределяемый.ПриПолученииРазделовПолнотекстовогоПоиска(РазделыПоиска)` - дерево областей поиска (по умолчанию строится по подсистемам). Перед добавлением объекта проверьте `ПравоДоступа("Просмотр", ...)` и `ОбщегоНазначения.ОбъектМетаданныхДоступенПоФункциональнымОпциям` (пример в комментарии процедуры).
3. Форма поиска - `ОбщаяФорма.ФормаПоиска` (обработка `ПолнотекстовыйПоискВДанных`); своего кода в объектах не нужно.

**Главные методы API** (`api/ПолнотекстовыйПоиск.md`): `ПолнотекстовыйПоискСервер.ИндексПоискаАктуален()`, `ПолнотекстовыйПоискСервер.ЗначениеФлажкаИспользоватьПоиск()`, `ПолнотекстовыйПоискСервер.ОбновлениеИндексаППД` / `СлияниеИндексаППД` (обработчики регламентных заданий), `ПолнотекстовыйПоискКлиент.ПоказатьНастройку()`.

**Подводные камни:** объем индекса и время его обновления растут с каждым включенным реквизитом - включайте поиск только по нужным реквизитам, служебные (хранилища, технические строки) исключайте. На больших базах обновление индекса - долгое регламентное задание, не запускайте его чаще, чем нужно.

## ГрупповоеИзменениеОбъектов - «Изменить выделенные...»

**Когда использовать:** массово проставить реквизит/доп. реквизит у выделенных в списке элементов. Заменяет самописные обработки «Групповая установка реквизита».

**Встраивание (рецепт):**
1. **Переопределяемый** - включить команду в формах списков:
   ```bsl
   // ГрупповоеИзменениеОбъектовПереопределяемый
   Процедура ПриОпределенииОбъектовСКомандойГрупповогоИзмененияОбъектов(Объекты) Экспорт
       Объекты.Добавить(Метаданные.Справочники.Номенклатура);
   КонецПроцедуры
   ```
   Команда «Изменить выделенные...» добавляется через ПодключаемыеКоманды (вид «Администрирование», только во «Все действия») и только при праве `Изменение` на объект - форма списка должна быть подключена к ПодключаемыеКоманды.
2. **Ограничение реквизитов** - в модуле менеджера объекта:
   ```bsl
   // СтандартныеПодсистемы.ГрупповоеИзменениеОбъектов
   Функция РеквизитыНеРедактируемыеВГрупповойОбработке() Экспорт
       Результат = Новый Массив;
       Результат.Добавить("ВидНоменклатуры");
       Возврат Результат;
   КонецФункции
   // Конец СтандартныеПодсистемы.ГрупповоеИзменениеОбъектов
   ```
   и зарегистрировать объект: `ГрупповоеИзменениеОбъектовПереопределяемый.ПриОпределенииОбъектовСРедактируемымиРеквизитами(Объекты)` -> `Объекты.Вставить(Метаданные.Справочники.Номенклатура.ПолноеИмя(), "РеквизитыНеРедактируемыеВГрупповойОбработке")` (или `"*"`, если объявлены обе функции; вторая - `РеквизитыРедактируемыеВГрупповойОбработке`). Альтернатива без функций в менеджере - `ПриОпределенииРедактируемыхРеквизитовОбъекта(Объект, Редактируемые, Нередактируемые)`; при заполнении обоих списков приоритет у нередактируемых.
3. Вызов из своей команды: `ГрупповоеИзменениеОбъектовКлиент.ИзменитьВыделенные(Элементы.Список)`.

**Главные методы API** (`api/ГрупповоеИзменениеОбъектов.md`): `ГрупповоеИзменениеОбъектовКлиент.ИзменитьВыделенные`, три процедуры `ГрупповоеИзменениеОбъектовПереопределяемый.*`.

**Подводные камни:** обработка записывает объекты обычной записью - срабатывают все обработчики `ПередЗаписью`/проверки, документы перепроводятся по выбору пользователя; ключевые реквизиты (влияющие на движения, номер, владельца) обязательно закрывайте через `РеквизитыНеРедактируемыеВГрупповойОбработке`.

## ЗагрузкаДанныхИзФайла - загрузка из Excel в справочник и табличную часть

**Когда использовать:** «загрузить номенклатуру/цены/строки заказа из Excel» с сопоставлением колонок и разрешением неоднозначностей. Заменяет самописные обработки чтения xlsx в ТЧ.

**Встраивание в справочник (рецепт):**
1. По умолчанию загрузка доступна в справочники «как есть». Свой алгоритм - в `ЗагрузкаДанныхИзФайлаПереопределяемый.ПриОпределенииСправочниковДляЗагрузкиДанных(ЗагружаемыеСправочники)`:
   ```bsl
   Сведения = ЗагружаемыеСправочники.Добавить();
   Сведения.ПолноеИмя = Метаданные.Справочники.Номенклатура.ПолноеИмя();
   Сведения.Представление = Метаданные.Справочники.Номенклатура.Представление();
   Сведения.ПрикладнаяЗагрузка = Истина;
   // исключить справочник: найти строку по "ПолноеИмя" и удалить
   ```
2. При `ПрикладнаяЗагрузка = Истина` в справочнике нужен макет `ЗагрузкаИзФайла` (табличный документ - шапка колонок) и в модуле менеджера экспортные процедуры, которые вызывает обработка `ЗагрузкаДанныхИзФайла`: `ОпределитьПараметрыЗагрузкиДанныхИзФайла(Параметры)`, `СопоставитьЗагружаемыеДанныеИзФайла(ЗагружаемыеДанные)`, `ЗагрузитьИзФайла(Данные, ПараметрыЗагрузки, Отказ)`. Доп. реквизиты из колонок - `ЗагрузкаДанныхИзФайла.ЗаписатьСвойстваОбъекта(Ссылка, СтрокаТаблицы)`.

**Встраивание в табличную часть документа:**
1. Макет в документе `ЗагрузкаИзФайла<ИмяТЧ>` или `ЗагрузкаИзФайла` (шапка колонок), либо колонки кодом: `ЗагрузкаДанныхИзФайла.СформироватьОписаниеКолонок("Документы.ЗаказКлиента.ТабличныеЧасти.Товары", "Номенклатура, Количество, Цена")` / `ЗагрузкаДанныхИзФайлаКлиентСервер.ОписаниеКолонкиМакета(...)`.
2. В модуле менеджера документа (обработка вызывает их по имени): `УстановитьПараметрыЗагрузкиИзФайлаВТЧ(Параметры)`, `СопоставитьЗагружаемыеДанные(АдресЗагружаемыхДанных, АдресТаблицыСопоставления, СписокНеоднозначностей, ПолноеИмяТабличнойЧасти, ДополнительныеПараметры)`, при неоднозначностях - `ЗаполнитьСписокНеоднозначностей(ПолноеИмяТабличнойЧасти, СписокНеоднозначностей, ИмяКолонки, ЗначенияЗагружаемыхКолонок, ДополнительныеПараметры)`. Таблица сопоставления - `ЗагрузкаДанныхИзФайла.ТаблицаСопоставления(Адрес)`, неоднозначности - `ЗагрузкаДанныхИзФайла.НовыйСписокНеоднозначностей()`.
3. Команда на форме (клиент):
   ```bsl
   ПараметрыЗагрузки = ЗагрузкаДанныхИзФайлаКлиент.ПараметрыЗагрузкиДанных();
   ПараметрыЗагрузки.ПолноеИмяТабличнойЧасти = "ЗаказКлиента.Товары";
   ПараметрыЗагрузки.Заголовок = НСтр("ru = 'Загрузка товаров из файла'");
   Оповещение = Новый ОписаниеОповещения("ЗагрузитьТоварыИзФайлаЗавершение", ЭтотОбъект);
   ЗагрузкаДанныхИзФайлаКлиент.ПоказатьФормуЗагрузки(ПараметрыЗагрузки, Оповещение);
   // форма загрузки закрывается с результатом АдресЗагруженныхДанных: в ЗагрузитьТоварыИзФайлаЗавершение(Результат, ДП)
   // на сервере получить таблицу ПолучитьИзВременногоХранилища(Результат) и дописать в Объект.Товары
   ```

**Главные методы API** (`api/ЗагрузкаДанныхИзФайла.md`): `ЗагрузкаДанныхИзФайлаКлиент.ПараметрыЗагрузкиДанных` / `ПоказатьФормуЗагрузки`, `ЗагрузкаДанныхИзФайла.СформироватьОписаниеКолонок`, `ТаблицаСопоставления`, `НовыйСписокНеоднозначностей`, `ЗаписатьСвойстваОбъекта`, `НастройкиЗагрузкиДанных`, `ЗагрузкаДанныхИзФайлаКлиентСервер.ОписаниеКолонкиМакета`.

**Подводные камни:** имена процедур менеджера не проверяются компилятором - опечатка дает ошибку «метод не найден» только при загрузке; сопоставление делайте одним запросом по всей таблице, а не поиском на каждую строку; в ТЧ данные возвращаются через временное хранилище - запись в объект выполняет ваша процедура завершения.

## ВыгрузкаОбъектовВФайлы - выгрузка объекта в XML/JSON/XLSX по пользовательскому макету

**Встраивание:** кода в объектах нет. **Подводные камни:** для интеграций между системами это не замена обмену/HTTP-сервисам - формат задается пользователем и может быть изменен без ведома разработчика.

## СтруктураПодчиненности - «Связанные документы»

**Когда использовать:** показать дерево документов-оснований и подчиненных (заказ -> реализация -> оплата). Заменяет самописные отчеты «цепочка документов».

**Встраивание (рецепт):**
1. **Метаданные (основное):**
   - Критерий отбора `СвязанныеДокументы`: в «Тип» добавить ссылочные типы участвующих объектов, в «Состав» - реквизиты, ссылающиеся на другие документы (например `Документ.РасходнаяНакладная.Реквизит.ЗаказКлиента`, реквизиты ТЧ тоже можно). В поставке критерий пустой (тип Строка).
   - Общая команда `СвязанныеДокументы`: в «Тип параметра команды» добавить типы объектов, в формах которых нужна команда (панель навигации «Перейти»). Типы из критерия, которых нет в параметре команды, выводятся в дереве, но без команды у себя (`СтруктураПодчиненностиСлужебный.ИндексТиповСвязанныхОбъектов`).
   - Роль `ПросмотрСвязанныеДокументы`.
2. **Переопределяемый:** `СтруктураПодчиненностиПереопределяемый.ПриОпределенииНастроек(Настройки)` - если сумма/валюта лежат не в реквизитах `СуммаДокумента`/`Валюта`:
   ```bsl
   Реквизиты = Новый Соответствие;
   Реквизиты.Вставить("СуммаДокумента", Метаданные.Документы.СчетНаОплату.Реквизиты.СуммаОплаты.Имя);
   Реквизиты.Вставить("Валюта", Метаданные.Документы.СчетНаОплату.Реквизиты.ВалютаДокумента.Имя);
   Настройки.Реквизиты.Вставить(Метаданные.Документы.СчетНаОплату.ПолноеИмя(), Реквизиты);
   ```
   Своё представление - `Настройки.РеквизитыДляПредставления` + `ПриПолученииПредставления`; скрыть служебные объекты - `ПередВыводомСвязанногоОбъекта(Объект, СвойстваОбъекта, Отказ)`.

**Главные методы API** (`api/СтруктураПодчиненности.md`): только три переопределяемые процедуры; программного API нет.

**Подводные камни:** каждый реквизит в составе критерия участвует в поиске связей при каждом открытии отчета - включайте только реквизиты-ссылки на документы, не на справочники. Забыли тип в параметре команды - команды нет на форме, хотя критерий настроен.

**Когда использовать:** пользователю/консультанту нужно посмотреть движения документа по всем регистрам. Заменяет самописные «Движения документа» и обработки просмотра движений.

**Встраивание (рецепт):**
1. По умолчанию команда добавляется для всех документов с проведением и непустыми движениями (`Отчеты.ДвиженияДокумента.ДобавитьКомандуОтчетОДвиженияхДокумента`), но только в формах, подключенных к ПодключаемыеКоманды (команду добавляет `Отчеты.ДвиженияДокумента.ПередДобавлениемКомандОтчетов`, регистрировать документ в `ВариантыОтчетовПереопределяемый.ОпределитьОбъектыСКомандамиОтчетов` не требуется - это для объектов со своей `ДобавитьКомандыОтчетов`). 2. Ограничить список документов - в `ВариантыОтчетовПереопределяемый.ПередДобавлениемКомандОтчетов` вызвать `Отчеты.ДвиженияДокумента.ДобавитьКомандуОтчетОДвиженияхДокумента(КомандыОтчетов, Параметры, МассивДокументов)`.

**Главные методы API** (`api/ОтчетОДвиженияхДокумента.md`): три процедуры `ОтчетОДвиженияхДокументаПереопределяемый.*`; `Отчеты.ДвиженияДокумента.ДобавитьКомандуОтчетОДвиженияхДокумента` (модуль менеджера отчета).

**Подводные камни:** отчет читает регистры с правами пользователя - без прав на регистр движения по нему просто не видны (это не ошибка отчета).

## Обсуждения - система взаимодействия, сообщения из кода

**Когда использовать:** уведомить пользователя/группу о событии в ИБ («заказ согласован») сообщением в «Обсуждениях» 1С, контекстные обсуждения объекта. Заменяет самописные «почтовые ящики» в ИБ и всплывающие уведомления через регистры.

**Встраивание (рецепт):**
1. Регистрация ИБ в системе взаимодействия - администратор (`ОбсужденияКлиент.ПоказатьПодключение()`, обработка `ПодключениеОбсуждений`). Контекстные обсуждения на формах объектов дает платформа, кода в объекте не нужно. Общая команда `Обсуждения` (параметр - `СправочникСсылка.Пользователи`).
2. Отправка из кода (сервер):
   ```bsl
   Если Обсуждения.ОбсужденияДоступны() Тогда
       Сообщение = Обсуждения.ОписаниеСообщения(НСтр("ru = 'Заказ согласован'"));
       Попытка
           Обсуждения.ОтправитьУведомление(Пользователи.ТекущийПользователь(), Сообщение, ЗаказСсылка); // в контекст объекта
           // или адресно: Обсуждения.ОтправитьСообщение(Автор, МассивПользователей, Сообщение);
       Исключение
           ЗаписьЖурналаРегистрации(...); // методы бросают исключение при недоступности сервиса
       КонецПопытки;
   КонецЕсли;
   ```

**Главные методы API** (`api/Обсуждения.md`): `Обсуждения.ОтправитьСообщение`, `Обсуждения.ОтправитьУведомление`, `Обсуждения.ОписаниеСообщения` / `ОписаниеКнопки` / `ОписаниеВложения`, `Обсуждения.ОбсужденияДоступны` / `СистемаВзаимодействийПодключена`, `Обсуждения.ПользовательСистемыВзаимодействия`, `ОбсужденияКлиент.ПоказатьПодключение`.

**Подводные камни:** внешний сервис - не отправляйте сообщения внутри транзакции записи документа (откат транзакции не отзовет сообщение, а таймаут сервиса затянет запись); выносите в `ПриЗаписи` вне транзакции / фоновое задание и всегда в `Попытка`. Пользователь ИБ без пользователя системы взаимодействия не получит сообщение.

## УчетОригиналовПервичныхДокументов - состояние бумажных оригиналов

**Когда использовать:** отслеживать, получен ли подписанный бумажный оригинал по каждой печатной форме документа (накладная, акт, счет-фактура), журнал оригиналов, установка состояния сканером штрихкода. Заменяет реквизиты «Оригинал получен» в документах.

**Встраивание в свой документ (рецепт):**
1. **Метаданные:** определяемый тип `ОбъектСУчетомОригиналовПервичныхДокументов` += `ДокументСсылка.<Имя>`; документ должен быть подключен к Печать (состояния ведутся по печатным формам). Для документов по нескольким сотрудникам - тип `Сотрудник` и `ПриОпределенииМногосотрудниковыхДокументов`. Роли: `ЧтениеСостоянийОригиналовПервичныхДокументов`, `ИзменениеСостоянийОригиналовПервичныхДокументов`, `ДобавлениеИзменениеСостоянийОригиналовПервичныхДокументов`; добавить в профили - `УчетОригиналовПервичныхДокументов.ДополнитьПрофильРольюДля...`. ФО `ИспользоватьУчетОригиналовПервичныхДокументов`.
2. **Переопределяемый:**
   ```bsl
   // УчетОригиналовПервичныхДокументовПереопределяемый
   Процедура ПриОпределенииОбъектовСКомандамиУчетаОригиналов(СписокОбъектов) Экспорт
       СписокОбъектов.Добавить("Документ.РасходнаяНакладная"); // строка, сравнивается с именем формы
   КонецПроцедуры
   Процедура ЗаполнитьТаблицуУчетаОригиналов(ТаблицаУчетаОригиналов) Экспорт
       // пусто = учет по всем печатным формам подключенных объектов
       НоваяСтрока = ТаблицаУчетаОригиналов.Добавить();
       НоваяСтрока.ОбъектМетаданных = Метаданные.Документы.РасходнаяНакладная;
       НоваяСтрока.Идентификатор = "РасходнаяНакладная"; // идентификатор команды печати
   КонецПроцедуры
   ```
   `ПриОпределенииНастроек(Настройки)` - `ВыводитьКнопкиНаФормеДокумента`, `ОткрыватьВыпадающиеМенюПоГиперссылке`, `ОтображатьПодсказкуВФормеИзмененияСостояний`.
3. **Форма документа:**
   ```bsl
   // ПриСозданииНаСервере
   УчетОригиналовПервичныхДокументов.ПриСозданииНаСервере_ФормаДокумента(ЭтотОбъект, Элементы.ГруппаСостояниеОригинала);
   // ОбработкаОповещения
   УчетОригиналовПервичныхДокументовКлиент.ОбработчикОповещенияФормаДокумента(ИмяСобытия, ЭтотОбъект, Источник);

   &НаКлиенте
   Процедура Подключаемый_ДекорацияСостояниеОригиналаНажатие() // имя задает подсистема
       УчетОригиналовПервичныхДокументовКлиент.ОткрытьМенюВыбораСостояния(ЭтотОбъект);
   КонецПроцедуры
   &НаСервере
   Процедура Подключаемый_ОбновитьКомандыСостоянияОригинала() // вызывается обработчиком ожидания
       УчетОригиналовПервичныхДокументов.ОбновитьКомандыСостоянияОригинала(ЭтотОбъект);
   КонецПроцедуры
   ```
4. **Форма списка:** `УчетОригиналовПервичныхДокументов.ПриСозданииНаСервере_ФормаСписка(ЭтотОбъект, Элементы.Список)`; событие списка `ПриПолученииДанныхНаСервере` -> `УчетОригиналовПервичныхДокументов.ПриПолученииДанныхНаСервере(Строки)`; `Выбор` -> `УчетОригиналовПервичныхДокументовКлиент.СписокВыбор(Поле.Имя, ЭтотОбъект, Элементы.Список, СтандартнаяОбработка)`; `ОбработкаОповещения` -> `ОбработчикОповещенияФормаСписка(ИмяСобытия, ЭтотОбъект, Элементы.Список, Источник)`; `Подключаемый_ОбновитьКомандыСостоянияОригинала` -> `ОбновитьКомандыСостоянияОригинала(ЭтотОбъект, Элементы.Список)`. Команды установки состояния приходят через ПодключаемыеКоманды (`УчетОригиналовПервичныхДокументовКлиент.Подключаемый_УстановитьСостояниеОригинала`).

**Главные методы API** (`api/УчетОригиналовПервичныхДокументов.md`): `ПриСозданииНаСервере_ФормаДокумента` / `ПриСозданииНаСервере_ФормаСписка` / `ПриПолученииДанныхНаСервере`, `УстановитьНовоеСостояниеОригинала`, `СведенияОСостоянииОригиналаПоСсылке`, `ЗаписатьСостоянияОригиналовПослеПечати`, `ВсеСостояния`, клиент `УстановитьСостояниеОригинала` / `ОбработатьШтрихкод`.

**Подводные камни:** идентификаторы в `ЗаполнитьТаблицуУчетаОригиналов` должны совпадать с `Идентификатор` команд печати - переименовали команду печати, «потеряли» историю состояний.
