## ПодключаемыеКоманды - подменю «Печать», «Отчеты», «Заполнить», «Создать на основании» на формах объектов
**Когда использовать:** на форму документа/справочника нужно вывести печатные формы, контекстные отчеты, команды
заполнения, создания на основании, перемещения вверх/вниз, команды доп. обработок. Вместо кнопок и команд формы,
добавленных вручную, команды описываются в модулях менеджеров и выводятся единообразно с учетом прав, ФО и типа объекта.
Механизм - общий транспорт для подсистем Печать, ВариантыОтчетов, НастройкаПорядкаЭлементов, ДополнительныеОтчетыИОбработки.

**Встраивание в свой объект (рецепт):**
1. Метаданные: нет обязательных. Для команд «на основании»/«заполнения»/«отчетов» объект регистрируется в
   переопределяемых модулях (п.2). Отчет/обработка, которая сама дает команды чужим объектам, включается в подсистему
   конфигурации `ПодключаемыеОтчетыИОбработки` и в модуле менеджера объявляет `ПриОпределенииНастроек(Настройки)`
   (`Настройки.Размещение.Добавить(Метаданные.Документы.Заказ)`, `Настройки.ДобавитьКомандыОтчетов = Истина` /
   `ДобавитьКомандыПечати` / `ДобавитьКомандыЗаполнения`).
   На форме можно создать группу `ПодключаемыеКоманды` в командной панели - туда выводятся подменю; иначе создаются автоматически.
2. Переопределяемые процедуры:
   - `СозданиеНаОснованииПереопределяемый.ПриОпределенииОбъектовСКомандамиСозданияНаОсновании(Объекты)` - `Объекты.Добавить(Метаданные.Документы.Заказ)`;
   - `ЗаполнениеОбъектовПереопределяемый.ПриОпределенииОбъектовСКомандамиЗаполнения(Объекты)`;
   - `ВариантыОтчетовПереопределяемый.ОпределитьОбъектыСКомандамиОтчетов(Объекты)`;
   - печать - см. pattern-файл подсистемы Печать (`УправлениеПечатьюПереопределяемый.ПриОпределенииОбъектовСКомандамиПечати`);
   - свой вид подменю: `ПодключаемыеКомандыПереопределяемый.ПриОпределенииВидовПодключаемыхКоманд(ВидыПодключаемыхКоманд)`,
     общие команды для всех объектов - `ПриОпределенииКомандПодключенныхКОбъекту(НастройкиФормы, Источники, ПодключенныеОтчетыИОбработки, Команды)`.
3. Модуль менеджера объекта (зарегистрированного в п.2):
```bsl
// СтандартныеПодсистемы.ПодключаемыеКоманды
Процедура ДобавитьКомандыСозданияНаОсновании(КомандыСозданияНаОсновании, Параметры) Экспорт
	Документы.РасходнаяНакладная.ДобавитьКомандуСоздатьНаОсновании(КомандыСозданияНаОсновании);
КонецПроцедуры

// Для вызова из ДобавитьКомандыСозданияНаОсновании других менеджеров: "этот документ можно создать на основании".
Функция ДобавитьКомандуСоздатьНаОсновании(КомандыСозданияНаОсновании) Экспорт
	Команда = СозданиеНаОсновании.ДобавитьКомандуСозданияНаОсновании(КомандыСозданияНаОсновании, Метаданные.Документы.Заказ);
	Если Команда <> Неопределено Тогда
		Команда.ФункциональныеОпции = "ИспользоватьЗаказы";
		Команда.Важность = "СмТакже";
	КонецЕсли;
	Возврат Команда;
КонецФункции

Процедура ДобавитьКомандыОтчетов(КомандыОтчетов, Параметры) Экспорт
	Если Не ПравоДоступа("Просмотр", Метаданные.Отчеты.ИсторияЗаказа) Тогда
		Возврат;
	КонецЕсли;
	Команда = КомандыОтчетов.Добавить();
	Команда.Представление      = НСтр("ru = 'История заказа'");
	Команда.Менеджер           = "Отчет.ИсторияЗаказа";
	Команда.КлючВарианта       = "Основной";
	Команда.МножественныйВыбор = Ложь;
	Команда.ТипПараметра       = Новый ОписаниеТипов("ДокументСсылка.Заказ");
КонецПроцедуры
// Аналогично: ДобавитьКомандыЗаполнения(КомандыЗаполнения, Параметры)
// Конец СтандартныеПодсистемы.ПодключаемыеКоманды
```
   Видимость по данным строки: `ПодключаемыеКоманды.ДобавитьУсловиеВидимостиКоманды(Команда, "Проведен", Истина)`.
   Поля команды: `Обработчик` ("ОбщийМодуль.Процедура" или процедура формы/менеджера), `РежимЗаписи`
   ("НеЗаписывать"/"Записывать"/"Проводить"), `ИзменяетВыбранныеОбъекты`, `Назначение` ("ДляСписка"/"ДляОбъекта").
4. Модуль формы объекта (шаблон из документов БСП, без изменений копируется в каждую форму):
```bsl
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
	// СтандартныеПодсистемы.ПодключаемыеКоманды
	ПодключаемыеКоманды.ПриСозданииНаСервере(ЭтотОбъект);
	// Конец СтандартныеПодсистемы.ПодключаемыеКоманды
КонецПроцедуры

&НаСервере
Процедура ПриЧтенииНаСервере(ТекущийОбъект)
	ПодключаемыеКомандыКлиентСервер.ОбновитьКоманды(ЭтотОбъект, Объект);
КонецПроцедуры

&НаКлиенте
Процедура ПриОткрытии(Отказ)
	ПодключаемыеКомандыКлиент.НачатьОбновлениеКоманд(ЭтотОбъект);
КонецПроцедуры

&НаКлиенте
Процедура ПослеЗаписи(ПараметрыЗаписи)
	ПодключаемыеКомандыКлиент.ПослеЗаписи(ЭтотОбъект, Объект, ПараметрыЗаписи);
КонецПроцедуры

// СтандартныеПодсистемы.ПодключаемыеКоманды
&НаКлиенте
Процедура Подключаемый_ВыполнитьКоманду(Команда)
	ПодключаемыеКомандыКлиент.НачатьВыполнениеКоманды(ЭтотОбъект, Команда, Объект);
КонецПроцедуры

&НаКлиенте
Процедура Подключаемый_ПродолжитьВыполнениеКомандыНаСервере(ПараметрыВыполнения, ДополнительныеПараметры) Экспорт
	ВыполнитьКомандуНаСервере(ПараметрыВыполнения);
КонецПроцедуры

&НаСервере
Процедура ВыполнитьКомандуНаСервере(ПараметрыВыполнения)
	ПодключаемыеКоманды.ВыполнитьКоманду(ЭтотОбъект, ПараметрыВыполнения, Объект);
КонецПроцедуры

&НаКлиенте
Процедура Подключаемый_ОбновитьКоманды()
	ПодключаемыеКомандыКлиентСервер.ОбновитьКоманды(ЭтотОбъект, Объект);
КонецПроцедуры
// Конец СтандартныеПодсистемы.ПодключаемыеКоманды
```
   Форма списка: те же `ПриСозданииНаСервере` и три процедуры `Подключаемый_*`, но третий параметр - `Элементы.Список`;
   в `СписокПриАктивизацииСтроки` - `ПодключаемыеКомандыКлиент.НачатьОбновлениеКоманд(ЭтотОбъект)`.
   Несколько таблиц на форме - несколько вызовов с `ПодключаемыеКоманды.ПараметрыРазмещения()` (`Источники`, `КоманднаяПанель`, `ПрефиксГрупп`).

**Главные методы API:** (api/ПодключаемыеКоманды.md)
- `ПодключаемыеКоманды.ПриСозданииНаСервере(Форма, ПараметрыРазмещения)` - вывести команды на форму.
- `ПодключаемыеКоманды.ПараметрыРазмещения()` - для второстепенных таблиц/форм обработок.
- `ПодключаемыеКоманды.ВыполнитьКоманду(Форма, ПараметрыВыполнения, Источник)` - серверная часть команды.
- `ПодключаемыеКомандыКлиент.НачатьВыполнениеКоманды(Форма, Команда, Источник)` - обработчик всех подключаемых команд.
- `ПодключаемыеКомандыКлиент.НачатьОбновлениеКоманд(Форма)` / `ПодключаемыеКомандыКлиентСервер.ОбновитьКоманды(Форма, Источник)` - доступность по данным.
- `ПодключаемыеКоманды.ДобавитьУсловиеВидимостиКоманды(Команда, Реквизит, Значение, ВидСравнения)`.
- `СозданиеНаОсновании.ДобавитьКомандуСозданияНаОсновании(Команды, ОбъектМетаданных)`.

**Подводные камни:**
- Список команд кэшируется по имени формы (повторно используемые значения): изменения в `ДобавитьКоманды*` видны после
  перезапуска сеанса; не делайте состав команд зависящим от данных конкретного объекта - для этого `УсловияВидимости`.
- Процедуры `Подключаемый_*` должны называться ровно так - БСП ищет их по имени.
- Право на команду проверяйте в `ДобавитьКоманды*` (`ПравоДоступа`), а не в обработчике.
- Платформенные «Ввод на основании» и программные команды одновременно дублируют меню: настройка
  `СозданиеНаОснованииПереопределяемый.ПриОпределенииНастроек` → `ИспользоватьКомандыВводаНаОсновании`.

## ВариантыОтчетов - панель отчетов, варианты и пользовательские настройки, контекстные отчеты
**Когда использовать:** любой отчет на СКД в конфигурации. Дает единую форму отчета (`ОбщаяФорма.ФормаОтчета`), хранение
вариантов в справочнике, панели отчетов по разделам, поиск, рассылки, контекстные команды отчетов на формах объектов.
Заменяет самописные формы отчетов с кнопкой «Сформировать» и сохранение настроек в своих регистрах.

**Встраивание в свой отчет (рецепт):**
1. Метаданные отчета: `Основная форма` = `ОбщаяФорма.ФормаОтчета`, `Форма настроек` = `ОбщаяФорма.ФормаНастроекОтчета`,
   `Форма варианта` = `ОбщаяФорма.ФормаВариантаОтчета`, `Хранилище вариантов` = `ХранилищеВариантовОтчетов`
   (лучше - задать эти свойства для всей конфигурации). Включить отчет в подсистему-раздел командного интерфейса - размещение в
   панели отчетов берется из метаданных. Пользователям - роль `ЧтениеВариантовОтчетов`; для сохранения своих вариантов -
   `ДобавлениеИзменениеЛичныхВариантовОтчетов` (общих - `ДобавлениеИзменениеВариантовОтчетов`).
2. Переопределяемые процедуры:
```bsl
// ВариантыОтчетовПереопределяемый.НастроитьВариантыОтчетов(Настройки)
ВариантыОтчетов.НастроитьОтчетВМодулеМенеджера(Настройки, Метаданные.Отчеты.ИсторияЗаказа);
// без модуля менеджера - прямо здесь:
НастройкиВарианта = ВариантыОтчетов.ОписаниеВарианта(Настройки, Метаданные.Отчеты.Остатки, "Основной");
НастройкиВарианта.Размещение.Вставить(Метаданные.Подсистемы.Склад, "Важный");
```
   Переименовали вариант (имя в СКД) - зарегистрируйте в `ЗарегистрироватьИзмененияКлючейВариантовОтчетов(Изменения)`,
   иначе пропадут пользовательские настройки и рассылки. Контекстные команды - `ОпределитьОбъектыСКомандамиОтчетов` (см. ПодключаемыеКоманды).
3. Модуль менеджера и объекта отчета:
```bsl
// Модуль менеджера
// СтандартныеПодсистемы.ВариантыОтчетов
Процедура НастроитьВариантыОтчета(Настройки, НастройкиОтчета) Экспорт
	ВариантыОтчетов.УстановитьРежимВыводаВПанеляхОтчетов(Настройки, НастройкиОтчета, Ложь);
	НастройкиОтчета.ОпределитьНастройкиФормы = Истина;
	НастройкиВарианта = ВариантыОтчетов.ОписаниеВарианта(Настройки, НастройкиОтчета, "Основной");
	НастройкиВарианта.Описание = НСтр("ru = 'Движение заказа по статусам.'");
КонецПроцедуры
// Конец СтандартныеПодсистемы.ВариантыОтчетов

// Модуль объекта (если ОпределитьНастройкиФормы = Истина)
Процедура ОпределитьНастройкиФормы(Форма, КлючВарианта, Настройки) Экспорт
	Настройки.ФормироватьСразу = Истина;
	Настройки.События.ПриСозданииНаСервере = Истина; // и в объекте отчета - ПриСозданииНаСервере(Форма, Отказ, СтандартнаяОбработка)
КонецПроцедуры
```
   Структуру `Настройки` см. `ОтчетыКлиентСервер.НастройкиОтчетаПоУмолчанию()`. Открыть вариант из кода -
   `ВариантыОтчетовКлиент.ОткрытьФормуОтчета(ФормаВладелец, Вариант)`.

**Главные методы API:** (api/ВариантыОтчетов.md)
- `ВариантыОтчетов.НастроитьОтчетВМодулеМенеджера(Настройки, ОтчетМетаданные)` - вызывает `НастроитьВариантыОтчета` отчета.
- `ВариантыОтчетов.ОписаниеОтчета(Настройки, Отчет)` / `ОписаниеВарианта(Настройки, Отчет, КлючВарианта)` - настройки (Включен, Размещение, Описание, ФункциональныеОпции, НастройкиДляПоиска).
- `ВариантыОтчетов.УстановитьРежимВыводаВПанеляхОтчетов(Настройки, ОтчетИлиПодсистема, ГруппироватьПоОтчетам)`.
- `ВариантыОтчетов.ВариантОтчета(Отчет, КлючВарианта)` - ссылка на вариант.
- `ОтчетыСервер.ИнициализироватьКомпоновщикНастроек(...)`, `ОтчетыСервер.ПодключитьСхему(Отчет, Контекст, Схема, КлючСхемы)` - смена СКД в `ПередЗагрузкойНастроекВКомпоновщик`.
- `ОтчетыКлиентПереопределяемый.ОбработкаРасшифровки`, `ОтчетыПереопределяемый.ПриСозданииНаСервере` - общие доработки формы отчета.

**Подводные камни:**
- Отчет без `ОбщаяФорма.ФормаОтчета` в панели отчетов работает, но теряет все возможности подсистемы - собственная
  форма отчета требует обоснования.
- Предопределенные варианты обновляются регламентным заданием/при обновлении ИБ - после изменения
  `НастроитьВариантыОтчета` нужно обновление (номер версии) или `ОбновлениеПредопределенныхВариантовОтчетов`.
- Частичное внедрение (хранилище вариантов задано у отдельных отчетов) - перенос пользовательских вариантов:
  `ВариантыОтчетов.ПеренестиПользовательскиеИзСтандартногоХранилища("Отчет1, Отчет2")` в обработчике обновления.
- Отчеты из расширений настраиваются только через подсистему `ПодключаемыеОтчетыИОбработки`, не через `НастроитьВариантыОтчетов`.

## Мультиязычность - реквизиты на нескольких языках
**Когда использовать:** наименования/описания справочников нужно вводить на 2-3 языках (казахский/английский интерфейс,
печать на языке контрагента). Заменяет свои реквизиты «НаименованиеEN» и ручной выбор по `ТекущийЯзык()`.

**Встраивание в свой справочник (рецепт):**
1. Метаданные - один из двух вариантов хранения:
   - реквизиты с суффиксами `НаименованиеЯзык1`, `НаименованиеЯзык2` (для 1-2 дополнительных языков, работает в запросах);
   - табличная часть `Представления` с реквизитом `КодЯзыка` и колонками мультиязычных реквизитов (`Наименование`, ...).
2. Переопределяемая процедура:
```bsl
// МультиязычностьПереопределяемый.ПриОпределенииНастроек(Настройки)
Настройки.КодДополнительногоЯзыка1 = "kk";
Настройки.КодДополнительногоЯзыка2 = "en";
```
3. Форма элемента / модули (как в `Справочник.ЗначенияСвойствОбъектов`):
```bsl
// ПриСозданииНаСервере
МультиязычностьСервер.ПриСозданииНаСервере(ЭтотОбъект, Объект);
// ПриЧтенииНаСервере(ТекущийОбъект)
МультиязычностьСервер.ПриЧтенииНаСервере(ЭтотОбъект, ТекущийОбъект);
// ПередЗаписьюНаСервере(Отказ, ТекущийОбъект, ПараметрыЗаписи)
МультиязычностьСервер.ПередЗаписьюНаСервере(ТекущийОбъект);
// &НаКлиенте Подключаемый_Открытие(Элемент, СтандартнаяОбработка) - кнопка открытия у поля
МультиязычностьКлиент.ПриОткрытии(ЭтотОбъект, Объект, Элемент, СтандартнаяОбработка);

// Модуль менеджера: представление на языке пользователя
Процедура ОбработкаПолученияПредставления(Данные, Представление, СтандартнаяОбработка)
	МультиязычностьКлиентСервер.ОбработкаПолученияПредставления(Данные, Представление, СтандартнаяОбработка);
КонецПроцедуры
Процедура ОбработкаПолученияПолейПредставления(Поля, СтандартнаяОбработка)
	МультиязычностьКлиентСервер.ОбработкаПолученияПолейПредставления(Поля, СтандартнаяОбработка);
КонецПроцедуры
// Модуль объекта: обработчик ПриЧтенииПредставленийНаСервере() -> МультиязычностьСервер.ПриЧтенииПредставленийНаСервере(ЭтотОбъект)
```
   Ввод по строке на языке пользователя - `МультиязычностьСервер.ОбработкаПолученияДанныхВыбора(ДанныеВыбора, Параметры, СтандартнаяОбработка, Метаданные.Справочники.X)`.
   Начальное заполнение - `МультиязычностьСервер.ЗаполнитьМультиязычныйРеквизит(Элемент, "Наименование", "ru = '...'; en = '...'", КодыЯзыков)`.

**Главные методы API:** (api/Мультиязычность.md)
- `МультиязычностьСервер.ИзменитьПолеЗапросаПодТекущийЯзык(ТекстЗапроса, "Т.Наименование")` - поле запроса → `НаименованиеЯзык1`.
- `МультиязычностьСервер.СуффиксТекущегоЯзыка()`, `ИспользуетсяДополнительныйЯзык(ПорядковыйНомерЯзыка)`, `СведенияОЯзыках()`.
- `ОбщегоНазначения.ЗначенияРеквизитовОбъекта(Ссылка, "Наименование", , КодЯзыка)` - чтение на нужном языке.
- `ПереводТекстаНаДругиеЯзыки.ПеревестиТекст(...)` - машинный перевод (если подключен сервис).

**Подводные камни:** в запросах обращение к `Наименование` дает основной язык - используйте
`ИзменитьПолеЗапросаПодТекущийЯзык` или `ОбработкаПолученияПредставления`; ТЧ `Представления` в запросах неудобна -
для данных, которые выбираются в отчетах, выбирайте вариант с суффиксами.

## КонструкторФормул - редактор формул пользователя
**Когда использовать:** пользователь сам задает формулу (расчет цены, показатель, условие) из доступных полей.
Заменяет самописный редактор с деревом полей; результат вычисляется через `ОбщегоНазначения.ВычислитьВБезопасномРежиме`.

**Встраивание:** метаданные - обработка `КонструкторФормул` (в составе БСП), переопределяемых процедур нет.
```bsl
&НаКлиенте
Процедура ФормулаНачалоВыбора(Элемент, ДанныеВыбора, СтандартнаяОбработка)
	СтандартнаяОбработка = Ложь;
	Параметры = КонструкторФормулКлиент.ПараметрыРедактированияФормулы();
	Параметры.Формула = Объект.Формула;
	Параметры.Операнды = АдресОперандов; // адрес во временном хранилище: ТаблицаЗначений/ДеревоЗначений полей
	КонструкторФормулКлиент.НачатьРедактированиеФормулы(Параметры,
		Новый ОписаниеОповещения("ФормулаЗавершениеРедактирования", ЭтотОбъект));
КонецПроцедуры
```
Список полей прямо на своей форме: `КонструкторФормул.ДобавитьСписокПолейНаФорму(Форма, КонструкторФормул.ПараметрыДобавленияСпискаПолей())`;
коллекции полей - `КонструкторФормул.ТаблицаПолей()`, `ДеревоПолей()`, `КоллекцияПолей(ИсточникПолей)`; представление формулы
для пользователя - `КонструкторФормул.ПредставлениеФормулы(Параметры)`. (api/КонструкторФормул.md)

**Подводные камни:** формула хранится во внутреннем виде (идентификаторы полей), показывать пользователю - через
`ПредставлениеФормулы`; вычислять только в безопасном режиме; `ДляЗапроса = Истина` меняет набор операторов.

## НастройкаПорядкаЭлементов - кнопки «вверх/вниз» в списке справочника
**Когда использовать:** пользователь должен вручную упорядочивать элементы справочника/ПВХ (статусы, этапы, виды).
Заменяет свой реквизит «Порядок» с ручной перенумерацией.

**Встраивание (рецепт):**
1. Метаданные: реквизит `РеквизитДопУпорядочивания` (Число, в БСП - 5 знаков); тип `СправочникОбъект.X` добавить в
   определяемый тип `ОбъектСНастраиваемымПорядком` - на него подписаны `ЗаполнитьЗначениеРеквизитаУпорядочивания`
   (ПередЗаписью) и `СброситьЗначениеРеквизитаУпорядочивания` (ПриКопировании).
2. Переопределяемых процедур нет.
3. Форма списка: подключить ПодключаемыеКоманды (раздел выше) - команды «Переместить вверх/вниз» добавит
   `НастройкаПорядкаЭлементов.ПриОпределенииКомандПодключенныхКОбъекту` (только при праве `Изменение`); в списке
   установить сортировку по `РеквизитДопУпорядочивания`.

**Главные методы API:** (api/НастройкаПорядкаЭлементов.md) `НастройкаПорядкаЭлементов.УстановитьЗначениеРеквизитаУпорядочивания(Объект)`
(для программно создаваемых элементов вне подписки), `СброситьЗначениеРеквизитаУпорядочивания(Источник, ОбъектКопирования)`.

**Подводные камни:** перемещение работает при сортировке списка по `РеквизитДопУпорядочивания` (для иерархии - в пределах
родителя/владельца); в запросах сортируйте по этому реквизиту, а не по коду.

## ПрефиксацияОбъектов - префиксы организации и ИБ в номерах и кодах
**Когда использовать:** номера документов должны быть уникальны между узлами РИБ/обмена и/или содержать префикс
организации: формат `ОРИБ-000123` (2 символа организации + 2 символа ИБ). Заменяет свои обработчики `ПриУстановкеНовогоНомера`.

**Встраивание (рецепт):**
1. Метаданные: создать **свою** подписку на событие `ПриУстановкеНовогоНомера` (для справочников - `ПриУстановкеНовогоКода`)
   с источниками - документами, обработчик одна из:
   `ПрефиксацияОбъектовСобытия.УстановитьПрефиксИнформационнойБазыИОрганизации` / `УстановитьПрефиксИнформационнойБазы` /
   `УстановитьПрефиксОрганизации` (сигнатура `(Источник, СтандартнаяОбработка, Префикс)`).
   Для смены номера при изменении даты/организации - подписка `ПередЗаписью` с `ПрефиксацияОбъектовСобытия.ПроверитьНомерДокументаПоДатеИОрганизации`
   (`ПроверитьНомерДокументаПоДате`, `ПроверитьКодСправочникаПоОрганизации`).
   Длину номера увеличить на длину префикса (4 символа + «-»).
2. Префикс организации берется из функциональной опции `ПрефиксыОрганизаций` с параметром `Организация` - **её нет в
   БСП**, создайте сами (хранение - реквизит `Префикс` справочника организаций). Префикс ИБ - из подсистемы ОбменДанными
   (ФО `ПрефиксИнформационнойБазы`). Реквизит организации в документе должен называться `Организация`, иначе -
   `ПрефиксацияОбъектовПереопределяемый.ПолучитьПрефиксообразующиеРеквизиты(Объекты)`.
3. Печать номера без префиксов: `ПрефиксацияОбъектовКлиентСервер.НомерНаПечать(Номер, Истина, Истина)`;
   свое правило - `ПрефиксацияОбъектовКлиентСерверПереопределяемый.ПриПолученииНомераНаПечать`.

**Главные методы API:** (api/ПрефиксацияОбъектов.md) `ПрефиксацияОбъектовКлиентСервер.НомерНаПечать`,
`УдалитьПрефиксыИзНомераОбъекта(Номер, УдалитьПрефиксОрганизации, УдалитьПрефиксИнформационнойБазы)`,
`УдалитьЛидирующиеНулиИзНомераОбъекта`, `ПользовательскийПрефикс`; `ПрефиксацияОбъектовПереопределяемый.ПриИзмененииНомера/ПриИзмененииКода`
- для нестандартных номеров при перепрефиксации.

**Подводные камни:** в библиотечном коде (как в ЗащитаПерсональныхДанных) подписка указывает на свою обертку с
`ПодсистемаСуществует`; в прикладной конфигурации - прямо на `ПрефиксацияОбъектовСобытия`. Нумерация в пределах
префикса: у документа включить контроль уникальности и периодичность, иначе номера разных организаций пересекутся.

## ГенерацияШтрихкода - картинка штрихкода/QR на сервере
**Когда использовать:** штрихкод/QR/DataMatrix на печатной форме, этикетке, в форме. Заменяет сторонние компоненты и
web-сервисы. Компонента поставляется в общем макете `КомпонентаПечатиШтрихкодов`; переопределяемых процедур нет.
```bsl
Параметры = ГенерацияШтрихкода.ПараметрыГенерацииШтрихкода();
Параметры.Ширина = 200; Параметры.Высота = 200;
Параметры.ТипКода = 16; // 16 - QR, 1 - EAN13, 4 - Code128, 99 - автовыбор, 18-24 - DataMatrix
Параметры.Штрихкод = СтрокаДанных;
Результат = ГенерацияШтрихкода.ИзображениеШтрихкода(Параметры);
Если Результат.Результат Тогда
	ОбластьМакета.Рисунки.QRКод.Картинка = Результат.Картинка;
КонецЕсли;
```
**Главные методы API:** (api/ГенерацияШтрихкода.md) `ГенерацияШтрихкода.ПараметрыГенерацииШтрихкода()`,
`ИзображениеШтрихкода(Параметры)` → `Результат, ДвоичныеДанные, Картинка`, `ДанныеQRКода(QRСтрока, УровеньКоррекции, Размер)` → PNG.

**Подводные камни:** только сервер/внешнее соединение; при массовой печати создавайте параметры один раз и меняйте
только `Штрихкод`; `Результат = Ложь` - проверяйте (недопустимые символы для EAN и т.п.).

## СклонениеПредставленийОбъектов - падежи наименований и ФИО
**Когда использовать:** в печатных формах/договорах нужны «в лице директора Иванова Ивана Ивановича», должности и
наименования в падежах. Заменяет самописные таблицы окончаний. Хранение - регистр `СклоненияПредставленийОбъектов`,
опционально сервис Morpher (константа `ИспользоватьСервисСклоненияMorpher`).

**Встраивание в свой справочник (рецепт):**
1. Метаданные: добавить `СправочникСсылка.X` в определяемый тип `ОбъектСклонения`; на форму - команду «Склонения».
2. Переопределяемых процедур нет; для печати через макеты офисных документов - `СклонениеПредставленийОбъектов.ПодключитьИсточникДанныхПечатиСклоненияСтрок(ИсточникиДанныхПечати)`.
3. Форма элемента:
```bsl
// ПриСозданииНаСервере
СклонениеПредставленийОбъектов.ПриСозданииНаСервере(ЭтотОбъект, Объект.Наименование);
// ПриЗаписиНаСервере(Отказ, ТекущийОбъект, ПараметрыЗаписи)
СклонениеПредставленийОбъектов.ПриЗаписиФормыОбъектаСклонения(ЭтотОбъект, ТекущийОбъект.Наименование, ТекущийОбъект.Ссылка);
// &НаКлиенте НаименованиеПриИзменении
ИзмененоПредставление = Истина; // реквизит формы, созданный в ПриСозданииНаСервере
// &НаКлиенте команда Склонения
СклонениеПредставленийОбъектовКлиент.ПоказатьСклонение(ЭтотОбъект, Объект.Наименование);
```
**Главные методы API:** (api/СклонениеПредставленийОбъектов.md) `СклонениеПредставленийОбъектов.ПросклонятьФИО(ФИО, Падеж, Объект, Пол)`,
`ПросклонятьПредставление(Представление, Падеж, Объект)` (Падеж: 1 - Именительный ... 6 - Предложный),
`СклонениеПредставленийОбъектовКлиентСервер.ПараметрыСклонения()`, `ДоступенСервисСклонения()`.

**Подводные камни:** `ПриСозданииНаСервере` добавляет реквизиты формы `ИзмененоПредставление` и `Склонения` - не создавайте
одноименные; без отметки `ИзмененоПредставление` склонения после смены наименования не пересчитаются; сервис Morpher -
внешний ресурс (запрещен в копии ИБ).

## ИнтерфейсOData - стандартный REST-интерфейс для внешних систем
**Когда использовать:** внешней системе (BI, сайт, интеграция) нужен доступ к данным через стандартный OData без
разработки HTTP-сервисов. Подсистема дает обработку `НастройкаСтандартногоИнтерфейсаOData` (выбор публикуемых объектов,
отдельный пользователь `ПользовательСтандартногоИнтерфейсаOData`) и роль `УдаленныйДоступOData`.

**Встраивание:** включить обработку в раздел администрирования; при публикации объекта, данные которого зависят от
других таблиц (например, регистр по документу), - `ИнтерфейсODataПереопределяемый.ПриЗаполненииЗависимыхТаблицДляВыгрузкиЗагрузкиOData(Таблицы)`.
Веб-публикацию с OData делают администраторы. (api/ИнтерфейсOData.md)

**Подводные камни:** OData работает в обход прикладной логики форм и проверок - для записи данных извне лучше свой
HTTP-сервис; права пользователя OData выдавайте только на нужные объекты (через обработку настройки, не полными правами).

## РаботаВМоделиСервиса - работа в модели сервиса (SaaS), кратко
Нужна только конфигурациям для 1cFresh; полноценная реализация - в библиотеке «Технология сервиса» (БТС), в БСП - API
обмена/доп. обработок в сервисе (api/РаботаВМоделиСервиса.md). Прикладному разработчику достаточно:
- `ОбщегоНазначения.РазделениеВключено()` / `ДоступноИспользованиеРазделенныхДанных()` - ветки кода для сервиса;
- не использовать в регламентных заданиях и коде без проверки разделения неразделенные данные;
- безопасное хранилище и `ВнешниеКомпонентыСервер` в сервисе ведут себя иначе (области данных, только одобренные компоненты).
