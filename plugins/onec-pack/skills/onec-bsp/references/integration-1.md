## ОбменДанными - синхронизация данных между ИБ и с внешними системами

**Когда использовать:**
- РИБ (распределенная ИБ, в т.ч. с фильтрами и автономное рабочее место) - всегда через БСП: она сама
  обрабатывает служебные данные подсистем при обмене, обновление конфигурации подчиненного узла, приоритетные данные.
- Обмен 1С <-> 1С между разными конфигурациями (БП <-> УТ/ERP/КА и т.п.) - через универсальный формат
  EnterpriseData (XDTO-пакеты `EnterpriseData_1_xx_x` уже в составе БСП). Типовые конфигурации уже содержат
  планы обмена; ваша задача обычно - доработать правила конвертации или добавить реквизит/объект.
- Обмен с другой 1С по правилам КД2 (XML-правила конвертации и регистрации) - «универсальный обмен».
- Пользователю нужен UI «Синхронизация данных»: помощник настройки, расписание (регламентное задание
  `СинхронизацияДанных` -> `ОбменДаннымиСервер.ВыполнитьОбменДаннымиПоРегламентномуЗаданию`, сценарии
  `Справочник.СценарииОбменовДанными`), протокол, предупреждения, сопоставление объектов, транспорты
  FILE/FTP/EMAIL/COM/WS/HTTP.

Заменяет самописное: ручные подписки «пометить измененное», свои журналы «что отправлено», свой протокол ошибок,
свой мастер подключения, свою загрузку XML.

### Выбор: БСП-обмен или своя HTTP/outbox-интеграция

| Ситуация | Решение |
|---|---|
| Узлы одной конфигурации, общая структура данных | РИБ на БСП (рецепт B) |
| Другая 1С-конфигурация на БСП (типовая или своя) | EnterpriseData (рецепт C) или типовой обмен из коробки |
| Внешняя система, которая уже умеет EnterpriseData (сайт-модуль, 1С:Шина) | EnterpriseData + `ВыполнитьОбменДаннымиСВнешнейСистемой` / веб-сервис `EnterpriseDataUpload_1_0_1_1` |
| Свой бэкенд (Node/Go/Java/Python), JSON-API, вебхуки, очереди | **НЕ БСП-обмен**, а свой outbox + HTTP (см. последний раздел) |
| Разовая загрузка/выгрузка, миграция | Обработка `ВыгрузкаЗагрузкаEnterpriseData` или свой код, без плана обмена |

Признаки, что БСП-обмен - лишний: внешней стороне нужен JSON по своему контракту; нужна синхронная
обработка запроса; нет второй 1С и никто не будет поддерживать XDTO-правила; нужен «отправить событие» а не
«синхронизировать справочники».

### Рецепт A. Подключить свой план обмена к БСП

1. **Метаданные.**
   - Создать `ПланОбмена.<Имя>`, заполнить «Состав» (что и с какой авторегистрацией).
   - Включить план в `ОбменДаннымиПереопределяемый.ПолучитьПланыОбмена` - иначе БСП план не видит
     (`ОбменДаннымиПовтИсп.СписокПлановОбменаБСП` строится только из этой процедуры).
   - Подписки БСП на узлы (`ВключитьИспользованиеПланаОбмена`, `ОтключитьИспользованиеПланаОбмена`,
     `ПередУдалениемПланаОбмена`, `ПроверитьВозможностьИзмененияНастроекОбменаДанными`,
     `ЗарегистрироватьИзмененияОбщихДанныхУзлов`, обработчики ПриОтправке/ПриПолучении для РИБ) уже имеют источник
     `ExchangePlanObject` (все планы) - добавлять ничего не надо, планы не из списка БСП они пропускают.
   - Функциональная опция `ИспользоватьСинхронизациюДанных` должна быть включена (панель администрирования).
   - Права: пользователям, которые запускают синхронизацию, - роль `ВыполнениеСинхронизацииДанных`
     (поставляемый профиль - `ОбменДаннымиСервер.ПрофильДоступаСинхронизацияДанныхСДругимиПрограммами()`).
   - Если регистрация не автоматическая, а по правилам - подписки на регистрацию (см. «Регистрация изменений»).
2. **Модуль менеджера плана обмена** - обязательная `ПриПолученииНастроек`; остальные процедуры - только если
   вы объявили их флагом в `Настройки.Алгоритмы` (иначе БСП их не вызывает). Структура настроек и все ключи:
   `ОбменДаннымиСервер.НастройкиПланаОбменаПоУмолчанию`, варианта - `ОписаниеВариантаНастройкиОбменаПоУмолчанию`.

```bsl
// СтандартныеПодсистемы.ОбменДанными

Процедура ПриПолученииНастроек(Настройки) Экспорт
	Настройки.ПредупреждатьОНесоответствииВерсийПравилОбмена = Ложь;
	// Для РИБ с фильтрами: Настройки.НазначениеПланаОбмена = "РИБСФильтром";
	// Для EnterpriseData: Настройки.ЭтоПланОбменаXDTO = Истина; Настройки.ВерсииФорматаОбмена.Вставить("1.20", МодульКонвертации);
	Настройки.Алгоритмы.ПриПолученииОписанияВариантаНастройки = Истина;
КонецПроцедуры

Процедура ПриПолученииОписанияВариантаНастройки(ОписаниеВарианта, ИдентификаторНастройки, ПараметрыКонтекста) Экспорт
	ОписаниеВарианта.КраткаяИнформацияПоОбмену = НСтр("ru = 'Обмен справочниками с филиалом'");
	ОписаниеВарианта.ЗаголовокКомандыДляСозданияНовогоОбменаДанными = НСтр("ru = 'Филиал'");
	ОписаниеВарианта.ИспользуемыеТранспортыСообщенийОбмена.Добавить(Перечисления.ВидыТранспортаСообщенийОбмена.FILE);
	ОписаниеВарианта.Отборы = Новый Структура("ДатаНачалаВыгрузкиДокументов", Дата(1, 1, 1));
КонецПроцедуры

// Конец СтандартныеПодсистемы.ОбменДанными
```

   Полный список флагов `Алгоритмы` (имя = имя экспортной процедуры/функции менеджера):
   `ПриПолученииВариантовНастроекОбмена`, `ПриПолученииОписанияВариантаНастройки`,
   `ОписаниеОграниченийПередачиДанных`, `ОписаниеЗначенийПоУмолчанию`, `ПредставлениеОтбораИнтерактивнойВыгрузки`,
   `НастроитьИнтерактивнуюВыгрузку`, `НастроитьИнтерактивнуюВыгрузкуВМоделиСервиса`,
   `ОбработчикПроверкиОграниченийПередачиДанных`, `ОбработчикПроверкиЗначенийПоУмолчанию`,
   `ОбработчикПроверкиПараметровУчета`, `ПриПодключенииККорреспонденту`, `ПриПолученииДанныхОтправителя`,
   `ПриОтправкеДанныхОтправителя`, `ПриСохраненииНастроекСинхронизацииДанных`,
   `ПриОпределенииПоддерживаемыхОбъектовФормата`, `ПриОпределенииПоддерживаемыхКорреспондентомОбъектовФормата`,
   `ПередНастройкойСинхронизацииДанных`. Сигнатуры смотрите в вызовах `ПланыОбмена[ИмяПланаОбмена].<Имя>(...)`
   в `ОбменДаннымиСервер` (например `ПриПолученииВариантовНастроекОбмена(ВариантыНастроекОбмена, ПараметрыОтбора)`,
   `ОписаниеОграниченийПередачиДанных(Настройка, ВерсияКорреспондента, ИдентификаторНастройки)`).
3. **Формы узла плана обмена.**

```bsl
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
	ОбменДаннымиСервер.ФормаУзлаПриСозданииНаСервере(ЭтотОбъект, Отказ);
КонецПроцедуры

&НаСервере
Процедура ПриЗаписиНаСервере(Отказ, ТекущийОбъект, ПараметрыЗаписи)
	ОбменДаннымиСервер.ФормаУзлаПриЗаписиНаСервере(ТекущийОбъект, Отказ);
КонецПроцедуры

&НаКлиенте
Процедура ПередЗаписью(Отказ, ПараметрыЗаписи)
	ОбменДаннымиКлиент.ПередЗаписью(ЭтотОбъект, Отказ, ПараметрыЗаписи);
КонецПроцедуры
```

   Форма настройки узла (отборы/значения по умолчанию): `ОбменДаннымиСервер.ФормаНастройкиУзлаПриСозданииНаСервере(ЭтотОбъект, "<ИмяПлана>")`
   в `ПриСозданииНаСервере`, `ОбменДаннымиКлиент.ФормаНастройкиПередЗакрытием(Отказ, ЭтотОбъект, ЗавершениеРаботы)` в `ПередЗакрытием`,
   кнопка «Закрыть» - `ОбменДаннымиКлиент.ФормаНастройкиУзлаКомандаЗакрытьФорму(ЭтотОбъект)`.
4. **Префикс ИБ** (уникальность номеров/кодов между узлами): `ОбменДаннымиПереопределяемый.ПриОпределенииПрефиксаИнформационнойБазыПоУмолчанию`.

### Рецепт B. РИБ

1. План обмена со свойством «Распределенная информационная база» - БСП определяет РИБ по этому свойству
   (`ОбменДаннымиПовтИсп.ЭтоПланОбменаРаспределеннойИнформационнойБазы`), назначение "РИБ" ставится автоматически,
   для РИБ с фильтрами явно: `Настройки.НазначениеПланаОбмена = "РИБСФильтром"`.
2. В состав плана включить все объекты конфигурации, которые должны жить в узле, включая объекты БСП.
3. **Не писать** логику в модуле объекта плана обмена в событиях `ПриОтправкеДанныхПодчиненному` и т.п.:
   БСП уже подписана на них (подписки `ПриОтправкеДанныхПодчиненному`, `ПриОтправкеДанныхГлавному`,
   `ПриПолученииДанныхОтГлавного`, `ПриПолученииДанныхОтПодчиненного`, `ОтменитьОтправкуДанныхУзлаВРаспределеннойИнформационнойБазе`).
   Свою логику - в `ОбщегоНазначенияПереопределяемый.ПриОтправкеДанныхПодчиненному(Источник, ЭлементДанных, ОтправкаЭлемента, СозданиеНачальногоОбраза)`
   и одноименных `ПриОтправкеДанныхГлавному`, `ПриПолученииДанныхОтПодчиненного`, `ПриПолученииДанныхОтГлавного`
   (выполняются после алгоритмов БСП).
4. Первичная настройка подчиненного узла (константы, ФО): `ОбменДаннымиПереопределяемый.ПриНастройкеПодчиненногоУзлаРИБ()`.
5. Проверки в коде: `ОбщегоНазначения.ЭтоПодчиненныйУзелРИБ()`, `ОбщегоНазначения.ЭтоПодчиненныйУзелРИБСФильтром()`,
   `ОбменДаннымиСервер.ЭтоАвтономноеРабочееМесто()`.
6. Обработчики обновления ИБ в РИБ - см. файл по `ОбновлениеВерсииИБ` (флаги выполнения только в главном узле);
   регистрация при обновлении управляется `ДополнительныеСвойства.РегистрироватьНаУзлахПлановОбменаПриОбновленииИБ`.

### Рецепт C. Обмен через EnterpriseData

1. Модуль менеджера плана: `Настройки.ЭтоПланОбменаXDTO = Истина`, `Настройки.ФорматОбмена` (пространство имен без версии),
   `Настройки.ВерсииФорматаОбмена.Вставить("<версия>", <ОбщийМодуль>)` - общий модуль с правилами конвертации
   (генерируется «Конвертацией данных 3.x»; БСП вызывает в нем `ЗаполнитьПравилаКонвертацииОбъектов`,
   `ЗаполнитьПравилаОбработкиДанных`, `ПередКонвертацией`, `ПослеКонвертации` и др.).
2. Расширение формата (свои объекты/реквизиты): XDTO-пакет расширения + `Настройки.РасширенияФорматаОбмена` или
   глобально `ОбменДаннымиПереопределяемый.ПриПолученииДоступныхРасширенийФормата`.
3. Поддерживаемые объекты формата: флаги `Алгоритмы.ПриОпределенииПоддерживаемыхОбъектовФормата` +
   процедура `ПриОпределенииПоддерживаемыхОбъектовФормата(ТаблицаОбъекты, Режим, УзелОбмена)` в менеджере.
4. Порядок загрузки (новый объектный механизм `КонвертацияОбъектно`): `ОбменДаннымиПереопределяемый.ПриОпределенииПриоритетовКонвертации`.
5. Внешняя система по EnterpriseData: транспорт `ВнешняяСистема`, итерация -
   `ОбменДаннымиСервер.ВыполнитьОбменДаннымиСВнешнейСистемой(Корреспондент, ПараметрыОбмена, ФлагОшибка)`;
   приемная сторона - веб-сервис `EnterpriseDataUpload_1_0_1_1` (операции `Ping`, `TestConnection`, `PutFilePart`, `PutData`, ...).
6. Вспомогательное в правилах: `ОбменДаннымиXDTOСервер.ЗаписатьОбъектВИБ`, `ОбменДаннымиXDTOСервер.СсылкаОбъектаПоУИДОбъектаXDTO`,
   `ОбменДаннымиXDTOСервер.ПоддерживаемыеОбъектыФормата`, `ОбменДаннымиXDTOСервер.ЗаписатьВПротоколВыполнения`.

Доработка типовой (БП/УТ/ERP) - правьте модуль менеджера обмена через формат в **расширении** или поставляйте
правила КД3; не меняйте `ОбменДаннымиXDTOСервер` - это код библиотеки.

### Регистрация изменений

- **Авторегистрация «Разрешить»** в составе плана - платформа регистрирует сама; БСП дополнительно отсекает
  немодифицированные объекты (режим `ОбменДаннымиРегистрацияСервер.РежимВыборочнойРегистрации*`).
- **Авторегистрация «Запретить» + правила регистрации (ПРО)** - нужны подписки `ПередЗаписью`/`ПередУдалением`
  на свои объекты. Обработчик подписки - в своем общем модуле, вызывает БСП:

```bsl
// Подписка: Источник = СправочникОбъект.Номенклатура, ...; Событие = ПередЗаписью
Процедура ОбменСФилиаломЗарегистрироватьИзменение(Источник, Отказ) Экспорт
	ОбменДаннымиСобытия.МеханизмРегистрацииОбъектовПередЗаписью("ОбменСФилиалом", Источник, Отказ);
КонецПроцедуры

// Документы: ПередЗаписью(Источник, Отказ, РежимЗаписи, РежимПроведения)
Процедура ОбменСФилиаломЗарегистрироватьИзменениеДокумента(Источник, Отказ, РежимЗаписи, РежимПроведения) Экспорт
	ОбменДаннымиСобытия.МеханизмРегистрацииОбъектовПередЗаписьюДокумента("ОбменСФилиалом", Источник, Отказ, РежимЗаписи, РежимПроведения);
КонецПроцедуры
```

  Остальные варианты: `МеханизмРегистрацииОбъектовПередЗаписьюРегистра(ИмяПланаОбмена, Источник, Отказ, Замещение)`,
  `...ПередЗаписьюКонстанты`, `МеханизмРегистрацииОбъектовПередУдалением`. Сами ПРО - XML из «Конвертации данных»,
  загружаются в `РегистрСведений.ПравилаДляОбменаДанными`; для производительности и безопасного режима -
  `Настройки.ПравилаРегистрацииВМенеджере = Истина` + `Настройки.ИмяМенеджераРегистрации = "<ОбщийМодуль>"`
  (иначе обработчики ПРО исполняются через `Выполнить()`).
- **Программно:** `ОбменДаннымиСобытия.ВыполнитьПравилаРегистрацииДляОбъекта(Объект, ИмяПланаОбмена)`,
  `ОбменДаннымиСобытия.ОпределитьПолучателей`, `ДополнитьПолучателей`, `СократитьПолучателей`.
- **Флаги в `ДополнительныеСвойства` записываемого объекта** (читаются в `ОбменДаннымиСобытия`):
  `ОтключитьМеханизмРегистрацииОбъектов` - не регистрировать; `РегистрироватьНаУзлахПлановОбменаПриОбновленииИБ`
  (Неопределено/Истина/Ложь) - при обновлении ИБ; `РегистрироватьОбъектНаУзлеОтправителе` - вернуть объект отправителю.
- **Начальная выгрузка:** ускорение через `ОбменДаннымиПереопределяемый.РегистрацияИзмененийНачальнойВыгрузкиДанных`
  (+ готовая `ОбменДаннымиСервер.ЗарегистрироватьДанныеПоДатеНачалаВыгрузкиИОрганизациям(Получатель, ДатаНачалаВыгрузки, Организации)`,
  находится в служебной области модуля, но рекомендована комментарием переопределяемой процедуры). Для РИБ не используется.

### Загрузка, коллизии, запреты

- В ваших `ПередЗаписью`/`ПриЗаписи`/`ОбработкаПроведения` первой строкой `Если ОбменДанными.Загрузка Тогда Возврат; КонецЕсли;`
  (кроме кода, который должен работать и при загрузке - как регистрация в БСП).
- Коллизии (объект изменен в обеих базах): `ОбменДаннымиПереопределяемый.ПриКоллизииИзмененийДанных(ЭлементДанных, ПолучениеЭлемента, Отправитель, ПолучениеОтГлавного)`;
  по умолчанию - побеждает главный узел.
- Даты запрета загрузки: `ОбменДаннымиСобытия.ЗагрузкаЗапрещена(Данные, УзелПланаОбмена)`. Комментарий БСП ссылается
  на несуществующую `ДатыЗапретаИзмененияПереопределяемый.ДанныеДляПроверкиЗапретаИзменения`; фактически источники
  данных задаются в `ДатыЗапретаИзмененияПереопределяемый.ЗаполнитьИсточникиДанныхДляПроверкиЗапретаИзменения`.
- Свой формат сообщения вместо стандартного: `ОбменДаннымиПереопределяемый.ПриВыгрузкеДанных` / `ПриЗагрузкеДанных`
  (`СтандартнаяОбработка = Ложь`, ошибки - через `ВызватьИсключение`).

### Запуск обмена и транспорт

- Пользователь: панель «Синхронизация данных» (`ОбменДаннымиКлиент.ОткрытьПанельСинхронизацииДанных`), расписание -
  сценарии обмена (регламентное задание `СинхронизацияДанных`).
- Из кода (не COM/WS): `ОбменДаннымиСервер.ВыполнитьДействиеОбмена(Отказ, Узел, Перечисления.ДействияПриОбмене.ВыгрузкаДанных)`
  и `...ЗагрузкаДанных`.
- Транспорты (`Обработка.ТранспортСообщенийОбмена*`: FILE, FTP, EMAIL, COM, WS, HTTP, ПассивныйРежим, ESB1C, GoogleDrive,
  ЯндексДиск); ограничить/добавить - `ТранспортСообщенийОбменаПереопределяемый.ПриОпределенииДоступныхТиповТранспорта`,
  `ПриОпределенииТиповТранспорта`; в варианте настройки - `ОписаниеВарианта.ИспользуемыеТранспортыСообщенийОбмена`.

### Подводные камни (ОбменДанными)

- План, не добавленный в `ПолучитьПланыОбмена`, не виден помощнику и регистрации БСП; процедуры менеджера,
  не отмеченные в `Настройки.Алгоритмы`, тихо не вызываются.
- `ПриПолученииНастроек` выполняется в привилегированном режиме и кешируется - без запросов к данным и без
  зависимости от пользователя.
- Подписки регистрации делайте отдельными на каждый план обмена; не ставьте `Источник` = «все объекты» -
  каждая запись будет вызывать правила регистрации.
- Код регистрации в БСП намеренно **не** проверяет `ОбменДанными.Загрузка` (нужна перерегистрация на другие узлы);
  не копируйте этот прием в прикладной код.
- В РИБ: обработчики платформы в модуле объекта плана обмена дублируют подписки БСП - логика выполнится дважды
  или в неправильном порядке; используйте `ОбщегоНазначенияПереопределяемый`.
- `ОбменДаннымиСервер.ВыполнитьДействиеОбмена` - тяжелая операция; запускать в фоне (длительная операция или
  регламентное задание), не в серверном вызове формы.
- Внешнее соединение (`ОбменДаннымиСервер.ВнешнееСоединениеСБазой`) работает только на Windows с зарегистрированным COM -
  в Linux-кластере выбирайте WS/HTTP/FILE.
- SaaS (`ОбменДаннымиВМоделиСервиса`, разделенные планы): регистрация неразделенных данных в разделенном режиме
  вызывает исключение - для обычной коробочной разработки не трогайте флаг `ПланОбменаИспользуетсяВМоделиСервиса`.

### Когда НЕ использовать: outbox + HTTP к своему бэкенду

Если корреспондент - ваш собственный сервис с JSON-API, БСП-обмен дает лишнее (XDTO, правила, сопоставление,
помощник) и не дает нужного (свой контракт, идемпотентность, ретраи по HTTP-кодам). Рецепт:

1. **Очередь изменений (outbox).** Вариант 1 - свой план обмена с одним узлом «Бэкенд» и авторегистрацией нужных
   объектов, **не** включенный в `ОбменДаннымиПереопределяемый.ПолучитьПланыОбмена` (подписки БСП его игнорируют).
   Вариант 2 - регистр сведений `ОчередьИсходящихСобытий` (ИД события, объект, тип события, статус, попытки),
   запись в той же транзакции, что и изменение данных (в `ПриЗаписи` объекта или подписке).
2. **Отправка** - регламентное задание: выборка порции (`ПланыОбмена.ВыбратьИзменения(Узел, НомерСообщения)` или запрос
   к регистру), сериализация в JSON (`ЗаписьJSON`), `HTTPСоединение` + `HTTPЗапрос`, по успешному ответу -
   `ПланыОбмена.УдалитьРегистрациюИзменений(Узел, НомерСообщения)` / статус «Отправлено». Ключ идемпотентности -
   `УникальныйИдентификатор` ссылки + версия данных, чтобы бэкенд мог безопасно принимать повтор.
3. **Прием** - свой HTTP-сервис конфигурации, валидация входа на границе, запись с `ОбменДанными.Загрузка = Истина`
   только когда действительно не нужны бизнес-проверки.
4. **Из БСП берите только инфраструктуру:** секреты - `ОбщегоНазначения.ЗаписатьДанныеВБезопасноеХранилище` /
   `ПрочитатьДанныеИзБезопасногоХранилища`; прокси - `ПолучениеФайловИзИнтернета.ПолучитьПрокси`;
   фоновые задания - `ДлительныеОперации`; разрешения на внешние ресурсы - профили безопасности
   (`РаботаВБезопасномРежиме`); журнал - `ЗаписьЖурналаРегистрации` со своим именем события.
5. Не делайте HTTP-вызов внутри транзакции записи объекта и в `ПередЗаписью` - сеть недоступна/медленна,
   транзакция держит блокировки; только через очередь.
