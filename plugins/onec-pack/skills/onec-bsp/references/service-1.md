## Печать - печатные формы, команды печати, макеты MXL/DOCX, подписи и печати

**Когда использовать:** любая печатная форма (накладная, акт, счет, договор), печать сразу на принтер, сохранение в PDF/DOCX, отправка по почте, комплекты, пользовательское редактирование макетов, факсимиле подписей и печатей. Заменяет самописные кнопки «Печать» на форме, ручное открытие `ТабличныйДокумент.Показать()`, собственные формы предпросмотра и хранение «исправленных» макетов. Форма предпросмотра - `ОбщаяФорма.ПечатьДокументов`.

### Рецепт A: своя процедура Печать (MXL)

1. **Метаданные.**
   - Макет объекта типа «Табличный документ» с именем `ПФ_MXL_<Имя>` (например `ПФ_MXL_РасходнаяНакладная`). Подстрока `ПФ_` в имени обязательна, чтобы макет попал в список «Макеты печатных форм» и его можно было переопределить у пользователя (`УправлениеПечатью`, отбор `СтрНайти(Макет.Имя, "ПФ_") > 0`). Для мультиязычности - суффикс `_ru`, `_en` (см. `МакетПечатнойФормы`).
   - Определяемые типы, только если нужны соответствующие функции: `ОбъектСОсновнымиПечатнымиФормами` (запоминание «основной» печатной формы), `ПолучательПечатныхФорм` (получатели письма).
   - Роли подсистемы: `РедактированиеПечатныхФорм` (редактирование/отправка/сохранение сформированных форм), `ИзменениеМакетовПечатныхФорм` (правка макетов). Готовый профиль: `УправлениеПечатью.ЗаполнитьПрофильРедактированиеПечатныхФорм(ОписанияПрофилей)` в `УправлениеДоступомПереопределяемый.ПриЗаполненииПоставляемыхПрофилейГруппДоступа`.

2. **Переопределяемый модуль** - зарегистрировать менеджер объекта:
   ```bsl
   // УправлениеПечатьюПереопределяемый
   Процедура ПриОпределенииНастроекПечати(Настройки) Экспорт
       Настройки.ОбъектыПечати.Добавить(Документы.РасходнаяНакладная);
       // Настройки.ПроверкаПроведенияПередПечатью = Истина; // умолчание для всех команд
   КонецПроцедуры
   ```
   Так же это делает сама БСП (`ЗащитаПерсональныхДанных`: `НастройкиПечати.ОбъектыПечати.Добавить(Документы.СогласиеНаОбработкуПерсональныхДанных)`). Процедура `ПриОпределенииОбъектовСКомандамиПечати` - устарела.

3. **Модуль менеджера** (область `ПрограммныйИнтерфейс` или `СлужебныйПрограммныйИнтерфейс`, блок `// СтандартныеПодсистемы.Печать`). Образец - `Документ.СогласиеНаОбработкуПерсональныхДанных`:
   ```bsl
   // СтандартныеПодсистемы.Печать

   // Параметры:
   //  Настройки - см. УправлениеПечатью.НастройкиПечатиОбъекта.
   Процедура ПриОпределенииНастроекПечати(Настройки) Экспорт
       Настройки.ПриДобавленииКомандПечати = Истина; // иначе ДобавитьКомандыПечати не вызывается
   КонецПроцедуры

   // Параметры:
   //  КомандыПечати - см. УправлениеПечатью.СоздатьКоллекциюКомандПечати
   Процедура ДобавитьКомандыПечати(КомандыПечати) Экспорт
       КомандаПечати = КомандыПечати.Добавить();
       КомандаПечати.Идентификатор = "РасходнаяНакладная";
       КомандаПечати.Представление = НСтр("ru = 'Расходная накладная'");
       КомандаПечати.ПроверкаПроведенияПередПечатью = Истина;
       // необязательные: Порядок, Картинка, СписокФорм, ФункциональныеОпции, СразуНаПринтер,
       // ФорматСохранения, ДополнительныеПараметры, ОсновнаяПечатнаяФорма; условия:
       // УправлениеПечатью.ДобавитьУсловиеВидимостиКоманды(КомандаПечати, "Статус", Перечисления.Статусы.Отгружен);
   КонецПроцедуры

   // Параметры: см. УправлениеПечатьюПереопределяемый.ПриПечати
   Процедура Печать(МассивОбъектов, ПараметрыПечати, КоллекцияПечатныхФорм, ОбъектыПечати, ПараметрыВывода) Экспорт
       ПечатнаяФорма = УправлениеПечатью.СведенияОПечатнойФорме(КоллекцияПечатныхФорм, "РасходнаяНакладная");
       Если ПечатнаяФорма <> Неопределено Тогда
           ПечатнаяФорма.ТабличныйДокумент = ПечатьРасходнойНакладной(МассивОбъектов, ОбъектыПечати);
           ПечатнаяФорма.СинонимМакета = НСтр("ru = 'Расходная накладная'");
           ПечатнаяФорма.ПолныйПутьКМакету = "Документ.РасходнаяНакладная.ПФ_MXL_РасходнаяНакладная";
       КонецЕсли;
   КонецПроцедуры

   // Конец СтандартныеПодсистемы.Печать
   ```
   Формирование табличного документа (служебная область):
   ```bsl
   Функция ПечатьРасходнойНакладной(МассивОбъектов, ОбъектыПечати)
       ТабличныйДокумент = Новый ТабличныйДокумент;
       ТабличныйДокумент.КлючПараметровПечати = "ПараметрыПечати_РасходнаяНакладная";
       Макет = УправлениеПечатью.МакетПечатнойФормы("Документ.РасходнаяНакладная.ПФ_MXL_РасходнаяНакладная");
       Выборка = ДанныеДляПечати(МассивОбъектов); // ОДИН запрос на все объекты
       Пока Выборка.Следующий() Цикл
           Если ТабличныйДокумент.ВысотаТаблицы > 0 Тогда
               ТабличныйДокумент.ВывестиГоризонтальныйРазделительСтраниц();
           КонецЕсли;
           НомерСтрокиНачало = ТабличныйДокумент.ВысотаТаблицы + 1;
           Область = Макет.ПолучитьОбласть("Заголовок");
           Область.Параметры.Заполнить(Выборка);
           ТабличныйДокумент.Вывести(Область);
           // ... строки, подвал ...
           УправлениеПечатью.ЗадатьОбластьПечатиДокумента(ТабличныйДокумент, НомерСтрокиНачало, ОбъектыПечати, Выборка.Ссылка);
       КонецЦикла;
       Возврат ТабличныйДокумент;
   КонецФункции
   ```
   Несколько форм в одной процедуре: проверять `УправлениеПечатью.НужноПечататьМакет(КоллекцияПечатныхФорм, "Имя")` и выводить через `УправлениеПечатью.ВывестиТабличныйДокументВКоллекцию(...)`. Имя файла при сохранении/отправке - `ПечатнаяФорма.ИмяФайлаПечатнойФормы` (строка или `Соответствие` ссылка -> имя). Тема/получатели письма - `ПараметрыВывода.ПараметрыОтправки`.

4. **Формы объекта и списка** - подключить ПодключаемыеКоманды (так в `Документ.СогласиеНаОбработкуПерсональныхДанных.ФормаДокумента`):
   ```bsl
   // ПриСозданииНаСервере
   ПодключаемыеКоманды.ПриСозданииНаСервере(ЭтотОбъект);
   // ПриЧтенииНаСервере (форма объекта)
   ПодключаемыеКомандыКлиентСервер.ОбновитьКоманды(ЭтотОбъект, Объект);
   // ПриОткрытии
   ПодключаемыеКомандыКлиент.НачатьОбновлениеКоманд(ЭтотОбъект);
   // ПослеЗаписи
   ПодключаемыеКомандыКлиент.ПослеЗаписи(ЭтотОбъект, Объект, ПараметрыЗаписи);

   &НаКлиенте
   Процедура Подключаемый_ВыполнитьКоманду(Команда)
       ПодключаемыеКомандыКлиент.НачатьВыполнениеКоманды(ЭтотОбъект, Команда, Объект);
   КонецПроцедуры
   &НаКлиенте
   Процедура Подключаемый_ПродолжитьВыполнениеКомандыНаСервере(ПараметрыВыполнения, ДополнительныеПараметры) Экспорт
       ВыполнитьКомандуНаСервере(ПараметрыВыполнения);
   КонецПроцедуры
   &НаСервере
   Процедура ВыполнитьКомандуНаСервере(ПараметрыВыполнения)
       ПодключаемыеКоманды.ВыполнитьКоманду(ЭтотОбъект, ПараметрыВыполнения, Объект);
   КонецПроцедуры
   &НаКлиенте
   Процедура Подключаемый_ОбновитьКоманды()
       ПодключаемыеКомандыКлиентСервер.ОбновитьКоманды(ЭтотОбъект, Объект);
   КонецПроцедуры
   ```
   В форме списка вместо `Объект` передается `Элементы.Список`. Подменю «Печать» создается автоматически; если на форме несколько подменю печати - `КомандаПечати.МестоРазмещения`.

### Рецепт B: печать по макету и данным печати

Макет заполняется подсистемой сама, код формирования не нужен; пользователь может править макет и добавлять поля в редакторе.
- Команда: `КомандаПечати.МенеджерПечати = "УправлениеПечатью"`, `КомандаПечати.Идентификатор = "Документ.<Имя>.ПФ_MXL_<Макет>"` (или `ПФ_DOC_<Макет>_ru` для Office Open XML, `Картинка = БиблиотекаКартинок.ФорматWord`). Так сделано в `Документ.АктОбУничтоженииПерсональныхДанных`.
- Источник полей: если у объекта есть макет СКД с именем **`ДанныеПечати`** - используется он; иначе схема генерируется автоматически по всем реквизитам объекта (`ПриОпределенииИсточниковДанныхПечати`, комментарий в `УправлениеПечатьюПереопределяемый`). В схеме обязательно поле `Ссылка` (по нему отбор).
- Если в схеме есть набор данных-объект, объявить в модуле менеджера:
  ```bsl
  Процедура ПриПодготовкеДанныхПечати(ИсточникиДанных, ВнешниеНаборыДанных, КодЯзыка, ДополнительныеПараметры) Экспорт
      ВнешниеНаборыДанных.Вставить("ДанныеПечати", ДанныеПечати(ИсточникиДанных, КодЯзыка, ДополнительныеПараметры));
  КонецПроцедуры
  ```
  Внимание: у процедуры менеджера 4 параметра, у `УправлениеПечатьюПереопределяемый.ПриПодготовкеДанныхПечати` - 5 (плюс `ИдентификаторСхемыКомпоновкиДанных`). Вызов идет в менеджер, если идентификатор схемы - полное имя объекта метаданных.
- Дополнительные источники для отдельных полей (склонение ФИО и т.п.) - процедура менеджера `ПриОпределенииИсточниковДанныхПечати(Объект, ИсточникиДанныхПечати)`, см. `Документ.АктОбУничтоженииПерсональныхДанных`. Общие поля для всех объектов - `УправлениеПечатьюПереопределяемый.ПриЗаполненииСпискаОбщихПолей`.
- `УправлениеПечатью.ДанныеПечати(Объекты, Поля, КодЯзыка)` существует, но лежит в области `СлужебныйПрограммныйИнтерфейс` - из прикладного кода не вызывать.

### Рецепт C: офисный документ DOCX из кода

Макет объекта `ПФ_DOC_<Имя>` типа «Двоичные данные» (DOCX). Параметры в тексте шаблона - `{v8 ИмяПараметра}` (`УправлениеПечатьюСлужебный`), области размечаются парными тегами `{v8 ...}` / `{/v8 ...}` - точный синтаксис разметки областей сверяйте с поставляемыми макетами `ПФ_DOC_*`. Типы областей: `ВерхнийКолонтитул`, `НижнийКолонтитул`, `Общая`, `СтрокаТаблицы`, `Список` (+ титульные/четные колонтитулы).
```bsl
// внутри Процедура Печать(...) модуля менеджера
ПечатнаяФорма = УправлениеПечатью.СведенияОПечатнойФорме(КоллекцияПечатныхФорм, "ДоговорDOCX");
Если ПечатнаяФорма <> Неопределено Тогда
    ОфисныеДокументы = Новый Соответствие;
    ДвоичныеДанныеМакета = УправлениеПечатью.МакетПечатнойФормы("Документ.Договор.ПФ_DOC_Договор");
    Для Каждого Ссылка Из МассивОбъектов Цикл
        Макет = УправлениеПечатью.ИнициализироватьМакетОфисногоДокумента(ДвоичныеДанныеМакета, "");
        ДокументDOCX = Неопределено;
        Попытка
            ДокументDOCX = УправлениеПечатью.ИнициализироватьПечатнуюФорму(Неопределено, Неопределено, Макет);
            Области = Новый Структура;
            УправлениеПечатью.ДобавитьОписаниеОбласти(Области, "Шапка", "Общая");
            УправлениеПечатью.ДобавитьОписаниеОбласти(Области, "Строка", "СтрокаТаблицы");
            Данные = ДанныеДоговора(Ссылка); // Структура полей + Массив структур строк
            УправлениеПечатью.ПрисоединитьОбластьИЗаполнитьПараметры(ДокументDOCX,
                УправлениеПечатью.ОбластьМакета(Макет, Области.Шапка), Данные.Шапка);
            УправлениеПечатью.ПрисоединитьИЗаполнитьКоллекцию(ДокументDOCX,
                УправлениеПечатью.ОбластьМакета(Макет, Области.Строка), Данные.Строки);
            Адрес = УправлениеПечатью.СформироватьДокумент(ДокументDOCX);
            ОфисныеДокументы.Вставить(Адрес, СтрШаблон(НСтр("ru = 'Договор %1.docx'"), Данные.Шапка.Номер));
        Исключение
            УправлениеПечатью.ОчиститьСсылки(ДокументDOCX);
            УправлениеПечатью.ОчиститьСсылки(Макет);
            ВызватьИсключение;
        КонецПопытки;
        УправлениеПечатью.ОчиститьСсылки(ДокументDOCX);
        УправлениеПечатью.ОчиститьСсылки(Макет);
    КонецЦикла;
    ПечатнаяФорма.ОфисныеДокументы = ОфисныеДокументы; // Ключ - адрес во временном хранилище, Значение - имя файла
КонецЕсли;
```
`ОчиститьСсылки` удаляет временные файлы распакованного DOCX - вызывать всегда, в том числе при ошибке (так требует комментарий метода). Старые параметры `УдалитьТипДокумента`/`УдалитьТипМакета` не используются. Для DOCX без собственного кода предпочитайте рецепт B.

### Прочие точки встраивания
- `УправлениеПечатьюПереопределяемый.ПриПолученииПодписейИПечатей(Документы, ПодписиИПечати)` - картинки факсимиле; в макете области/рисунки с именами, начинающимися на `Подпись...`, `Печать...`, `Факсимиле...`. Отключить механизм - `Настройки.ИспользоватьПодписиИПечати = Ложь` в `ПриОпределенииНастроекПечати`.
- `ПриПечати` (постобработка всех форм), `ПередПечатью`, `ПередОтправкойПоПочте`, `ПриПолученииКомандПечати` (подправить чужие команды без правки менеджера - удобно на типовых конфигурациях), `ПередДобавлениемКомандПечати` (общие формы без менеджера), `ПриПолученииНастроекСпискаКомандПечати` (журналы документов).
- Клиентский обработчик вместо серверного: `КомандаПечати.Обработчик = "МойМодульКлиент.МояПечать"` - вызывается через `Вычислить`, поэтому это должна быть **функция**.
- Печать из своего кода: клиент - `УправлениеПечатьюКлиент.ВыполнитьКомандуПечати("Документ.РасходнаяНакладная", "РасходнаяНакладная", МассивСсылок, ЭтотОбъект)`; сервер/фон (почта, регламент) - `УправлениеПечатью.НапечататьВФайл(КомандыПечати, СписокОбъектов, УправлениеПечатью.НастройкиСохранения())`.
- Перенос макета в другой объект при рефакторинге - `ЗарегистрироватьНовоеИмяМакета` + `ПеренестиПользовательскиеМакеты` в обработчике обновления (иначе пользовательские правки макета потеряются).

**Главные методы API** (`api/Печать.md`):
- `УправлениеПечатью.СоздатьКоллекциюКомандПечати` - описание всех колонок команды печати (читать перед заполнением).
- `УправлениеПечатью.СведенияОПечатнойФорме` / `НужноПечататьМакет` - найти заказанную форму в `КоллекцияПечатныхФорм`.
- `УправлениеПечатью.МакетПечатнойФормы(ПутьКМакету, КодЯзыка)` - макет с учетом пользовательских изменений и языка.
- `УправлениеПечатью.ЗадатьОбластьПечатиДокумента` - разметка объекта в общем табличном документе.
- `УправлениеПечатью.ВывестиТабличныйДокументВКоллекцию` - добавить готовый табличный документ.
- `УправлениеПечатью.ДобавитьУсловиеВидимостиКоманды` - видимость команды по значению реквизита.
- `УправлениеПечатью.НапечататьВФайл` - печать в файлы на сервере.
- `УправлениеПечатью.ИнициализироватьМакетОфисногоДокумента` / `ОбластьМакета` / `ПрисоединитьОбластьИЗаполнитьПараметры` / `СформироватьДокумент` / `ОчиститьСсылки` - DOCX.
- `УправлениеПечатьюКлиент.ВыполнитьКомандуПечати` / `ПечатьДокументов` - запуск печати с клиента.

**Подводные камни:**
- `ПолучитьМакет("...")` напрямую игнорирует макет, исправленный пользователем, - всегда `УправлениеПечатью.МакетПечатнойФормы`.
- Без `ЗадатьОбластьПечатиДокумента` при печати нескольких объектов не работает разбиение на файлы/письма по объектам.
- Без `Настройки.ПриДобавленииКомандПечати = Истина` в менеджере команды не появятся, даже если `ДобавитьКомандыПечати` есть; без регистрации в `ОбъектыПечати` не вызывается и `ПриОпределенииНастроекПечати`.
- Процедура `Печать` выполняется на сервере в правах пользователя (RLS действует) - чтение «чужих» данных для формы (реквизиты организации, подписанты) при необходимости через `УстановитьПривилегированныйРежим` точечно, не на весь запрос.
- Не делать `ЗначениеРеквизитаОбъекта` в цикле по `МассивОбъектов` - один запрос на массив (`ОбщегоНазначения.ЗначенияРеквизитовОбъектов` или свой запрос).
- `КлючПараметровПечати` задавать уникальным - по нему запоминаются поля/ориентация.
- `ПриПечати` не вызывается для `УправлениеПечатьюКлиент.ПечатьДокументов` (комментарий в исходнике).
- На типовых конфигурациях (БП/УТ/ERP) не правьте `ДобавитьКомандыПечати` типового менеджера: добавляйте команды через `УправлениеПечатьюПереопределяемый.ПриПолученииКомандПечати` в расширении или внешние печатные формы (подсистема ДополнительныеОтчетыИОбработки).

## РаботаСФайлами - присоединенные файлы к любому объекту

**Когда использовать:** «прикрепить скан/договор/фото к документу или справочнику», картинка товара на форме, хранение файлов в томах, электронная подпись файлов, сканирование, отправка файлов почтой. Заменяет реквизиты типа `ХранилищеЗначения` в объекте, самописные регистры «файлы объекта» и ручные диалоги выбора файла.

**Встраивание в свой объект (рецепт):**
1. **Метаданные.**
   - Создать справочник хранения `<ИмяВладельца>ПрисоединенныеФайлы` - суффикс обязателен (`РаботаСФайламиСлужебный.СуффиксСправочникаПрисоединенныеФайлы()` = `"ПрисоединенныеФайлы"`). Структуру скопировать с `Справочник.МашиночитаемыеДоверенностиПрисоединенныеФайлы`: неиерархический, без кода, наименование 150, реквизиты `Автор, ВладелецФайла, ДатаЗаема, ДатаМодификацииУниверсальная, ДатаСоздания, Зашифрован, Изменил, ИндексКартинки, Описание, ПодписанЭП, ПутьКФайлу, Размер, Расширение, Редактирует, СтатусИзвлеченияТекста, ТекстХранилище, ТипХраненияФайла, Том, ФайлХранилище, ХранитьВерсии, Служебный`; `ВладелецФайла` - ссылка на ваш объект (это реквизит, не «Владелец» справочника). Модули объекта/формы не нужны - логику дают подписки.
   - Определяемые типы:
     - `ВладелецПрисоединенныхФайлов` += `СправочникСсылка.<Владелец>` (от него зависит общая команда `ПрисоединенныеФайлы` в панели навигации);
     - `ВладелецПрисоединенныхФайловОбъект` += `СправочникОбъект.<Владелец>` (подписка `УстановитьПометкуУдаленияПрисоединенныхФайлов` - пометка удаления файлов вместе с владельцем);
     - `ПрисоединенныйФайл` += `СправочникСсылка.<Владелец>ПрисоединенныеФайлы`;
     - `ПрисоединенныйФайлОбъект` += `СправочникОбъект.<Владелец>ПрисоединенныеФайлы` (подписки `ВыполнитьДействияПередЗаписьюПрисоединенногоФайла`, `ВыполнитьДействияПриЗаписиПрисоединенногоФайла`, `ВыполнитьДействияПередУдалениемПрисоединенногоФайла`, `ОбработкаПроверкиЗаполненияПрисоединенногоФайла`).
   - `ВладелецФайлов` - это для справочника `Файлы` (папки/задачи), для присоединенных файлов не нужен.
   - Роли: права на новый справочник выдать в тех же ролях, что и на владельца (чтение/изменение). Роль подсистемы `ДобавлениеИзменениеПапокИФайлов` - для общего справочника `Файлы`.
2. **Модуль менеджера справочника файлов** (как у `МашиночитаемыеДоверенностиПрисоединенныеФайлы`):
   ```bsl
   // СтандартныеПодсистемы.ГрупповоеИзменениеОбъектов
   Функция РеквизитыРедактируемыеВГрупповойОбработке() Экспорт
       Возврат ОбщегоНазначения.ОбщийМодуль("РаботаСФайлами").РеквизитыРедактируемыеВГрупповойОбработке();
   КонецФункции
   // СтандартныеПодсистемы.УправлениеДоступом
   Процедура ПриЗаполненииОграниченияДоступа(Ограничение) Экспорт
       Ограничение.Текст =
       "РазрешитьЧтение
       |ГДЕ
       |	ЧтениеОбъектаРазрешено(ВладелецФайла)
       |;
       |РазрешитьИзменениеЕслиРазрешеноЧтение
       |ГДЕ
       |	ИзменениеОбъектаРазрешено(ВладелецФайла)";
   КонецПроцедуры
   ```
3. **Переопределяемые (по необходимости):**
   - `РаботаСФайламиПереопределяемый.ПриОпределенииСправочниковХраненияФайлов(ТипВладелецФайла, ИменаСправочников)` - если справочников хранения несколько или файлы нужно класть в общий `Файлы`:
     ```bsl
     Если ТипВладелецФайла = Тип("СправочникСсылка.Номенклатура") Тогда
         ИменаСправочников["НоменклатураПрисоединенныеФайлы"] = Ложь;
         ИменаСправочников.Вставить("Файлы", Истина); // Истина = основной для интерактивной работы
     КонецЕсли;
     ```
   - `РаботаСФайламиПереопределяемый.ПриОпределенииНастроек(Настройки)` - `НеОчищатьФайлы`, `НеСинхронизироватьФайлы`, `НеСоздаватьФайлыПоШаблону`, `ДоступенФайловыйАрхив`.
   - `ПриСозданииФайла`, `ПриОтправкеФайловПочтой`, `ПриОпределенииГиперссылкиФайлов` - тонкая настройка.
4. **Форма владельца** (образец - `Документ.Встреча.ФормаДокумента`):
   ```bsl
   // ПриСозданииНаСервере
   ГиперссылкаФайлов = РаботаСФайлами.ГиперссылкаФайлов();
   ГиперссылкаФайлов.Размещение = "КоманднаяПанель"; // или имя группы формы
   РаботаСФайлами.ПриСозданииНаСервере(ЭтотОбъект, ГиперссылкаФайлов);
   // поле картинки: ПараметрыПоля = РаботаСФайлами.ПолеФайла(); ПараметрыПоля.ПутьКДанным = "Объект.ФайлКартинки";
   //                ПараметрыПоля.ПутьКДаннымИзображения = "АдресКартинки"; - можно передать массив из обоих

   // ПриОткрытии
   РаботаСФайламиКлиент.ПриОткрытии(ЭтотОбъект, Отказ);
   // ОбработкаОповещения
   РаботаСФайламиКлиент.ОбработкаОповещения(ЭтотОбъект, ИмяСобытия);
   // ПриЗаписиНаСервере - если на форме есть поле файла
   РаботаСФайлами.ПриЗаписиНаСервере(Отказ, ТекущийОбъект, ПараметрыЗаписи, ЭтотОбъект);

   &НаКлиенте
   Процедура Подключаемый_КомандаПанелиПрисоединенныхФайлов(Команда)
       РаботаСФайламиКлиент.КомандаУправленияПрисоединеннымиФайлами(ЭтотОбъект, Команда);
   КонецПроцедуры
   // для поля картинки дополнительно: Подключаемый_ПолеПредпросмотраНажатие,
   // Подключаемый_ПолеПредпросмотраПроверкаПеретаскивания, Подключаемый_ПолеПредпросмотраПеретаскивание
   // -> РаботаСФайламиКлиент.ПолеПредпросмотраНажатие / ...ПроверкаПеретаскивания / ...Перетаскивание
   ```
   Имена обработчиков `Подключаемый_*` фиксированы - их подставляет `РаботаСФайлами` при создании элементов.

5. **Программная работа (сервер):**
   ```bsl
   ПараметрыФайла = РаботаСФайлами.ПараметрыДобавленияФайла();
   ПараметрыФайла.ВладелецФайлов = ДокументСсылка;
   ПараметрыФайла.ИмяБезРасширения = "Скан договора";
   ПараметрыФайла.РасширениеБезТочки = "pdf";
   Адрес = ПоместитьВоВременноеХранилище(ДвоичныеДанные, Новый УникальныйИдентификатор);
   Файл = РаботаСФайлами.ДобавитьФайл(ПараметрыФайла, Адрес);
   // чтение: ДД = РаботаСФайлами.ДвоичныеДанныеФайла(Файл, Ложь); // Неопределено вместо исключения
   ```

**Главные методы API** (`api/РаботаСФайлами.md`):
- `РаботаСФайлами.ПриСозданииНаСервере` / `ГиперссылкаФайлов` / `ПолеФайла` - элементы на форме.
- `РаботаСФайлами.ДобавитьФайл` + `ПараметрыДобавленияФайла` - создать файл из временного хранилища.
- `РаботаСФайлами.ДобавитьФайлСДиска(ВладелецФайлов, ПутьКФайлуНаДиске)` - файл с диска сервера.
- `РаботаСФайлами.ДвоичныеДанныеФайла` / `ДвоичныеДанныеФайлов` / `ДанныеФайла` - получить содержимое и сведения.
- `РаботаСФайлами.ЗаполнитьПрисоединенныеФайлыКОбъекту(ВладелецФайла, Файлы)` - список файлов владельца.
- `РаботаСФайлами.СкопироватьПрисоединенныеФайлы(Источник, Получатель)` - при копировании/вводе на основании.
- `РаботаСФайлами.ОбновитьФайл` - заменить содержимое.
- `РаботаСФайламиКлиент.ДобавитьФайлы` / `ОткрытьФайл` / `ОткрытьФормуСпискаФайлов` / `ДобавитьСоСканера` - клиент.

**Подводные камни:**
- Забыли `...Объект` определяемый тип - файлы не помечаются на удаление вместе с владельцем и не работают проверки при записи файла.
- Нет RLS на справочнике файлов - пользователь видит файлы чужих документов (ограничение по `ВладелецФайла` обязательно при включенном УправлениеДоступом).
- `ДвоичныеДанныеФайла` по умолчанию бросает исключение, если файл не найден в томе - в регламентах передавайте `ВызыватьИсключение = Ложь`.
- Тома на диске (`ХранитьФайлыВТомахНаДиске`) - путь тома должен быть доступен всем рабочим процессам кластера; не пишите в `ФайлХранилище` напрямую - только API.
- Большие файлы - ограничение `РаботаСФайлами.МаксимальныйРазмерФайла()`; передача на клиент - через временное хранилище, не через параметры серверного вызова.
- В модели сервиса константы `...ОбластиДанных` - отдельные; приклад их не трогает.

## Свойства - дополнительные реквизиты и сведения, метки

**Когда использовать:** пользователь (не разработчик) должен сам добавлять поля к справочнику/документу без доработки конфигурации; разный состав полей по видам (вид номенклатуры); метки (теги) на объектах. Заменяет «универсальные» ТЧ «Характеристика/Значение», регистры «произвольные реквизиты» и ПВХ, сделанные вручную.

Два вида: **дополнительные реквизиты** - хранятся в ТЧ объекта, редактируются в форме объекта, меняют версию объекта; **дополнительные сведения** - хранятся в регистре `ДополнительныеСведения`, редактируются отдельной командой, не требуют права изменения объекта.

**Встраивание в свой объект (рецепт):**
1. **Метаданные.**
   - Для доп. реквизитов: в объект добавить табличную часть `ДополнительныеРеквизиты` с реквизитами `Свойство` (ПВХ `ДополнительныеРеквизитыИСведения`), `Значение` (тип - Характеристика.ДополнительныеРеквизитыИСведения), `ТекстоваяСтрока` (Строка неограниченной длины). В свойстве объекта «Характеристики» добавить связь как у `Документ.СогласиеНаОбработкуПерсональныхДанных`: виды - `Справочник.НаборыДополнительныхРеквизитовИСведений.ТабличнаяЧасть.ДополнительныеРеквизиты` (ключ `Свойство`, отбор типов `ИмяПредопределенногоНабора`), значения - ТЧ `ДополнительныеРеквизиты` объекта (объект `Ссылка`, вид `Свойство`, значение `Значение`).
   - Для доп. сведений: определяемый тип `ВладелецДополнительныхСведений` += ссылка на объект (измерение регистра `ДополнительныеСведения` и параметр общей команды `ДополнительныеСведенияКоманднаяПанель`); вторая характеристика: виды - ТЧ `ДополнительныеСведения` набора (ключ `Свойство`, отбор `ИмяПредопределенногоНабора`), значения - `РегистрСведений.ДополнительныеСведения` (объект `Объект`, вид `Свойство`, значение `Значение`).
   - Метки: тип владельца в определяемый тип `ВладелецМеток`.
   - Подписки `ДополнительныеРеквизитыОбработкаПроверкиЗаполнения` и `СвойстваПередУдалениемСсылочногоОбъекта` уже настроены на все объекты по типу - их не трогать.
   - Роли подсистемы: `ДобавлениеИзменениеДополнительныхРеквизитовИСведений` (настройка), `ЧтениеДополнительныхСведений`, `ИзменениеДополнительныхСведений`.
2. **Переопределяемый модуль** - предопределенный набор свойств объекта (в 3.2 наборы задаются кодом, не предопределенными элементами):
   ```bsl
   // УправлениеСвойствамиПереопределяемый
   Процедура ПриПолученииПредопределенныхНаборовСвойств(Наборы) Экспорт
       Набор = Наборы.Строки.Добавить();
       Набор.Имя = "Документ_РасходнаяНакладная"; // полное имя с "." -> "_"
       Набор.Идентификатор = Новый УникальныйИдентификатор("<новый Random UUID v4>");
       // Набор.Используется = ПолучитьФункциональнуюОпцию(...); // необязательно
   КонецПроцедуры
   ```
   Пример в БСП - `ЗащитаПерсональныхДанных.ПриПолученииПредопределенныхНаборовСвойств`. Несколько наборов по виду объекта - `ЗаполнитьНаборыСвойствОбъекта(Объект, ТипСсылки, НаборыСвойств, СтандартнаяОбработка, КлючНазначения)`, а в модуле объекта «вида» вызывать `УправлениеСвойствами.ПередЗаписьюВидаОбъекта(ЭтотОбъект, "Номенклатура")` (имя объекта без вида метаданных; реквизит набора в виде по умолчанию `НаборСвойств`) и `ПередУдалениемВидаОбъекта`. Ссылка на набор по имени - `УправлениеСвойствами.НаборСвойствПоИмени("Документ_РасходнаяНакладная")`.
3. **Форма объекта** (образец - `Документ.СогласиеНаОбработкуПерсональныхДанных.ФормаДокумента`):
   ```bsl
   // ПриСозданииНаСервере
   ДополнительныеПараметры = Новый Структура;
   ДополнительныеПараметры.Вставить("ИмяЭлементаДляРазмещения", "СтраницаДополнительныеРеквизиты");
   УправлениеСвойствами.ПриСозданииНаСервере(ЭтотОбъект, ДополнительныеПараметры);
   // ПриЧтенииНаСервере
   УправлениеСвойствами.ПриЧтенииНаСервере(ЭтотОбъект, ТекущийОбъект);
   // ОбработкаПроверкиЗаполненияНаСервере
   УправлениеСвойствами.ОбработкаПроверкиЗаполнения(ЭтотОбъект, Отказ, ПроверяемыеРеквизиты);
   // ПередЗаписьюНаСервере
   УправлениеСвойствами.ПередЗаписьюНаСервере(ЭтотОбъект, ТекущийОбъект);
   // ПриОткрытии
   УправлениеСвойствамиКлиент.ПослеЗагрузкиДополнительныхРеквизитов(ЭтотОбъект);
   // ОбработкаОповещения
   Если УправлениеСвойствамиКлиент.ОбрабатыватьОповещения(ЭтотОбъект, ИмяСобытия, Параметр) Тогда
       ОбновитьЭлементыДополнительныхРеквизитов(); // &НаСервере: УправлениеСвойствами.ОбновитьЭлементыДополнительныхРеквизитов(ЭтотОбъект)
       УправлениеСвойствамиКлиент.ПослеЗагрузкиДополнительныхРеквизитов(ЭтотОбъект);
   КонецЕсли;

   &НаКлиенте
   Процедура Подключаемый_СвойстваВыполнитьКоманду(ЭлементИлиКоманда, НавигационнаяСсылка = Неопределено, СтандартнаяОбработка = Неопределено)
       УправлениеСвойствамиКлиент.ВыполнитьКоманду(ЭтотОбъект, ЭлементИлиКоманда, СтандартнаяОбработка);
   КонецПроцедуры
   &НаКлиенте
   Процедура Подключаемый_ПриИзмененииДополнительногоРеквизита(Элемент)
       УправлениеСвойствамиКлиент.ОбновитьЗависимостиДополнительныхРеквизитов(ЭтотОбъект);
   КонецПроцедуры
   &НаКлиенте
   Процедура ОбновитьЗависимостиДополнительныхРеквизитов()
       УправлениеСвойствамиКлиент.ОбновитьЗависимостиДополнительныхРеквизитов(ЭтотОбъект);
   КонецПроцедуры
   ```
   В БСП эти вызовы обернуты в `ОбщегоНазначения.ПодсистемаСуществует("СтандартныеПодсистемы.Свойства")` + `ОбщийМодуль(...)` - так нужно в коде библиотек/расширений, которые могут жить без подсистемы; в прикладной конфигурации с внедренной подсистемой допустим прямой вызов.
   Метки на форме - `ДополнительныеПараметры.ПараметрыОтображенияМеток` (`УправлениеСвойствами.ПараметрыОтображенияМеток()`), обработчики `Подключаемый_СвойстваМеткиНачалоВыбора`, `Подключаемый_УстановитьВидимостьЛегендыМеток`. Форма списка с колонками доп. реквизитов/метками - `УправлениеСвойствами.ПриПолученииДанныхНаСервере(Настройки, Строки)`.

**Главные методы API** (`api/Свойства.md`):
- `УправлениеСвойствами.ПриСозданииНаСервере` / `ПриЧтенииНаСервере` / `ПередЗаписьюНаСервере` / `ОбработкаПроверкиЗаполнения` - встраивание в форму.
- `УправлениеСвойствами.ЗначенияСвойств(Объекты, ...)` / `ЗначениеСвойства(Объект, Свойство)` - чтение значений (в т.ч. для отчетов, печати).
- `УправлениеСвойствами.ЗаписатьСвойстваУОбъекта(Владелец, ТаблицаСвойствИЗначений)` - запись записанному объекту (в транзакции).
- `УправлениеСвойствами.УстановитьСвойстваУОбъекта(ОбъектВладелец, Соответствие)` - заполнить ещё не записанный объект (только реквизиты и метки).
- `УправлениеСвойствами.ДобавитьСвойство` / `ПараметрыДобавленияСвойства` / `ДобавитьЗначениеСвойства` - создать свойство кодом (обновление ИБ, загрузка).
- `УправлениеСвойствами.СвойстваОбъекта` / `ПроверитьСвойствоУОбъекта` / `ИспользоватьДопРеквизиты` / `ИспользоватьДопСведения`.
- `УправлениеСвойствами.НаборСвойствПоИмени` - ссылка на предопределенный набор.

**Подводные камни:**
- Свойство ищите не по наименованию (пользователь переименует), а по `Имя` ПВХ `ДополнительныеРеквизитыИСведения` или создавайте кодом с фиксированным `Имя`.
- Идентификатор набора - уникальный UUID v4; скопированный из другого набора ломает обновление наборов.
- Без вызова `ПередЗаписьюНаСервере` значения с формы не попадут в ТЧ (реквизиты формы создаются динамически).
- Дополнительные сведения пишутся в регистр - при записи объекта не проверяются и не версионируются; для обязательных полей используйте доп. реквизиты.
- Условия «доступность/видимость/обязательность» доп. реквизитов вычисляются на клиенте (`ОбновитьЗависимостиДополнительныхРеквизитов`) - не забудьте `Подключаемый_ПриИзмененииДополнительногоРеквизита`.
- Отбор по доп. реквизиту в запросе - соединение с ТЧ `<Объект>.ДополнительныеРеквизиты` по `Свойство`; по доп. сведению - с регистром `ДополнительныеСведения` (`Объект`, `Свойство`).
