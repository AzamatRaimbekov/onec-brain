## КонтактнаяИнформация - адреса, телефоны, email на форме и в данных любого справочника/документа

**Когда использовать:** у справочника (контрагент, партнер, физлицо, склад, организация) или документа есть адрес,
телефон, email, сайт, Skype, факс. Подсистема даёт: табличную часть со структурированным значением (JSON), формы ввода
адреса с подбором по ГАР, проверку, команды «позвонить / написать / показать на карте / история», настраиваемые
пользователем виды КИ (справочник `ВидыКонтактнойИнформации`), поиск/отборы по городу, телефону, домену почты.
Заменяет самописные реквизиты `Адрес`, `Телефон`, `Email` строкой и самописные формы ввода адреса.

### 1. Метаданные

1. **Табличная часть `КонтактнаяИнформация`** в своем объекте. Проще всего скопировать её из `Справочник.Пользователи`
   (имя ТЧ и реквизитов должны совпадать). Обязательный состав в БСП 3.2.1:

   | Реквизит | Тип | Индекс |
   |---|---|---|
   | `Тип` | `ПеречислениеСсылка.ТипыКонтактнойИнформации` | да |
   | `Вид` | `СправочникСсылка.ВидыКонтактнойИнформации` | да |
   | `Представление` | Строка(500) | |
   | `ЗначенияПолей` | Строка(неогр.) - устаревший XML, для совместимости | |
   | `Значение` | Строка(неогр.) - внутренний формат JSON | |
   | `Страна`, `Регион`, `Город`, `АдресЭП`, `ДоменноеИмяСервера`, `НомерТелефона`, `НомерТелефонаБезКодов` | Строка | |
   | `ВидДляСписка` | `СправочникСсылка.ВидыКонтактнойИнформации` (для вывода в списках) | |

   Опционально: `ДействуетС` (Дата) - включает историю изменений КИ (виды с `ХранитьИсториюИзменений`);
   `ИдентификаторСтрокиТабличнойЧасти` (Число) - если КИ хранится и в строках других ТЧ (контактные лица в ТЧ).
2. **Определяемый тип `ВладелецКонтактнойИнформации`** - добавить **тип объекта** (`СправочникОбъект.Контрагенты`,
   `ДокументОбъект.ЗаказКлиента`), не ссылки. В поставке там `CatalogObject.Пользователи`. На этот тип подписаны три
   подписки БСП, которые после этого начинают работать для вашего объекта автоматически:
   - `ЗаполнитьКонтактнуюИнформацию` (ОбработкаЗаполнения) -> `УправлениеКонтактнойИнформацией.ОбработкаЗаполненияКонтактнойИнформации`
   - `ОбновитьКонтактнуюИнформацию` (ПередЗаписью) -> `УправлениеКонтактнойИнформацией.ОбработкаОбновленияКонтактнойИнформации` (заполняет служебные поля, `ВидДляСписка`)
   - `КонтактнаяИнформацияОбработкаПроверкиЗаполнения` (ОбработкаПроверкиЗаполнения) -> `УправлениеКонтактнойИнформациейСлужебный.КонтактнаяИнформацияОбработкаПроверкиЗаполнения`
3. **Форма**: обычная группа для размещения полей, по умолчанию имя `ГруппаКонтактнаяИнформация`
   (иначе передать имя в `ПараметрыКонтактнойИнформации().ИмяЭлементаДляРазмещения`). Поля КИ создаются программно - в
   конструкторе формы ничего, кроме пустой группы, рисовать не нужно.
4. **Роли**: `ДобавлениеИзменениеВидовКонтактнойИнформации` - тем, кто настраивает виды. Чтение видов уже входит в
   `БазовыеПраваБСП`. Права на сам объект-владелец - ваши.

### 2. Виды КИ (поставляемые) и переопределяемый модуль

Виды КИ объекта лежат в группе справочника `ВидыКонтактнойИнформации`, имя которой = полное имя объекта без точки:
`Справочник.Контрагенты` -> группа `СправочникКонтрагенты` (см. `УправлениеКонтактнойИнформациейСлужебныйПовтИсп.ГруппаВидаКонтактнойИнформацииПоИмениОбъекта`:
сравнивается `ИмяПредопределенногоВида`, а если пусто - `ИмяПредопределенныхДанных`). Нет группы - на форме нет полей.

Рекомендуемый способ (не меняет объект БСП на поддержке) - `УправлениеКонтактнойИнформациейПереопределяемый.ПриНачальномЗаполненииЭлементов`.
Ключевой реквизит заполнения - `ИмяПредопределенногоВида` (служебная `ИмяКлючевогоРеквизита()` в модуле менеджера `ВидыКонтактнойИнформации`),
`Родитель` можно передать строкой - именем группы (механизм `ОбновлениеИнформационнойБазыСлужебный` ищет его по ключевому реквизиту):

```bsl
Процедура ПриНачальномЗаполненииЭлементов(КодыЯзыков, Элементы, ТабличныеЧасти) Экспорт

	Элемент = Элементы.Добавить();
	Элемент.ИмяПредопределенногоВида = "СправочникКонтрагенты";
	Элемент.ЭтоГруппа    = Истина;
	Элемент.Используется = Истина;
	Элемент.Наименование = НСтр("ru = 'Контактная информация справочника ""Контрагенты""'");

	Элемент = Элементы.Добавить();
	Элемент.ИмяПредопределенногоВида = "ЮридическийАдресКонтрагента";
	Элемент.Родитель     = "СправочникКонтрагенты";
	Элемент.Тип          = Перечисления.ТипыКонтактнойИнформации.Адрес;
	Элемент.Наименование = НСтр("ru = 'Юридический адрес'");
	Элемент.Используется = Истина;
	Элемент.ВидРедактирования = "ПолеВводаИДиалог"; // "ПолеВвода" | "Диалог"
	Элемент.ОтображатьВсегда  = Истина;
	Элемент.МожноИзменятьСпособРедактирования = Истина;
	Элемент.РеквизитДопУпорядочивания = 1;
	Элемент.ИдентификаторДляФормул = "ЮридическийАдрес";

	Элемент = Элементы.Добавить();
	Элемент.ИмяПредопределенногоВида = "ТелефонКонтрагента";
	Элемент.Родитель     = "СправочникКонтрагенты";
	Элемент.Тип          = Перечисления.ТипыКонтактнойИнформации.Телефон;
	Элемент.Наименование = НСтр("ru = 'Телефон'");
	Элемент.Используется = Истина;
	Элемент.РазрешитьВводНесколькихЗначений = Истина;
	Элемент.РеквизитДопУпорядочивания = 2;

КонецПроцедуры
```
Мультиязычность: если есть `СтандартныеПодсистемы.Мультиязычность`, наименование заполнять через
`МультиязычностьСервер.ЗаполнитьМультиязычныйРеквизит(Элемент, "Наименование", "ru = '...'", КодыЯзыков)` (так делает
`Справочник.ВидыКонтактнойИнформации.МодульМенеджера.ПриНачальномЗаполненииЭлементов`).

Остальные переопределяемые процедуры `УправлениеКонтактнойИнформациейПереопределяемый`:
- `ПриОпределенииНастроек(Настройки)` - команды КИ по типам/видам: `Настройки.ОписаниеКоманд[Перечисления.ТипыКонтактнойИнформации.Адрес].ЗапланироватьВстречу.Действие = "МойМодульКлиент.Процедура"`;
  отдельный набор для вида - `ОбщегоНазначения.СкопироватьРекурсивно(УправлениеКонтактнойИнформацией.КомандыТипаКонтактнойИнформации(Тип))`.
  Процедура-действие (клиент, экспорт) получает `(КонтактнаяИнформация, ДополнительныеПараметры)`, где есть `.ВладелецКонтактнойИнформации` и `.Форма`.
- `ПриПолученииНаименованийВидовКонтактнойИнформации(Наименования, КодЯзыка)` - переводы: `Наименования["ТелефонКонтрагента"] = НСтр("ru='Телефон'; en='Phone'", КодЯзыка);`
- `ПриНастройкеНачальногоЗаполненияЭлементов(Настройки)`, `ПриНачальномЗаполненииЭлемента(Объект, Данные, ДополнительныеПараметры)` - тонкая настройка заполнения.

Добавить вид в уже работающую базу из обработчика обновления - `УправлениеКонтактнойИнформацией.ПараметрыВидаКонтактнойИнформации(Тип)`
+ `УправлениеКонтактнойИнформацией.УстановитьСвойстваВидаКонтактнойИнформации(Параметры)` (поля `Имя`, `Наименование`, `Группа`,
`Порядок` - рекомендуется не задавать или 0, `ВидРедактирования`, `ОбязательноеЗаполнение`, `РазрешитьВводНесколькихЗначений`,
`ХранитьИсториюИзменений`, `НастройкиПроверки`...). Получить вид в коде - `УправлениеКонтактнойИнформацией.ВидКонтактнойИнформацииПоИмени("ТелефонКонтрагента")`.

### 3. Модуль формы объекта

Шаблон 1:1 как в `Справочник.Пользователи.ФормаЭлемента` / `Справочник.ВнешниеПользователи.ФормаЭлемента`.
Имена клиентских обработчиков **фиксированы** - подсистема назначает их программно созданным элементам.

```bsl

	ДополнительныеПараметры = УправлениеКонтактнойИнформацией.ПараметрыКонтактнойИнформации();
	ДополнительныеПараметры.ИмяЭлементаДляРазмещения = "ГруппаКонтактнаяИнформация";
	// ДополнительныеПараметры.ОтложеннаяИнициализация = Истина; // если группа на неактивной странице
	УправлениеКонтактнойИнформацией.ПриСозданииНаСервере(ЭтотОбъект, Объект, ДополнительныеПараметры);
	// Конец СтандартныеПодсистемы.КонтактнаяИнформация
КонецПроцедуры

	УправлениеКонтактнойИнформацией.ПриЧтенииНаСервере(ЭтотОбъект, ТекущийОбъект);

КонецПроцедуры

&НаСервере
```

В библиотечном/межподсистемном коде БСП вызывает модули через `ОбщегоНазначения.ОбщийМодуль("УправлениеКонтактнойИнформацией")`
под `ОбщегоНазначения.ПодсистемаСуществует("СтандартныеПодсистемы.КонтактнаяИнформация")`; в прикладной конфигурации,
где подсистема внедрена всегда, допустим прямой вызов.

Отложенная инициализация (группа на другой странице): `ОтложеннаяИнициализация = Истина` в параметрах и при показе страницы
серверный вызов `УправлениеКонтактнойИнформацией.ВыполнитьОтложеннуюИнициализацию(ЭтотОбъект, Объект, "ГруппаКонтактнаяИнформация")`.
Скрыть часть видов на форме (выведены своими полями) - `ДополнительныеПараметры.СкрываемыеВиды` / `РазмещеныНаФорме`
(`ИсключаемыеВиды` устарел). Только просмотр - `УправлениеКонтактнойИнформацией.УстановитьДоступностьЭлементовКонтактнойИнформации`.

Открыть форму ввода адреса/телефона для своего реквизита (без ТЧ, например адрес доставки в документе):
`УправлениеКонтактнойИнформациейКлиент.ОткрытьФормуКонтактнойИнформации(УправлениеКонтактнойИнформациейКлиент.ПараметрыФормыКонтактнойИнформации(Вид, Значение, Представление), ЭтотОбъект, Оповещение)`.

### 4. Чтение и запись КИ из кода

Значение КИ - строка JSON (поле `Значение`); представление - строка. Не парсить представление руками.

```bsl
// Чтение: представление одного вида
Вид = УправлениеКонтактнойИнформацией.ВидКонтактнойИнформацииПоИмени("ЮридическийАдресКонтрагента");
Адрес = УправлениеКонтактнойИнформацией.ПредставлениеКонтактнойИнформацииОбъекта(Контрагент, Вид);

// Чтение пакетом по многим владельцам (ТЗ: Объект, Вид, Тип, Значение, Представление, Дата, ...)
Отбор = УправлениеКонтактнойИнформацией.ОтборКонтактнойИнформации();
Отбор.ТипыКонтактнойИнформации.Добавить(Перечисления.ТипыКонтактнойИнформации.АдресЭлектроннойПочты);
Таблица = УправлениеКонтактнойИнформацией.КонтактнаяИнформация(МассивКонтрагентов, Отбор);

// Разбор адреса на поля (регион, город, улица, дом, коды) и телефона на части
Сведения = УправлениеКонтактнойИнформацией.СведенияОбАдресе(СтрокаКИ.Значение); // при наличии РаботаСАдресами перенаправляется туда
Телефон  = УправлениеКонтактнойИнформацией.СведенияОТелефоне(СтрокаКИ.Значение);

// Запись: по представлению или JSON. Ссылка -> объект будет ЗАПИСАН; Объект -> только изменен.
УправлениеКонтактнойИнформацией.ДобавитьКонтактнуюИнформацию(КонтрагентОбъект, "+7 495 1234567", ВидТелефон, , Ложь);

// Массовая запись: таблица из НоваяКонтактнаяИнформация()
КИ = УправлениеКонтактнойИнформацией.НоваяКонтактнаяИнформация(Ложь);
Стр = КИ.Добавить(); Стр.Вид = ВидEmail;
Стр.Значение = УправлениеКонтактнойИнформацией.КонтактнаяИнформацияПоПредставлению("info@firm.ru", ВидEmail);
УправлениеКонтактнойИнформацией.УстановитьКонтактнуюИнформациюОбъекта(КонтрагентОбъект, КИ); // Замещать = Истина
```
Для загрузки из внешних систем адрес строкой: `ДобавитьКонтактнуюИнформацию(..., РаспознатьАдрес = Истина)` распознаёт по ГАР
(может обратиться к веб-сервису 1С). Создание нового объекта с КИ - передать её в `ДанныеЗаполнения`, подписка `ЗаполнитьКонтактнуюИнформацию` заполнит ТЧ.

### 5. КИ в запросах и динамических списках

```bsl
ВЫБРАТЬ К.Ссылка, ЕСТЬNULL(КИ.Представление, "") КАК Телефон
ИЗ Справочник.Контрагенты КАК К
	ЛЕВОЕ СОЕДИНЕНИЕ Справочник.Контрагенты.КонтактнаяИнформация КАК КИ
	ПО КИ.Ссылка = К.Ссылка И КИ.Вид = &ВидТелефон
```
Для отборов использовать служебные колонки ТЧ (`Город`, `Регион`, `НомерТелефона`, `АдресЭП`, `ДоменноеИмяСервера`) - они
заполняются подпиской перед записью. Для КИ нескольких объектов во временной таблице - `УправлениеКонтактнойИнформацией.СоздатьВТКонтактнаяИнформация(МВТ, МассивОбъектов, Типы, Виды, Дата)`.
Колонка `ВидДляСписка` для вывода в списках пересчитывается `ОбновитьКонтактнуюИнформациюДляСписков(Ссылка)`.

**Главные методы API** (подробно: `api/КонтактнаяИнформация.md`):
- `УправлениеКонтактнойИнформацией.ПриСозданииНаСервере / ПриЧтенииНаСервере / ПередЗаписьюНаСервере / ОбработкаПроверкиЗаполненияНаСервере` - встраивание в форму.
- `УправлениеКонтактнойИнформацией.ПредставлениеКонтактнойИнформацииОбъекта` - строка КИ вида у объекта (`ТолькоПервая`, разделитель).
- `УправлениеКонтактнойИнформацией.КонтактнаяИнформация(Источник, Отбор)` - КИ массива владельцев; `КонтактнаяИнформацияОбъекта` - старый аналог.
- `УправлениеКонтактнойИнформацией.ДобавитьКонтактнуюИнформацию` / `УстановитьКонтактнуюИнформациюОбъекта` - запись.
- `УправлениеКонтактнойИнформацией.КонтактнаяИнформацияПоПредставлению` - строка -> JSON.
- `УправлениеКонтактнойИнформацией.СведенияОбАдресе`, `РаботаСАдресами.СведенияОбАдресе` (поля + коды), `УправлениеКонтактнойИнформацией.СведенияОТелефоне`.
- `УправлениеКонтактнойИнформацией.ВидКонтактнойИнформацииПоИмени` - вид по имени.
- `УправлениеКонтактнойИнформацией.ПараметрыВидаКонтактнойИнформации` + `УстановитьСвойстваВидаКонтактнойИнформации` - вид из обработчика обновления.
- `УправлениеКонтактнойИнформациейКлиент.ОткрытьФормуКонтактнойИнформации` - форма ввода для «своего» реквизита.
- `РаботаСАдресами.РегионАдресаКонтактнойИнформации`, `ГородАдресаКонтактнойИнформации`, `ПроверитьАдрес` - адреса РФ.

**Подводные камни:**
- В `ВладелецКонтактнойИнформации` добавляют `СправочникОбъект.*` / `ДокументОбъект.*`. Добавили ссылку - подписки не сработают.
- Нет группы видов с именем `Справочник<Имя>` / `Документ<Имя>` - форма пустая, без ошибок. Проверять имя группы.
- `ПередЗаписьюНаСервере` вызывать с `ТекущийОбъект`, не с `Объект`: иначе ввод на форме не попадёт в базу.
- Обработчики `Подключаемый_КонтактнаяИнформация*` обязаны существовать в модуле формы с точными именами, иначе ошибка при открытии/вводе.
- `ДобавитьКонтактнуюИнформацию` со **ссылкой** сам записывает объект (лишняя запись, срабатывают все подписки). В цикле - передавать объект и писать один раз.
- `ПредставлениеКонтактнойИнформацииОбъекта` / `КонтактнаяИнформацияОбъекта` для видов с историей требуют `Дата`, иначе исключение.
- Не хранить JSON-значение в своих строковых реквизитах ограниченной длины - поле `Значение` неограниченное; в документах используйте строку неогр. длины.
- Распознавание/проверка адресов и `РаботаСАдресами` с `КодыАдреса` могут ходить в веб-сервис 1С: не вызывать массово в `ПриСозданииНаСервере` и в цикле проведения.
- `ЗначенияПолей` (XML) - только для совместимости; новый код работает с `Значение` (JSON) и `КонтактнаяИнформацияВJSON` / `КонтактнаяИнформацияВXML` для конвертации.
- Регламентное задание `ИсправлениеУстаревшихАдресов` входит в подсистему - учитывать его в настройках регламентных заданий.

## АдресныйКлассификатор - ГАР (ФИАС): подбор и проверка адресов РФ, коды ОКТМО/ИФНС

**Когда использовать:** ввод адресов РФ с подбором, проверка корректности, получение кодов (ОКТМО, ОКАТО, ИФНС, КЛАДР,
идентификаторы ГАР) и часового пояса по адресу; справочник субъектов РФ. Работает поверх КонтактнойИнформации: формы
ввода адреса используют его автоматически. Свою логику «адрес по ФИАС» не писать.

**Встраивание в свой объект (рецепт):**
1. Метаданные: своих объектов не добавляют. В подсистеме: регистры сведений `АдресныеОбъекты`, `ДомаЗданияСтроения`,
   `АдминистративнаяИерархия`, `МуниципальнаяИерархия` и др., константы `ИсточникДанныхАдресногоКлассификатора`,
   `ПараметрыАдресногоКлассификатора`, ФО `ИсточникДанныхАдресногоКлассификатора`, роль `ДобавлениеИзменениеАдресныхСведений`
   (тем, кто загружает классификатор). Источник данных: загруженные в базу регионы или веб-сервис 1С (нужна Интернет-поддержка, БИП).
2. Переопределяемых модулей нет. Настройка - в «Администрирование - Интернет-поддержка и сервисы» (доступ к веб-сервису) и загрузка регионов.
3. В коде работать через адрес в формате JSON (из ТЧ `КонтактнаяИнформация.Значение`):

```bsl
// Коды адреса (ОКТМО, ИФНС...) - может идти в веб-сервис до 20 с: вызывать в фоне (ДлительныеОперации)
Коды = АдресныйКлассификатор.КодыАдреса(АдресJSON, "ЗагруженныеДанные");
ОКТМО = Коды.ОКТМО;

// Поля адреса с кодами одним вызовом
Доп = Новый Структура("КодыАдреса", Истина);
Сведения = РаботаСАдресами.СведенияОбАдресе(АдресJSON, Доп);
```
Открыть загрузку классификатора из своей команды: `АдресныйКлассификаторКлиент.ЗагрузитьАдресныйКлассификатор()`.

**Главные методы API** (`api/АдресныйКлассификатор.md`, адресные функции - в `api/КонтактнаяИнформация.md`, модуль `РаботаСАдресами`):
- `АдресныйКлассификатор.КодыАдреса(Адрес, Источник)` - ОКТМО, ОКАТО, ИФНС ФЛ/ЮЛ, КЛАДР, идентификаторы ГАР.
- `АдресныйКлассификатор.ПроверитьАдреса(Адреса)` - проверка по ГАР с вариантами исправления (до 120 с - фон).
- `АдресныйКлассификатор.АдресныйКлассификаторЗагружен()` - есть ли данные или доступен сервис (до 7 с).
- `АдресныйКлассификатор.РазрешенДоступВИнтернет()` - разрешен ли веб-сервис адресов.
- `АдресныйКлассификатор.СубъектыРФ()`, `НаименованиеРегионаПоКоду`, `КодРегионаПоНаименованию` - регионы.
- `АдресныйКлассификатор.СведенияПоОКТМО`, `ПроверитьОКТМОБюджетополучателя` - работа с ОКТМО.
- `АдресныйКлассификатор.НомерЧасовойЗоны` - часовой пояс по адресу.
- `РаботаСАдресами.СведенияОбАдресе` / `СведенияОбАдресах` / `ПоляАдресаВJSON` / `ПроверитьАдрес` - разбор, сборка, проверка адреса.
- `АдресныйКлассификаторКлиент.ЗагрузитьАдресныйКлассификатор` - форма загрузки.

**Подводные камни:**
- Почти все функции могут синхронно обращаться к веб-сервису 1С (orgaddress): 7-120 с. Не вызывать в `ПриСозданииНаСервере`, `ОбработкаПроведения`, в цикле по документам; пакет (`СведенияОбАдресах`, `ПроверитьАдреса`) - в фоновом задании.
- Если доступ к Интернету запрещен и регионы не загружены, коды возвращаются пустыми без исключения - проверяйте результат, а не рассчитывайте на ошибку.
- Подсистема работает только с адресами РФ; иностранный адрес - тип «Иностранный», кодов нет.
- Модель сервиса (РаботаВМоделиСервиса): загрузкой классификатора управляет провайдер, в прикладном коде её не инициировать.
