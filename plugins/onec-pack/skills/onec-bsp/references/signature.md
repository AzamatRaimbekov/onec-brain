Общая схема хранения (одинакова для всех четырех подсистем):
- подписи лежат в `РегистрСведений.ЭлектронныеПодписи` (измерение `ПодписанныйОбъект` с типом `ОпределяемыйТип.ПодписанныйОбъект`, `Ведущее = Истина` - записи удаляются вместе с объектом);
- сертификаты шифрования - в `РегистрСведений.СертификатыШифрования` (измерение `ЗашифрованныйОбъект`, тот же определяемый тип);
- связь «подпись - МЧД» - в `РегистрСведений.ЭлектронныеПодписиМЧД`;
- сам подписанный объект хранит только флаги `ПодписанЭП` / `Зашифрован` (Булево).

## ЭлектроннаяПодпись - подписание, проверка и шифрование данных и объектов, справочник сертификатов

**Когда использовать:** любая задача «подписать / проверить подпись / зашифровать / расшифровать» в 1С: подписание файлов и печатных форм, подписание XML/строк для обмена (XMLDSig, CMS), хранение сертификатов пользователей, проверка подписи из входящего файла, штамп ЭП на печатной форме. Заменяет самописную работу с `МенеджерКриптографии` (выбор криптопровайдера, ввод пароля, поиск сертификата, проверка УЦ/квалифицированности, классификатор ошибок, усовершенствование CAdES-T/A, продление меток времени регламентным заданием `ПродлениеДостоверностиПодписей`). Своя криптография поверх платформы - только когда БСП нет.

Включение: константы/ФО `ИспользоватьЭлектронныеПодписи`, `ИспользоватьШифрование`, `СоздаватьЭлектронныеПодписиНаСервере`, `ПроверятьЭлектронныеПодписиНаСервере` (форма `ОбщаяФорма.НастройкиЭлектроннойПодписиИШифрования`, открывается `ЭлектроннаяПодписьКлиент.ОткрытьНастройкиЭлектроннойПодписиИШифрования`).

Роли подсистемы (давать в профилях групп доступа): `ДобавлениеИзменениеЭлектронныхПодписей`, `УдалениеЭлектронныхПодписей`, `ШифрованиеИРасшифровкаДанных`, `РасшифровкаДанных`, `ЧтениеСертификатовКлючейЭлектроннойПодписиИШифрования`, `ДобавлениеИзменениеСертификатовКлючейЭлектроннойПодписиИШифрования`, `ЧтениеЛичныхСертификатовКлючейЭлектроннойПодписиИШифрования`, `ДобавлениеИзменениеЛичныхСертификатовКлючейЭлектроннойПодписиИШифрования`, `ДобавлениеИзменениеПрограммЭлектроннойПодписиИШифрования`.

### Встраивание (общие шаги для любого варианта)

1. **Определяемые типы.**
   - `ОпределяемыйТип.ПодписанныйОбъект` - добавить ссылочный тип каждого объекта, к которому будут привязываться подписи/сертификаты шифрования. В поставке БСП там только справочники присоединенных файлов (`Файлы`, `*ПрисоединенныеФайлы`, `МашиночитаемыеДоверенностиПрисоединенныеФайлы`). Без типа в этом списке `ДобавитьПодпись`/`ПодписиОбъекта` падают на `ПроверитьПараметр` (список берется из `ЭлектроннаяПодписьСлужебныйПовтИсп.ТипыВладельцев`).
   - `ОпределяемыйТип.Организация` и `ОпределяемыйТип.ФизическоеЛицо` - в БСП это заглушки `Строка`; заменить на `СправочникСсылка.Организации` / `СправочникСсылка.ФизическиеЛица` своей конфигурации. Используются в карточке сертификата, отборе сертификатов по организации, заявлении на сертификат, подписантах мобильного сервиса и МЧД.
2. **Реквизиты подписываемого объекта:** `ПодписанЭП` (Булево) - обязателен для подписи; `Зашифрован` (Булево) - обязателен, если объект шифруется. Их устанавливает сама БСП (`ДобавитьПодпись`, `УдалитьПодпись`, `ЗаписатьСертификатыШифрования`).
3. **Переопределяемые процедуры** (заполнять только при необходимости):
   - `ЭлектроннаяПодписьПереопределяемый.ПриОпределенииНастроек(Настройки)` - `Настройки.ФизическоеЛицоИспользуется = Ложь`, если в конфигурации нет физлиц (скроет поле в карточке сертификата и заявлении).
   - `ЭлектроннаяПодписьПереопределяемый.ПередНачаломРедактированияСертификатаКлюча(Ссылка, Сертификат, ПараметрыРеквизитов)` - сделать реквизиты карточки сертификата только для просмотра / обязательными / задать значение заполнения:
     ```bsl
     Строка = ПараметрыРеквизитов.Найти("Организация", "ИмяРеквизита");
     Если Строка <> Неопределено Тогда
         Строка.ПроверкаЗаполнения = Истина;
     КонецЕсли;
     ```
   - `ЭлектроннаяПодписьПереопределяемый.ПриСозданииФормыПроверкаСертификата(...)` + `ПриДополнительнойПроверкеСертификата(Параметры)` (и клиентский двойник в `ЭлектроннаяПодписьКлиентПереопределяемый`) - добавить свою проверку сертификата (например, авторизация у оператора ЭДО).
   - `ЭлектроннаяПодписьПереопределяемый.ПередНачаломОперации(Операция, ВходныеПараметры, ВыходныеПараметры)` / `ЭлектроннаяПодписьКлиентПереопределяемый.ПередНачаломОперации(...)` - серверная подготовка при открытии форм подписания/расшифровки без лишнего серверного вызова; входные данные приходят из `ОписаниеДанных.ПараметрыДополнительныхДействий`.
   - `ЭлектроннаяПодписьПереопределяемый.ПриЗаполненииВидовОграниченийПравОбъектовМетаданных(Описание)` - если вы добавили к справочнику сертификатов свои виды доступа (RLS).
   - `ЭлектроннаяПодписьКлиентПереопределяемый.ПослеДобавленияВСправочникСертификатовЭлектроннойПодписи(Параметры)` - реакция на интерактивное добавление сертификата (замена старого сертификата в своих настройках).
   - `ЗаявлениеНаСертификатПереопределяемый.ПриЗаполненииРеквизитовОрганизацииВЗаявленииНаСертификат` и соседние - заполнение заявления на выпуск КЭП из своих справочников (только если используется обработка `ЗаявлениеНаВыпускНовогоКвалифицированногоСертификата`).
4. **Модули объектов/форм** - см. рецепты A-C ниже.

### Рецепт A: подписывать присоединенные файлы (рекомендуемый)

Так устроена сама БСП: подписывается файл (печатная форма, выгрузка XML, скан), подпись хранится у файла, исходные данные для повторной проверки всегда есть. Требуется подсистема `РаботаСФайлами` и справочник `<Объект>ПрисоединенныеФайлы` (он уже в `ПодписанныйОбъект`, если создан по шаблону БСП - иначе добавить).

Форма объекта, команда «Подписать файл»:
```bsl
&НаКлиенте
Процедура ПодписатьФайл(Команда)
    ПараметрыПодписи = ЭлектроннаяПодписьКлиент.НовыйТипПодписи();
    ПараметрыПодписи.ВыборДоверенности = Истина; // если подписывают по МЧД
    РаботаСФайламиКлиент.ПодписатьФайл(Элементы.Файлы.ТекущаяСтрока, УникальныйИдентификатор,
        Новый Структура("ОбработкаРезультата", Новый ОписаниеОповещения("ПослеПодписания", ЭтотОбъект)),
        ПараметрыПодписи);
КонецПроцедуры
```
Серверный вариант для уже полученной подписи: `РаботаСФайлами.ДобавитьПодписьКФайлу(ПрисоединенныйФайл, СвойстваПодписи, ИдентификаторФормы)`. Подробнее о файлах - в рецептах подсистемы РаботаСФайлами.

Печатные формы: общая форма `ПечатьДокументов` уже умеет «подписать и сохранить / отправить» (вызывает `ЭлектроннаяПодписьКлиент.Подписать` с `ВыборДоверенности = Истина`), отдельный код не нужен.

### Рецепт B: подписывать сам объект (справочник/документ)

Подходит для «утверждения» объекта подписью (согласование, акт, заявка), когда подписываемые данные однозначно воспроизводимы.

1. Метаданные: тип ссылки в `ОпределяемыйТип.ПодписанныйОбъект`; реквизит `ПодписанЭП` (Булево); при шифровании - `Зашифрован`.
2. Модуль объекта - защита от изменения подписанного объекта (по образцу `РаботаСФайлами.ПроверитьЗаписьПодписанногоОбъектаПередЗаписью`). При записи из `ДобавитьПодпись`/`УдалитьПодпись` БСП ставит `ДополнительныеСвойства.ЗаписьПодписанногоОбъекта = Истина`:
   ```bsl
   Процедура ПередЗаписью(Отказ)
       Если ОбменДанными.Загрузка Тогда
           Возврат;
       КонецЕсли;
       Если ДополнительныеСвойства.Свойство("ЗаписьПодписанногоОбъекта") Тогда
           Возврат; // запись флага ПодписанЭП самой БСП
       КонецЕсли;
       Если Не ЭтоНовый() И ОбщегоНазначения.ЗначениеРеквизитаОбъекта(Ссылка, "ПодписанЭП") Тогда
           ВызватьИсключение НСтр("ru = 'Подписанный документ нельзя изменять. Удалите подписи.'");
       КонецЕсли;
   КонецПроцедуры
   ```
3. Модуль менеджера (или общий модуль) - функция, которая детерминированно формирует подписываемые данные (`ДвоичныеДанные`: XML/JSON/печатная форма в PDF). Она же нужна для проверки.
4. Форма - команда «Подписать»:
   ```bsl
   &НаКлиенте
   Процедура Подписать(Команда)
       ОписаниеДанных = Новый Структура;
       ОписаниеДанных.Вставить("Операция",        НСтр("ru = 'Подписание документа'"));
       ОписаниеДанных.Вставить("ЗаголовокДанных", НСтр("ru = 'Документ'"));
       ОписаниеДанных.Вставить("Данные",          ДанныеДляПодписанияНаСервере()); // адрес во временном хранилище
       ОписаниеДанных.Вставить("Объект",          Объект.Ссылка);  // БСП сама вызовет ДобавитьПодпись
       ОписаниеДанных.Вставить("Представление",   Объект.Ссылка);
       ОписаниеДанных.Вставить("ОтборСертификатов", Новый Структура("Организация", Объект.Организация));
       ЭлектроннаяПодписьКлиент.Подписать(ОписаниеДанных, ЭтотОбъект,
           Новый ОписаниеОповещения("ПослеПодписания", ЭтотОбъект));
   КонецПроцедуры

   &НаКлиенте
   Процедура ПослеПодписания(Результат, ДополнительныеПараметры) Экспорт
       Если Результат.Успех Тогда
           Прочитать(); // ПодписанЭП изменен и объект записан на сервере
       КонецЕсли;
   КонецПроцедуры

   &НаСервере
   Функция ДанныеДляПодписанияНаСервере()
       Данные = Документы.Заявка.ДанныеДляПодписания(Объект.Ссылка);
       Возврат ПоместитьВоВременноеХранилище(Данные, УникальныйИдентификатор);
   КонецФункции
   ```
   Объект должен быть записан (нужна ссылка). Форма передается для блокировки объекта (`ЗаблокироватьДанныеДляРедактирования` с ее идентификатором); если форма объекта открыта и модифицирована - сначала записать.
5. Видимость команды: `ПриСозданииНаСервере` - `Элементы.ФормаПодписать.Видимость = ЭлектроннаяПодпись.ИспользоватьЭлектронныеПодписи();` (ФО `ИспользоватьЭлектронныеПодписи` можно повесить и на саму команду).
6. Вывод списка подписей на форме: `ЭлектроннаяПодпись.ПодписиОбъекта(Ссылка)` -> таблица формы; статус для показа - `ЭлектроннаяПодписьКлиентСервер.ЗаполнитьСтатусПодписи`. Удаление - `ЭлектроннаяПодпись.УдалитьПодпись(Ссылка, ПорядковыйНомер, УникальныйИдентификатор)` (нужна роль `УдалениеЭлектронныхПодписей`).

Несколько объектов разом: `ОписаниеДанных.НаборДанных` - массив структур `Данные/Объект/Представление` + `ПредставлениеНабора = "Документы (%1)"`.

### Рецепт C: подписание без формы, на сервере (регламент, интеграция)

Публичного серверного «Подписать» в БСП нет - используется платформенный менеджер криптографии, полученный через БСП, и `ДобавитьПодпись`:
```bsl
МенеджерКриптографии = ЭлектроннаяПодпись.МенеджерКриптографии("Подписание"); // исключение при ошибке
ДанныеСертификата = ОбщегоНазначения.ЗначениеРеквизитаОбъекта(СертификатСсылка, "ДанныеСертификата").Получить();
СертификатКриптографии = Новый СертификатКриптографии(ДанныеСертификата);
МенеджерКриптографии.ПарольДоступаКЗакрытомуКлючу = Пароль; // из безопасного хранилища, не из констант
Подпись = МенеджерКриптографии.Подписать(Данные, СертификатКриптографии);

СвойстваПодписи = ЭлектроннаяПодписьКлиентСервер.НовыеСвойстваПодписи();
ЗаполнитьЗначенияСвойств(СвойстваПодписи, ЭлектроннаяПодпись.СвойстваПодписи(Подпись)); // ТипПодписи, Сертификат, Отпечаток, КомуВыданСертификат...
СвойстваПодписи.Подпись = Подпись;
ЭлектроннаяПодпись.ДобавитьПодпись(ДокументСсылка, СвойстваПодписи); // блокирует, ставит ПодписанЭП, записывает
```
Если в `ДобавитьПодпись` передать не ссылку, а сам объект (`ДокументОбъект`), он будет изменен без блокировки и без записи - так делают внутри собственной транзакции записи.

### Проверка, штампы, шифрование

- Проверка на клиенте: `ЭлектроннаяПодписьКлиент.ПроверитьПодпись(Оповещение, ИсходныеДанные, Подпись, , , Параметры)`, где `Параметры = ЭлектроннаяПодписьКлиент.ПараметрыПроверкиПодписи()`, `Параметры.РезультатВВидеСтруктуры = Истина` - получите `ЭлектроннаяПодписьКлиентСервер.РезультатПроверкиПодписи`. Результат записать: `ЭлектроннаяПодпись.ОбновитьПодпись(Объект, СвойстваПодписи)`.
- Проверка на сервере: `ЭлектроннаяПодпись.ПроверитьПодпись(МенеджерКриптографии, ИсходныеДанные, Подпись, ОписаниеОшибки, НаДату, РезультатСтруктура)`; `МенеджерКриптографии = Неопределено` - БСП создаст сама. Передайте `ОписаниеОшибки = ""`, иначе (Null) при ошибке будет исключение.
- Подпись из файла `.sig`: `ЭлектроннаяПодписьКлиент.ДобавитьПодписьИзФайла(ОписаниеДанных, ...)`; выгрузка с подписью: `ЭлектроннаяПодписьКлиент.СохранитьДанныеВместеСПодписью(ОписаниеДанных)`.
- XML: `ЭлектроннаяПодписьКлиент.КонвертXML` + `ПараметрыXMLDSig` (SOAP/XMLDSig), `ПараметрыCMS` (открепленная/прикрепленная CMS) - передаются в `ОписаниеДанных.Данные` как структура.
- Штамп ЭП на печатной форме: `Штампы = ЭлектроннаяПодпись.ШтампыВизуализацииЭлектронныхПодписей(ПодписанныйОбъект); ЭлектроннаяПодпись.ДобавитьШтампыВТабличныйДокумент(ТабДок, Штампы);` Место штампа задается областями макета `ШтампЭП1`, `ШтампЭП2`... (2 колонки x 7 строк с произвольной шириной колонок).
- Шифрование: `ЭлектроннаяПодписьКлиент.Зашифровать(ОписаниеДанных, ...)` (`Данные`, `Объект`, `НаборСертификатов`), `ЭлектроннаяПодписьКлиент.Расшифровать(...)`; сертификаты шифрования объекта - `ЭлектроннаяПодпись.СертификатыШифрования` / `ЗаписатьСертификатыШифрования` (ставит `Зашифрован`).
- Сертификаты: найти/создать элемент справочника - `ЭлектроннаяПодпись.СсылкаНаСертификат`, `ЗаписатьСертификатВСправочник`; интерактивно - `ЭлектроннаяПодписьКлиент.ДобавитьСертификат`, проверка - `ЭлектроннаяПодписьКлиент.ПроверитьСертификатСправочника`.

**Главные методы API** (полный список - [api/ЭлектроннаяПодпись.md](api/ЭлектроннаяПодпись.md)):
- `ЭлектроннаяПодписьКлиент.Подписать` - интерактивное подписание данных/объекта(ов), форма выбора сертификата, пароль, МЧД, мобильная подпись.
- `ЭлектроннаяПодписьКлиент.НовыйТипПодписи` - параметры подписания: `ТипыПодписи`, `ВыборДоверенности`, `РазрешитьОтправкуНаПодписание`, `ПроверятьСертификат`.
- `ЭлектроннаяПодписьКлиент.ПроверитьПодпись` / `ЭлектроннаяПодпись.ПроверитьПодпись` - проверка подписи на клиенте/сервере.
- `ЭлектроннаяПодпись.ДобавитьПодпись` / `ОбновитьПодпись` / `УдалитьПодпись` - работа с регистром подписей объекта.
- `ЭлектроннаяПодпись.ПодписиОбъекта` (+ `НовыйПараметрыПолученияПодписейОбъекта`) - подписи объекта, опционально с данными МЧД и ожидаемыми мобильными подписями.
- `ЭлектроннаяПодпись.МенеджерКриптографии` - менеджер криптографии на сервере по настройкам программ.
- `ЭлектроннаяПодпись.СвойстваПодписи` - разбор двоичных данных подписи (тип, дата, сертификат).
- `ЭлектроннаяПодпись.ШтампыВизуализацииЭлектронныхПодписей` + `ДобавитьШтампыВТабличныйДокумент` - штампы на печатной форме.
- `ЭлектроннаяПодписьКлиент.Зашифровать` / `Расшифровать` - шифрование.
- `ЭлектроннаяПодпись.УсовершенствоватьПодписьОбъекта` - довести подпись до CAdES-T/CAdES-A.

**Подводные камни:**
- Забыли тип в `ОпределяемыйТип.ПодписанныйОбъект` или реквизит `ПодписанЭП` - ошибка «Недопустимое значение параметра Объект» в `ДобавитьПодпись` / ошибка записи. Оба нужны одновременно.
- `ОпределяемыйТип.Организация` / `ФизическоеЛицо` оставлены строкой - отбор сертификатов по организации и МЧД не работают.
- В регистре хранится только подпись, не данные. Для рецепта B проверка возможна, только если данные пересобираются байт-в-байт (любое изменение формата выгрузки/макета ломает проверку старых подписей). Нужна неизменяемость - выбирайте рецепт A (подписан файл).
- Подписание интерактивное и асинхронное (`ОписаниеОповещения`), модальных вызовов нет. Подписывать из обработчика `ПередЗаписью` формы нельзя - сначала записать объект, потом `Подписать`.
- Где выполняется криптография, решает настройка `СоздаватьЭлектронныеПодписиНаСервере`/`ПроверятьЭлектронныеПодписиНаСервере` (`ОписаниеДанных.ВыполнятьНаСервере` переопределяет). На сервере нужен установленный криптопровайдер и сертификат в хранилище пользователя, под которым работает rphost; на клиенте - расширение работы с криптографией (`ЭлектроннаяПодписьКлиент.УстановитьРасширение`).
- `ДобавитьПодпись`, `УдалитьПодпись`, `ЗаписатьСертификатыШифрования` проверяют право изменения объекта (`УправлениеДоступом.ПроверитьИзменениеРазрешено`), `ПодписиОбъекта` - право чтения. Пишут в регистры в привилегированном режиме - прямой записи в `РегистрСведений.ЭлектронныеПодписи` в своем коде быть не должно.
- `ЭлектроннаяПодпись.МенеджерКриптографии` и `СвойстваПодписи` в исходнике помечены как «для интеграции с БЭД/БРО» (область `ДляВызоваИзДругихПодсистем`) - использовать можно, но это единственный путь серверного подписания без формы.
- Пароль к закрытому ключу не хранить в константах/реквизитах открытым текстом (используйте `ОбщегоНазначения.ЗаписатьДанныеВБезопасноеХранилище`). Для клиентского сценария без ввода пароля есть `ЭлектроннаяПодписьКлиент.УстановитьПарольСертификата` + `БезПодтверждения`.
- «Подписи и печати» в `УправлениеПечатьюПереопределяемый` (`ИспользоватьПодписиИПечати`, факсимиле) - это картинки, не ЭП. Не путать.
- Подпись по МЧД: МЧД выбирается, только если `НовыйТипПодписи().ВыборДоверенности = Истина`.

## ЭлектроннаяПодписьСервисаDSS - облачная подпись через КриптоПро DSS

**Когда использовать:** ключи пользователей хранятся на сервере КриптоПро DSS (облачная КЭП), подписание с подтверждением в myDSS/SMS, нет локального криптопровайдера (веб-клиент, тонкий клиент без CSP). Включается константой/ФО `ИспользоватьСервисDSS`.

**Встраивание:**
1. Метаданные: прикладной код не меняется - DSS встраивается в механизм `ЭлектроннаяПодпись` (`ОпределяемыйТип.ПрограммаЭлектроннойПодписи` уже содержит `СправочникСсылка.УчетныеЗаписиDSS`). Сертификаты DSS попадают в справочник сертификатов и становятся доступны в стандартной форме `ЭлектроннаяПодписьКлиент.Подписать`. Справочники `ЭкземплярыСервераDSS`, `УчетныеЗаписиDSS`, регистр `СертификатыПользователяDSS`, обработка `УправлениеПодключениемDSS`.
2. Роли: `ДобавлениеИзменениеСерверовDSS` (администратор), `ДобавлениеИзменениеУчетныхЗаписейСерверовDSS`, `ЧтениеДанныхСервисаDSS` (пользователи).
3. Переопределяемые: `СервисКриптографииDSSПереопределяемый.СписокПервичнойАвторизации(МассивСпособов)` / `СписокВторичнойАвторизации(МассивСпособов)` - ограничить способы аутентификации (`Перечисления.СпособыАвторизацииDSS`); `ПриВключенииСервисаОблачнойПодписи()` - реакция на включение константы; `ИспользоватьСинхронныйРежим(ТекущийРежим)` - для веб-клиента по умолчанию асинхронный.

**Главные методы API** ([api/ЭлектроннаяПодписьСервисаDSS.СервисКриптографииDSS.md](api/ЭлектроннаяПодписьСервисаDSS.СервисКриптографииDSS.md), клиент - [...СервисКриптографииDSSКлиент.md](api/ЭлектроннаяПодписьСервисаDSS.СервисКриптографииDSSКлиент.md)): прямой вызов нужен только для нестандартных сценариев - `СервисКриптографииDSS.Подписать`, `ПодписатьПакет`, `ПроверитьПодпись`, `Зашифровать`/`Расшифровать`, `ПолучитьСертификатыСервиса`, `АутентификацияПоЛогину`. Первый параметр у всех - `ИдентификаторПользователя` (учетная запись DSS).

**Подводные камни:** нужен доступ сервера 1С к адресу DSS (прокси, `ЭлектроннаяПодпись.РазрешенДоступКИнтернетСервисам`); подтверждение операций асинхронное - не вызывать из транзакций и фоновых заданий без сохраненной аутентификации; для обычных задач используйте `ЭлектроннаяПодписьКлиент.Подписать`, а не прямые вызовы `СервисКриптографииDSS`.

## СервисМобильнойПодписи - отправка на подпись в мобильное приложение и Госключ

**Когда использовать:** документ должен подписать человек, у которого нет сертификата на компьютере (руководитель, сотрудник, физлицо-контрагент): документ отправляется в мобильный сервис/Госключ, подпись забирается регламентным заданием `ПолучениеРезультатовИзСервисаМобильнойПодписи` и добавляется к объекту автоматически. Включение: константы/ФО `ИспользоватьСервисМобильнойПодписи`, `ИспользоватьГосключ` (программно - `СервисМобильнойПодписи.НастроитьРаботуССервисомМобильнойПодписи(Истина)`, `НастроитьРаботуСГосключом(Истина)`).

**Встраивание:**
1. Метаданные: объект - в `ОпределяемыйТип.ПодписанныйОбъект` с реквизитом `ПодписанЭП` (как для обычной подписи). `ОпределяемыйТип.Организация`, `ФизическоеЛицо` - свои справочники (используются справочником `ПодписантыСервисаМобильнойПодписи`). Роли: `ДобавлениеИзменениеПодписантовМобильногоСервиса`, `ДобавлениеИзменениеНастроекОтправкиВГосключ`.
2. Переопределяемые (`СервисМобильнойПодписиПереопределяемый`): `ПриЗаполненииРеквизитовОрганизации(РеквизитыОрганизации, СтандартнаяОбработка)` (ИНН, ОГРН, наименование, ОКАТО для Госключа, руководители), `ПриЗаполненииРеквизитовФизическогоЛица(РеквизитыФизическогоЛица)` (ФИО, ИНН, телефон, должность), `ПриУдаленииОжидаемойПодписиОбъекта(...)`.
3. Форма: тот же вызов `ЭлектроннаяПодписьКлиент.Подписать`, но `ПараметрыПодписи.РазрешитьОтправкуНаПодписание = Истина` - пользователь выбирает «подписать здесь» или «отправить на подписание». `Представление` (или `ИмяФайла`) обязательно, имя файла до 250 символов, без дублей в наборе. Только отправка: `ЭлектроннаяПодписьКлиент.ОтправитьНаПодписание(...)`. Подписанта можно передать в `ОписаниеДанных.Подписант` (см. `ЭлектроннаяПодписьКлиент.ПараметрыПодписанта`).
4. Отображение ожидаемых подписей: `ЭлектроннаяПодпись.ПодписиОбъекта(Ссылка, Параметры)` с `Параметры.ВозвращатьОжидаемыеПодписи = Истина`.

**Главные методы API** ([api/СервисМобильнойПодписи.md](api/СервисМобильнойПодписи.md)): `СервисМобильнойПодписи.ОтправитьНаПодписание(НаборДанных, Подписант, Параметры)` - серверная отправка без формы; `СервисМобильнойПодписи.РезультатыПодписанияИзСервисаМобильнойПодписи(ИдентификаторыДокументов)` - забрать результаты; `ЭлектроннаяПодпись.РезультатОтправкиНаПодписание` - то же через ЭП; `СервисМобильнойПодписиКлиент.ДобавитьПодписанта`; `ЭлектроннаяПодпись.ИспользоватьСервисМобильнойПодписи()`.

**Подводные камни:** варианты `Данные` = `ОписаниеОповещения` и XML/CMS-структуры для отправки в сервис недоступны - только двоичные данные/адрес; подпись приходит асинхронно (регламентное задание), объект между отправкой и получением может измениться - передавайте `ВерсияОбъекта` и блокируйте редактирование отправленного; в SaaS-режиме регламентное задание управляется очередью заданий.

## МашиночитаемыеДоверенности - МЧД ФНС: хранение, подписание, проверка подписи по доверенности

**Когда использовать:** документ подписывает не руководитель, а представитель по доверенности (ЭДО, отчетность, кадровые документы); нужно создать/импортировать МЧД (формат `EMCHD_1`), зарегистрировать ее в распределенном реестре ФНС, при подписании выбрать доверенность, а при получении подписи - проверить полномочия подписанта. Заменяет самописные справочники доверенностей и ручную проверку «ИНН/СНИЛС сертификата = представитель».

**Встраивание:**
1. Метаданные:
   - `ОпределяемыйТип.Организация`, `ОпределяемыйТип.Контрагент`, `ОпределяемыйТип.ФизическоеЛицо` - в БСП заглушки `Строка`, заменить своими справочниками; тип участника МЧД определяется по ним (`РеквизитыУчастникаПоСсылке` вызывает исключение «Не определен тип участника», если ссылка не входит ни в один).
   - `ОпределяемыйТип.СторонаМЧД` - объединение тех же типов (тип реквизитов доверителя/представителя справочника `МашиночитаемыеДоверенности`).
   - Роли: `ДобавлениеИзменениеМашиночитаемыхДоверенностей`, `ЧтениеМашиночитаемыхДоверенностей`. Регламентные задания: `ОбновлениеСтатусовМЧД`, `ОбновлениеКлассификаторовМЧД`.
   - Подписываемые объекты, для которых проверяется подпись по МЧД, - в `ОпределяемыйТип.ПодписанныйОбъект` (связь в регистре `ЭлектронныеПодписиМЧД`).
2. Переопределяемые (`МашиночитаемыеДоверенностиФНСПереопределяемый`):
   - `ПриЗаполненииРеквизитовОрганизации(Организация, Реквизиты, СтандартнаяОбработка)` - ИНН/КПП/ОГРН, адреса, «лицо без доверенности»; `СтандартнаяОбработка = Ложь`, если подсистема `Организации` не используется.
   - `ПриЗаполненииРеквизитовФизическогоЛица(ФизическоеЛицо, Реквизиты)` - ФИО, ИННФЛ, СНИЛС, документ, дата рождения.
   - `ПриЗаполненииРеквизитовКонтрагента(Контрагент, Реквизиты)`.
   - `ПриПроверкеДоверенностиПодписи(ДанныеДоверенности, Сертификат, ПротоколПроверки)` - прикладная проверка: доверитель = организация документа, полномочия покрывают вид документа:
     ```bsl
     Проверка = МашиночитаемыеДоверенностиФНС.РезультатПроверкиДляПротокола();
     Проверка.ЗаголовокПроверки = НСтр("ru = 'Проверка документа'");
     Проверка.Верна = ДоверительСоответствуетОрганизацииДокумента(ДанныеДоверенности); // своя функция
     Если Не Проверка.Верна Тогда
         Проверка.ТекстПроверки = НСтр("ru = 'Организация документа не соответствует доверителю'");
     КонецЕсли;
     ПротоколПроверки.Вставить("ПроверкаДокумента", Проверка);
     ```
   - `ПриЗаполненииНалоговыхОргановДействия`, `ПриПолученииСтатусаРегистрации`/`ПриРегистрацииДоверенности`/`ПриОпределенииНастроек`/`ПриПолученииСтатусов` - только для регистрации в других реестрах (ФТС и т.п.).
   - Клиентские (`МашиночитаемыеДоверенностиФНСКлиентПереопределяемый`): `ПриНачалеПодписания`, `ПриНачалеВыбораПолномочий`, `ПриРегистрацииДоверенности` и др. - свой UI (например, подписание через 1С-Отчетность).
3. Форма подписываемого объекта:
   ```bsl
   ОписаниеДанных.Вставить("ОтборДоверенностей", Новый Структура("Организация, Полномочия, КлючОтбора",
       Объект.Организация, КодыПолномочий, "ДляМоихАктов")); // КлючОтбора запоминает выбранную МЧД
   ПараметрыПодписи = ЭлектроннаяПодписьКлиент.НовыйТипПодписи();
   ПараметрыПодписи.ВыборДоверенности = Истина;
   ЭлектроннаяПодписьКлиент.Подписать(ОписаниеДанных, ЭтотОбъект, Оповещение, ПараметрыПодписи);
   ```
   Результат проверки по МЧД сохраняется вместе с подписью (`СвойстваПодписи.РезультатПроверкиПодписиПоМЧД` -> `ДобавитьПодпись` пишет `ЭлектронныеПодписиМЧД`). Чтение - `ПодписиОбъекта` с `ВозвращатьДанныеМЧД = Истина`.
4. Открыть список / создать МЧД из своей формы: `МашиночитаемыеДоверенностиФНСКлиент.ОткрытьСписокМЧД(Отборы)` (`ОтборыСпискаДоверенностей()`), `СоздатьМЧД(ПараметрыСозданияМЧД())`.

**Главные методы API** ([api/МашиночитаемыеДоверенности.md](api/МашиночитаемыеДоверенности.md)):
- `МашиночитаемыеДоверенностиФНС.ДоверенностиСОтбором(Отбор, ВыбранныеПоля, НаДату)` - действующие подписанные МЧД по ИНН/СНИЛС/коду полномочия.
- `МашиночитаемыеДоверенностиФНС.ОтборДляДоверенностейПоСертификату(Сертификат, Префикс)` - отбор по субъекту сертификата (ИНН/ОГРН/СНИЛС, нотариус).
- `МашиночитаемыеДоверенностиФНС.РезультатПроверкиПодписиПоМЧД(ПодписанныйОбъект, ИдентификаторПодписи, СертификатПодписи, НаДату)` - проверка подписи по связанным МЧД.
- `МашиночитаемыеДоверенностиФНС.РезультатПроверкиДоверенности(Доверенность)` / `МашиночитаемыеДоверенностиФНСКлиент.ПроверитьДоверенность` - проверка самой МЧД (подписи доверителей, реестр ФНС).
- `МашиночитаемыеДоверенностиФНС.ФайлыДоверенности(Доверенность, ДляНалоговыхОрганов)` - XML + подписи для отправки контрагенту.
- `МашиночитаемыеДоверенностиФНС.ЗагрузитьДоверенностиВИнформационнуюБазу(ЗагруженныеФайлы)` / `РеквизитыДоверенностиИзФайла` - импорт входящих МЧД.
- `МашиночитаемыеДоверенностиФНС.СоздатьИзменитьМашиночитаемуюДоверенность(Доверенность, ДанныеЗаполнения)` (+ `ШаблонОбщихРеквизитовМЧД`, `ДобавитьДоверителя`, `ДобавитьПредставителя`, `ДобавитьПолномочия`) - программное создание (статус `Черновик`).

**Подводные камни:**
- Определяемые типы `Организация`/`Контрагент`/`ФизическоеЛицо`/`СторонаМЧД` не настроены - форма МЧД не открывается или падает на «Не определен тип участника».
- `ДоверенностиСОтбором` по умолчанию возвращает только `Верна = Истина`, `Подписана = Истина` и действующие на дату; пустая `НаДату` отключает отбор по периоду.
- Регистрация в реестре ФНС и обновление статусов идут через интернет-сервис (`ЭлектроннаяПодпись.РазрешенДоступКИнтернетСервисам`, константа `АдресСервисаМЧДРР`) - на закрытых контурах статусы не обновятся.
- `ПриПроверкеДоверенностиПодписи` выполняется при каждой проверке подписи - без тяжелых запросов в цикле; результат сохраняется в базе, менять логику задним числом бесполезно для уже проверенных подписей.
- Подписание МЧД самим доверителем делается из формы справочника `МашиночитаемыеДоверенности`; добавить подпись к файлу МЧД программно - `МашиночитаемыеДоверенностиФНС.ДобавитьПодписьКФайлуДоверенности`.
