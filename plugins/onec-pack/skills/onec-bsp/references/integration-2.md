## РаботаСПочтовымиСообщениями - отправка/получение почты из кода

**Когда использовать:** любое письмо из программы (уведомление, счет клиенту, отчет). Заменяет самописный
`ИнтернетПочта`/`ИнтернетПочтовыйПрофиль` с паролями в константах: учетные записи хранятся в
`Справочник.УчетныеЗаписиЭлектроннойПочты` (пароли - в безопасном хранилище), есть помощник настройки, OAuth,
расшифровка ошибок сервера, статусы доставки (регламентное `ПолучениеСтатусовЭлектронныхПисем`).

**Встраивание (рецепт):**
1. Метаданные: ничего добавлять не нужно. Роли: `ЧтениеУчетныхЗаписейЭлектроннойПочты` (отправка с доступных записей),
   `ДобавлениеИзменениеУчетныхЗаписейЭлектроннойПочты` (настройка). Для уведомлений из фона -
   системная запись `РаботаСПочтовымиСообщениями.СистемнаяУчетнаяЗапись()` (предопределенный элемент).
2. Переопределяемые: `РаботаСПочтовымиСообщениямиПереопределяемый.ПриОпределенииНастроек` (`ДоступноПолучениеПисем`,
   `ИспользоватьПротоколPOP3`); `ПослеОтправкиПисьма` - журналирование своих писем; `ПередПолучениемСтатусовПисем` /
   `ПослеПолученияСтатусовПисем` - отслеживать доставку своих писем (образец - `РассылкаОтчетов`).
   Клиент: `РаботаСПочтовымиСообщениямиКлиентПереопределяемый.ПередОткрытиемФормыОтправкиПисьма`.
3. Код. Серверная отправка:

```bsl
УчетнаяЗапись = РаботаСПочтовымиСообщениями.СистемнаяУчетнаяЗапись();
Если Не РаботаСПочтовымиСообщениями.УчетнаяЗаписьНастроена(УчетнаяЗапись, Истина) Тогда
	Возврат; // или сообщить администратору
КонецЕсли;
ПараметрыПисьма = Новый Структура;
ПараметрыПисьма.Вставить("Кому", "client@example.com");
ПараметрыПисьма.Вставить("Тема", НСтр("ru = 'Счет на оплату'"));
ПараметрыПисьма.Вставить("Тело", ТекстHTML);
ПараметрыПисьма.Вставить("ТипТекста", "HTML");
Письмо = РаботаСПочтовымиСообщениями.ПодготовитьПисьмо(УчетнаяЗапись, ПараметрыПисьма);
Попытка
	Результат = РаботаСПочтовымиСообщениями.ОтправитьПисьмо(УчетнаяЗапись, Письмо);
Исключение
	ТекстОшибки = РаботаСПочтовымиСообщениями.РасширенноеПредставлениеОшибки(ИнформацияОбОшибке(),
		ОбщегоНазначения.КодОсновногоЯзыка(), , УчетнаяЗапись);
	ЗаписьЖурналаРегистрации(НСтр("ru = 'Отправка счета'"), УровеньЖурналаРегистрации.Ошибка, , , ТекстОшибки);
КонецПопытки;
```

   Интерактивно (открыть форму письма с вложениями): `РаботаСПочтовымиСообщениямиКлиент.ПараметрыОтправкиПисьма()` ->
   заполнить `Получатель`, `Тема`, `Текст`, `Вложения` (адреса во временном хранилище), `Предмет` ->
   `РаботаСПочтовымиСообщениямиКлиент.СоздатьНовоеПисьмо(Параметры)`. Перед этим - `ПроверитьНаличиеУчетнойЗаписиДляОтправкиПочты`.

**Главные методы API** (api/РаботаСПочтовымиСообщениями.md):
- `РаботаСПочтовымиСообщениями.ПодготовитьПисьмо` - собрать `ИнтернетПочтовоеСообщение` из структуры.
- `РаботаСПочтовымиСообщениями.ОтправитьПисьмо` / `ОтправитьПисьма` - отправка одного/пачки (одно соединение).
- `РаботаСПочтовымиСообщениями.ЗагрузитьПочтовыеСообщения` - получить входящие.
- `РаботаСПочтовымиСообщениями.ДоступныеУчетныеЗаписи`, `УчетнаяЗаписьНастроена`, `ДоступнаОтправкаПисем` - проверки.
- `РаботаСПочтовымиСообщениями.ПодключениеКПочте` - открыть соединение для серии операций.
- `РаботаСПочтовымиСообщениями.РасширенноеПредставлениеОшибки` / `ПоясненияПоОшибке` - понятный текст ошибки сервера.
- `РаботаСПочтовымиСообщениями.ОтключитьНебезопасноеСодержимое` - очистка входящего HTML перед показом.
- `РаботаСПочтовымиСообщениямиКлиент.СоздатьНовоеПисьмо` - форма письма.

**Подводные камни:**
- `ОтправитьПисьмо` вызывает исключение - всегда `Попытка`; `ОтправитьПисьма` при частичном успехе исключения
  **не** бросает - проверяйте возвращенное соответствие и `ТекстОшибки`.
- Не отправлять в транзакции записи документа и в `ОбработкаПроведения` - сеть может висеть минутами; отправка -
  после записи или через очередь/фоновое задание.
- `Тело` по умолчанию - простой текст; для HTML явно `ТипТекста = "HTML"`.
- Если подсистема `Взаимодействия` внедрена и включен почтовый клиент (ФО `ИспользоватьПочтовыйКлиент`), пользователь
  ожидает письмо в журнале взаимодействий - для интерактивной отправки используйте `СоздатьНовоеПисьмо` / шаблоны,
  а не прямую серверную отправку.
- Входящий HTML показывать только после `ОтключитьНебезопасноеСодержимое` (скрипты, внешние ресурсы).

## ОтправкаSMS - отправка SMS через провайдера

**Когда использовать:** уведомления/коды по SMS. Встроены провайдеры (модули `ОтправкаSMSЧерез*`: МТС, Билайн,
SMS.RU, SMS4B, СМС-Центр, СМС-Услуги). Заменяет самописные HTTP-вызовы к SMS-шлюзам и хранение логина в константах.

**Встраивание (рецепт):**
1. Метаданные: роль `ОтправкаSMS` (проверяется в `ОтправкаSMS.ОтправитьSMS` через права на общую форму `ОтправкаSMS`).
   Если внедрены `Взаимодействия`, SMS из форм сохраняются документом `СообщениеSMS`, отправка/статусы - регламентные
   `ОтправкаSMS` и `ОбновлениеСтатусовДоставкиSMS`.
2. Переопределяемые: свой провайдер - `ОтправкаSMSПереопределяемый.ОтправитьSMS(ПараметрыОтправки, Результат)` +
   `СтатусДоставки` + `ПриПроверкеНастроекОтправкиSMS` + `ПриПолученииРазрешений` (разрешения на URL провайдера);
   клиент - `ОтправкаSMSКлиентПереопределяемый.ПриОтправкеSMS` (подменить форму), `ПриПолученииАдресаПровайдераВИнтернете`.
3. Код:

```bsl
Если ОтправкаSMS.ДоступнаОтправкаSMS() Тогда
	Номера = Новый Массив;
	Номера.Добавить("+79990000000");
	Результат = ОтправкаSMS.ОтправитьSMS(Номера, ТекстСообщения);
	Если ЗначениеЗаполнено(Результат.ОписаниеОшибки) Тогда
		// записать в журнал, не падать
	КонецЕсли;
КонецЕсли;
```

**Главные методы API** (api/ОтправкаSMS.md): `ОтправкаSMS.ОтправитьSMS` (возвращает `ОтправленныеСообщения` с
`ИдентификаторСообщения`), `ОтправкаSMS.СтатусДоставки`, `ОтправкаSMS.ДоступнаОтправкаSMS`,
`ОтправкаSMS.НастройкаОтправкиSMSВыполнена`, `ОтправкаSMSКлиент.ОтправитьSMS` (форма), `ОтправкаSMSКлиент.ОткрытьФормуНастроек`.

**Подводные камни:**
- Ошибка провайдера возвращается в `Результат.ОписаниеОшибки`, а отсутствие прав - исключением; обрабатывайте оба.
- Номер в формате `+<код страны><номер>`; статус доставки асинхронный - храните `ИдентификаторСообщения`.
- Из регламентного задания без пользователя проверка прав на форму не пройдет у служебного пользователя без роли -
  запускайте задание под пользователем с ролью `ОтправкаSMS`.
- Своему провайдеру нужны разрешения профиля безопасности (`ПриПолученииРазрешений`), иначе в защищенном кластере вызов упадет.

## РассылкаОтчетов - отчеты по расписанию на почту/в папку/FTP

**Когда использовать:** «присылать отчет каждый понедельник», персональные отчеты каждому менеджеру/контрагенту.
Заменяет самописные регламентные задания с `ТабличныйДокумент.Записать` + отправкой почты.

**Встраивание (рецепт):**
1. Метаданные: отчет должен быть подключен к подсистеме `ВариантыОтчетов` (см. файл по отчетам) - рассылаются
   только варианты из `Справочник.ВариантыОтчетов` и дополнительные отчеты. Новый тип получателей (например
   `Справочник.Контрагенты`) - добавить в определяемый тип `ПолучательРассылки` (в БСП: `Пользователи`, `ГруппыПользователей`);
   у типа должна быть контактная информация с e-mail. Роли: `ЧтениеРассылокОтчетов`, `ДобавлениеИзменениеРассылокОтчетов`.
   ФО `ХранитьИсториюРассылкиОтчетов` + регламентное `ОчисткаИсторииРассылкиОтчетов`.
2. Переопределяемые (`РассылкаОтчетовПереопределяемый`):
   - `ПереопределитьТаблицуТиповПолучателей` - вид КИ e-mail по умолчанию, объединение типов:

```bsl
Процедура ПереопределитьТаблицуТиповПолучателей(ТаблицаТипов, ДоступныеТипы) Экспорт
	Настройки = Новый Структура;
	Настройки.Вставить("ОсновнойТип", Тип("СправочникСсылка.Контрагенты"));
	Настройки.Вставить("ВидКИ", УправлениеКонтактнойИнформацией.ВидКонтактнойИнформацииПоИмени("EmailКонтрагента"));
	РассылкаОтчетов.ДобавитьЭлементВТаблицуТиповПолучателей(ТаблицаТипов, ДоступныеТипы, Настройки);
КонецПроцедуры
```

   - `ОпределитьИсключаемыеОтчеты` - отчеты, которые нельзя рассылать (интерактивные, с обязательными параметрами).
   - `ПриПодготовкеПараметровФормированияОтчета` - подставить параметры перед формированием.
   - `ПередФормированиемСпискаПолучателейРассылки` - свой состав получателей.
   - `ПриОпределенииПараметровТекстаПисьма` + `ПриПолученииПараметровТекстаПисьма` - свои параметры темы/текста.
   - `ПереопределитьПараметрыФорматов`, `ПередСохранениемТабличногоДокументаВФормат` - форматы.
3. Отчет для персонализированной рассылки: в настройках варианта - отбор по полю типа получателя со значением
   `[Получатель]`; `ПараметрыДоставки.Персонализирована = Истина` отключает все способы доставки кроме почты.
   Программная рассылка без справочника рассылок:

```bsl
Отчеты = РассылкаОтчетов.ОтчетыДляРассылки();
СтрокаОтчета = Отчеты.Добавить();
СтрокаОтчета.Отчет = ВариантОтчета; // СправочникСсылка.ВариантыОтчетов
СтрокаОтчета.Форматы = Новый Массив; // колонка типа Массив, в новой строке пусто
СтрокаОтчета.Форматы.Добавить(Перечисления.ФорматыСохраненияОтчетов.XLSX);
Доставка = РассылкаОтчетов.ПараметрыДоставки();
Доставка.ИспользоватьЭлектроннуюПочту = Истина;
Доставка.УчетнаяЗапись = РаботаСПочтовымиСообщениями.СистемнаяУчетнаяЗапись();
Доставка.Получатели = Новый Соответствие;
Доставка.Получатели.Вставить(Пользователь, "boss@example.com");
РассылкаОтчетов.ВыполнитьРассылку(Отчеты, Доставка, НСтр("ru = 'Еженедельный отчет'"));
```


**Главные методы API** (api/РассылкаОтчетов.md): `РассылкаОтчетов.ВыполнитьРассылкуОтчетов` (по элементу
`Справочник.РассылкиОтчетов`), `ВыполнитьРассылку` (произвольные отчеты), `ОтчетыДляРассылки`, `ПараметрыДоставки`,
`ПараметрыЖурнала`, `ДобавитьЭлементВТаблицуТиповПолучателей`, `УстановитьПараметрыФормата`, `ВыполнитьРассылкиВФоновомЗадании`.

**Подводные камни:**
- Формирование идет в регламентном задании `РассылкаОтчетов` от имени автора рассылки - права автора определяют
  данные в отчете (RLS). Персональная рассылка контрагентам из-под администратора раскроет лишнее, если отбор
  `[Получатель]` не настроен.
- Отчеты не на СКД рассылаются только если умеют формироваться без формы (через `Настройки` = Структура реквизитов).
- Тяжелые отчеты по многим получателям - узкое место; ограничивайте периодом и отбором, не делайте «весь год каждому».
- Удаление объекта метаданных-типа получателя отключает рассылки (подписка `ОтключитьРассылкиПередУдалениемТипаПолучателейРассылки`).

## ШаблоныСообщений - письма и SMS по шаблонам с подстановкой реквизитов

**Когда использовать:** пользователь сам редактирует текст уведомлений («Ваш заказ [Заказ.Номер] отгружен»), нужны
вложения печатных форм, отправка по кнопке «Отправить -> Почта/SMS» из формы объекта. Заменяет хардкод текстов писем.

**Встраивание в свой объект (рецепт):**
1. Метаданные: добавить тип ссылки объекта в определяемый тип `ПредметШаблонаСообщения` (в БСП: `НазначениеОпросов`,
   `ИдентификаторыОбъектовМетаданных`). Владелец шаблонов (если шаблоны привязываются к объекту) - `ВладелецШаблонаСообщения`.
   Команды «Отправить -> Почта / SMS» и общие команды `ОтправитьПисьмо` / `ОтправитьSMS` (группа `Органайзер`)
   появляются автоматически по типу параметра - форма объекта должна быть подключена к `ПодключаемыеКоманды`
   (`ПодключаемыеКоманды.ПриСозданииНаСервере` в форме). ФО: `ИспользоватьШаблоныСообщений`,
   `ИспользоватьЭлектроннуюПочтуВШаблонахСообщений`, `ИспользоватьОтправкуSMSВШаблонахСообщений`.
   Роли: `ЧтениеШаблоновСообщений`, `ДобавлениеИзменениеШаблоновСообщений`, `ДобавлениеИзменениеЛичныхШаблоновСообщений`.
2. **Модуль менеджера объекта** - все четыре процедуры обязательны (БСП вызывает их без проверки наличия; образец -
   `Документ.НазначениеОпросов`):

```bsl
// СтандартныеПодсистемы.ШаблоныСообщений

Процедура ПриПодготовкеШаблонаСообщения(Реквизиты, Вложения, ДополнительныеПараметры) Экспорт
	// Добавить вычисляемый реквизит в дерево выбора параметров шаблона.
	НовыйРеквизит = Реквизиты.Добавить();
	НовыйРеквизит.Имя = "СуммаПрописью";
	НовыйРеквизит.Представление = НСтр("ru = 'Сумма прописью'");
КонецПроцедуры

Процедура ПриФормированииСообщения(Сообщение, ПредметСообщения, ДополнительныеПараметры) Экспорт
	Если Сообщение.ЗначенияРеквизитов["СуммаПрописью"] <> Неопределено Тогда
		Сумма = ОбщегоНазначения.ЗначениеРеквизитаОбъекта(ПредметСообщения, "СуммаДокумента");
		Сообщение.ЗначенияРеквизитов["СуммаПрописью"] = ЧислоПрописью(Сумма, , "рубль, рубля, рублей, м, копейка, копейки, копеек, ж, 2");
	КонецЕсли;
КонецПроцедуры

Процедура ПриЗаполненииТелефоновПолучателейВСообщении(ПолучателиSMS, ПредметСообщения) Экспорт
	ШаблоныСообщений.ЗаполнитьПолучателей(ПолучателиSMS, ПредметСообщения, "Контрагент");
КонецПроцедуры

Процедура ПриЗаполненииПочтыПолучателейВСообщении(ПолучателиПисьма, ПредметСообщения) Экспорт
	ШаблоныСообщений.ЗаполнитьПолучателей(ПолучателиПисьма, ПредметСообщения, "Контрагент");
КонецПроцедуры

// Конец СтандартныеПодсистемы.ШаблоныСообщений
```

   `ПредметСообщения` в двух последних процедурах может быть ссылкой **или** структурой (`Предмет`, `ПроизвольныеПараметры`, ...) -
   проверяйте тип. `Сообщение.ЗначенияРеквизитов` - уже поддерево параметров типа назначения (БСП берет
   `ПараметрыТекстаСообщения[ПолноеИмяТипаНазначения]`), поэтому ключи - имена реквизитов без префикса типа;
   в соответствие попадают только реквизиты, реально использованные в тексте шаблона.
3. Переопределяемые (`ШаблоныСообщенийПереопределяемый`): `ПриОпределенииНастроек` (общие реквизиты, назначения без
   объекта метаданных с макетом СКД, `РасширенныйСписокПолучателей`), сквозные `ПриПодготовкеШаблонаСообщения`,
   `ПриФормированииСообщения`, `ПриЗаполнении*ПолучателейВСообщении` (получают еще `НазначениеШаблона`),
   поставляемые шаблоны - `ПриНачальномЗаполненииЭлементов`.
4. Отправка из кода (например, при смене статуса заказа):

```bsl
Шаблон = ...; // СправочникСсылка.ШаблоныСообщений, найденный по назначению/коду
Параметры = ШаблоныСообщений.ПараметрыОтправкиПисьмаПоШаблону();
Результат = ШаблоныСообщений.СформироватьСообщениеИОтправить(Шаблон, Заказ, Новый УникальныйИдентификатор, Параметры);
```

**Главные методы API** (api/ШаблоныСообщений.md): `ШаблоныСообщений.СформироватьСообщение` (подготовить без отправки),
`СформироватьСообщениеИОтправить`, `ПараметрыОтправкиПисьмаПоШаблону`, `ЗаполнитьПолучателей`, `СоздатьШаблон`,
`ОписаниеПараметровШаблона`, `ИспользуютсяШаблоныСообщений`; клиент - `ШаблоныСообщенийКлиент.СформироватьСообщение(Предмет, "Письмо"|"СообщениеSMS")`,
`ШаблоныСообщенийКлиент.ВыбратьШаблон`.

**Подводные камни:**
- Тип в `ПредметШаблонаСообщения` без четырех процедур в модуле менеджера = ошибка выполнения при открытии/формировании шаблона.
- `СформироватьСообщениеИОтправить` при внедренных `Взаимодействиях` создает документ письма; `ОтправитьСразу = Ложь`
  кладет его в исходящие (отправит регламентное задание `ПолучениеИОтправкаЭлектронныхПисем`).
- Тяжелые вычисления в `ПриФормированииСообщения` делайте только если реквизит реально используется в шаблоне
  (проверка `Сообщение.ЗначенияРеквизитов[Имя] <> Неопределено`).
- Без системной/личной учетной записи почты отправка вернет ошибку в результате, а не исключение - проверяйте результат.

## Взаимодействия - почтовый клиент, звонки, встречи по предметам и контактам

**Когда использовать:** CRM-контур - вся переписка, звонки, встречи и SMS привязаны к контрагенту/контактному лицу
(контакт) и к сделке/заказу (предмет), история видна из карточки. Документы: `ЭлектронноеПисьмоВходящее`,
`ЭлектронноеПисьмоИсходящее`, `ТелефонныйЗвонок`, `Встреча`, `ЗапланированноеВзаимодействие`, `СообщениеSMS`;
журнал `Взаимодействия`. Заменяет самописные «журналы звонков» и табличные части «история общения».

**Встраивание (рецепт):**
1. Метаданные:
   - Свой объект как **контакт** (кому пишем/звоним): тип в определяемый тип `КонтактВзаимодействия`
     (в БСП: `Пользователи`, `СтроковыеКонтактыВзаимодействий`); у объекта должна быть контактная информация (e-mail/телефон).
   - Свой объект как **предмет** (о чем общаемся): тип в `ПредметВзаимодействия` (в БСП - сами документы взаимодействий).
   - Команды журнала `ВзаимодействияПоКонтакту`, `ВзаимодействияПоПредмету` (панель навигации «Перейти»),
     `ЗапланироватьВзаимодействиеПоКонтакту/ПоПредмету`, `ЗапланироватьВстречуПоКонтакту` появятся в формах автоматически
     по типу параметра.
   - Роли: `ДобавлениеИзменениеВзаимодействий`; ФО `ИспользоватьПочтовыйКлиент`, `ИспользоватьПрочиеВзаимодействия`.
2. Переопределяемые:

```bsl
// ВзаимодействияКлиентСерверПереопределяемый
Процедура ПриОпределенииВозможныхПредметов(ТипыПредметов) Экспорт
	ТипыПредметов.Добавить("ДокументСсылка.ЗаказКлиента");
КонецПроцедуры

Процедура ПриОпределенииВозможныхКонтактов(ТипыКонтактов) Экспорт
	Контакт = ВзаимодействияКлиентСервер.НовоеОписаниеКонтакта();
	Контакт.Тип = Тип("СправочникСсылка.Контрагенты");
	Контакт.Имя = "Контрагенты";
	Контакт.Представление = НСтр("ru = 'Контрагенты'");
	Контакт.ВозможностьИнтерактивногоСоздания = Истина;
	ТипыКонтактов.Добавить(Контакт);
КонецПроцедуры

// ВзаимодействияПереопределяемый - подсказка контактов по предмету
Процедура ПриПоискеКонтактов(Знач ИмяТаблицыКонтактов, ТекстЗапросаДляПоиска) Экспорт
	Если ИмяТаблицыКонтактов = "Документ.ЗаказКлиента" Тогда // приходит ПолноеИмя() метаданных
		ТекстЗапросаДляПоиска = "
		|ОБЪЕДИНИТЬ ВСЕ
		|ВЫБРАТЬ РАЗЛИЧНЫЕ Заказ.Контрагент
		|ИЗ Документ.ЗаказКлиента КАК Заказ
		|ГДЕ Заказ.Ссылка = &Предмет";
	КонецЕсли;
КонецПроцедуры
```

   (Фрагмент дописывается к запросу БСП через конкатенацию, поэтому начинается с `ОБЪЕДИНИТЬ ВСЕ` и возвращает одно поле.)
   Ограничение доступа к документам взаимодействий - `ВзаимодействияПереопределяемый.ПриЗаполненииНаборовЗначенийДоступа`
   (+ `Взаимодействия.ЗаполнитьНаборыЗначенийДоступаПоУмолчанию`).
3. Формы и модули своего предмета/контакта:
   - форма предмета, `ПослеЗаписи` (клиент): `ВзаимодействияКлиент.ВзаимодействиеПредметПослеЗаписи(ЭтотОбъект, Объект, ПараметрыЗаписи, "ЗаказКлиента");`
   - форма контакта, `ПослеЗаписи`: `ВзаимодействияКлиент.КонтактПослеЗаписи(ЭтотОбъект, Объект, ПараметрыЗаписи, "Контрагенты");`
   - предмет, созданный «на основании» письма/звонка: в `ПриЗаписиНаСервере` формы -
     `Взаимодействия.ПриЗаписиПредметаИзФормы(ТекущийОбъект.Ссылка, Параметры.Основание, Отказ);`
     (метод сам проверяет, что основание - взаимодействие); в `ОбработкаЗаполнения` модуля объекта -
     `Взаимодействия.ЗаполнитьРеквизитыПоУмолчанию(ЭтотОбъект, ДанныеЗаполнения);`
   - закрытый заказ/сделка: `Взаимодействия.УстановитьПризнакАктивен(Предмет, Ложь)` - скрывает из активных предметов.

**Главные методы API** (api/Взаимодействия.md): `Взаимодействия.ПриЗаписиПредметаИзФормы`, `ЗаполнитьРеквизитыПоУмолчанию`,
`УстановитьПризнакАктивен`, `ПредметВзаимодействия`, `ИспользуетсяПочтовыйКлиент`; `ВзаимодействияКлиент.ВзаимодействиеПредметПослеЗаписи`,
`КонтактПослеЗаписи`, `ОткрытьФормуОтправкиSMS`; `ВзаимодействияКлиентСервер.НовоеОписаниеКонтакта`.

**Подводные камни:**
- Тип в определяемом типе без регистрации в `ПриОпределенииВозможныхПредметов/Контактов` (и наоборот) - команды есть,
  а подбор/поиск контактов не работает. Делайте обе вещи вместе.
- `ВзаимодействияКлиентСерверПереопределяемый` - клиент-серверный модуль: только `Тип(...)`, строки и `НСтр`, без обращений к БД.
- Почтовый клиент грузит всю почту ящиков в ИБ (регламентное `ПолучениеИОтправкаЭлектронныхПисем`) - объем базы и
  вложений растет быстро; ограничивайте ящики и правила обработки.
- Документы взаимодействий - объект RLS; без `ПриЗаполненииНаборовЗначенийДоступа` применяются наборы по умолчанию.

## Анкетирование - опросы пользователей и контрагентов

**Когда использовать:** опросы удовлетворенности, анкеты сотрудников, интервью клиента оператором. Объекты:
`ПланВидовХарактеристик.ВопросыДляАнкетирования`, `Справочник.ШаблоныАнкет`, `Документ.НазначениеОпросов`,
`Документ.Анкета`, `РегистрСведений.ОтветыНаВопросыАнкет`, отчеты `АнализОпроса`, `АналитическийОтчетПоАнкетированию`,
обработка `ДоступныеАнкеты`.

**Встраивание (рецепт):**
1. Метаданные: добавить тип респондента (например `СправочникСсылка.Контрагенты`) в определяемый тип `Респондент`
   (в БСП - только `Пользователи`); интервьюер - `Интервьюер`. Тогда общая команда `НачатьИнтервью`
   (параметр - `Респондент`, группа «Важное» командной панели формы) появится в форме контрагента, а в
   `НазначениеОпросов.ТипРеспондентов` можно выбрать новый тип. ФО `ИспользоватьАнкетирование`. Роли:
   `ДобавлениеИзменениеШаблоновАнкет`, `ДобавлениеИзменениеОпросов`, `ДобавлениеИзменениеОтветовНаВопросыАнкет`,
   `ЧтениеОтветовНаВопросыАнкет`.
2. Переопределяемых модулей нет. Приглашение на опрос по почте - через `ШаблоныСообщений`
   (`Документ.НазначениеОпросов` уже в `ПредметШаблонаСообщения`).
3. Пользователь-респондент проходит анкеты через обработку `ДоступныеАнкеты`; оператор - командой `НачатьИнтервью`
   из карточки респондента (режим `Перечисление.РежимыАнкетирования.Интервью`).

**Главные методы API:** публичного программного интерфейса у подсистемы нет (модуль `Анкетирование` - только служебные
методы); ответы читайте запросом к `РегистрСведений.ОтветыНаВопросыАнкет` и `Документ.Анкета`.

**Подводные камни:**
- Внешние респонденты (контрагенты) не заходят в 1С - для них только режим интервью или своя веб-форма, сохраняющая
  `Документ.Анкета`; публичного API для этого нет, опирайтесь на структуру документа и регистра (может меняться между версиями БСП).
- Не вызывайте служебные методы `Анкетирование.*` из прикладного кода - они не входят в ПрограммныйИнтерфейс.

## БизнесПроцессыИЗадачи - задачи исполнителям, роли, маршруты

**Когда использовать:** поручения, согласования, контроль сроков, ролевая адресация («главный бухгалтер организации X»),
уведомления о новых и просроченных задачах. Метаданные: `БизнесПроцесс.Задание` (поручение с проверкой),
`Задача.ЗадачаИсполнителя` (единая задача для всех процессов), `Справочник.РолиИсполнителей`,
`ПланВидовХарактеристик.ОбъектыАдресацииЗадач`. Заменяет самописные справочники «Задачи» с полем «Исполнитель».

**Встраивание (рецепт):**
1. Задачи по своему объекту: добавить тип в определяемый тип `ПредметЗадачи` - в форме появится общая команда
   `ЗадачиПоПредмету` (панель навигации «Перейти»). Создание поручения по объекту - `БизнесПроцессыИЗадачиКлиент.СоздатьЗадание(ЭтотОбъект, ПараметрыФормы)`
   или `БизнесПроцессы.Задание` на основании (ДанныеЗаполнения = ссылка на предмет).
2. **Свой бизнес-процесс:**
   - метаданные: свойство «Задача» = `Задача.ЗадачаИсполнителя`; реквизиты `Автор`, `ДатаЗавершения`, `Наименование`
     (копируются подпиской в `РегистрСведений.ДанныеБизнесПроцессов`), желательно `Состояние` (`Перечисление.СостоянияБизнесПроцессов`),
     `Предмет`, `ГлавнаяЗадача`, `Важность` - как в `БизнесПроцесс.Задание`;
   - добавить тип в определяемые типы `БизнесПроцесс` и `БизнесПроцессОбъект` (на `БизнесПроцессОбъект` подписаны
     `ЗаписатьВСписокБизнесПроцессов`, `ОбновитьСостояниеБизнесПроцесса`, `УстановитьПометкуУдаленияЗадач`),
     для отложенного старта - `ОтложенныйБизнесПроцесс`;
   - подписки `ПолучитьПредставлениеБизнесПроцесса` / `ПолучитьПоляПредставленияБизнесПроцесса` - добавить свой
     `BusinessProcessManager` в источник (в БСП там только `Задание`);
   - зарегистрировать в `БизнесПроцессыИЗадачиПереопределяемый.ПриОпределенииБизнесПроцессов`:
     `ПодключенныеБизнесПроцессы.Вставить(Метаданные.БизнесПроцессы.Согласование.ПолноеИмя(), "");`
   - модуль менеджера процесса - три экспортных метода (образец `БизнесПроцесс.Задание`):

```bsl
// СтандартныеПодсистемы.БизнесПроцессыИЗадачи

Функция ФормаВыполненияЗадачи(ЗадачаСсылка, ТочкаМаршрутаБизнесПроцесса) Экспорт
	Результат = Новый Структура;
	Результат.Вставить("ПараметрыФормы", Новый Структура("Ключ", ЗадачаСсылка));
	Результат.Вставить("ИмяФормы", Метаданные.БизнесПроцессы.Согласование.Формы.ДействиеСогласовать.ПолноеИмя());
	Возврат Результат;
КонецФункции

Процедура ПриПеренаправленииЗадачи(ЗадачаСсылка, НоваяЗадачаСсылка) Экспорт
КонецПроцедуры

Процедура ОбработкаВыполненияПоУмолчанию(ЗадачаСсылка, БизнесПроцессСсылка, ТочкаМаршрутаБизнесПроцесса) Экспорт
КонецПроцедуры

// Конец СтандартныеПодсистемы.БизнесПроцессыИЗадачи
```

   - модуль объекта процесса: в `ПередЗаписью` (после проверки `ОбменДанными.Загрузка`) -
     `БизнесПроцессыИЗадачиСервер.ПроверитьПраваНаИзменениеСостоянияБизнесПроцесса(ЭтотОбъект);` в `ОбработкаЗаполнения` -
     `БизнесПроцессыИЗадачиСервер.ЗаполнитьГлавнуюЗадачу(ЭтотОбъект, ДанныеЗаполнения);` в `ПриСозданииЗадач` точек
     маршрута - заполнить у задач `Исполнитель` или `РольИсполнителя` + `ОсновнойОбъектАдресации`, `Предмет`, `СрокИсполнения`;
     RLS - `ЗаполнитьНаборыЗначенийДоступа` с вызовом `БизнесПроцессыИЗадачиПереопределяемый.ПриЗаполненииНаборовЗначенийДоступа`.
   - форма выполнения задачи: `ПриСозданииНаСервере` - `БизнесПроцессыИЗадачиСервер.ФормаЗадачиПриСозданииНаСервере(ЭтотОбъект, Объект, Элементы.ГруппаСостояние, Элементы.ДатаИсполнения)`;
     `ОбработкаОповещения` - `БизнесПроцессыИЗадачиКлиент.ФормаЗадачиОбработкаОповещения(ЭтотОбъект, ИмяСобытия, Параметр, Источник)`;
     кнопка «Выполнено» - `БизнесПроцессыИЗадачиКлиент.ЗаписатьИЗакрытьВыполнить(ЭтотОбъект, Истина)`;
     принятие к исполнению - `ПринятьЗадачуКИсполнению` / `ОтменитьПринятиеЗадачиКИсполнению` / `ОбновитьДоступностьКомандПринятияКИсполнению`.
   - форма процесса: «Остановить/Продолжить» - `БизнесПроцессыИЗадачиКлиент.ОстановитьБизнесПроцессИзФормыОбъекта(ЭтотОбъект)` /
     `ПродолжитьБизнесПроцессИзФормыОбъекта`, выбор исполнителя - как в форме `Задание` (`БизнесПроцессыИЗадачиКлиент.ВыбратьИсполнителя` экспортный,
     но лежит в служебной области модуля; для выбора роли - публичные `ПараметрыФормыВыбораРолиИсполнителя` + `ОткрытьФормуВыбораРолиИсполнителя`).
3. Переопределяемые: `ПриНачальномЗаполненииРолейИсполнителей` / `ПриНачальномЗаполненииОбъектовАдресацииЗадач` -
   поставляемые роли («Руководитель подразделения» с адресацией по подразделению); `ПриПолученииФормыВыполненияЗадачи`,
   `ПриПроверкеПравНаОстановкуБизнесПроцесса`, `ПриЗаписиСпискаБизнесПроцессов`; клиент - `ПриВыбореИсполнителя`.
4. Регламентные: `УведомлениеИсполнителейОНовыхЗадачах`, `МониторингЗадач` (просроченные), `СтартОтложенныхПроцессов`.
   ФО: `ИспользоватьБизнесПроцессыИЗадачи`, `ИспользоватьПодчиненныеБизнесПроцессы`, `ИспользоватьДатуНачалаЗадач`,
   `ИспользоватьДатуИВремяВСрокахЗадач`. Роли: `ИзменениеВыполнениеЗадач`, `ЧтениеЗадач`.

**Главные методы API** (api/БизнесПроцессыИЗадачи.md): `БизнесПроцессыИЗадачиСервер.ВыполнитьЗадачу`,
`ПеренаправитьЗадачи`, `ЗаблокироватьБизнесПроцессы` / `ЗаблокироватьЗадачи`, `ОстановитьБизнесПроцесс` / `СделатьАктивнымБизнесПроцесс`,
`ДобавитьПроцессДляОтложенногоСтарта`, `ИсполнительСтрокой`, `ФормаЗадачиПриСозданииНаСервере`;
`БизнесПроцессыИЗадачиКлиент.СоздатьЗадание`, `ЗаписатьИЗакрытьВыполнить`, `ПринятьЗадачиКИсполнению`.

**Подводные камни:**
- Изменение процесса из задачи (как `ОбработкаВыполненияПоУмолчанию`) - в транзакции с
  `БизнесПроцессыИЗадачиСервер.ЗаблокироватьБизнесПроцессы` до `ПолучитьОбъект()`, иначе конфликты блокировок при
  массовом выполнении.
- Свой процесс, не добавленный в `ПриОпределенииБизнесПроцессов`, не получит вызовы `ФормаВыполненияЗадачи` и
  перенаправления - задачи откроются стандартной формой.
- Ролевая адресация: задача с `РольИсполнителя` без `Исполнитель` - исполнителей ищут по регистру `ИсполнителиЗадач`;
  проверяйте, что у роли есть исполнители, иначе задача «повиснет».
- `ПередЗаписью` процесса меняет состояние под проверкой прав; при программной остановке процесса используйте
  `ОстановитьБизнесПроцесс`, а не прямую запись `Состояние`.
