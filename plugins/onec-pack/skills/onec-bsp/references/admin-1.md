## ОбновлениеВерсииИБ - обработчики обновления и начального заполнения данных

**Когда использовать:** любое изменение структуры данных, которое требует преобразовать уже существующие данные
(новый реквизит надо заполнить, перенести данные из старого регистра в новый, пересчитать поле), создать/обновить
предопределенные или поставляемые элементы, заполнить данные в пустой базе. Заменяет самописные «обработки для
перехода», ручные запуски из конфигуратора и флажки-константы «ДанныеПерезаполнены». БСП сама решает, какие обработчики
выполнить при смене номера версии, показывает прогресс, пишет ошибки в журнал и форму «Результаты обновления программы».

### Как устроено (что нужно знать до рецепта)
- Каждая «подсистема» (БСП, библиотека, основная конфигурация, ваша доработка) описывается **серверным общим модулем**
  с процедурами `ПриДобавленииПодсистемы` и `ПриДобавленииОбработчиковОбновления` (полный состав - как в
  `ОбновлениеИнформационнойБазыБСП`: ещё `ПередОбновлениемИнформационнойБазы`, `ПослеОбновленияИнформационнойБазы`,
  `ПриПодготовкеМакетаОписанияОбновлений`, `ПриОпределенииРежимаОбновленияДанных`,
  `ПриДобавленииОбработчиковПереходаСДругойПрограммы`, `ПриЗавершенииПереходаСДругойПрограммы` - все экспортные, можно пустые).
- Модуль регистрируется в `ПодсистемыКонфигурацииПереопределяемый.ПриДобавленииПодсистем(МодулиПодсистем)`.
  Модуль БСП добавлять не нужно - он добавляется сам.
- Версия ИБ хранится **отдельно для каждого `Описание.Имя`**. Обработчик выполняется, если его `Версия` больше версии ИБ
  этой подсистемы и не больше `Описание.Версия`.
- Для основной конфигурации (`Описание.Имя = Метаданные.Имя`) `Описание.Версия` обязана совпадать с `Метаданные.Версия`,
  иначе исключение «версия ... не совпадает с версией конфигурации в метаданных» (`СтандартныеПодсистемыПовтИсп.ОписанияПодсистем`).

### Режимы выполнения (`Обработчик.РежимВыполнения`)
| Режим | Когда выполняется | Для чего | Ограничения |
|---|---|---|---|
| `"Монопольно"` (по умолчанию, если пусто) | при первом запуске после обновления, монопольно, до входа пользователей | изменения, без которых программа не может работать (структура, обязательные константы) | держит всех пользователей; только быстрые операции |
| `"Оперативно"` | при запуске, без монопольного режима, но до входа пользователей | быстрые изменения малого объема данных (константы, предопределенные, регламентные задания) | при больших объемах - блокировки и долгий старт |
| `"Отложенно"` | после входа, в фоне регламентным заданием `ОтложенноеОбновлениеИБ`, порциями | обработка больших объемов (документы, регистры) | нужны `Идентификатор`, `Комментарий`, у библиотеки с `РежимВыполненияОтложенныхОбработчиков = "Параллельно"` - ещё `ПроцедураЗаполненияДанныхОбновления`, `ЧитаемыеОбъекты`/`ИзменяемыеОбъекты` |

Специальные значения `Версия`: `"*"` - выполнять при **каждой** смене версии (обязательный обработчик, только Монопольно/Оперативно);
пустая строка + `НачальноеЗаполнение = Истина` - только при начальном заполнении пустой базы.
Допустимые значения режима проверяются: любое другое значение - ошибка «Допустимое значение: "Монопольно", "Отложенно", "Оперативно"».

### Встраивание (рецепт)
1. **Метаданные.** Создать серверный общий модуль (флаги Сервер + ВнешнееСоединение, не глобальный, без ПовтИсп),
   например `ОбновлениеИнформационнойБазыМояДоработка`. Для своей конфигурации - модуль самой конфигурации
   (`Описание.Имя = Метаданные.Имя`). Отдельных определяемых типов/подписок не нужно: регистрацию данных к обработке
   БСП ведет в плане обмена `ОбновлениеИнформационнойБазы` (служебный, в нем ничего не менять).
2. **Переопределяемые процедуры.**
   ```bsl
   // ПодсистемыКонфигурацииПереопределяемый
   Процедура ПриДобавленииПодсистем(МодулиПодсистем) Экспорт
       МодулиПодсистем.Добавить("ОбновлениеИнформационнойБазыМояДоработка");
   КонецПроцедуры
   ```
   В самом модуле:
   ```bsl
   Процедура ПриДобавленииПодсистемы(Описание) Экспорт
       Описание.Имя    = "МояДоработка";        // или Метаданные.Имя для основной конфигурации
       Описание.Версия = "1.0.3.1";             // для основной конфигурации = Метаданные.Версия
       Описание.ТребуемыеПодсистемы.Добавить("СтандартныеПодсистемы");
       Описание.РежимВыполненияОтложенныхОбработчиков = "Параллельно"; // как у БСП
       Описание.ПараллельноеОтложенноеОбновлениеСВерсии = "1.0.0.1";
   КонецПроцедуры
   ```
   Общие настройки: `ОбновлениеИнформационнойБазыПереопределяемый.ПриОпределенииНастроек(Параметры)` -
   `МногопоточноеОбновление`, `КоличествоПотоковОбновленияИнформационнойБазыПоУмолчанию`, `ОбъектыСНачальнымЗаполнением`,
   текст о невыполненных отложенных обработчиках (`ПараметрыСообщенияОНевыполненныхОтложенныхОбработчиках.ЗапрещатьПродолжение`).
3. **Регистрация обработчиков** (`ПриДобавленииОбработчиковОбновления`). Рабочий образец из БСП
   (`Анкетирование.ПриДобавленииОбработчиковОбновления`):
   ```bsl
   Обработчик = Обработчики.Добавить();
   Обработчик.Версия = "3.1.9.6";
   Обработчик.Идентификатор = Новый УникальныйИдентификатор("a1581723-c1f5-4b90-b716-a180a4d5a4ad"); // сгенерировать один раз и не менять
   Обработчик.Процедура = "ПланыВидовХарактеристик.ВопросыДляАнкетирования.ОбработатьДанныеДляПереходаНаНовуюВерсию";
   Обработчик.Комментарий = НСтр("ru = 'Заполнение значений новых реквизитов ... До завершения обработки вид вопросов будет отображаться некорректно.'");
   Обработчик.РежимВыполнения = "Отложенно";
   Обработчик.ПроцедураЗаполненияДанныхОбновления = "ПланыВидовХарактеристик.ВопросыДляАнкетирования.ЗарегистрироватьДанныеКОбработкеДляПереходаНаНовуюВерсию";
   Обработчик.ПроцедураПроверки  = "ОбновлениеИнформационнойБазы.ДанныеОбновленыНаНовуюВерсиюПрограммы";
   Обработчик.ЧитаемыеОбъекты    = "ПланВидовХарактеристик.ВопросыДляАнкетирования";
   Обработчик.ИзменяемыеОбъекты  = "ПланВидовХарактеристик.ВопросыДляАнкетирования";
   Обработчик.БлокируемыеОбъекты = "ПланВидовХарактеристик.ВопросыДляАнкетирования";
   ```
   Оперативный/монопольный - достаточно `Версия`, `Процедура`, `РежимВыполнения`; процедура может быть без параметров.
   Начальное заполнение: `НачальноеЗаполнение = Истина`, `РежимВыполнения = "Оперативно"`.
   Порядок между отложенными: `Обработчик.ПриоритетыВыполнения = ОбновлениеИнформационнойБазы.ПриоритетыВыполненияОбработчика()`,
   строки с `Порядок` = "До"/"После"/"Любой" и `Процедура` (или `Идентификатор`) другого обработчика.
   `Обработчик.Порядок` - `Перечисления.ПорядокОбработчиковОбновления.Критичный/Обычный/Некритичный`
   (для `Некритичный` свойство `БлокируемыеОбъекты` игнорируется).
4. **Модуль менеджера: пара процедур отложенного обработчика** (образец - `ПланыВидовХарактеристик.ВопросыДляАнкетирования`):
   ```bsl
   // Регистрирует на плане обмена ОбновлениеИнформационнойБазы объекты, которые нужно обновить.
   Процедура ЗарегистрироватьДанныеКОбработкеДляПереходаНаНовуюВерсию(Параметры) Экспорт
       Запрос = Новый Запрос("ВЫБРАТЬ Т.Ссылка ИЗ Справочник.Номенклатура КАК Т ГДЕ Т.НовыйРеквизит = &Пусто");
       Запрос.УстановитьПараметр("Пусто", ...);
       ОбновлениеИнформационнойБазы.ОтметитьКОбработке(Параметры, Запрос.Выполнить().Выгрузить().ВыгрузитьКолонку("Ссылка"));
   КонецПроцедуры

   Процедура ОбработатьДанныеДляПереходаНаНовуюВерсию(Параметры) Экспорт
       ПолноеИмя = "Справочник.Номенклатура";
       Выборка = ОбновлениеИнформационнойБазы.ВыбратьСсылкиДляОбработки(Параметры.Очередь, ПолноеИмя); // порция
       Обработано = 0; Проблемных = 0;
       Пока Выборка.Следующий() Цикл
           Представление = Строка(Выборка.Ссылка);
           НачатьТранзакцию();
           Попытка
               Блокировка = Новый БлокировкаДанных;
               Блокировка.Добавить(ПолноеИмя).УстановитьЗначение("Ссылка", Выборка.Ссылка);
               Блокировка.Заблокировать();
               Объект = Выборка.Ссылка.ПолучитьОбъект();
               Если Объект = Неопределено Тогда            // удален - снять с регистрации
                   ОбновлениеИнформационнойБазы.ОтметитьВыполнениеОбработки(Выборка.Ссылка);
               Иначе
                   Объект.НовыйРеквизит = ...;
                   ОбновлениеИнформационнойБазы.ЗаписатьДанные(Объект); // пишет с ОбменДанными.Загрузка и снимает отметку
               КонецЕсли;
               ЗафиксироватьТранзакцию();
               Обработано = Обработано + 1;
           Исключение
               ОтменитьТранзакцию();
               Проблемных = Проблемных + 1;
               ОбновлениеИнформационнойБазы.ЗаписатьОшибкуВЖурналРегистрации(Выборка.Ссылка, Представление, ИнформацияОбОшибке());
           КонецПопытки;
       КонецЦикла;
       Параметры.ОбработкаЗавершена = ОбновлениеИнформационнойБазы.ОбработкаДанныхЗавершена(Параметры.Очередь, ПолноеИмя);
       Если Обработано = 0 И Проблемных <> 0 Тогда
           ВызватьИсключение НСтр("ru = 'Не удалось обработать некоторые элементы (пропущены)'"); // как в БСП
       КонецЕсли;
   КонецПроцедуры
   ```
   Для документов-регистраторов: `ОтметитьРегистраторыКОбработке(Параметры, Регистраторы, ПолноеИмяРегистра)` +
   `ВыбратьРегистраторыРегистраДляОбработки(Очередь, ПолноеИмяДокумента, ПолноеИмяРегистра)`; для независимого регистра
   сведений - `ДополнительныеПараметрыОтметкиОбработки()` с `ЭтоНезависимыйРегистрСведений = Истина`, `ПолноеИмяРегистра`
   и `ВыбратьИзмеренияНезависимогоРегистраСведенийДляОбработки`.
5. **Многопоточный обработчик** (только при `РежимВыполненияОтложенныхОбработчиков = "Параллельно"`, иначе ошибка
   «включено недопустимое свойство "Многопоточный"»): `Обработчик.Многопоточный = Истина`; в регистрации заполнить
   `Параметры.ПараметрыВыборки` (`ПолныеИменаРегистров`/`ПолныеИменаОбъектов`, `СпособВыборки = ОбновлениеИнформационнойБазы.СпособВыборкиСсылки()`
   / `СпособВыборкиРегистраторыРегистра()` / `СпособВыборкиИзмеренияНезависимогоРегистраСведений()`), а в обработке брать порцию
   через `ОбновлениеИнформационнойБазы.ДанныеДляОбновленияВМногопоточномОбработчике(Параметры)` (образец -
   `РегистрыСведений.ДанныеБизнесПроцессов`). Включить потоки: `ПриОпределенииНастроек` → `МногопоточноеОбновление = Истина`.
6. **Защита форм и объектов, пока данные не обновлены.**
   ```bsl
   // Форма объекта, ПриСозданииНаСервере (как Справочник.ВариантыОтчетов.ФормаЭлемента)
   ОбновлениеИнформационнойБазы.ПроверитьОбъектОбработан(Объект, ЭтотОбъект); // форма станет ТолькоПросмотр
   // Модуль объекта/набора, ПередЗаписью
   ОбновлениеИнформационнойБазы.ПроверитьОбъектОбработан(ЭтотОбъект);          // исключение, если не обработан
   ```
   Это работает только для объектов из `БлокируемыеОбъекты` и при заполненной `ПроцедураПроверки`.
   В коде, который читает «новые» данные: `ОбновлениеИнформационнойБазы.ОбъектОбработан(Данные)` / `МожноЧитатьИМенять`.
7. **Начальное заполнение и предопределенные элементы (декларативно, без кода создания).**
   - В модуле менеджера: `ПриНастройкеНачальногоЗаполненияЭлементов(Настройки)` и
     `ПриНачальномЗаполненииЭлементов(КодыЯзыков, Элементы, ТабличныеЧасти)` (+ при необходимости
     `ПриНачальномЗаполненииЭлемента`), пример - `Справочник.СостоянияОригиналовПервичныхДокументов`:
     ```bsl
     Элемент = Элементы.Добавить();
     Элемент.ИмяПредопределенныхДанных = "ФормаНапечатана";
     Элемент.Наименование = НСтр("ru='Форма напечатана'", ОбщегоНазначения.КодОсновногоЯзыка());
     Элемент.Код = "000000001";
     ```
   - Объект добавить в `ОбновлениеИнформационнойБазыПереопределяемый.ПриОпределенииНастроек` →
     `Параметры.ОбъектыСНачальнымЗаполнением.Добавить(Метаданные.Справочники.Х)`.
   - Изменили поставляемые значения в новой версии - отложенный обработчик (образец `Справочник.РолиИсполнителей`):
     `ЗарегистрироватьПредопределенныеЭлементыДляОбновления(Параметры, Метаданные.Справочники.Х)` в регистрации и
     `ЗаполнитьЭлементыНачальнымиДанными(Параметры, Метаданные.Справочники.Х, ОбновлениеИнформационнойБазы.НастройкиЗаполнения())`
     в обработке. Для оперативного обновления - `ОбновитьПредопределенныеЭлементы(ОбъектМетаданных)`.

### Нумерация версий (правила)
- Формат `Р.П.В.С` из четырех чисел; нулевая версия и неверный формат - ошибка свойства обработчика.
- Новый обработчик = версия **следующей сборки**, и в том же коммите поднять `Описание.Версия` (и `Метаданные.Версия`
  для основной конфигурации) до этого номера. Обработчик с версией ≤ текущей версии ИБ на уже обновленных базах **не выполнится**.
- Нельзя менять `Версия` и `Процедура` у уже выпущенного обработчика; переименование процедуры отложенного обработчика
  допустимо только при сохранении `Идентификатор` (дубли идентификаторов - ошибка «совпадают уникальные идентификаторы»).
- Для доработок типовой (БП/УТ/ERP) - **своя подсистема со своим `Имя` и версией** (п.2), тогда ваши версии не
  конфликтуют с номерами вендора, а версия ИБ вашей доработки хранится отдельно.

**Главные методы API** (подробно - `api/ОбновлениеВерсииИБ.md`):
- `ОбновлениеИнформационнойБазы.НоваяТаблицаОбработчиковОбновления` - описание всех колонок обработчика.
- `ОбновлениеИнформационнойБазы.ОтметитьКОбработке` / `ОтметитьРегистраторыКОбработке` - регистрация данных к обработке.
- `ОбновлениеИнформационнойБазы.ВыбратьСсылкиДляОбработки` / `ВыбратьРегистраторыРегистраДляОбработки` - выборка порции.
- `ОбновлениеИнформационнойБазы.ЗаписатьДанные` / `ЗаписатьОбъект` / `ЗаписатьНаборЗаписей` / `УдалитьДанные` - запись в обработчике.
- `ОбновлениеИнформационнойБазы.ОтметитьВыполнениеОбработки` - снять отметку без записи.
- `ОбновлениеИнформационнойБазы.ОбработкаДанныхЗавершена` - значение для `Параметры.ОбработкаЗавершена`.
- `ОбновлениеИнформационнойБазы.ПроверитьОбъектОбработан` / `ОбъектОбработан` - защита от работы с необновленными данными.
- `ОбновлениеИнформационнойБазы.ЗаписатьОшибкуВЖурналРегистрации` - ошибка по объекту без прерывания обработчика.
- `ОбновлениеИнформационнойБазы.ЗаполнитьЭлементыНачальнымиДанными` / `ОбновитьПредопределенныеЭлементы` - поставляемые элементы.
- `ОбновлениеИнформационнойБазы.ОтложенноеОбновлениеЗавершено`, `ВыполняетсяОбновлениеИнформационнойБазы` - состояние обновления.

**Подводные камни:**
- `Параметры.ОбработкаЗавершена` обязан быть заполнен в каждом вызове отложенного обработчика, иначе
  «Обработчик обновления не инициализировал параметр ОбработкаЗавершена» и прерывание.
- Отложенный обработчик вызывается многократно порциями: никаких «обработать всё за один вызов» и глобальных транзакций;
  транзакция + управляемая блокировка на каждый объект.
- `ЗаписатьДанные`/`ЗаписатьОбъект` по умолчанию пишут с `ОбменДанными.Загрузка = Истина` (бизнес-логика, проведение
  и подписки не работают) и без регистрации на узлах обмена. Нужна логика - `ВключитьБизнесЛогику = Истина` осознанно;
  нужно передать в РИБ - `РегистрироватьНаУзлахПлановОбмена = Истина`.
- `Объект.Записать()` напрямую в отложенном обработчике не снимает объект с регистрации - обработчик зациклится.
- Отложенный обработчик не может иметь `ОбщиеДанные = Истина` и `МонопольныйРежим` (ошибки проверки).
  `ЗапускатьТолькоВГлавномУзле` и `ЗапускатьИВПодчиненномУзлеРИБСФильтрами` одновременно - ошибка.
- Монопольные/оперативные обработчики с большим объемом данных = долгий простой при обновлении. Всё, что
  обрабатывает документы/регистры, - только `"Отложенно"`.
- Пока отложенные обработчики не завершены, нельзя обновляться на следующую версию (сообщение из `ПриОпределенииНастроек`);
  пишите обработчики так, чтобы они гарантированно завершались, а ошибочные объекты логировались и пропускались.
- `ЧитаемыеОбъекты`/`ИзменяемыеОбъекты` используются для построения очередей; неполные списки = гонки между обработчиками.

## РегламентныеЗадания - управление регламентными заданиями и их зависимость от ФО

**Когда использовать:** любое фоновое периодическое действие (загрузка, расчет, очистка). БСП дает: включение/выключение
задания вместе с функциональной опцией, блокировку заданий с внешними ресурсами в копии базы, единый API для
локального режима и очереди заданий в модели сервиса, форму «Регламентные и фоновые задания». Заменяет ручные
`РегламентныеЗадания.НайтиПредопределенное(...)`, проверки «а не копия ли это базы» и самописные флажки.

**Встраивание в свой объект (рецепт):**
1. **Метаданные:** объект «Регламентное задание» с методом в серверном общем модуле (обычно `<Модуль>.<Имя>ОбработчикЗадания`).
   Предопределенное - если задание одно, непредопределенное - если экземпляров несколько (с параметрами/ключом).
2. **Переопределяемые процедуры:** `РегламентныеЗаданияПереопределяемый.ПриОпределенииНастроекРегламентныхЗаданий(Настройки)`:
   ```bsl
   Настройка = Настройки.Добавить();
   Настройка.РегламентноеЗадание = Метаданные.РегламентныеЗадания.ЗагрузкаЗаказовССайта;
   Настройка.ФункциональнаяОпция = Метаданные.ФункциональныеОпции.ИспользоватьИнтеграциюССайтом;
   Настройка.РаботаетСВнешнимиРесурсами = Истина; // модифицирует внешние данные: отключится в копии ИБ
   Настройка.ДоступноВМоделиСервиса = Ложь;
   ```
   `ОбращаетсяКВнешнимРесурсам = Истина` - только читает Интернет-сервисы (как `ЗагрузкаКурсовВалют`).
   Свои механизмы, недопустимые в копии ИБ: `БлокировкаРаботыСВнешнимиРесурсамиПереопределяемый.ПриЗапретеРаботыСВнешнимиРесурсами`
   / `ПриРазрешенииРаботыСВнешнимиРесурсами`.
3. **Обработчик задания** - первой строкой (образец `УправлениеИтогамиИАгрегатамиСлужебный.ОбновлениеАгрегатовОбработчикЗадания`):
   ```bsl
   Процедура ЗагрузкаЗаказовССайтаОбработчикЗадания() Экспорт
       ОбщегоНазначения.ПриНачалеВыполненияРегламентногоЗадания(Метаданные.РегламентныеЗадания.ЗагрузкаЗаказовССайта);
       // ... работа ...
   КонецПроцедуры
   ```
   Это прерывает запуск, если не завершено обновление ИБ, выключена ФО, это копия ИБ для заданий с внешними ресурсами.
   Включение из кода (например, при изменении настройки):
   `РегламентныеЗаданияСервер.УстановитьИспользованиеПредопределенногоРегламентногоЗадания(Метаданные.РегламентныеЗадания.Х, Истина)`.

**Главные методы API** (`api/БазоваяФункциональность.РегламентныеЗаданияСервер.md`, `api/РегламентныеЗадания.md`):
- `РегламентныеЗаданияСервер.НайтиЗадания(Отбор)` - поиск (в сервисе - по очереди заданий).
- `РегламентныеЗаданияСервер.ДобавитьЗадание(Параметры)` / `ИзменитьЗадание` / `УдалитьЗадание` - непредопределенные задания.
- `РегламентныеЗаданияСервер.УстановитьИспользованиеПредопределенногоРегламентногоЗадания` - вкл/выкл предопределенного.
- `РегламентныеЗаданияСервер.УстановитьРасписаниеРегламентногоЗадания` / `РасписаниеРегламентногоЗадания`.
- `РегламентныеЗаданияСервер.ВыполнитьЗадание(Идентификатор, ПараметрыВыполнения)` - запуск вручную в фоне.
- `РегламентныеЗаданияСервер.УстановитьСлужебногоПользователяРегламентногоЗадания` - запуск под пользователем без прав.
- `РегламентныеЗаданияСервер.РаботаСВнешнимиРесурсамиЗаблокирована` - проверка «это копия базы».
- `ОбщегоНазначения.ПриНачалеВыполненияРегламентногоЗадания` - обязательная проверка в начале обработчика.

**Подводные камни:**
- Без `ПриНачалеВыполненияРегламентногоЗадания` задание запускается во время обновления ИБ и в копиях базы
  (двойные отправки писем, обмен из тестовой базы с боевыми системами).
- Обращение к `РегламентныеЗадания.*` платформы напрямую ломает работу в модели сервиса и обходит блокировку
  внешних ресурсов - используйте `РегламентныеЗаданияСервер`.
- Обработчик выполняется без пользователя/с пользователем задания: не полагайтесь на `Пользователи.ТекущийПользователь()`
  и права интерактивного пользователя; привилегированный режим включайте точечно.
- В модели сервиса задания области данных работают через очередь заданий БТС (там разрешенные методы регистрируются
  отдельно - `ПриОпределенииПсевдонимовОбработчиков`); в БСП - только флаг `ДоступноВМоделиСервиса`.

## ДополнительныеОтчетыИОбработки - внешние печатные формы, обработки заполнения и отчеты без изменения конфигурации

**Когда использовать:** нужна печатная форма/обработка заполнения/создание связанных объектов/отчет для **типовой**
конфигурации без снятия с поддержки, или регламентная обработка, которую администратор подключает сам
(справочник `ДополнительныеОтчетыИОбработки`, ФО `ИспользоватьДополнительныеОтчетыИОбработки`). Заменяет
`ВнешниеОбработки.Создать(Путь)` и «обработки на рабочем столе бухгалтера».

**Встраивание - сторона конфигурации:**
1. **Метаданные / подключение объекта.** Внешние печатные формы появляются у объектов, подключенных к подсистеме
   «Печать» (объект в `УправлениеПечатьюПереопределяемый.ПриОпределенииОбъектовСКомандамиПечати`) и выводящих подключаемые
   команды (`ПодключаемыеКоманды.ПриСозданииНаСервере` в форме) - см. рецепты Печати/ПодключаемыхКоманд. Команды
   «Заполнить» и «Создать на основании» из внешних обработок добавляются тем же механизмом подключаемых команд
   (вид команд `ЗаполнениеОбъектов`, общая команда `СозданиеСвязанныхОбъектов`).
2. **Глобальные обработки/отчеты в разделах.** Для каждого раздела, где нужна кнопка «Дополнительные обработки»,
   добавить раздел в `ДополнительныеОтчетыИОбработкиПереопределяемый.ОпределитьРазделыСДополнительнымиОбработками(Разделы)`
   (`Разделы.Добавить(Метаданные.Подсистемы.Продажи)`; начальная страница -
   `ДополнительныеОтчетыИОбработкиКлиентСервер.ИмяНачальнойСтраницы()`), аналогично `ОпределитьРазделыСДополнительнымиОтчетами`,
   и разместить в разделе общую команду по образцу `ОбщиеКоманды.ДополнительныеОбработкиАдминистрирование`:
   ```bsl
   &НаКлиенте
   Процедура ОбработкаКоманды(ПараметрКоманды, ПараметрыВыполненияКоманды)
       ДополнительныеОтчетыИОбработкиКлиент.ОткрытьФормуКомандДополнительныхОтчетовИОбработок(ПараметрКоманды,
           ПараметрыВыполненияКоманды, ДополнительныеОтчетыИОбработкиКлиентСервер.ВидОбработкиДополнительнаяОбработка(), "Продажи");
   КонецПроцедуры
   ```
3. Регламентный запуск глобальных обработок - уже есть задание `ЗапускДополнительныхОбработок`, ничего писать не надо.

**Встраивание - сторона внешней обработки (модуль объекта .epf/.erf):**
```bsl
Функция СведенияОВнешнейОбработке() Экспорт
    ПараметрыРегистрации = ДополнительныеОтчетыИОбработки.СведенияОВнешнейОбработке("3.2.1.541");
    ПараметрыРегистрации.Вид = ДополнительныеОтчетыИОбработкиКлиентСервер.ВидОбработкиПечатнаяФорма();
    ПараметрыРегистрации.Версия = "1.0";
    ПараметрыРегистрации.Назначение.Добавить("Документ.РеализацияТоваровУслуг");
    ПараметрыРегистрации.БезопасныйРежим = Истина;
    Команда = ПараметрыРегистрации.Команды.Добавить();
    Команда.Представление = НСтр("ru = 'Акт сверки (внешний)'");
    Команда.Идентификатор = "АктСверкиВнешний";
    Команда.Использование = ДополнительныеОтчетыИОбработкиКлиентСервер.ТипКомандыВызовСерверногоМетода();
    Команда.Модификатор   = "ПечатьMXL";
    Возврат ПараметрыРегистрации;
КонецФункции

// Обработчик печати (Вид = "ПечатнаяФорма")
Процедура Печать(МассивОбъектов, КоллекцияПечатныхФорм, ОбъектыПечати, ПараметрыВывода) Экспорт
    ПечатнаяФорма = УправлениеПечатью.СведенияОПечатнойФорме(КоллекцияПечатныхФорм, "АктСверкиВнешний");
    Если ПечатнаяФорма <> Неопределено Тогда
        ТабличныйДокумент = Новый ТабличныйДокумент;
        ТабличныйДокумент.КлючПараметровПечати = "АктСверкиВнешний";
        Для Каждого Ссылка Из МассивОбъектов Цикл
            Если ТабличныйДокумент.ВысотаТаблицы > 0 Тогда
                ТабличныйДокумент.ВывестиГоризонтальныйРазделительСтраниц();
            КонецЕсли;
            НачалоОбласти = ТабличныйДокумент.ВысотаТаблицы + 1;
            // ... вывод ...
            УправлениеПечатью.ЗадатьОбластьПечатиДокумента(ТабличныйДокумент, НачалоОбласти, ОбъектыПечати, Ссылка);
        КонецЦикла;
        ПечатнаяФорма.ТабличныйДокумент = ТабличныйДокумент;
    КонецЕсли;
КонецПроцедуры
```
Глобальная обработка/отчет (`ВидОбработкиДополнительнаяОбработка()` / `ВидОбработкиДополнительныйОтчет()`) с серверной
командой: `Процедура ВыполнитьКоманду(ИдентификаторКоманды, ПараметрыВыполнения) Экспорт`. Другие типы команд -
`ТипКомандыОткрытиеФормы()`, `ТипКомандыВызовКлиентскогоМетода()`, `ТипКомандыЗаполнениеФормы()`,
`ТипКомандыЗагрузкаДанныхИзФайла()`; шаблоны обработчиков - в комментариях этих функций.

**Главные методы API** (`api/ДополнительныеОтчетыИОбработки.md`):
- `ДополнительныеОтчетыИОбработки.СведенияОВнешнейОбработке(ВерсияБСП)` - шаблон регистрационных сведений.
- `ДополнительныеОтчетыИОбработкиКлиентСервер.ВидОбработки*` / `ТипКоманды*` - константы видов и типов команд.
- `ДополнительныеОтчетыИОбработки.ВыполнитьКоманду` / `ВыполнитьКомандуИзФормыВнешнегоОбъекта` - выполнение команды на сервере.
- `ДополнительныеОтчетыИОбработкиКлиент.ВыполнитьКомандуВФоне` - длительная команда в фоне.
- `ДополнительныеОтчетыИОбработки.ПодключитьВнешнююОбработку` / `ОбъектВнешнейОбработки` - получить объект по ссылке справочника.
- `ДополнительныеОтчетыИОбработкиКлиент.ОткрытьФормуКомандДополнительныхОтчетовИОбработок` - команда раздела.
- `ДополнительныеОтчетыИОбработки.ПечатьПоВнешнемуИсточнику` - печать внешней формой из кода.

**Подводные камни:**
- `БезопасныйРежим = Истина` по умолчанию: нет COM, файлов (кроме временных), Интернета, внешних компонент,
  привилегированный режим игнорируется. Нужно больше - декларировать `Разрешения` (`РаботаВБезопасномРежиме.Разрешение*`)
  или `БезопасныйРежим = Ложь` (осознанное решение: код обработки получит полные права сеанса; при включенных
  профилях безопасности кластера форма регистрации показывает запрос разрешений).
- `Назначение` - полные имена объектов (`"Документ.Х"`); при опечатке обработка регистрируется, но команды нигде не видно.
- `Идентификатор` печатной команды должен совпадать с именем в `СведенияОПечатнойФорме`, иначе форма пустая.
  Модификатор `"ПечатьMXL"` - для табличных макетов.
- Если у объекта форма не вызывает `ПодключаемыеКоманды.ПриСозданииНаСервере` (самописная форма), внешние
  команды не появятся даже при правильной регистрации.
- Функциональная опция `ИспользоватьДополнительныеОтчетыИОбработки` выключена → команд нет нигде; при вызове
  `ВыполнитьКоманду` из своего кода проверку ФО делает вызывающий.
- Версия в `СведенияОВнешнейОбработке` - «Старший.Младший»; при обновлении файла меняйте версию, чтобы администратор
  видел, что загружена новая.
