## Пользователи - справочники пользователей и внешних пользователей, авторизация, проверка ролей

**Когда использовать:** всегда, когда в объекте нужен «кто» (автор, ответственный, исполнитель), когда код
проверяет права/роли текущего сеанса, создаёт пользователей ИБ программно, или когда http/web-сервис принимает
подключения обычных пользователей. Заменяет: прямую работу с `ПользователиИнформационнойБазы`,
`ПараметрыСеанса.ТекущийПользователь`, `РольДоступна(...)` и самописные справочники «Сотрудники-логины».

**Встраивание в свой объект (рецепт):**
1. Метаданные:
   - реквизит «Автор/Ответственный» - тип `СправочникСсылка.Пользователи` (если допускаются внешние пользователи -
     составной `Пользователи` + `ВнешниеПользователи`).
   - Определяемые типы, которые прикладное решение заполняет своими типами (в поставке БСП это заглушки `Строка`):
     `ФизическоеЛицо`, `Подразделение` (показываются в карточке пользователя), `ВнешнийПользователь` - типы
     объектов авторизации внешних пользователей (на нём построен реквизит `ВнешниеПользователи.ОбъектАвторизации`,
     например `СправочникСсылка.Контрагенты`). `Пользователь` - типы пользователей (в БСП `СправочникСсылка.Пользователи`).
   - В любой профиль/набор ролей обычного пользователя входит роль `БазовыеПраваБСП`
     (для внешних - `БазовыеПраваВнешнихПользователейБСП`).
2. Переопределяемые процедуры (`ПользователиПереопределяемый`):
   - `ПриОпределенииНастроек(Настройки)` - `ОбщиеНастройкиВхода`, `РедактированиеРолей` (обычно Ложь, если роли
     раздаются только профилями УправлениеДоступом), `ФизическоеЛицоИспользуется`, `ПодразделениеИспользуется`.
   - `ПриОпределенииНазначенияРолей(НазначениеРолей)` - разметить свои роли:
     `НазначениеРолей.ТолькоДляВнешнихПользователей.Добавить("ЧтениеЗаказовКлиентаВнешнимПользователем");`
     (массивы `ТолькоДляАдминистраторовСистемы`, `ТолькоДляПользователейСистемы`,
     `ТолькоДляВнешнихПользователей`, `СовместноДляПользователейИВнешнихПользователей`).
   - `ИзменитьДействияВФорме` - скрыть/запретить роли, КИ, свойства пользователя ИБ в карточке.
   - `ПриЗаписиПользователяИнформационнойБазы` / `ПослеУдаленияПользователяИнформационнойБазы` - синхронизация своих регистров.
   - `ПриУстановкеНачальныхНастроек` - начальный интерфейс для новых пользователей.
   - `ПриОпределенииНастроекРегистрацииСобытийДоступаКДанным` - свои поля для события «Доступ.Доступ».
3. Модуль объекта / формы:
   ```bsl
   // Модуль объекта документа: автозаполнение ответственного
   Процедура ОбработкаЗаполнения(ДанныеЗаполнения, ТекстЗаполнения, СтандартнаяОбработка)
       Если Не ЗначениеЗаполнено(Ответственный) Тогда
           Ответственный = Пользователи.ТекущийПользователь(); // исключение в сеансе внешнего пользователя
       КонецЕсли;
   КонецПроцедуры
   ```
   ```bsl
   // HTTP-сервис для обычных пользователей: в начале каждого обработчика
   Функция ЗаказыGET(Запрос)
       Пользователи.АвторизоватьТекущегоПользователяПриВходе(); // проверка ограничений входа + параметры сеанса
       ...
   ```

**Главные методы API** ([api/Пользователи.md](api/Пользователи.md)):
- `Пользователи.ТекущийПользователь()` - текущий пользователь; в сеансе внешнего пользователя вызывает исключение.
- `Пользователи.АвторизованныйПользователь()` - пользователь или внешний пользователь (код, поддерживающий оба).
- `Пользователи.ЭтоПолноправныйПользователь(Пользователь, ПроверятьПраваАдминистрированияСистемы, УчитыватьПривилегированныйРежим)`.
- `Пользователи.РолиДоступны(ИменаРолей, Пользователь, УчитыватьПривилегированныйРежим)` - хотя бы одна роль из списка
  (через запятую) или полноправность; вместо платформенного `РольДоступна`.
- `Пользователи.ЭтоСеансВнешнегоПользователя()`, `ВнешниеПользователи.ТекущийВнешнийПользователь()`,
  `ВнешниеПользователи.ПолучитьОбъектАвторизацииВнешнегоПользователя()`.
- `Пользователи.АвторизоватьТекущегоПользователяПриВходе(ВызыватьИсключение)` - для http/web-сервисов, COM.
- `Пользователи.НовоеОписаниеПользователяИБ()` + `Пользователи.УстановитьСвойстваПользователяИБ(...)` /
  `Пользователи.СвойстваПользователяИБ(...)` / `Пользователи.УдалитьПользователяИБ(...)` - программная работа с пользователями ИБ.
- `Пользователи.НайтиПоИмени(ИмяДляВхода)`, `Пользователи.НайтиПоСсылке(Пользователь)`.
- `Пользователи.СоздатьАдминистратора()` - при начальном заполнении ИБ.
- `ПользователиКлиент.ТекущийПользователь()`, `ПользователиКлиент.ЭтоПолноправныйПользователь()` - то же на клиенте без серверного вызова.

**Подводные камни:**
- `ТекущийПользователь()` падает под внешним пользователем - в общем коде (печать, файлы, заметки) использовать
  `АвторизованныйПользователь()`.
- Не создавать/менять `ПользователиИнформационнойБазы` напрямую: запись справочника `Пользователи` сама
  синхронизирует пользователя ИБ, роли выдаёт подсистема УправлениеДоступом по группам доступа. Роли, назначенные
  руками в Конфигураторе, будут перезаписаны при `УправлениеДоступом.ОбновитьРолиПользователей`.
- `РолиДоступны` с `УчитыватьПривилегированныйРежим = Истина` (по умолчанию) вернёт Истина в привилегированном
  режиме - для проверки «настоящих» прав в фоновых/привилегированных участках передавать Ложь.
- В http-сервисах без `АвторизоватьТекущегоПользователяПриВходе` не заполнены параметры сеанса
  `ТекущийПользователь`/`АвторизованныйПользователь` - RLS и `ТекущийПользователь()` работают некорректно.

## УправлениеДоступом - профили, группы доступа и ограничение доступа на уровне записей (RLS)

**Когда использовать:** любые требования «пользователь видит/меняет только свои организации/склады/контрагентов/
документы, где он ответственный», выдача ролей через профили вместо ручного назначения, проверка права
на конкретный объект из кода. Заменяет: самописные шаблоны RLS в ролях, параметры сеанса «РазрешенныеОрганизации»,
отборы в формах списков «для безопасности» и проверки в `ПередЗаписью`.

### Модель: профили, группы доступа, виды доступа
- **Роли** конфигурации пользователю напрямую не назначаются. **Профиль группы доступа** (`Справочник.ПрофилиГруппДоступа`) =
  набор ролей + список видов доступа. **Группа доступа** (`Справочник.ГруппыДоступа`) = профиль + участники
  (пользователи/группы) + разрешённые значения по видам доступа. Роли пользователя ИБ = объединение ролей профилей его групп.
- **Вид доступа** - разрез ограничения (Организации, Склады, ГруппыНоменклатуры). Описывается в
  `ПриЗаполненииВидовДоступа`; предопределены `Пользователи`, `ВнешниеПользователи`; литерал `Объект` - «по правам на другой объект».
- **Режимы вида в профиле:** `ВначалеВсеЗапрещены` (по умолчанию), `ВначалеВсеРазрешены`, `Предустановленный`
  (значения задаются в профиле, а не в группе).
- Включение RLS - константа `ОграничиватьДоступНаУровнеЗаписей` (панель администрирования), вариант -
  `ОграничиватьДоступНаУровнеЗаписейУниверсально`.

### Два варианта RLS: универсальный (производительный) и стандартный
| | Универсальный (производительный), основной в 3.x | Стандартный (устаревающий) |
|---|---|---|
| Где логика | текст ограничения в модуле менеджера (`ПриЗаполненииОграниченияДоступа`) | процедура `ЗаполнитьНаборыЗначенийДоступа` в модуле объекта |
| Что в роли | `#ДляОбъекта("")` / `#ДляРегистра(...)` | `#ПоЗначениям...` / `#ПоНаборамЗначений` / `#ПоЗначениямИНаборамРасширенный` |
| Хранение | ключи доступа (`РегистрСведений.КлючиДоступаКОбъектам`, `КлючиДоступаКРегистрам`, `КлючиДоступаГруппДоступа`...) | `РегистрСведений.НаборыЗначенийДоступа` |
| Обновление | регламентные `ОбновлениеДоступаНаУровнеЗаписей`, `ЗаполнениеДанныхДляОграниченияДоступа` | при записи объекта |

В ролях БСП обе ветки пишутся вместе:
```
#Если &ОграничениеДоступаНаУровнеЗаписейУниверсально #Тогда
#ДляОбъекта("")
#Иначе
#ПоЗначениямРасширенный( "Документ.ЗаказКлиента", "", "", "", "", "Организации","Т.Организация","И", ... )
#КонецЕсли
```
`ПриОпределенииНастроек`: `Настройки.СтандартныйВариант = Ложь` - разрешено оставить в ролях только `#ДляОбъекта/#ДляРегистра`
(менять только на этапе разработки); `Настройки.ОграничениеНаУровнеЗаписей = Ложь` - RLS выключен полностью
(нельзя вычислять по данным ИБ, только по метаданным). **Новые объекты делать только под универсальный вариант**;
стандартную ветку добавлять, если конфигурация ещё поддерживает переключение на стандартный вариант.

### Рецепт А. Ограничить свой документ или справочник (универсальный вариант)
Пример: `Документ.ЗаказКлиента` - чтение/изменение по `Организация` и `Склад`.

1. **Вид доступа** (если ещё нет) в `УправлениеДоступомПереопределяемый.ПриЗаполненииВидовДоступа`:
   ```bsl
   ВидДоступа = ВидыДоступа.Добавить();
   ВидДоступа.Имя           = "Склады";
   ВидДоступа.Представление = НСтр("ru = 'Склады'");
   ВидДоступа.ТипЗначений   = Тип("СправочникСсылка.Склады");
   // ВидДоступа.ТипГруппЗначений = Тип("СправочникСсылка.ГруппыДоступаСкладов"); // если значения раздаются группами
   ```
   Тип значений (и тип групп) добавить в **определяемый тип `ЗначениеДоступа`**. Если у значения есть группы значений
   доступа/иерархия - объектный тип (`СправочникОбъект.Склады`) в **`ЗначениеДоступаОбъект`** (на нём подписки
   `ОбновитьГруппыЗначенийДоступаПередЗаписью`/`...ПриЗаписи`); при нехватке типа БСП при запуске вызывает
   исключение с их перечнем. Использование вида от функциональной опции - `ПриЗаполненииИспользованияВидаДоступа`.
2. **Зарегистрировать список** в `ПриЗаполненииСписковСОграничениемДоступа`:
   `Списки.Вставить(Метаданные.Документы.ЗаказКлиента, Истина);` (Истина = текст в модуле менеджера;
   Ложь = текст в `УправлениеДоступомПереопределяемый.ПриЗаполненииОграниченияДоступа(Список, Ограничение)` - так
   переопределяют ограничение чужого/типового объекта без снятия с поддержки).
3. **Текст ограничения** в модуле менеджера:
   ```bsl
   #Область ДляВызоваИзДругихПодсистем
   // СтандартныеПодсистемы.УправлениеДоступом

   // Параметры:
   //   Ограничение - см. УправлениеДоступомПереопределяемый.ПриЗаполненииОграниченияДоступа.Ограничение.
   Процедура ПриЗаполненииОграниченияДоступа(Ограничение) Экспорт
       Ограничение.Текст =
       "РазрешитьЧтениеИзменение
       |ГДЕ
       |    ЗначениеРазрешено(Организация)
       |    И ЗначениеРазрешено(Склад)";
       // Ограничение.ТекстДляВнешнихПользователей = "..."; // пусто = внешним доступ запрещён
   КонецПроцедуры

   // Конец СтандартныеПодсистемы.УправлениеДоступом
   #КонецОбласти
   ```
4. **Определяемые типы владельцев ключей доступа** (на них построены подписки `ПроверитьДоступПередЗаписью*`,
   `ПроверитьДоступПриЗаписи*`, `ПроверитьДоступПередУдалением*`):
   - `ВладелецЗначенийКлючейДоступа` - ссылочный тип (`ДокументСсылка.ЗаказКлиента`);
   - документ - `ВладелецЗначенийКлючейДоступаДокумент` (`ДокументОбъект.ЗаказКлиента`);
     справочник/ПВХ/БП/задача и т.п. - `ВладелецЗначенийКлючейДоступаОбъект`;
   - типы полей, по которым ограничиваете (Организации, Склады), - в `ЗначениеДоступа` (п.1).
   Точный список недостающих типов выдаёт `УправлениеДоступомСлужебный.РезультатПроверкиОграниченияДоступа(ПолноеИмя)`
   (свойства `ВладелецЗначенийКлючейДоступа*`, `ЗначениеДоступа`, `ПолеРегистраКлючейДоступаКРегистрам`)
   и внешний отчёт ПроверкаВнедренияБСП.erf (упоминается в комментариях БСП).
5. **Роли.** Во **все** роли, где у объекта есть право Чтение/Изменение/Добавление/Удаление, на каждое право
   поставить ограничение:
   ```
   #Если &ОграничениеДоступаНаУровнеЗаписейУниверсально #Тогда
   #ДляОбъекта("")
   #Иначе
   ГДЕ ЛОЖЬ        // или стандартный шаблон, если поддерживаете стандартный вариант
   #КонецЕсли
   ```
   и скопировать в роль шаблоны ограничения `ДляОбъекта(ПолеОбъекта)` (и `ДляРегистра(...)` при необходимости) из
   роли **`ИзменениеУчастниковГруппДоступа`** - это эталон актуальной версии (иначе в сеансе ошибка
   «Используется устаревшая версия ... шаблона ограничения доступа ДляОбъекта»).
   Для подчинённых объектов, ограничиваемых по владельцу, - `#ДляОбъекта("Владелец")` / `#ДляОбъекта("БизнесПроцесс")`.
6. **Отчёт «Права доступа».** В `ПриЗаполненииВидовОграниченийПравОбъектовМетаданных` дописать строки
   `"Документ.ЗаказКлиента.Чтение.Организации"`, `"...Изменение.Склады"` и т.д. (иначе отчёт показывает неверно).
7. **Формы** - см. раздел «Формы...» ниже (`ПриЧтенииНаСервере`, `ПослеЗаписиНаСервере`).
8. **Запросы:** в прикладных запросах к ограниченным таблицам - `ВЫБРАТЬ РАЗРЕШЕННЫЕ`;
   `ОбщегоНазначения.ЗначенияРеквизитовОбъекта(Ссылка, "...", Истина)` - параметр `ВыбратьРазрешенные`.
9. **Обновление:** после изменения текста ограничения БСП сама планирует пересчёт ключей при обновлении ИБ.
   Для типовых решений, где RLS включается впервые, - `УправлениеДоступом.ДобавитьОбработчикОбновленияДляВключенияУниверсальногоОграничения`
   (только в конечных решениях, не в библиотеках).

### Рецепт Б. Ограничить регистр
```bsl
// Модуль менеджера регистра сведений ЦеныПоставщиков
Процедура ПриЗаполненииОграниченияДоступа(Ограничение) Экспорт
    Ограничение.Текст =
    "РазрешитьЧтениеИзменение
    |ГДЕ
    |    ЗначениеРазрешено(Поставщик)";
КонецПроцедуры
```
Роль: `#ДляРегистра("ИдентификаторыОбъектовМетаданных.РегистрСведенийЦеныПоставщиков", "Поставщик", "", "", "", "")`
(до 5 опорных полей регистра). Нужно:
- предопределённый элемент `РегистрСведенийЦеныПоставщиков` в `Справочник.ИдентификаторыОбъектовМетаданных`
  (для расширений - `ИдентификаторыОбъектовРасширений`);
- набор записей - в `ВладелецЗначенийКлючейДоступаНаборЗаписей` (регистр расчета - `...НаборЗаписейРегистраРасчета`);
- типы опорных полей - в `ПолеРегистраКлючейДоступаКРегистрам` (измерения `Поле1..ПолеN` регистра `КлючиДоступаКРегистрам`).
- Если опорных полей больше, чем в общем регистре, или типы конфликтуют - создать отдельный регистр сведений
  `КлючиДоступаКРегистру<ИмяРегистра>` (копия `КлючиДоступаКРегиструРезультатыПроверкиУчета`) и в роли указать его:
  `#ДляРегистра("КлючиДоступаКРегиструЦеныПоставщиков", "Поставщик", ...)`.
- Регистры, полностью зависящие от объекта, ограничивать через него:
  `ЧтениеОбъектаРазрешено(Объект)` + `Ограничение.ПоВладельцуБезЗаписиКлючейДоступа = Истина` (как `РегистрСведений.ВерсииОбъектов`).

### Язык ограничений доступа
Ключевые слова (из словаря `УправлениеДоступомСлужебный`):
- Инструкции: `РазрешитьЧтениеИзменение`, `РазрешитьЧтение` + `;` + `РазрешитьИзменениеЕслиРазрешеноЧтение`,
  `ПрисоединитьДополнительныеТаблицы ЭтотСписок КАК ... ЛЕВОЕ СОЕДИНЕНИЕ ... ПО ...`.
- Функции: `ЗначениеРазрешено(Поле)`, `ЭтоАвторизованныйПользователь(Поле)`, `ЧтениеОбъектаРазрешено(Поле)`,
  `ИзменениеОбъектаРазрешено(Поле)`, `ЧтениеСпискаРазрешено(Поле)`, `ИзменениеСпискаРазрешено(Поле)`,
  `ДляВсехСтрок(...)`, `ДляОднойИзСтрок(...)` (условия по табличной части), `ПравоДоступа(...)`, `РольДоступна(...)`,
  `ТипЗначения(Поле) = Тип(Справочник.X)`, `ВЫРАЗИТЬ(Поле КАК Справочник.X)`, `ВЫБОР КОГДА ... КОНЕЦ`, `ЕстьNull`.
- Уточнения сравнения внутри функций: `ПустаяСсылка КАК Истина|Ложь`, `Отключено КАК Ложь`, `Неопределено КАК ...`, `Null КАК ...`.
  По коду БСП: значение `Null`/`Неопределено` по умолчанию даёт Ложь; если вид доступа не используется в группе
  доступа - Истина. Поэтому в условиях через `ИЛИ` пишут `Отключено КАК Ложь`, иначе отключённый вид откроет всё.

Примеры из БСП:
```
// Документ.Встреча - автор или ответственный
"РазрешитьЧтениеИзменение
|ГДЕ
|    ЗначениеРазрешено(Ответственный, Отключено КАК Ложь)
|    ИЛИ ЗначениеРазрешено(Автор, Отключено КАК Ложь)"

// Справочник.Заметки - только свои
"РазрешитьЧтениеИзменение ГДЕ ЭтоАвторизованныйПользователь(Автор)"

// Справочник.Файлы - чтение по владельцу, изменение по праву изменения владельца
"РазрешитьЧтение
|ГДЕ
|    ЧтениеОбъектаРазрешено(ВладелецФайла)
|;
|РазрешитьИзменениеЕслиРазрешеноЧтение
|ГДЕ
|    ИзменениеОбъектаРазрешено(ВладелецФайла)"

// Задача.ЗадачаИсполнителя - присоединение регистра
"ПрисоединитьДополнительныеТаблицы
|ЭтотСписок КАК ЗадачаИсполнителя
|ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.ИсполнителиЗадач КАК ИсполнителиЗадач
|ПО ЗадачаИсполнителя.РольИсполнителя = ИсполнителиЗадач.РольИсполнителя
|;
|РазрешитьЧтение
|ГДЕ ЗначениеРазрешено(Исполнитель) ИЛИ ЗначениеРазрешено(ИсполнителиЗадач.Исполнитель)
|    ИЛИ ЧтениеОбъектаРазрешено(БизнесПроцесс)
|;
|РазрешитьИзменениеЕслиРазрешеноЧтение
|ГДЕ ЗначениеРазрешено(Исполнитель)"
```
Свойства `Ограничение`: `Текст`, `ТекстДляВнешнихПользователей` (пусто = внешним запрещено; для обычных пусто = разрешено),
`ПоВладельцуБезЗаписиКлючейДоступа` (Истина - не писать свои ключи, брать ключи владельца; только если ограничение
строго по одному полю-владельцу), `ПоВладельцуБезЗаписиКлючейДоступаДляВнешнихПользователей`.
Зависимость «подчинённый от ведущего» с нестандартной проверкой (изменение подчинённого по праву *чтения* ведущего) -
`ПриЗаполненииЗависимостейПравДоступа`.

### Рецепт В. Стандартный вариант: наборы значений доступа
Нужен, только если конфигурация поддерживает стандартный вариант или объект ограничивается по «Объект» в стандартных шаблонах.
1. Типы: `ВладелецНаборовЗначенийДоступаОбъект` (подписка `ЗаписатьНаборыЗначенийДоступа`, ПриЗаписи);
   для объектов, на чьи наборы ссылаются другие, - `ВладелецВнешнихЗначенийВНаборахЗначенийДоступаОбъект`
   (`ЗаписатьЗависимыеНаборыЗначенийДоступа`); для объектов с табличной частью `НаборыЗначенийДоступа`, которая
   должна заполняться перед записью, - `ВладелецСОграничениемПоНаборамЗначенийДоступаОбъект` / `...Документ`
   (подписки `ЗаполнитьНаборыЗначенийДоступаТабличныхЧастей*`).
2. В модуле объекта (образец из комментария к `УправлениеДоступом.ЗаполнитьНаборыЗначенийДоступа`):
   ```bsl
   // См. УправлениеДоступом.ЗаполнитьНаборыЗначенийДоступа.
   Процедура ЗаполнитьНаборыЗначенийДоступа(Таблица) Экспорт
       // Чтение: Организация. Изменение: Организация И Ответственный.
       Строка = Таблица.Добавить();
       Строка.НомерНабора     = 1;
       Строка.Чтение          = Истина;
       Строка.ЗначениеДоступа = Организация;

       Строка = Таблица.Добавить();
       Строка.НомерНабора     = 2;
       Строка.Изменение       = Истина;
       Строка.ЗначениеДоступа = Организация;
       Строка = Таблица.Добавить();
       Строка.НомерНабора     = 2;
       Строка.ЗначениеДоступа = Ответственный;
   КонецПроцедуры
   ```
   Строки одного `НомерНабора` объединяются по И, разные наборы - по ИЛИ. `ВидДоступа` заполнять не надо
   (кроме спец. `ПравоЧтения`/`ПравоИзменения`); колонку `Уточнение` не трогать.
3. Роль: `#ПоЗначениямИНаборамРасширенный( "Документ.X", "", "", "", "", "Объект","Т.Ссылка","", ...)`.
4. `ПриИзмененииНаборовЗначенийДоступа(Ссылка, СсылкиНаЗависимыеОбъекты)` - перезапись зависимых наборов.

### Рецепт Г. Поставляемые профили групп доступа
`УправлениеДоступомПереопределяемый.ПриЗаполненииПоставляемыхПрофилейГруппДоступа(ОписанияПрофилей, ПараметрыОбновления)`:
```bsl
ОписаниеПрофиля = УправлениеДоступом.НовоеОписаниеПрофиляГруппДоступа();
ОписаниеПрофиля.Имя           = "МенеджерПоПродажам";
ОписаниеПрофиля.Идентификатор = "75fa0ecb-98aa-11df-b54f-e0cb4ed5f655"; // GUID ссылки, созданной в 1С:Предприятии
ОписаниеПрофиля.Наименование  = НСтр("ru = 'Менеджер по продажам'", ОбщегоНазначения.КодОсновногоЯзыка());
ОписаниеПрофиля.Роли.Добавить("ЗапускТонкогоКлиента");
ОписаниеПрофиля.Роли.Добавить("ЗапускВебКлиента");
ОписаниеПрофиля.Роли.Добавить("БазовыеПраваБСП");
ОписаниеПрофиля.Роли.Добавить("ДобавлениеИзменениеЗаказовКлиентов");
ОписаниеПрофиля.ВидыДоступа.Добавить("Организации");
ОписаниеПрофиля.ВидыДоступа.Добавить("Склады", "ВначалеВсеРазрешены");
ОписанияПрофилей.Добавить(ОписаниеПрофиля);
```
- Папки профилей - `УправлениеДоступом.НовоеОписаниеПапкиПрофилейГруппДоступа()` + `ОписаниеПрофиля.Родитель`.
- Для внешних пользователей - заполнить `ОписаниеПрофиля.Назначение` типами из `Метаданные.ОпределяемыеТипы.ВнешнийПользователь`.
- `ПараметрыОбновления.ЗапретитьИзменениеПрофилей = Ложь` - разрешить администратору править поставляемые профили.
- Переименовали/удалили роль - `УправлениеДоступом.ЗаменитьРолиВПрофилях(...)` в обработчике обновления
  (поставляемые профили обновятся сами, непоставляемые - нет).
- Программно: `УправлениеДоступом.ВключитьПрофильПользователю(Пользователь, "МенеджерПоПродажам")` /
  `ВыключитьПрофильПользователю` - **только для упрощённой настройки прав** (персональные группы доступа,
  `ПриОпределенииИнтерфейсаНастройкиДоступа`); в обычном интерфейсе - добавить пользователя в табличную часть `Пользователи` нужного элемента
  `Справочник.ГруппыДоступа` (`УстановитьПраваПользователя` размечена в коде как API для ТехнологииСервиса). Также `ПоставляемыйПрофильПоИдентификатору`, `ПрофильАдминистратор()`,
  `ГруппаДоступаАдминистраторы()`, `ИзменитьСоставАдминистраторов(...)`.

### Формы, проверки прав в коде, массовая запись
Формы элементов ограничиваемых объектов (как в `Справочник.ПапкиФайлов.ФормаЭлемента`):
```bsl
&НаСервере
Процедура ПриЧтенииНаСервере(ТекущийОбъект)
    // СтандартныеПодсистемы.УправлениеДоступом
    Если ОбщегоНазначения.ПодсистемаСуществует("СтандартныеПодсистемы.УправлениеДоступом") Тогда
        МодульУправлениеДоступом = ОбщегоНазначения.ОбщийМодуль("УправлениеДоступом");
        МодульУправлениеДоступом.ПриЧтенииНаСервере(ЭтотОбъект, ТекущийОбъект); // ТолькоПросмотр, если изменение запрещено
    КонецЕсли;
    // Конец СтандартныеПодсистемы.УправлениеДоступом
КонецПроцедуры

&НаСервере
Процедура ПослеЗаписиНаСервере(ТекущийОбъект, ПараметрыЗаписи)
    // СтандартныеПодсистемы.УправлениеДоступом
    Если ОбщегоНазначения.ПодсистемаСуществует("СтандартныеПодсистемы.УправлениеДоступом") Тогда
        МодульУправлениеДоступом = ОбщегоНазначения.ОбщийМодуль("УправлениеДоступом");
        МодульУправлениеДоступом.ПослеЗаписиНаСервере(ЭтотОбъект, ТекущийОбъект, ПараметрыЗаписи); // ускоряет обновление доступа
    КонецЕсли;
    // Конец СтандартныеПодсистемы.УправлениеДоступом
КонецПроцедуры
```
В своей конфигурации (не библиотеке) можно вызывать `УправлениеДоступом.ПриЧтенииНаСервере(...)` напрямую.
Форма значения доступа с группами (реквизит `ГруппаДоступа`) - `УправлениеДоступом.ПриСозданииФормыЗначенияДоступа(ЭтотОбъект)`
в `ПриСозданииНаСервере`.

Массовая запись (загрузка, обработки) - отключить обновление ключей и включить в конце:
```bsl
УправлениеДоступом.ОтключитьОбновлениеКлючейДоступа(Истина); // только полноправный или привилегированный режим
Попытка
    // запись набора объектов
    УправлениеДоступом.ОтключитьОбновлениеКлючейДоступа(Ложь);
Исключение
    УправлениеДоступом.ОтключитьОбновлениеКлючейДоступа(Ложь); // в транзакции: (Ложь, Ложь) после ОтменитьТранзакцию()
    ВызватьИсключение;
КонецПопытки;
```

**Главные методы API** ([api/УправлениеДоступом.md](api/УправлениеДоступом.md)):
- `УправлениеДоступом.ЧтениеРазрешено(ОписаниеДанных, Пользователь)` / `ИзменениеРазрешено(...)` - право на конкретный
  объект/ключ записи/набор с учётом RLS; `ПроверитьЧтениеРазрешено` / `ПроверитьИзменениеРазрешено` - то же с исключением.
- `УправлениеДоступом.ЕстьРоль(Роль, СсылкаНаОбъект, Пользователь)` - роль в профилях групп, дающих доступ к объекту
  («может ли этот менеджер согласовать заказ этой организации»).
- `УправлениеДоступом.ЕстьПраво(Право, СсылкаНаОбъект, Пользователь)` - права из настроек прав объектов (папки файлов и т.п.).
- `УправлениеДоступом.ПраваДоступаКДанным(ОписаниеДанных, ...)` - кто из пользователей может читать/менять данные.
- `УправлениеДоступом.ОграничиватьДоступНаУровнеЗаписей()`, `УправлениеДоступом.ПроизводительныйВариант()`.
- `УправлениеДоступом.ПриЧтенииНаСервере(Форма, ТекущийОбъект)`, `УправлениеДоступом.ПослеЗаписиНаСервере(...)`.
- `УправлениеДоступом.ОтключитьОбновлениеКлючейДоступа(Отключить, ПланироватьОбновление)`.
- `УправлениеДоступом.ЗапланироватьОбновлениеДоступа(Таблица)` + `ЗапуститьОбновлениеДоступа()` - ручная актуализация
  ключей, если данные, от которых зависит ограничение, изменены в обход стандартной записи.
- `УправлениеДоступом.НастроитьОтборыДинамическогоСписка(Список, ОписаниеОтборов)` /
  `РазрешенныеЗначенияДляДинамическогоСписка(...)` - ускорение тяжёлых списков отбором по разрешённым значениям.
- `УправлениеДоступом.НовоеОписаниеПрофиляГруппДоступа()`, `ВключитьПрофильПользователю`, `ЗаменитьРолиВПрофилях`.
- `УправлениеДоступом.ЗаполнитьНаборыЗначенийДоступа(Объект, Таблица)`, `ТаблицаНаборыЗначенийДоступа()`,
  `ДобавитьНаборыЗначенийДоступа(...)` - стандартный вариант.

**Подводные камни:**
- Ограничение только в роли без регистрации в `ПриЗаполненииСписковСОграничениемДоступа` и без процедуры в модуле
  менеджера - ошибка «Требуется актуализировать ограничение доступа»/«Не удалось определить вариант ограничения...».
- Шаблоны в роли - копировать из роли `ИзменениеУчастниковГруппДоступа` при каждом обновлении БСП; устаревшая версия
  шаблона ломает чтение таблицы у всех пользователей, кроме полноправных.
- Проверка `Добавление/Изменение/Удаление` в универсальном варианте выполняется подписками `ПередЗаписью/ПриЗаписи`
  (в роли для этих прав шаблон даёт `ГДЕ ИСТИНА`) - объект, не включённый в определяемые типы `ВладелецЗначенийКлючейДоступа*`,
  записывается без проверки.
- Привилегированный режим отключает RLS: в `УстановитьПривилегированныйРежим(Истина)` не отдавать данные на клиент
  без явной проверки `ЧтениеРазрешено`. Для обычных запросов - `ВЫБРАТЬ РАЗРЕШЕННЫЕ`, иначе «Недостаточно прав».
- `ОбменДанными.Загрузка = Истина` не отменяет пересчёт ключей - массовую загрузку оборачивать в `ОтключитьОбновлениеКлючейДоступа`.
- Текст ограничения не может зависеть от данных ИБ/функциональных опций напрямую - использовать
  `ПриЗаполненииИспользованияВидаДоступа` или `ЗначениеРазрешено(..., Отключено КАК ...)`.
- Файловая ИБ: при программной записи настроек доступа/новых объектов в длинных транзакциях -
  `УправлениеДоступом.УстановитьБлокировкуПередЗаписьюВФайловойИБ` (предотвращение взаимоблокировок).
- `ПриЗаполненииВидовОграниченийПравОбъектовМетаданных` - только для отчёта «Права доступа», на сам доступ не влияет;
  но если не заполнить - отчёт показывает неправду, а аудиторы доверяют ему.
- SaaS: профили синхронизируются с Менеджером сервиса (`ОбновитьПрофильГруппДоступаПоШаблону` и пр.) - в локальных внедрениях не вызывать.
