Область применения - управляемое, мобильное и обычное приложение, если не указано иное.

### std773 Использование признака ОбменДанными.Загрузка в обработчиках событий объекта - [its](https://its.1c.ru/db/v8std/content/773/hdoc)
Стандарт
- В ПередЗаписью, ПриЗаписи, ПередУдалением любые действия выполнять только после проверки ОбменДанными.Загрузка
  (при Истина - сразу Возврат). Бизнес-логика уже отработала в узле-источнике, данные грузятся «как есть».
- Общий принцип: любой универсальный механизм должен суметь записать объект с Загрузка = Истина так, будто
  обработчиков нет (например, загрузка всей базы из XML) - без проверок, дозаполнения, побочных действий.
- Исключение: регистрация изменений к выгрузке на другие узлы при загрузке. Чтобы отключить и ее при использовании
  БСП «Обмен данными», ставить ДополнительныеСвойства.ОтключитьМеханизмРегистрацииОбъектов. Любое другое исключение
  обосновывать комментарием в коде.
- То же действует для обработчиков подписок на эти события.
- Код, выставляющий Загрузка = Истина, отвечает за целостность объекта. При загрузке по правилам конвертации или
  EnterpriseData дозаполнять объект сам; такую логику класть в экспортные процедуры модуля объекта.
```bsl
Процедура ПередЗаписью(Отказ)
	Если ОбменДанными.Загрузка Тогда
		Возврат;
	КонецЕсли;
	// проверки и дозаполнение
КонецПроцедуры

// запись "как есть" без регистрации к обмену (БСП)
Объект.ОбменДанными.Загрузка = Истина;
Объект.ДополнительныеСвойства.Вставить("ОтключитьМеханизмРегистрацииОбъектов");
Объект.Записать();
```

### std396 Обработчик события ОбработкаЗаполнения - [its](https://its.1c.ru/db/v8std/content/396/hdoc)
Стандарт (п.1-2), Рекомендация (п.3)
- Ограничения «Создать на основании» проверять в ОбработкаЗаполнения модуля объекта (набора записей): например,
  запрет ввода на основании группы справочника/ПВХ или непроведенного документа.
- Причину отказа сообщать через ВызватьИсключение. Не делать для этого собственных команд ввода на основании с
  проверками в их обработчиках.
- Рекомендуемая структура обработчика (шаги можно пропускать):
  1. Специальное заполнение по типу ДанныеЗаполнения (Структура - по отбору; ссылка на документ - на основании).
  2. Общее заполнение по умолчанию - только незаполненных реквизитов (проверять ЗначениеЗаполнено).
- Где можно, использовать свойство метаданных «Значение заполнения»: платформа подставит его после обработчика,
  если СтандартнаяОбработка = Истина и реквизит остался пустым.
```bsl
Процедура ОбработкаЗаполнения(ДанныеЗаполнения, ТекстЗаполнения, СтандартнаяОбработка)
	Если ТипЗнч(ДанныеЗаполнения) = Тип("ДокументСсылка.ЗаказПоставщику") Тогда
		Если Не ОбщегоНазначения.ЗначениеРеквизитаОбъекта(ДанныеЗаполнения, "Проведен") Тогда
			ВызватьИсключение НСтр("ru = 'Ввод на основании непроведенного заказа невозможен.'");
		КонецЕсли;
		ЗаполнитьПоЗаказу(ДанныеЗаполнения);
	КонецЕсли;
	Если Не ЗначениеЗаполнено(Склад) Тогда
		Склад = ЗначенияПоУмолчаниюПовтИсп.ОсновнойСклад();
	КонецЕсли;
КонецПроцедуры
```

### std463 Обработчик события ОбработкаПроверкиЗаполнения - [its](https://its.1c.ru/db/v8std/content/463/hdoc)
Стандарт (п.1.4 - рекомендация)
- Использовать, когда простой проверки на заполненность мало: значение зависит от другого реквизита, или
  обязательность условная.
- Условную обязательность реализовать только так: реквизит в метаданных = «Выдавать ошибку» (std478), в обработчике
  собрать массив НепроверяемыеРеквизиты и удалить их из ПроверяемыеРеквизиты (с проверкой, что имя там есть).
- Неправильно: добавлять реквизиты в ПроверяемыеРеквизиты кодом (прячет обязательность из свойства «Проверка
  заполнения»).
- Если реквизит проверен своей логикой и ошибка выдана сообщением - тоже добавить его в НепроверяемыеРеквизиты, чтобы
  не было второго сообщения от платформы.
- Обработчик вызывается не при каждой записи: при программной записи его нет.
- (Рекомендация) С БСП «Обмен данными» он вызывается при отложенном проведении документов после загрузки - часть
  проверок можно отключать по ДополнительныеСвойства.ОтложенноеПроведение.
- Проверки здесь идут вне транзакции записи - самое дешевое место, операция прерывается до записи. Помнить: новое
  состояние объекта еще не в базе; для запроса по данным объекта (например, по товарам ТЧ) передавать их во временную
  таблицу.
- Проверки, от которых зависит целостность данных (движения, связанные объекты), сюда не ставить - их место в
  транзакции: ПередЗаписью, ПриЗаписи, ОбработкаПроведения.
- Транзакционные проверки двух видов:
  - контроль остатков в оперативном учете - имеет смысл в транзакции, только если ВСЕ документы, меняющие ресурс,
    проверяют его в транзакции; иначе проверять вне транзакции. Допустимо обоснованное исключение для редкого
    документа (Инвентаризация);
  - проверка связанных объектов - применять редко; правило должно проверяться симметрично с обеих сторон
    (Подразделение.Руководитель и Сотрудник.Должность): либо в транзакции у обоих, либо вне у обоих, либо нигде.
```bsl
Процедура ОбработкаПроверкиЗаполнения(Отказ, ПроверяемыеРеквизиты)
	НепроверяемыеРеквизиты = Новый Массив;
	Если ВидКонтрагента <> Перечисления.ВидыКонтрагентов.ФизическоеЛицо Тогда
		НепроверяемыеРеквизиты.Добавить("ДокументУдостоверяющийЛичность");
	КонецЕсли;
	ОбщегоНазначения.УдалитьНепроверяемыеРеквизитыИзМассива(ПроверяемыеРеквизиты, НепроверяемыеРеквизиты);
КонецПроцедуры
```

### std464 Обработчик события ПередЗаписью - [its](https://its.1c.ru/db/v8std/content/464/hdoc)
Стандарт
- Место для: дозаполнения реквизитов объекта (набора записей, значения константы), проверок их корректности и
  согласованности с внешними данными, чтения «старых» значений из базы до перезаписи.
- Первым делом - проверка ОбменДанными.Загрузка (std773).

### std465 Обработчик события ПриЗаписи - [its](https://its.1c.ru/db/v8std/content/465/hdoc)
Стандарт
- Место для записи связанных данных в других объектах и прочих действий, вызванных изменением объекта.
- Менять сам записываемый объект здесь запрещено - он уже записан в БД.
- Первым делом - проверка ОбменДанными.Загрузка (std773).

### std752 Обработчик события ПередУдалением - [its](https://its.1c.ru/db/v8std/content/752/hdoc)
Стандарт
- Место для действий перед удалением (например, очистить ссылку на удаляемый присоединенный файл у владельца).
- Первым делом - проверка ОбменДанными.Загрузка: при удалении через обмен такая логика ломается (например, обращение
  к предопределенным после очистки области данных).

### std466 Обработчик события ПриКопировании - [its](https://its.1c.ru/db/v8std/content/466/hdoc)
Стандарт
- Здесь - действия при создании объекта копированием, прежде всего очистка реквизитов, значения которых не должны
  переноситься в копию.

### std746 Обработчики ОбработкаПолученияПредставления и ОбработкаПолученияПолейПредставления - [its](https://its.1c.ru/db/v8std/content/746/hdoc)
Стандарт; управляемое и мобильное приложение
- Переопределяют представление ссылки в полях и списках; реализуются в модуле менеджера. В
  ОбработкаПолученияПолейПредставления перечислить нужные поля, в ОбработкаПолученияПредставления собрать строку из
  Данные; в обоих - СтандартнаяОбработка = Ложь.
- Вызываются очень часто, поэтому: минимум полей; никаких запросов и чтения объектов, в т.ч. обращения к реквизитам
  ссылок через точку (читает объект целиком); нежелательно получать представления и реквизиты ссылок.
- Могут вызываться при записи/удалении в режиме обмена (для журнала регистрации) - требования как к логике
  регистрации объектов в планах обмена (в т.ч. обмены по правилам конвертации через БСП). В частности, не сравнивать
  с предопределенными элементами: их может еще/уже не быть в базе.
- Учитывать требования к поддержке толстого клиента в клиент-серверном варианте.
```bsl
Процедура ОбработкаПолученияПолейПредставления(Поля, СтандартнаяОбработка)
	Поля.Добавить("Номер");
	Поля.Добавить("Дата");
	СтандартнаяОбработка = Ложь;
КонецПроцедуры

Процедура ОбработкаПолученияПредставления(Данные, Представление, СтандартнаяОбработка)
	Представление = СтрШаблон(НСтр("ru = 'Заявка %1 от %2'"), Данные.Номер, Формат(Данные.Дата, "ДЛФ=D"));
	СтандартнаяОбработка = Ложь;
КонецПроцедуры
```

## Регламентные задания

Область применения - управляемое и обычное приложение (std760 - только управляемое).

### std540 Общие требования к регламентным заданиям - [its](https://its.1c.ru/db/v8std/content/540/hdoc)
Стандарт
- Регламентное задание - для периодических или разовых действий по расписанию.
- Если задание не нужно создавать/удалять по действиям пользователя или логике - делать его предопределенным
  (курсы валют, извлечение текста для ППД, обновление агрегатов).
- Задание, зависящее от функциональности, при выключенной ФО запускаться не должно (иначе впустую стартуют сеансы).
  Предопределенное зависимое задание - с выключенным флажком Использование; включать/выключать программно вслед за ФО.
  - БСП: в РегламентныеЗаданияПереопределяемый.ПриОпределенииНастроекРегламентныхЗаданий добавить настройку с
    РегламентноеЗадание и ФункциональнаяОпция (при необходимости ДоступноВМоделиСервиса), и включить константу ФО
    в определяемый тип МестоХраненияФункциональныхОпций.
  - Без БСП: например, в ПриЗаписи модуля менеджера значения константы ФО найти задание
    РегламентныеЗадания.НайтиПредопределенное и синхронизировать Использование.
- Страховка от включения в обход ФО (через консоль): в начале обработчика проверять ФО и вызывать исключение; с
  настроенной зависимостью в БСП достаточно вызова из последнего пункта.
- Задание зависит от данных ИБ (обмен с каждым узлом по своему расписанию, запуск дополнительных обработок) -
  снять Предопределенное, создавать экземпляры РегламентныеЗадания.СоздатьРегламентноеЗадание с параметрами
  (узел, элемент справочника); в Наименование писать представление объекта-основания.
- БСП: параметризованные задания объявить в ПриОпределенииНастроекРегламентныхЗаданий с Параметризуется = Истина -
  это запрещает создавать и запускать их интерактивно из формы «Регламентные и фоновые задания».
- Задания, обращающиеся к внешним ресурсам (почта, синхронизация), должны автоматически блокироваться в копиях ИБ
  (тестовая, у поддержки). БСП: настройка РаботаетСВнешнимиРесурсами = Истина - при переносе базы администратору
  будет задан вопрос об отключении.
- Для заданий из трех случаев выше при БСП в начале обработчика обязательно
  ОбщегоНазначения.ПриНачалеВыполненияРегламентногоЗадания(Метаданные.РегламентныеЗадания.<Имя>) - первый параметр
  заполнять всегда.
```bsl
// РегламентныеЗаданияПереопределяемый.ПриОпределенииНастроекРегламентныхЗаданий
Настройка = Настройки.Добавить();
Настройка.РегламентноеЗадание = Метаданные.РегламентныеЗадания.ВыгрузкаНаСайт;
Настройка.ФункциональнаяОпция = Метаданные.ФункциональныеОпции.ИспользоватьОбменССайтом;
Настройка.РаботаетСВнешнимиРесурсами = Истина;

// модуль обработчика задания
Процедура ВыгрузкаНаСайт() Экспорт
	ОбщегоНазначения.ПриНачалеВыполненияРегламентногоЗадания(Метаданные.РегламентныеЗадания.ВыгрузкаНаСайт);
	// ...
КонецПроцедуры
```

### std402 Настройка расписания регламентных заданий - [its](https://its.1c.ru/db/v8std/content/402/hdoc)
Стандарт
- Запускать не чаще, чем требует прикладная задача: частые задания нагружают сервер приложений.
- Нормальный интервал для большинства заданий - 1 день; чаще - только если прикладно критична актуальность данных.
- Период меньше 1 минуты не задавать никогда.
- Для заданий чаще раза в день согласовывать период с длительностью выполнения (20 секунд работы раз в минуту -
  скорее всего избыточно).
- Тяжелые задания - на минимальную загрузку (ночь, выходные); несколько тяжелых - разносить по времени с учетом
  их длительности.

### std539 Запуск регламентных заданий - [its](https://its.1c.ru/db/v8std/content/539/hdoc)
Рекомендация
- Работа системы не должна зависеть от автозапуска заданий (их могут выключить на кластере; в файловом режиме
  автозапуска исторически нет) - давать ручной запуск того же действия.
- Задание обслуживает конкретное рабочее место (поиск, почта, распределение по партиям) - в этой форме показывать
  дату актуальности данных и команду выполнить то же действие («Обновить», «Получить почту»); команда доступна только
  при наличии прав. Перед ручным стартом проверять, что фоновое задание с тем же методом уже не активно.
- Задание влияет на ИБ в целом или на неизвестное число мест (агрегаты, период рассчитанных итогов) или не меняет
  данные, а делает рассылки/отчеты - отдельное рабочее место; в БСП это форма «Регламентные и фоновые задания».
- На время обновления ИБ задания блокировать. Для неподготовленных пользователей (особенно файловый режим):
  при неудаче монопольного режима предлагать перезапуск с /AllowExecuteScheduledJobs -Off; в начале обработчика
  прерывать задание исключением, пока обновление не завершено. В БСП - подсистема «Обновление версии ИБ» и вызов
  ОбщегоНазначения.ПриНачалеВыполненияРегламентногоЗадания в начале обработчика.
```bsl
&НаСервере
Процедура ВыполнитьОбменСейчасНаСервере()
	ИмяМетода = Метаданные.РегламентныеЗадания.ВыгрузкаНаСайт.ИмяМетода;
	Отбор = Новый Структура("ИмяМетода, Состояние", ИмяМетода, СостояниеФоновогоЗадания.Активно);
	Если ФоновыеЗадания.ПолучитьФоновыеЗадания(Отбор).Количество() = 0 Тогда
		ФоновыеЗадания.Выполнить(ИмяМетода, , , НСтр("ru = 'Ручной запуск: выгрузка на сайт'"));
	КонецЕсли;
КонецПроцедуры
```

### std760 Ограничения на регламентные задания при работе в модели сервиса - [its](https://its.1c.ru/db/v8std/content/760/hdoc)
Стандарт; управляемое приложение, решения для 1cFresh
- Регламентные задания не включать в состав ни одного разделителя (общего реквизита-разделителя): тысячи областей
  перегрузят рабочие процессы.
- Регулярный код в областях данных запускать через БТС «Очередь заданий» (или свой аналог очереди):
  - единое для ИБ расписание (пересчет итогов раз в месяц) - предопределенное неразделенное задание + его ИмяМетода в
    ОчередьЗаданийПереопределяемый.ПриПолученииСпискаШаблонов;
  - индивидуальное расписание на область (обмен с сайтом при включенной ФО) - непредопределенное неразделенное
    задание + псевдоним в ОчередьЗаданийПереопределяемый.ПриОпределенииПсевдонимовОбработчиков; при включении ФО
    РегламентныеЗаданияСервер.ДобавитьЗадание / ИзменитьЗадание, при выключении - УдалитьЗадание / ИзменитьЗадание;
  - выполнение от конкретного пользователя - передать имя пользователя в РегламентныеЗаданияСервер.ДобавитьЗадание,
    а не через менеджер регламентных заданий.
- Не управлять заданиями напрямую через РегламентныеЗадания.* - только через программный интерфейс
  РегламентныеЗаданияСервер (НайтиЗадания, ИзменитьЗадание с УникальныйИдентификатор и структурой параметров).
- Очередь заданий не гарантирует точное расписание (зависит от числа заданий, их длительности и константы
  «Максимальное количество исполняющихся фоновых заданий»). Поэтому:
  - как правило не давать пользователям настраивать расписание в сервисе;
  - нужна оперативность - при наличии push-уведомлений от внешней системы обходиться без задания (загружать по
    уведомлению, отправлять по потребности);
  - иначе оставить задание в очереди, а в рабочем месте при открытии делать разовую догрузку только для данных
    текущего пользователя и периодический обмен клиентским обработчиком ожидания; серверную часть - длительной
    операцией, минимальной по объему.
```bsl
// Неправильно в сервисе: РегламентныеЗадания.ПолучитьРегламентныеЗадания(...) и Задание.Записать()
Задания = РегламентныеЗаданияСервер.НайтиЗадания(Новый Структура("Метаданные", "ПроверкаЦен"));
Если Задания.Количество() = 1 Тогда
	РегламентныеЗаданияСервер.ИзменитьЗадание(Задания[0].УникальныйИдентификатор,
		Новый Структура("Использование", Истина));
КонецЕсли;
```
