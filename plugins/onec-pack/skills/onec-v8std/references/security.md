Содержание:

## Серверный API и внешний код

### std678 Безопасность прикладного программного интерфейса сервера - [its](https://its.1c.ru/db/v8std/content/678/hdoc)
Стандарт
- Тонкий и веб-клиент ходят на сервер по открытому HTTP - любой серверный метод, доступный клиенту, может вызвать
  сторонняя программа в обход клиентской логики.
- Поверхность атаки: экспорт общих модулей с «Сервер» + «Вызов сервера»; ВСЕ методы модуля формы с `&НаСервере` и
  `&НаСервереБезКонтекста` (даже неэкспортные) - их можно дернуть у полученной формы, минуя клиентские проверки.
- Не класть бизнес-логику в серверные методы формы - только клиент-серверная обвязка и работа с реквизитами формы;
  проверки (даты запрета, права) выполнять на сервере в том же методе, который делает действие.
- Особое внимание - методам с `УстановитьПривилегированныйРежим` и модулям с признаком «Привилегированный».
- Любая возможность выполнить на сервере внешний код или произвольный текст запроса - прямая угроза (порча/кража
  данных, зависание процесса). Внешние обработки могут вызывать любые серверные общие модули, модули объектов и
  менеджеров.
- Данные, отданные клиенту, не защищены - возвращать в форму только итог расчета, не исходные/промежуточные данные.

```bsl
// Плохо: проверка только на клиенте, серверный метод можно вызвать напрямую
&НаСервере
Процедура ЗарегистрироватьУвольнение()
	ПроверитьДатуЗапретаИзменения(ДатаУвольнения); // проверка обязана быть здесь
	// ...
КонецПроцедуры
```

### std679 Ограничение на установку признака «Вызов сервера» у общих модулей - [its](https://its.1c.ru/db/v8std/content/679/hdoc)
Стандарт
- Не ставить «Вызов сервера» всем серверным модулям подряд. В модули «Вызов сервера» помещать только методы,
  предназначенные для клиента, которые делают лишь разрешенное пользователю и отдают на клиент лишь разрешенные ему
  данные (итог расчета, а не исходники, недоступные пользователю).
- Особый контроль - привилегированный режим и модули «Привилегированный».
- Серверные методы не для клиента - в модули без «Вызов сервера».
- В толстом клиенте в управляемом режиме не создавать и не получать объекты (`СправочникОбъект`, `ДокументОбъект`...) в
  клиентских общих модулях (через `#Если ТолстыйКлиентУправляемоеПриложение`) и в обычных формах - иначе на клиенте
  исполняются модули объектов и подписки, растут серверные вызовы. Обычные формы - только для обычного приложения.
- Если конфигурация не поддерживает толстый клиент в управляемом режиме - снять в свойствах проверки флажок
  «Толстый клиент (вариант клиент-сервер)» (меньше ложных ошибок проверки).

### std669 Ограничение на выполнение «внешнего» кода - [its](https://its.1c.ru/db/v8std/content/669/hdoc)
Стандарт; управляемое и обычное приложение
- Внешний код = внешние отчеты/обработки, расширения, внешние компоненты и т.п. Особенно критично в модели сервиса.
- П.1. Запрещено выполнять на сервере в небезопасном режиме код, не являющийся частью конфигурации (кроме прошедшего
  аудит): подключаемые пользователем обработки/расширения/компоненты; введенные пользователем алгоритмы и тексты
  запросов, передаваемые в `Выполнить`/`Вычислить`; пользовательское редактирование или загрузка из файла СКД с
  разрешенными внешними функциями (стандартная форма отчета этого не дает).
- С БСП внешний код подключать только подсистемами: расширения - «Базовая функциональность»; внешние отчеты и
  обработки - «Дополнительные отчеты и обработки»; компоненты - «Внешние компоненты»; запуск программ - см. std774.
- П.2. По умолчанию всем пользователям запрещено интерактивно открывать внешние отчеты/обработки (Файл - Открыть); в
  настройках программы - возможность разрешить, с предупреждением о проверке источника. В БСП уже реализовано.
- П.3. Перед подключением любого внешнего кода предупреждать администратора о вреде кода из недоверенных источников и
  давать отказаться. Остальным пользователям при исполнении кода, одобренного администратором, предупреждений не
  показывать. С БСП - отключать платформенные предупреждения об опасных действиях запрещено где-либо, кроме самих
  подсистем БСП.
- П.4. Обновление из .cf/.cfu, восстановление из резервной копии, загрузка .dt в режиме Предприятия: только роль
  «Администратор системы»; только интерактивно текущим пользователем (не служебным с полными правами); предупреждение
  о надежности источника файла; при обновлении через Интернет - защищенное соединение и предупреждение при настройке
  источника. С БСП - только подсистемы «Обновление конфигурации» и «Резервное копирование ИБ».
- П.5. Если можно загружать произвольные файлы: администратору - белый/черный список расширений; блокировать открытие
  исполняемых файлов из программы. Документы Office отдельно не защищать (кроме открытия через COM, std775). С БСП -
  только подсистема «Работа с файлами».
- П.6. Внешние компоненты: не грузить из недоверенных источников; пользователь без админ-прав не может загружать,
  устанавливать и подключать компоненты на сервере; установку на клиенте всегда подтверждает пользователь.
  - Сторонние компоненты - в отдельном справочнике, писать в который может только администратор; подключать по
    навигационной ссылке на реквизит с двоичными данными, не по имени файла или ProgID (подменяемы).
  - Компоненты из состава конфигурации - в макетах типа «Внешняя компонента» (не локализуются).
  - С БСП запрещено напрямую вызывать `ПодключитьВнешнююКомпоненту`, `НачатьУстановкуВнешнейКомпоненты`,
    `УстановитьВнешнююКомпоненту`, `НачатьПодключениеВнешнейКомпоненты`, `ЗагрузитьВнешнююКомпоненту`. Использовать
    `ОбщегоНазначенияКлиент.ПодключитьКомпонентуИзМакета` (клиент), `ОбщегоНазначения.ПодключитьКомпонентуИзМакета`
    (сервер), `ВнешниеКомпонентыКлиент.ПодключитьКомпоненту` (из хранилища компонент).
- П.7. Код/данные из внешних источников - только из доверенных источников, по защищенному каналу с проверкой
  сертификата сервера. Касается HTTPS/FTPS через `HTTPСоединение`, `FTPСоединение`, `WSПрокси`, `WSОпределения`,
  `WSСсылкаМенеджер.СоздатьWSПрокси`. С БСП - `ОбщегоНазначенияКлиентСервер.НовоеЗащищенноеСоединение()`.
- П.8. Для сервиса с переносом данных из локальной версии - отключать весь пользовательский внешний код и тексты
  запросов, введенные локально.

```bsl
SSL = Новый ЗащищенноеСоединениеOpenSSL(, Новый СертификатыУдостоверяющихЦентровОС);
Соединение = Новый HTTPСоединение(Хост, , , , , 30, SSL);
```

## Выполнить / Вычислить

### std770 Ограничения на использование Выполнить и Вычислить на сервере - [its](https://its.1c.ru/db/v8std/content/770/hdoc)
Стандарт; управляемое и обычное приложение
- По возможности полностью отказаться от `Выполнить`/`Вычислить`. Не касается неизменного внешнего кода, проверяемого
  заранее (расширение до установки, внешняя обработка до открытия; по источнику и хешу).
- Пользовательские формулы - собирать из заранее заданных составляющих и считать без `Выполнить`/`Вычислить`. Если
  нельзя - вычислять в безопасном режиме, исключив вызов любых методов, кроме предусмотренных. С БСП - подсистема
  «Конструктор формул».
- Самое опасное - исполнение кода, собранного из параметров серверных методов (с клиента или из БД): злоумышленник
  подставит свою строку. Еще хуже, если такой метод в модуле «Вызов сервера».
- Если без них никак:
  - перед вызовом включать `УстановитьБезопасныйРежим(Истина)`; в модели сервиса также
    `УстановитьБезопасныйРежимРазделенияДанных(Разделитель, Истина)` для всех разделителей. С БСП -
    `ОбщегоНазначения.ВыполнитьВБезопасномРежиме()` / `ОбщегоНазначения.ВычислитьВБезопасномРежиме()`;
  - не давать вызвать непредусмотренные методы платформы и конфигурации.
- Технологический вызов метода по имени - заменить прямым вызовом. Если нельзя - в том же методе непосредственно перед
  `Выполнить` проверить каждую часть имени (через точку), параметры передавать через переменную-Массив. С БСП -
  `ОбщегоНазначения.ВыполнитьМетодКонфигурации()` / `ВыполнитьМетодОбъекта()`.
- В механизмах встраивания библиотек хранить имя модуля (или полное имя менеджера) + фиксированное имя процедуры и
  вызывать через `ОбщегоНазначения.ОбщийМодуль(Имя).Процедура(...)`, а не полное имя обработчика строкой.
- В модулях, чьи методы вызываются через `ВыполнитьМетодКонфигурации`/`ВыполнитьМетодОбъекта`, добавить экспортную
  `ПриОпределенииМетодовРазрешенныхДляВызоваКакПроизвольныйКод(Методы)` и перечислить имена строковыми литералами (без
  переменных и вызовов). Размещение - вне требований структуры модуля, рекомендовано в конце модуля в последней
  области. Непредусмотренный метод вызывает исключение; в БСП 3.2.2 отсутствие процедуры еще разрешает всё, с 3.2.3 -
  исключение.
- Код, не работающий в безопасном режиме (например, с файлами), - вынести во внешний код (расширение / внешняя
  обработка), провести аудит, админ размещает его в расширениях или справочнике, доступном на запись только ему;
  вызывать его экспортный метод. С БСП - форма «Расширения» или «Дополнительные отчеты и обработки».
- Регламентные задания по умолчанию работают с полными правами, безопасный режим права не урезает - запускать задание
  от служебного пользователя с ограниченными правами: (а, рекомендуется) пустой список ролей, чтение/запись данных в
  привилегированном режиме, формула - в безопасном (он отключает привилегированный); (б) реальный пользователь (для
  разовых); (в) роли только на нужные таблицы. С БСП вариант (а) -
  `РегламентныеЗаданияСервер.УстановитьСлужебногоПользователяРегламентногоЗадания` в начале обработчика.

```bsl
// Процедура в конце общего модуля, методы которого вызываются по имени
// См. СтандартныеПодсистемыСервер.ПриОпределенииМетодовРазрешенныхДляВызоваКакПроизвольныйКод
Процедура ПриОпределенииМетодовРазрешенныхДляВызоваКакПроизвольныйКод(Методы) Экспорт
	Методы.Вставить("ОбновитьКурсыВалют");
КонецПроцедуры
```

### std801 Ограничения на использование Выполнить и Вычислить на клиенте - [its](https://its.1c.ru/db/v8std/content/801/hdoc)
Стандарт; управляемое и обычное приложение
- Те же п.1-2, что std770: отказаться от произвольного кода; формулы из составляющих, иначе - на сервере в безопасном
  режиме (БСП «Конструктор формул»).
- На клиенте безопасного режима нет - запрещено получать текст с сервера (в т.ч. из БД) и исполнять его на клиенте.
- Вызов функции по имени - заменить прямым вызовом через `Если ... ИначеЕсли`.
- Если без `Выполнить`/`Вычислить` нельзя - прямо перед вызовом в том же методе проверить, что строка - корректное имя
  функции/переменной (имена через точку), иначе `ВызватьИсключение(..., КатегорияОшибки.ОшибкаКонфигурации)`.

```bsl
Если ЭтоПереходНазад Тогда
	Результат = РезультатНазад(Параметры);
Иначе
	Результат = РезультатВперед(Параметры);
КонецЕсли;
```

## Запуск программ, COM, внешние ресурсы

### std774 Безопасность запуска приложений - [its](https://its.1c.ru/db/v8std/content/774/hdoc)
Стандарт; управляемое и обычное приложение
- Строку запуска собирать только из проверенных частей. Части из БД, поля ввода или хранилища настроек перед запуском
  проверять на отсутствие `$`, обратной кавычки, `|`, `||`, `;`, `&`, `&&`.
- Касается `КомандаСистемы`, `ЗапуститьПриложение`, `НачатьЗапускПриложения`, `ПерейтиПоНавигационнойСсылке`, COM
  `Wscript.Shell` и `Shell.Application`.
- С БСП использовать:
  - открыть проводник на файле - `ФайловаяСистемаКлиент.ОткрытьПроводник`;
  - открыть файл в ассоциированной программе - `ФайловаяСистемаКлиент.ОткрытьФайл` (не запускает .exe/.bin/.apk);
  - веб-страница, протоколы (mailto:, tel:, skype:), навигационные ссылки - `ФайловаяСистемаКлиент.ОткрытьНавигационнуюСсылку`;
    `file://` для файлов/проводника не формировать;
  - запуск исполняемых файлов, системных команд (ping, rac...), команд на сервере, получение кода возврата/stdout/stderr -
    `ФайловаяСистемаКлиент.ЗапуститьПрограмму` (клиент) / `ФайловаяСистема.ЗапуститьПрограмму` (сервер), параметры через
    `ФайловаяСистема.ПараметрыЗапускаПрограммы()`.
- Не генерировать исполняемые файлы (bat и т.п.) во временном каталоге - это вынуждает админов исключать temp из
  политик запуска. Вместо этого: строка запуска для `ЗапуститьПрограмму`, или статический исполняемый файл с
  параметрами командной строки / неисполняемым ini-файлом параметров (тогда админ разрешит хеш).
- Команды, требующие повышения прав (UAC), - только кнопкой/пунктом меню на форме со значком щита (общая картинка БСП
  `ЗначокЩита`).

```bsl
Параметры = ФайловаяСистема.ПараметрыЗапускаПрограммы();
Параметры.ДождатьсяЗавершения = Истина;
Параметры.ПолучитьПотокВывода = Истина;
Результат = ФайловаяСистема.ЗапуститьПрограмму("ping 127.0.0.1 -n 3", Параметры);
```

### std775 Безопасность ПО, вызываемого через открытые интерфейсы - [its](https://its.1c.ru/db/v8std/content/775/hdoc)
Стандарт; управляемое и обычное приложение
- При интеграции через COM и др. открытые интерфейсы отключать исполнение произвольного кода в вызываемом приложении.
- Word: перед `Documents.Open` вызвать `WordBasic.DisableAutoMacros(1)`. Excel: перед `Workbooks.Open` выставить
  `AutomationSecurity = 3` (msoAutomationSecurityForceDisable).
- Если автомакросы нужны - формы настройки отдельно для клиента и сервера с вариантами «Запретить автоматический
  запуск» / «Разрешить запуск подписанных макросов (рекомендуется)» (по умолчанию) / «Разрешить запуск не подписанных
  макросов (опасно)». Клиентская - каждому пользователю, хранится по пользователю, видна только ему; серверная - только
  администратору. Учитывать при открытии.
- Проверка подписи: открыть с отключенными макросами, проверить `Документ.VBASigned`; подписан - включить и выполнить
  автомакрос (Word: `RunAutoMacro(2)`) / переоткрыть (Excel), иначе закрыть и вызвать исключение.

```bsl
Excel = Новый COMОбъект("Excel.Application");
Excel.AutomationSecurity = 3; // принудительно отключить макросы
Книга = Excel.Workbooks.Open(ИмяФайла);
```

### std794 Ограничения на использование внешних ресурсов - [its](https://its.1c.ru/db/v8std/content/794/hdoc)
Стандарт; управляемое и обычное приложение
- Где возможно - средства платформы вместо внешних компонент, программ ОС и COM (например, `ВызватьПаузу` вместо
  пауз через ОС/компоненты/COM).
- С БСП - подсистема «Профили безопасности»: все внешние ресурсы (постоянные и зависящие от ФО/настроек интеграции)
  перечислить в `РаботаВБезопасномРежимеПереопределяемый`.
- При включении/выключении функции, работающей с внешними ресурсами, предварительно запрашивать разрешение
  администратора через `РаботаВБезопасномРежимеКлиент`.

## Пароли

### std740 Безопасное хранение паролей - [its](https://its.1c.ru/db/v8std/content/740/hdoc)
Стандарт
- По умолчанию не хранить пароли и иную конфиденциальную информацию в ИБ (особенно файловая база - ее копирует любой
  пользователь): запросить у пользователя и сразу использовать.
- Хранение в ИБ допустимо, если запрос на каждую операцию неудобен или обмен идет на сервере без пользователя -
  предупредить пользователей о рисках.
- Не хранить пароли в реквизитах рабочих объектов - отдельный объект метаданных (например, регистр сведений) с
  закрытым правами доступом.
- С БСП - только безопасное хранилище: `ОбщегоНазначения.ЗаписатьДанныеВБезопасноеХранилище`,
  `ПрочитатьДанныеИзБезопасногоХранилища`, `УдалитьДанныеИзБезопасногоХранилища` (доступ только в привилегированном
  режиме, хранение в закрытом виде, исключено из планов обмена).
- Не держать пароль в реквизитах формы (уйдет на клиент открытым текстом); читать на сервере непосредственно перед
  использованием. Привилегированный режим включать вокруг вызова в вызывающем коде, а не внутри функций хранилища.
- Для маскированного поля пароля в форме: в `ПриСозданииНаСервере` положить в реквизит заглушку (`УникальныйИдентификатор`
  формы), если пароль задан; в `ПриЗаписиНаСервере` при изменении записать новый пароль в хранилище и снова заменить
  реквизит заглушкой.

```bsl
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
	УстановитьПривилегированныйРежим(Истина);
	Сохраненный = ОбщегоНазначения.ПрочитатьДанныеИзБезопасногоХранилища(Объект.Ссылка, "Пароль");
	УстановитьПривилегированныйРежим(Ложь);
	Пароль = ?(ЗначениеЗаполнено(Сохраненный), Строка(УникальныйИдентификатор), "");
КонецПроцедуры
```
