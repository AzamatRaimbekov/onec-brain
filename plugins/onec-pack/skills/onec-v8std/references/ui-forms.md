# Пользовательские интерфейсы: формы, списки, диалоги - стандарты 1С (v8std)

> Пересказ разделов «Разработка пользовательских интерфейсов», «Реализация работы формы», «Реализация форм списков»,
> «Организация диалога с пользователем» системы стандартов its.1c.ru/db/v8std, снят 2026-10-07. Это не копия: при
> сомнении открыть первоисточник по ссылке. Нумерация stdNNN совпадает с сайтом.

Оглавление:
- Общее: std430 сочетания клавиш, std468 представления объектов, std548 печатные формы, std642 длительные операции на
  сервере, std755 длительные операции на клиенте, std789 печатные формы и пользовательские макеты
- Работа формы: std399 предупреждение при редактировании, std404 открытие форм, std533 табличный документ в веб-клиенте,
  std536 автоэлементы, std537 «Изменяет данные», std545 пользовательские элементы, std628 ДанныеФормыКоллекция,
  std630 модули форм, std636 контекстные/внеконтекстные вызовы, std703 модальность, std710 условное оформление,
  std730 поле HTML, std734 вертикальная прокрутка, std741 параметризированные формы, std742 блокирующее/независимое
  открытие, std744 история выбора, std800 формы объектов
- Формы списков: std397 общие команды для списков, std489 ограничения динамических списков, std495 команды в формах
  списков, std558 обновление списков, std702 поле Ссылка и «Использовать всегда», std732 запросы динамических списков,
  std745 поле «Дата», doc768 (пусто)
- Диалог: std400 информирование пользователя, std418 запрет Сообщить, std700 установка внешних компонент

## Общие требования к интерфейсу

### std430 Использование сочетаний клавиш, список зарезервированных сочетаний - [its](https://its.1c.ru/db/v8std/content/430/hdoc)
Стандарт; управляемое приложение
- Частым и общеупотребимым действиям назначать горячие клавиши (рекомендация).
- Зарезервированные сочетания обязательны для своих действий и запрещены для любых других.
- Прикладные резервы: `Ctrl+Shift+F` полнотекстовый поиск, `F7` поиск по штрихкоду, `F8` вкл/выкл активность проводок в
  журнале операций, `F11` установить текущее учреждение, `F12` «Управление данными работника».
- Платформенные резервы - почти все `Ctrl+буква`, `F1-F12` с модификаторами, навигация и Num-клавиши, `Ctrl+Enter`
  (сформировать отчет), `F4`/`Shift+F4`, `F9`, `Ins`/`Del`; перед назначением своей комбинации свериться с первоисточником.

### std468 Пользовательские представления объектов - [its](https://its.1c.ru/db/v8std/content/468/hdoc)
Стандарт; управляемое приложение
- Синоним - обязателен, кратко и осмысленно описывает объект.
- Представление объекта (для регистра - записи) - единственное число («Валюта»); заполнять, только если синоним не
  годится как имя одного объекта. Коротко: «Версия», а не «Версия проверяемой конфигурации».
- Расширенное представление объекта - полное имя в ед. числе, если краткое малоинформативно («Реализация товаров и
  услуг» при представлении «Реализация»).
- Представление списка - множественное число («Валюты») или самостоятельный термин («Классификатор ОКОФ»); заполнять,
  если синоним не подходит как имя списка. Для объектов-действий можно не заполнять или писать «Документы <действия>».
- Расширенное представление списка / расширенное представление - полные названия, если основные малоинформативны.
- Пояснение - законченными предложениями, когда представление не раскрывает назначение.
- Картинка 32x32 - для подсистем верхнего уровня с флажком «Включать в командный интерфейс».

### std548 Формирование печатных форм - [its](https://its.1c.ru/db/v8std/content/548/hdoc)
Стандарт; управляемое приложение
- Для печати достаточно прав на чтение данных + права на команду печати; права на отдельные печатные формы можно
  ограничивать через права на команды.
- Предусматривать печать нескольких объектов сразу; данные всех объектов выбирать одним запросом и обходить в цикле
  (не запрос в цикле).
- Нерегламентированные формы: состав и порядок строк ТЧ как на экране, без дополнительной группировки; если на экране
  строки уже сгруппированы - группировать так же.
- Всегда выводить колонку номера строки; если «НомерСтроки» на экране не виден - нумеровать в порядке вывода.
  Заголовок колонки по специфике формы («№», в ТОРГ-12 - «Номер по порядку»).
- Порядок строк должен быть одинаков на всех СУБД: явно сортировать (по номеру строки или другому полю, лучше
  индексированному).
- Данные не должны обрезаться. Совет: в табличных макетах для строк ТЧ ставить `АвтоВысотаСтроки = Истина`.
- Не задавать поля табличного документа меньше физических полей принтера, нулевые поля запрещены (сервер не знает
  принтер клиента - текст пропадет). Обычно поля не трогать, кроме регламентированных (ГОСТ Р 6.30-2003: 20/10/20/20 мм).

### std642 Длительные операции на сервере - [its](https://its.1c.ru/db/v8std/content/642/hdoc)
Стандарт; управляемое приложение
- Серверный вызов с клиента, который в обычном сценарии может длиться более 8 секунд (отчет, групповая обработка,
  обмен, заполнение больших ТЧ), выполнять асинхронно в фоновом задании. Иначе - «зависание» браузера, 504 от
  веб-сервера, невозможность отмены.
- Схема: длительный код в общем модуле (или модуле менеджера через обертку в общем модуле - фоновое задание вызывает
  только общие модули; с БСП `ДлительныеОперации` обертка не нужна) кладет результат во временное хранилище; запуск
  фонового задания с ожиданием 0.8 с; если не успело - на клиенте обработчик ожидания с интервалом от 1 до 15 с,
  множитель 1.4; на время работы индикатор; по завершении забрать результат из хранилища.
- Индикатор: для отчетов - через `ОтображениеСостояния` поля табличного документа; в прочих местах - блокирующая форма
  (`БлокироватьОкноВладельца`) с анимацией и кнопкой «Отмена».
- Асинхронность обязательна только для долгих отчетов без СКД или с переопределенным формированием
  (`СтандартнаяОбработка = Ложь` в `ПриКомпоновкеРезультата`). Такие отчеты ведут себя как СКД: форму не блокировать,
  разрешать перенастроить и переформировать, при закрытии формы прерывать формирование.
- С БСП использовать `ДлительныеОперации`, `ДлительныеОперацииКлиент`,
  `ОбщегоНазначенияКлиентСервер.УстановитьСостояниеПоляТабличногоДокумента`.
- Совет 3.1: результат кладется в хранилище на время жизни формы - сразу после чтения удалять
  `УдалитьИзВременногоХранилища`; если результат нужен между вызовами - заранее зарезервировать адрес в
  `ПриСозданииНаСервере` и передавать его в `ПараметрыВыполнения.АдресРезультата`.
- Фоновые задания/запись данных без участия пользователя (регулярное обновление формы, обработчики ожидания) не
  запускать, если `МонопольныйРежим()` - выйти.
- Операции, требующие монопольного режима (обновление ИБ, удаление помеченных, выгрузка в сервис): сначала установить
  монопольный режим, потом запустить фон (он его унаследует); на время работы открыть форму ожидания с
  `БлокироватьВесьИнтерфейс`; на ней не размещать поля ввода, динамические списки, отчеты (они запускают свои фоны).
- Безопасность (п. 6): параметры, которые можно не брать с клиента, формировать на сервере; имя запускаемого метода
  писать строковым литералом полного имени, без переменных и оберток - в `ВыполнитьВФоне`, `ВыполнитьФункцию`,
  `ВыполнитьПроцедуру`, `...ВНесколькоПотоков`, `ФоновыеЗадания.Выполнить`,
  `РасширенияКонфигурации.ВыполнитьФоновоеЗадание...`. Допустимо `Метаданные.РегламентныеЗадания.X.ИмяМетода`.
- С БСП: длительные операции запускать через `ДлительныеОперации`; служебные фоны - платформенными методами, а при
  имени метода в переменной - через `РегламентныеЗаданияСервер.ВыполнитьЗадание` или
  `ОбщегоНазначения.ВыполнитьФоновоеЗадание` (прикладной контекст сеанса туда не передается).
- В каждом модуле, методы которого запускаются через `ДлительныеОперации`/`ОбщегоНазначения.ВыполнитьФоновоеЗадание`,
  добавить экспортную `ПриОпределенииМетодовРазрешенныхДляВызоваКакПроизвольныйКод(Методы)` и перечислить имена
  строками (без переменных); место в модуле - любое. Без нее: БСП 3.1.13/3.2.2 пропускают, с 3.1.14/3.2.3 - исключение.
```bsl
&НаСервере
Функция НачатьРасчет()
	Параметры = ДлительныеОперации.ПараметрыВыполненияФункции(УникальныйИдентификатор);
	Возврат ДлительныеОперации.ВыполнитьФункцию(Параметры, "РасчетыСервер.РассчитатьОстатки", Объект.Ссылка);
КонецФункции

&НаКлиенте
Процедура ПриЗавершенииРасчета(Результат, Доп) Экспорт
	Если Результат = Неопределено Тогда Возврат; КонецЕсли; // отменено пользователем
	Если Результат.Статус = "Ошибка" Тогда
		СтандартныеПодсистемыКлиент.ВывестиИнформациюОбОшибке(Результат.ИнформацияОбОшибке);
		Возврат;
	КонецЕсли;
	Данные = ПолучитьИзВременногоХранилища(Результат.АдресРезультата);
	УдалитьИзВременногоХранилища(Результат.АдресРезультата);
КонецПроцедуры

// В модуле РасчетыСервер:
Процедура ПриОпределенииМетодовРазрешенныхДляВызоваКакПроизвольныйКод(Методы) Экспорт
	Методы.Вставить("РассчитатьОстатки", Истина);
КонецПроцедуры
```

### std755 Длительные операции на клиенте - [its](https://its.1c.ru/db/v8std/content/755/hdoc)
Стандарт; управляемое приложение
- Не выполнять долгий клиентский код (сеть, тяжелые алгоритмы) в обработчиках ожидания и событиях элементов
  (`ПриИзменении` и т.п.) - только по явной команде пользователя (кнопка «Проверить»).
- Периодические внешние запросы переносить на сервер: регламентное задание пишет в регистр, обработчик ожидания читает
  легким запросом.

### std789 Разработка печатных форм с учетом возможного внесения изменений в макет пользователем - [its](https://its.1c.ru/db/v8std/content/789/hdoc)
Стандарт; управляемое приложение
- Если пользователь может редактировать макеты (БСП «Печать»), любая область/параметр могут пропасть. Печать по макету СКД (БСП): при наличии макета `ДанныеПечати` поля можно только добавлять, не переименовывать и не
  удалять; без макета нельзя переименовывать реквизиты/ТЧ - сначала создать `ДанныеПечати`, зафиксировав прежний
  состав.
- Программная компоновка: перед получением области проверять ее наличие через `Макет.Области.Найти(Имя)` вместо
  прямого `ПолучитьОбласть`.
- Параметры области не присваивать поштучно; использовать `ЗаполнитьЗначенияСвойств(Область.Параметры, Данные)` или
  `Область.Параметры.Заполнить(Данные)`.
- Обязательное изменение макета (регламентная форма) - при обновлении отключить пользовательский макет и сообщить
  пользователю: `УправлениеПечатью.ОтключитьПользовательскийМакет`, проверка - `ПоставляемыйМакетИзменен`,
  `ИспользуетсяПользовательскийМакет`. Необязательное - новый код должен работать и со старым макетом.

## Реализация работы формы

### std399 Запрет редактирования полей таблицы по условию - [its](https://its.1c.ru/db/v8std/content/399/hdoc)
Методическая рекомендация; управляемое приложение
- Если поле таблицы бессмысленно заполнять до заполнения другого, предупреждать через свойства
  `ОтображениеПредупрежденияПриРедактировании` и `ПредупреждениеПриРедактировании` (текст задать в конфигураторе).
- Переключать отображение из кода в `ПриАктивизацииСтроки` и `ПриИзменении` влияющих полей; если текст зависит от
  условий - менять и `ПредупреждениеПриРедактировании`.
- Уже введенное «не по правилам» значение оставлять редактируемым, чтобы его можно было стереть.

### std404 Открытие форм - [its](https://its.1c.ru/db/v8std/content/404/hdoc)
Стандарт; управляемое приложение, мобильное приложение
- Открывать формы глобальным `ОткрытьФорму`; связку `ПолучитьФорму` + `Открыть` не использовать (лишний серверный
  вызов, инициализация размазывается вне `ПриСозданииНаСервере`).
- Все параметры открытия - через параметры формы (декларативно); не обращаться к элементам/методам формы после открытия.
- Результат формы получать через `ОписаниеОповещения` (обработчик завершения), а не чтением реквизитов открытой формы;
  возвращать значение методом `Закрыть(Результат)`. В обработчике учитывать `Неопределено` (закрыли без выбора).
- В `ПриОткрытии` не открывать другие формы (нарушится порядок окон) - использовать короткий обработчик ожидания или
  явное действие пользователя. Не открывать и не закрывать форму программно в одном обработчике.
- С БСП: формы только для внешних пользователей в `ПриСозданииНаСервере` проверять
  `ПользователиКлиентСервер.ЭтоСеансВнешнегоПользователя()` и ставить `Отказ = Истина` для обычных.
- Основная форма списка (всех объектов), основные формы обработок и отчетов должны открываться из «Все функции».
```bsl
Оповещение = Новый ОписаниеОповещения("ВыборПериодаЗавершение", ЭтотОбъект);
ОткрытьФорму("ОбщаяФорма.ВыборПериода", Новый Структура("Период", Период), ЭтотОбъект,,,, Оповещение,
	РежимОткрытияОкнаФормы.БлокироватьОкноВладельца);
```

### std533 Особенности табличного документа в веб-клиенте - [its](https://its.1c.ru/db/v8std/content/533/hdoc)
Методическая рекомендация; управляемое приложение
- При редактировании табличного документа пересчет зависимых ячеек и доступности делать на клиенте, точечно (только
  зависимые ячейки), без контекстных серверных вызовов; не перерисовывать доступность кнопок по текущей области -
  объяснять при нажатии или подбирать область автоматически.
- Если сервер нужен - один вызов, лучше `&НаСервереБезКонтекста`.
- Избегать большого числа колонок и объединений в макетах; использовать переменную ширину колонок по строкам.
- Объединенным ячейкам с левой рамкой задавать и нижнюю (IE 6/7). Числа с выравниванием вправо - `Размещение =
  Забивать` (полчисла бессмысленно), строки - `Обрезать`.

### std536 Обращение из кода к автоматически формируемым элементам управления формы - [its](https://its.1c.ru/db/v8std/content/536/hdoc)
Рекомендация; управляемое приложение
- Избегать программной настройки автоэлементов платформы: она их пересоздает (смена `ОсновнаяТаблица` списка
  перезаполняет командную панель) - после таких изменений настройку повторять.

### std537 Команды по модификации объектов - [its](https://its.1c.ru/db/v8std/content/537/hdoc)
Стандарт; управляемое приложение
- Свойство «Изменяет данные» = Истина у каждой команды, которая изменяет или может изменить объект, даже если в
  части сценариев (отказ на вопрос) изменения нет.
- Иначе команда останется доступной при `ТолькоПросмотр` формы и не будет автоматической блокировки объекта
  (конфликт при записи с другим пользователем).

### std545 Обращение из кода к пользовательским элементам управления формы - [its](https://its.1c.ru/db/v8std/content/545/hdoc)
Методическая рекомендация; управляемое приложение
- Элементы, добавленные пользователем через «Изменить форму», из кода недоступны: `ТекущаяСтраница` и `ТекущийЭлемент`
  могут быть `Неопределено` - проверять перед обращением к свойствам.
```bsl
Страница = Элементы.Страницы.ТекущаяСтраница;
ИмяСтраницы = ?(Страница = Неопределено, "", Страница.Имя);
```

### std628 Использование объекта ДанныеФормыКоллекция - [its](https://its.1c.ru/db/v8std/content/628/hdoc)
Стандарт; управляемое приложение, мобильное приложение
- `ДанныеФормыКоллекция` приходит на клиент порциями по мере обращения - перебор на клиенте дает неявные серверные
  вызовы. При 20+ строках обход и `НайтиСтроки` - только на сервере (один явный вызов, возвращающий итог).

### std630 Правила создания модулей форм - [its](https://its.1c.ru/db/v8std/content/630/hdoc)
Стандарт; управляемое приложение, мобильное приложение (п.1 также обычное приложение)
- В модуле формы - только логика этой формы в ее контексте.
- Экспортные методы в модуле формы не размещать (выносить в модули объекта/менеджера/общие). Параметризация -
  `ОткрытьФорму` с параметрами, результат - обработчик оповещения, связь с открытыми формами - `Оповестить` +
  `ОбработкаОповещения` (и `ОповеститьОЗаписиНового`, `ОповеститьОбАктивизации`, `ОповеститьОВыборе`).
- Исключение: экспортные обработчики оповещений (`ОписаниеОповещения.ИмяПроцедуры`).
- Общую для клиента и сервера логику формы писать в `&НаКлиентеНаСервереБезКонтекста`, передавая форму
  (`ФормаКлиентскогоПриложения`) или ее реквизит параметром - без дублирования кода.
```bsl
&НаКлиентеНаСервереБезКонтекста
Процедура НастроитьЭлементы(Форма)
	Форма.Элементы.ТоварыЦена.ТолькоПросмотр = Не Форма.Объект.РучнаяЦена;
```

### std636 Контекстная и внеконтекстная передача управления на сервер - [its](https://its.1c.ru/db/v8std/content/636/hdoc)
Стандарт; управляемое приложение, мобильное приложение
- `&НаСервереБезКонтекста` передает только явные параметры; `&НаСервере` - еще и все измененные с прошлого вызова данные
  формы, плюс инициализация серверного контекста (дороже).
- Контекстный вызов оправдан, когда платформа сама оптимизирует трафик (табличные документы, коллекции) и это
  экономит трафик/число вызовов. Во всех остальных случаях - внеконтекстный.
- В `ПередЗаписью`, `ПослеЗаписи`, `ПередЗакрытием`, `ПриЗакрытии` и др. контекстные вызовы и действия с неявным вызовом
  сервера недопустимы. Решения: сделать вызов внеконтекстным с минимумом данных; перенести код на клиент; отложить
  через однократный `ПодключитьОбработчикОжидания(..., 0.1, Истина)`.
- `ПриАктивизацииСтроки`, перестраивающий форму: подключать однократный обработчик ожидания, запоминать
  `ИдентификаторТекущейСтроки` и не обновлять, если строка не сменилась.
- Запрещено передавать по значению с клиента на сервер `ДанныеФормыСтруктура`, `ДанныеФормыКоллекция`,
  `ДанныеФормыСтруктураСКоллекцией`, `ДанныеФормыДерево`, `ТабличныйДокумент` - уходит полная копия. Вместо этого
  контекстный серверный метод формы, а из него - вызов общего модуля (сервер-сервер).
- Справка: структура передается целиком при любом изменении; коллекции - только измененные элементы (целиком);
  табличный документ - измененные области; динамический список не передается.
```bsl
// Плохо: ОбщийМодульВызовСервера.Посчитать(Объект.Товары) с клиента
&НаСервере
Функция КоличествоОтмененных()
	Возврат ЗаказыСервер.КоличествоОтмененных(Объект.Товары); // сервер-сервер
КонецФункции
```

### std732 Запросы в динамических списках - [its](https://its.1c.ru/db/v8std/content/732/hdoc)
Методическая рекомендация; управляемое приложение, мобильное приложение

## Организация диалога с пользователем

### std400 Информирование пользователя - [its](https://its.1c.ru/db/v8std/content/400/hdoc)
Стандарт; управляемое приложение
- Ошибки проверки заполнения - в панель сообщений формы. Проверку реквизитов делать вне транзакции записи (свойство
  «Проверка заполнения», `ОбработкаПроверкиЗаполнения` + `СообщениеПользователю`); проверки целостности связанных
  данных (остатки) - в транзакции (`ПередЗаписью`/`ПриЗаписи`, `СообщениеПользователю`, `Отказ = Истина`).
- `ВызватьИсключение` - когда ошибка исключительная и делает остальные проверки бессмысленными (ошибка настройки
  системы); если пользователь может быстро исправить ввод - `Отказ` + сообщения.
- В транзакции записи - только транзакционные проверки; остальное - в `ОбработкаПроверкиЗаполнения`.
- Протокол действий - в отдельном поле/реквизите формы или отдельной форме.
- Ошибка выполнения команды формы - отдельным диалогом: `ПоказатьПредупреждение`, а если есть вариант решения -
  `ПоказатьВопрос`. Ошибки в общих функциях/при записи (не задана валюта, закрытый период) - `ВызватьИсключение` с
  `НСтр`.
- Успех сообщать, если результат неочевиден (команда не должна «молча проглатываться»): `ПоказатьПредупреждение` или
  `ПоказатьОповещениеПользователя`. Об очевидном (заполнилась видимая таблица) не сообщать.
- Без формы: `ПоказатьОповещениеПользователя` по завершении; прогресс клиентских операций - `Состояние(Текст,
  Процент)`. Для серверных операций `Состояние` не использовать (много вызовов) - см. std642.

### std418 Ограничение на использование метода Сообщить - [its](https://its.1c.ru/db/v8std/content/418/hdoc)
Стандарт; управляемое приложение
- Всегда `СообщениеПользователю`, даже без привязки к полю; `Сообщить` не использовать.
- С БСП - `ОбщегоНазначения.СообщитьПользователю` / `ОбщегоНазначенияКлиент.СообщитьПользователю`.

### std700 Установка внешних компонент и расширений платформы - [its](https://its.1c.ru/db/v8std/content/700/hdoc)
Стандарт; управляемое приложение
- Установка только интерактивная, по решению пользователя; в диалоге - зачем компонента и что не будет работать без
  нее. Нельзя автоматически `УстановитьВнешнююКомпоненту` после неудачного `ПодключитьВнешнююКомпоненту`.
- Предлагать установку перед прикладным действием: объяснение + кнопка «Установить» + «Продолжить» (работает во всех
  браузерах).
- С БСП использовать `ФайловаяСистемаКлиент`: `ВыбратьКаталог`, `ЗагрузитьФайл`/`ЗагрузитьФайлы` (вместо
  `ПоместитьФайл(ы)`, `НачатьПомещение...`, диалога открытия), `ОткрытьФайл` (вместо `ЗапуститьПриложение`),
  `СохранитьФайл`/`СохранитьФайлы` (вместо `ПолучитьФайл(ы)`, диалога сохранения); прочее -
  `ПодключитьРасширениеДляРаботыСФайлами`.
- Дать отдельную функцию установки компонент/расширений в любой момент (персональные или административные настройки).
