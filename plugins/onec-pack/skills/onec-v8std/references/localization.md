## Общее

### std458 Общие требования по локализации конфигурации - [its](https://its.1c.ru/db/v8std/content/458/hdoc)
Стандарт.
- Исходить из того, что у конфигурации несколько языков интерфейса, а данные в базе вводятся на одном языке, который
  может отличаться от основного языка конфигурации (свойство `ОсновнойЯзык`).
- Не регламентируются: ввод данных сразу на нескольких языках и многоязычность метаданных, хранимых в данных
  (предопределённые элементы, дополнительные реквизиты).

## Тексты в коде

### std761 Интерфейсные тексты в коде - [its](https://its.1c.ru/db/v8std/content/761/hdoc)
Стандарт.
- Любая строка для пользователя (сообщения, надписи, команды, подсказки, выражения в настройках СКД) - только через
  `НСтр`, без голых литералов.
- `НСтр` применять к литералу прямо в месте объявления; передавать в `НСтр` переменную с текстом нельзя.
- Фразы - целиком, параметры подставлять `СтрШаблон` (или аналогом), а не конкатенацией: порядок слов в языках
  разный. Не дробить фразу параметром на куски (`'%1 пользователя...'` с глаголом в `%1`) - писать отдельную строку
  на каждый вариант.
- Допустимо: текст из нескольких предложений, каждое в своём `НСтр`; предложение, оканчивающееся двоеточием.
- Именованные параметры подстановки - только `[Параметр]` или `%Параметр%`, имя по правилам имён переменных.
- В БСП составные форматированные строки делать `СтроковыеФункции(Клиент).ФорматированнаяСтрока` с разметкой
  (`<b>...</b>`), а не сборкой `Новый ФорматированнаяСтрока` из кусков.
- Внутри `НСтр` текст в одинарных кавычках: `НСтр("ru = 'Тип ""Строка""'")`.
- Не показывать пользователю имена объектов метаданных и внутренние идентификаторы - только синонимы. Синоним брать
  из метаданных (`.Представление()` или сам объект метаданных в `СтрШаблон`), не дублировать текстом.
- Исключение: сообщения для разработчиков/внедренцев. Имена методов - полностью с модулем
  (`"УправлениеДоступом.ЕстьРоль"`), подставлять параметром; имена объектов - через `.ПолноеИмя()`.
- В `ЧислоПрописью`, `ПредставлениеПериода`, `СтрокаСЧислом` не указывать `Л=` / `L=` в форматной строке.
- `ПолучитьСклоненияСтрокиПоЧислу` вызывать запрещено (только для русского). Использовать
  `СтроковыеФункцииКлиентСервер.СтрокаСЧисломДляЛюбогоЯзыка`, `РаботаСКурсамиВалют.СформироватьСуммуПрописью`,
  `СтрокаСЧислом`, `ЧислоПрописью` или свои функции.
- Сложение строк допустимо в редких случаях (длинный лог); неязыковые символы на краях (перевод строки, пробел)
  выносить в отдельные литералы/`Символы.ПС`, а не прятать в конец `НСтр`.
- `ПоказатьВопрос` с кнопками: по возможности `КодВозвратаДиалога`; для своей кнопки задавать представление через
  `НСтр`.
```bsl
Текст = СтрШаблон(НСтр("ru = 'Не хватает товара %1 на складе %2.'"), Товар, Склад);
Текст = СтрШаблон(НСтр("ru = 'Отрицательные остатки по регистру ""%1"".'"),
	Метаданные.РегистрыНакопления.ТоварыНаСкладах.Представление());
Кнопки = Новый СписокЗначений;
Кнопки.Добавить("Отключить", НСтр("ru = 'Отключить'"));
Кнопки.Добавить(КодВозвратаДиалога.Отмена);
```

### std764 Строковые константные выражения в коде - [its](https://its.1c.ru/db/v8std/content/764/hdoc)
Стандарт.
- Внутренние строковые идентификаторы (не видны пользователю) не оборачивать в `НСтр`; именовать по правилам имён
  переменных: `"ОтгрузкаКлиентам"`, а не `"Отгрузка клиентам"`. То же в запросах и выражениях СКД.
- Предпочтительно возвращать такие константы функциями (`РезультатЗагрузкиУспешно()`) - видно, что это
  идентификатор, а не забытый `НСтр`.
- Не использовать в алгоритмах представления объектов и типов (`Строка(Значение) = "..."`): они зависят от языка.
  Предопределённые значения на клиенте - через `ПредопределенноеЗначение("Перечисление.X.Y")`.

## Запросы, СКД, формы

### std762 Запросы, динамические списки и отчёты на СКД - [its](https://its.1c.ru/db/v8std/content/762/hdoc)
Стандарт.
- Литералы запроса, попадающие в интерфейс, выносить в параметры запроса (`УстановитьПараметр(..., НСтр(...))`);
  ни литерал в тексте, ни `СтрЗаменить` по тексту запроса не допускаются.
- В наборах данных и выражениях СКД: сравнивать с параметрами (`&ВидОперацииОтгрузка`) или идентификаторами по
  правилам имён переменных, а локализуемое представление задавать в списке доступных значений поля; либо
  значение параметра устанавливать через `НСтр` в `ПриКомпоновкеРезультата`, а не в колонке «Выражение».
- В выражениях настроек СКД (выражение представления, упорядочивания и пр.) - `НСтр`, как в коде.
- Вычисляемому полю с псевдонимом в отчёте СКД обязательно задать заголовок: автозаголовок по имени не переводится
  и не попадает в инструменты редактирования текстов интерфейсов.
- В заголовках отчёта, полей, вычисляемых полей, параметров допустимы `%1, %2` и `[Параметр]` / `%Параметр%`,
  заменяемые в `ПриКомпоновкеРезультата`.
```bsl
Запрос.Текст = "ВЫБРАТЬ ВЫБОР КОГДА В.Выпущена ТОГДА &ТекстВыпущена ИНАЧЕ &ТекстВРаботе КОНЕЦ КАК Статус
	|ИЗ Справочник.Версии КАК В";
Запрос.УстановитьПараметр("ТекстВыпущена", НСтр("ru = 'выпущена'"));
Запрос.УстановитьПараметр("ТекстВРаботе", НСтр("ru = 'в разработке'"));
```

### std765 Элементы форм - [its](https://its.1c.ru/db/v8std/content/765/hdoc)
П.1 - стандарт; п.2-5 - методическая рекомендация.
- Не присваивать реквизитам формы, отображаемым в элементах, нелокализованные строки. Использовать список значений
  с локализуемыми представлениями или перечисления.
- Всем таблицам и группам формы задавать заголовок; если показывать не нужно - явно выключить отображение
  заголовка (иначе в «Изменить форму» видны непереводимые автозаголовки из имён).
- Удалять бессмысленные подсказки у групп; очищать заголовки реквизитов формы, не выведенных в элементы.
- Колонкам динамического списка с псевдонимом или вычисленным в запросе задавать заголовок явно (синоним из
  метаданных не подтягивается, а имена колонок видны в настройке формы).
- Полям со списком выбора ставить `РежимВыбораИзСписка = Истина` - тогда выводится локализуемое представление.

## Форматы, макеты, задания

### std763 Форматирование даты, числа, Булево - [its](https://its.1c.ru/db/v8std/content/763/hdoc)
Стандарт.
- Форматные строки в свойствах метаданных/форм переводятся всегда, как синонимы.
- Даты: по умолчанию локальный формат `ДЛФ` (`"ДЛФ=Д"`, `"ДЛФ=ДД"`). Если нужен `ДФ=` или `ДП=` - форматную строку
  обернуть в `НСтр`.
- Числа: `НСтр` для форматной строки, если задано `ЧН=` (представление нуля), `ЧФ=` (шаблон) или `ЧРД=`
  (разделитель дробной части).
- Булево: форматная строка (`БЛ=...; БИ=...`) для пользователя - всегда в `НСтр`.
- Не переопределять формат ОС: не использовать `Л=` / `L=` в `Формат`.
- В полях форм и отчётов СКД - тоже `ДЛФ`; иной формат только по сути задачи (он будет переводиться).
- Представления полей в СКД собирать `СтрШаблон(НСтр(...), ..., Формат(Дата, "ДЛФ=D"))`, не конкатенацией с `ДФ=`.
- Для машинного обмена значения не локализовать, а сериализовать: `XMLСтрока` / `XMLЗначение`, либо
  `ОписаниеТипов.ПривестиЗначение`. Отказ от локализации допустим, если формат специфичен (например, XML банк-клиента РФ).
- Даты в своих форматах - ISO 8601 (`2009-02-15T00:00:00Z`): `XMLСтрока(Дата)` или
  `ЗаписатьДатуJSON(Дата, ФорматДатыJSON.ISO)`; чтение - `XMLЗначение(Тип("Дата"), Стр)` / `ПрочитатьДатуJSON`.
  Не `Формат(Дата, "ДФ=гггг-ММ-дд...")`.
- Числа и Булево: `XMLСтрока`/`XMLЗначение`, а не `Строка()`/`Формат()`; для Булево допустимо `?(Б, "on", "off")`.
```bsl
Формат(Дата, "ДЛФ=ДД");
Формат(Дата, НСтр("ru = 'ДФ=''ММММ гггг'''"));
Формат(Сумма, НСтр("ru = 'ЧН=Отсутствует'"));
Формат(Флаг, НСтр("ru = 'БЛ=Нет; БИ=Да'"));
```

### std766 Макеты: локализация и разные языки интерфейса - [its](https://its.1c.ru/db/v8std/content/766/hdoc)
Стандарт.
- Табличные, текстовые, HTML-макеты обычно переводятся без подготовки. Особый случай - двоичные макеты (офисные
  печатные формы) и HTML с картинками/скриншотами: их копируют на каждый язык.
- Такие макеты именовать с постфиксом кода языка: `ПФ_ODT_СчетНаОплату_ru` (код - как в свойстве «Код языка»).
  Для новых языков добавлять макеты с их постфиксами.
- Получать макет каскадом: `Имя + "_" + ТекущийЯзык()` -> `Имя + "_" + Метаданные.ОсновнойЯзык.КодЯзыка` -> `Имя`;
  затем выставить код языка макета.
- Печать на языке, отличном от языка интерфейса: свойство `КодЯзыка` (табличный документ) или `КодЯзыкаМакета`
  (текстовый документ, HTML).
- Формы строго на одном языке (например, счёт-фактура РФ): постфикс языка, установка кода языка, не переводить;
  тексты для заполнения - `НСтр` со вторым параметром кода языка.
- В БСП `УправлениеПечатью.МакетПечатнойФормы("ПФ_MXL_СчетФактура")` сам найдёт `_ru` и выставит `КодЯзыка`.
- Именованные параметры в текстах макетов - по правилам std761.
- Кодировка макетов - UTF-8.
- Однотипные макеты объединять в один (с языковым постфиксом), а не плодить несколько.
- Внешние компоненты хранить в макетах типа «Внешняя компонента»; компонента должна обрабатывать `SetLocale` и при
  незнакомом коде локали переключаться на английский.
```bsl
Макет = ПолучитьМакет("ПФ_MXL_СчетФактура_ru");
Макет.КодЯзыка = Метаданные.Языки.Русский.КодЯзыка;
Область.Текст = НСтр("ru = 'Заголовок'", Метаданные.Языки.Русский.КодЯзыка);
```

### std767 Регламентные задания - [its](https://its.1c.ru/db/v8std/content/767/hdoc)
Стандарт.
- Предопределённым регламентным заданиям не задавать «Наименование» в конфигураторе - только синоним (наименование
  не локализуется, а без него платформа берёт локализуемый синоним).
- Непредопределённым (параметризованным) - наименование задавать программно через `НСтр`, можно с контекстом
  (`СтрШаблон(НСтр("ru = 'Рассылка отчетов: %1'"), Рассылка)`).

## Данные и поставка

### std778 Денежные поля - [its](https://its.1c.ru/db/v8std/content/778/hdoc)
Стандарт.
- Для стран с «дешёвой» валютой увеличить разрядность целой части денежных полей (Сумма, Цена, Себестоимость):
  вместо `Число(15, 2)` - определяемые типы `ДенежнаяСуммаНеотрицательная` (только >= 0) и
  `ДенежнаяСуммаЛюбогоЗнака` (флаг «Неотрицательное» снят).
- Где определяемый тип нельзя (параметр формы, составной тип) - `Число(31, 2)`; меньше - только из-за ограничений
  СУБД (например, ресурсы регистров).
- В БСП описание типа денежного поля - `РаботаСКурсамиВалют.ОписаниеТипаДенежногоПоля()`, а не
  `Новый ОписаниеТипов("Число", Новый КвалификаторыЧисла(15, 2))`.
- В запросах `ВЫРАЗИТЬ(... КАК ЧИСЛО(31, 2))` (целая часть 29 - предел DB2).
- В `Формат` и форматах элементов форм/полей СКД не задавать общую длину `ЧЦ=` - только `ЧДЦ=2`.

### std784 Автогенерированные данные в ИБ - [its](https://its.1c.ru/db/v8std/content/784/hdoc)
Стандарт.
- Строки, которые код записывает в ИБ и которые видят пользователи (начальное заполнение, комментарии проводок,
  `ИмяСобытия` в `ЗаписьЖурналаРегистрации`), формировать на языке ИБ, а не текущего пользователя: второй параметр
  `НСтр` - код основного языка. Иначе перепроведение англоязычным пользователем изменит данные.
- Код языка данных хранится в константе `ОсновнойЯзык`; в БСП - `ОбщегоНазначения.КодОсновногоЯзыка()`.
- Помечать такие места комментарием, что строка - данные, а не интерфейс.
- То же для обработчиков начального заполнения строковых реквизитов предопределённых элементов. Новые
  предопределённые - новый обработчик с версией или дополнение существующего (std690).
- В БСП свои обработчики начального заполнения не создавать: данные - в `ПриНачальномЗаполненииЭлементов` модуля
  менеджера (объект регистрируется в `ОбновлениеИнформационнойБазыПереопределяемый.ПриОпределенииНастроек`). При
  изменении элемента - обработчик перехода на версию + дублировать изменение в `ПриНачальномЗаполненииЭлементов`.
```bsl
Комментарий = НСтр("ru = 'Начисление амортизации'", ОбщегоНазначения.КодОсновногоЯзыка()); // строка пишется в ИБ
```

### std769 Поставка международной версии конфигурации - [its](https://its.1c.ru/db/v8std/content/769/hdoc)
Стандарт; для локализуемых конфигураций (и их библиотек), из которых делают национальные решения.
- Выпускать международную версию, подготовленную для национальных; локализованные версии вести на её базе. Все
  требования раздела действуют для обеих версий.
- Перед выделением специфики изучить зарубежные версии конфигураций на портале 1С.
- Национальную (российскую) специфику кода и форм выносить в отдельные объекты метаданных, которых нет в
  международной версии:
  - национальные реквизиты можно оставить в объектах, но конфигурация должна работать при их удалении;
  - часть формы со спецификой - в отдельную форму; если юзабилити сильно страдает - вся форма считается
    национальной;
  - национальные алгоритмы (загрузка курсов валют) - в отдельные объекты;
  - подсистема почти целиком национальная - относить к специфике всю подсистему.
- Если объект в основном международный - общий модуль с постфиксом `Локализация`, вызываемый из точек расширения;
  его процедуры - в области `ПрограммныйИнтерфейс`; в международной поставке они пустые. В национальной версии код
  внутри процедуры обрамлять `// Локализация` ... `// Конец Локализация` (при сборке международной вырезается
  вместе с комментариями).
- Не обрамлять этими комментариями фрагменты в других модулях - вместо этого вызвать модуль `...Локализация`.
```bsl
Иначе
	РаботаСФайламиЛокализация.ПриОпределенииАдресаОблачногоСервиса(Сервис, Адрес);
// в РаботаСФайламиЛокализация - тело внутри // Локализация ... // Конец Локализация
```
- Перечислить объекты с национальной спецификой в файле `ЛокализуемыеОбъекты<...>.txt` в дистрибутиве: по одному
  `ОбъектМетаданных.ПолноеИмя()` на строку (вплоть до реквизита), комментарии `//` допустимы.
- В процедурах переопределяемых модулей - только вызовы процедур конфигурации, код - в своих модулях
  (`ВариантыОтчетовУТ.ОпределитьРазделыСВариантамиОтчетов(Разделы)`).
