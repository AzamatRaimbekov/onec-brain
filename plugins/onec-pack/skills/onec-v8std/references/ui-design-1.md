## Интерфейс 8.3 - общее

### std687 Шрифты - [its](https://its.1c.ru/db/v8std/content/687/hdoc)
Стандарт; управляемое приложение, платформа 8.3.2+
- Использовать стилевые шрифты: `Шрифт текста`, `Мелкий шрифт текста`, `Крупный шрифт текста`, `Очень крупный шрифт
  текста`.
- Допустимы шрифты MS Core Fonts: Andale Mono, Arial, Arial Black, Comic Sans MS, Courier New, Georgia, Impact,
  Times New Roman, Trebuchet MS, Verdana, Webdings. Другие запрещены (не во всех ОС клиента).

### std722 Компоновка форм - [its](https://its.1c.ru/db/v8std/content/722/hdoc)
Рекомендация (п. 1.3.1 обязателен); управляемое приложение
- Заголовки однострочных полей, переключателей, тумблеров в форме - все слева или все сверху. Слишком длинный заголовок
  одного поля сокращать или переносить; поля связанных реквизитов группы выравнивать по опорной линии.
- Элементы с одинаковой функцией в разных формах называть одинаково и ставить в одно место («Контрагент» - левая
  колонка шапки).
- Влияющий элемент - раньше (выше/левее) зависимых: «Контрагент» левее «Договора», переключатель системы
  налогообложения - над вкладками; связанные ТЧ - рядом.
- Обязательно: не выделять группы вертикальной зеленой чертой (сильное выделение); использовать слабое/обычное
  выделение или без выделения. Исключение - группы реквизитов в несколько колонок по горизонтали.
- Шапка документа: левая колонка - важное, ручное, обязательное, внешние данные (номер/дата, контрагент, договор);
  правая - вспомогательное, автозаполняемое, необязательное, внутренние данные (организация, подразделение). Внизу -
  итоги и подвал (Ответственный, Комментарий, счет-фактура).
- ТЧ должна показывать не менее 7 строк (оптимально 10+); иначе вынести ТЧ на отдельную вкладку. Несвязанные ТЧ - на
  разные вкладки.
- Не перегружать форму: скрывать по настройкам/функциональным опциям, выносить во вкладки, свертываемые группы,
  вспомогательные формы.
- Вкладки: название отражает содержимое; обязательные поля - на вкладке, активной при открытии; не делать вкладок с
  1-2 элементами, если они не занимают всю площадь.
- Вспомогательные формы: туда - второстепенные, автозаполняемые, редко используемые реквизиты, разбитые на смысловые
  группы. Открывать гиперссылкой из основной формы, вспомогательная блокирует владельца. Текст ссылки - название формы
  или перечень значений (сначала важные и обязательные; при перечне добавить заголовок). Незаполненные обязательные
  внутри - ссылка цветом стиля `НезаполненныйРеквизит` (178,34,34). Командная панель внизу: «ОК» и «Отмена».
- Свертываемые группы: если все развернутые помещаются без вертикальной прокрутки - раскрыть все; если помещается
  первая развернутая + остальные свернутые - раскрыть первую.

### std727 Размеры экрана - [its](https://its.1c.ru/db/v8std/content/727/hdoc)
Стандарт; управляемое приложение
- Типовое разрешение 1280x768, разработка при 96 DPI.
- Учитывать панель задач ОС (-40 px) и рамку браузера (~-60 px): рабочая область 1280x668.
- В ней формы - без вертикальной и горизонтальной прокрутки; исключение - списки (вертикальная допустима,
  горизонтальная нежелательна).

### std753 Оформление групп разделов с настройками и справочниками - [its](https://its.1c.ru/db/v8std/content/753/hdoc)
Рекомендация; управляемое приложение
- Группа раздела: заголовок, реквизиты/настройки, информационные сообщения. Размеры - под 1280x768.
- Раздел из нескольких групп - свертываемые группы: `Поведение` = Свертываемая, `ОтображениеУправления` = Картинка,
  `Отображение` = Обычное выделение, `ЦветТекстаЗаголовка` и `ШрифтЗаголовка` = Авто.
- Сворачивать так, чтобы все группы помещались без вертикальной прокрутки; первую можно оставить развернутой, если
  форма не выходит за 1280x768.
- Раздел из одной группы - развернут, `Поведение` = Обычное, без заголовка.

## Командный интерфейс 8.3

### std711 Общие принципы построения командного интерфейса - [its](https://its.1c.ru/db/v8std/content/711/hdoc)
Рекомендация; управляемое приложение
- Состав: панель разделов, панель функций текущего раздела, меню функций, команды навигации и действий.
- Элементы панелей и меню должны помещаться без прокрутки при стандартном разрешении.
- Порядок - по убыванию важности и частоты.
- Не ставить рядом пункты с одинаковым началом названия («Регламентированные отчеты» рядом с «Регламентные операции»).
- Группировку проектировать с учетом мнения пользователей.

### std712 Панель разделов - [its](https://its.1c.ru/db/v8std/content/712/hdoc)
Рекомендация; управляемое приложение
- Разделы = реальные участки работ, как их видят пользователи. «Главное» - первым, только общеконфигурационные
  объекты.
- Условно-постоянные списки (справочники, РС, перечисления): в своем разделе (в конце меню или «См. также»), в
  отдельном разделе («Справочники», «НСИ», «Настройки») или в панели навигации «старшего» списка. Справочники, с
  которых начинается бизнес-процесс («Сотрудники»), - в группы меню своего раздела.
- Разделы настройки/администрирования/сервиса - в конце.
- Название раздела до 35 знаков с пробелами (2 строки); близкие по ширине; конкретные; без длинных слов. Сочетания:
  1-2 средних слова; длинное + короткое; два коротких + длинное.
- Только общепринятые аббревиатуры (НДС, МСФО), с расшифровкой во всплывающей подсказке.
- Не называть раздел «Сервис» (конфликт с меню и группой «Сервис»).
- Отображение «Картинка и текст»; картинки разные по форме и цвету, но в одном стиле, свет с одной стороны, фронтальная
  проекция.

### std714 Навигация внутри раздела - [its](https://its.1c.ru/db/v8std/content/714/hdoc)
Рекомендация; управляемое приложение
- Панель функций текущего раздела - для конфигураций с малым числом команд в разделе; при сложной структуре скрывать и
  использовать меню функций (там можно группировать).
- В раздел - списки и журналы документов, списки «первичных» данных (начало бизнес-процессов), рабочие места,
  обработки-списки, отчеты по своему участку. Второстепенные/подчиненные объекты (открываемые из одного документа,
  мало элементов) можно не выносить.
- Название команды до 38 символов, лучше до 30.
- Группировать по логике работы пользователя, а не по видам объектов; в группе до 7 команд; групп из одной команды не
  делать; запрещены группы, где только одна «важная» команда (без заголовка).
- Группам давать названия, не совпадающие с системными («Создать», «Отчеты», «Сервис», «Важное», «См. также»);
  обязательно - для групп из нескольких команд с одной важной.

### std715 Как вместить большое количество команд - [its](https://its.1c.ru/db/v8std/content/715/hdoc)
Рекомендация; управляемое приложение
- Панель разделов - вертикально слева, «Картинка и текст» с картинками 16x16; панели инструментов и открытых - сверху;
  панель функций текущего раздела скрыть, навигация - через меню функций.

## Формы документов 8.3

### std716 Командная панель документа - [its](https://its.1c.ru/db/v8std/content/716/hdoc)
Рекомендация; управляемое приложение
- Кнопка по умолчанию - крайняя левая (обычно «Провести и закрыть» / «Записать и закрыть»).
- Порядок команд одинаков во всех документах; состав и порядок системных кнопок не менять.
- При ширине 1280 и вертикальной панели инструментов слева важные команды видны без «Еще»: Провести и закрыть, Записать,
  Провести, Создать на основании, Печать, глобальные команды, Дополнительные сведения, Движения документа, Отчеты.
- При тесноте - важные кнопки картинкой без текста: «Записать», «Провести», подменю «Создать на основании» -
  `Отображение` = Картинка; подменю «Печать» и «Отчеты» - Авто.

### std717 Табличные части. Оформление списка - [its](https://its.1c.ru/db/v8std/content/717/hdoc)
Рекомендация; управляемое приложение
- Шапка ТЧ - в одну строку и для одно-, и для многоэтажных списков. В многоэтажных колонках - общий заголовок
  (`ОтображатьВШапке` выключить у вложенных) и подсказки в пустых ячейках: шрифт стиля `ПодсказкаНезаполненнойЯчейки`
  (8, наклонный) + свойство `ПодсказкаВвода`.
- Заголовок колонки помещается в шапку полностью.
- Если колонки не помещаются без горизонтальной прокрутки - важные идентифицирующие колонки (и № по порядку) первыми и
  зафиксировать (`ФиксацияВТаблице` = Лево).
- Числовым колонкам явно задавать ширину под частые значения (для сумм бухгалтерии обычно 10).

### std718 Итоги в документах - [its](https://its.1c.ru/db/v8std/content/718/hdoc)
Рекомендация; управляемое приложение
- Итоги полями ввода: сразу под таблицей(ами) без разделяющих элементов; в области итогов - только итоговые данные;
  выравнивание по правому краю формы; серый фон стиля `ИтогиФонГруппы` (220,220,220); поля `ТолькоПросмотр`; без слова
  «итог» в заголовках; валюта после поля, при связанных полях («Всего», «НДС (в т.ч.)») - только после первого.
- В подвале таблицы - когда итоги по многим (более 4) колонкам одной ТЧ не помещаются полями в одну строку.

### std719 Поля "Ответственный" и "Комментарий" - [its](https://its.1c.ru/db/v8std/content/719/hdoc)
Рекомендация; управляемое приложение
- «Комментарий» по умолчанию однострочный: внизу формы последним, заголовок слева, без кнопок выбора/списка.
- Если комментарии обычно большие - многострочное поле на отдельной вкладке «Комментарий»: заголовок только у вкладки,
  поле растянуто по обеим осям, при заполненном - картинка «Комментарий» в заголовке вкладки.
- «Ответственный» - внизу формы. Вместе с однострочным «Комментарием» - в одну группу в самом низу, в одну строку.

## Элементы интерфейса 8.3

### std720 Тумблер - [its](https://its.1c.ru/db/v8std/content/720/hdoc)
Рекомендация; управляемое приложение
- Тумблер - когда выбор меняет состав/расположение элементов формы. Кнопок мало, названия короткие; иначе выпадающий
  список. Заголовок - если назначение неочевидно из кнопок или тумблер работает как переключатель.

### std721 Подсказки на форме - [its](https://its.1c.ru/db/v8std/content/721/hdoc)
Рекомендация; управляемое приложение
- Подсказки - только для элементов, требующих пояснения; не для повседневных реквизитов; не писать инструкций - лучше
  упростить сценарий.
- Подсказку поля прятать за «?» (отображение подсказки «Кнопка»); со ссылками/иконками/форматированием - расширенная
  подсказка; не длиннее 255 символов, иначе - ссылка на статью ИТС.
- Подсказки к настройкам - под настройкой: свойство «Подсказка» с отображением «Отображать снизу» (или расширенная).
  Декорацию «Надпись» для подсказок - только если иначе нельзя (например, выравнивание с заголовком поля).

## Интерфейс 8.2 - общее (legacy, частично актуально для «Такси»)

### std401 Размещение большого количества команд в основном окне приложения - [its](https://its.1c.ru/db/v8std/content/401/hdoc)
Рекомендация; управляемое приложение
- Для многих команд отчетов: у большинства снять видимость по умолчанию, оставить самые востребованные; даже у самого
  полноправного пользователя видимых по умолчанию в панели действий не более 6-9.
- Сделать общую форму «Все отчеты по <подсистеме>» со всеми командами как гиперссылками (можно со смежными областями)
  и общую команду, которая только открывает эту форму (передавая `Источник`, `Уникальность`, `Окно` из
  `ПараметрыВыполненияКоманды`); включить ее в подсистему верхнего уровня, в группу панели навигации.

### std423 Правила создания иконок командных панелей - [its](https://its.1c.ru/db/v8std/content/423/hdoc)
Рекомендация (для дизайнера); управляемое приложение
- 16x16, фронтальная проекция, одинаковый визуальный вес и центр тяжести на одной линии.
- Палитра - серые от #4D4D4D до #FFFFFF; обводка 1 px со скруглением (прозрачность 10-50%); дополнительный контур от
  модификатора 1 px; теней нет; модификаторы зеленые/синие (кроме «опасных»); свет сверху, вертикальный градиент.

### std566 Общие рекомендации - [its](https://its.1c.ru/db/v8std/content/566/hdoc)
Рекомендация; управляемое приложение (см. 8.3 std727)
- Типовое разрешение 1280x768, окно на весь экран, видна панель задач; разработка при 96 DPI.
- Не вносить массовых изменений, ломающих умолчания платформы (например, контекстные меню), без указания стандартов.
- Проверять формы по «Чек-листу проверки интерфейса».

### std576 Панель действий - [its](https://its.1c.ru/db/v8std/content/576/hdoc)
Рекомендация; управляемое приложение (см. 8.3 std714)
- В ПД - самые частотные неконтекстные команды раздела (создать, типовые обработки, популярные отчеты). Не нужна, если
  частотных мало, все контекстны (создание групп) или работа идет через рабочие места.
- Видимо около 15 средних команд (15-20 символов), максимум 30 по высоте.
- Тексты стандартных команд берутся из синонима/представления объекта - давать однозначные; длина 5-30 символов; лучше
  с разных первых слов.
- Свои группы - только если не подходят «Создать», «Отчеты», «Сервис»; минимизировать. Подсказки - желательны.
- Мало отчетов - в ПД; много - отдельное рабочее место отчетов (в ПН, если открывается в основном окне; в «Сервис» ПД -
  если в отдельном).

### std578 Рабочий стол - [its](https://its.1c.ru/db/v8std/content/578/hdoc)
Рекомендация; управляемое приложение
- Отвечает на «что сделать сегодня, что нового, на что обратить внимание». Формы рабочего стола - по ролям; итог у
  реального пользователя 3-6 форм.
- Формы меньше обычных, без списков с горизонтальной прокруткой, без «Все действия», по возможности без справки,
  минимум команд, без команд поиска в списках, с командой обновления в динамических списках; в списках видно не менее
  3,5 строк. Делать формы «с запасом» невидимыми по умолчанию. Можно снять «Автозаполнение» командной панели.
- ПД рабочего стола - только при явных частотных неконтекстных командах.

### std585 Сообщения пользователю - [its](https://its.1c.ru/db/v8std/content/585/hdoc)
Рекомендация (запреты помечены); управляемое приложение
- Безличная форма, без «Вы/Вас»; без «!» и повелительного тона, кроме предупреждений об опасных действиях
  («Внимание. ...»); без жаргона разработчика (кроме сообщений администратору); без непонятных сокращений.
- Ошибку сообщать в момент ее возникновения (проверять поле при вводе, а не при формировании отчета).
- Запрещены вопросы с «не» и «бы» и вопросы-альтернативы с ответами Да/Нет.
- Многострочный текст разбивать по смысловым паузам; в панели сообщений текст не разбивать - переносится сам.
- В коде, выполняемом в транзакции, никаких диалогов. Для протоколов - отдельная форма, не сообщения.
- Панель сообщений - только ошибки (сообщения об успехе запрещены); привязывать к полю, иначе писать, что сделать.
  Ошибка отвечает на «что произошло, почему, что делать»; содержит побуждение («Укажите...», а не «Необходимо
  указать...»).
- Оповещение (`ПоказатьОповещениеПользователя`) - о выполненной операции без прерывания, лучше со ссылкой; текст до
  36 знаков, пояснение до ~100.
- `Состояние` - для процессов дольше 10 с: до начала, по ходу, по завершении.
- Предупреждение - только когда надо прервать работу и решения не требуется; не для старта длительных обработок; текст -
  законченный, с последствиями.
- Вопрос - перед необратимыми, опасными, массовыми, длительными действиями; кнопки - глаголы действий; по умолчанию -
  самая безопасная кнопка.

### std586 Окна на старте - [its](https://its.1c.ru/db/v8std/content/586/hdoc)
Рекомендация; управляемое приложение
- Необязательное стартовое окно - с флажком «Показывать при открытии программы» (включен по умолчанию) под содержимым.

### std596 Требования к изображениям - [its](https://its.1c.ru/db/v8std/content/596/hdoc)
Рекомендация (ограничения по альфа-каналу обязательны технически); управляемое приложение
- Узнаваемые современные метафоры в едином стиле; соседние иконки различаются формой и ведущим цветом, а не только
  цветом.
- PNG с 8-битным альфа-каналом (1-битный, если без потери качества). Без альфа-канала у картинок больше 40000 точек
  (200x200), кроме коллекций с меньшими элементами.
- Для поля HTML - png-8 (1-битная альфа) или png-24 без альфы; удалять из PNG палитру и гамму.
- Прозрачность пикселей только 0% или 100%.

### std600 Командный интерфейс - [its](https://its.1c.ru/db/v8std/content/600/hdoc)

### std615 Рабочее место - [its](https://its.1c.ru/db/v8std/content/615/hdoc)
Рекомендация; управляемое приложение
- Форма под одну бизнес-операцию или группу связанных (Приемка, Отгрузка): команды + актуальная информация (статусы,
  сроки, приоритеты).
- Понятно специалисту без знания программы; важное - сверху и цветом; инструменты в порядке решения задачи; без
  переключений в другие интерфейсы; переходы к смежным рабочим местам.
- Название - по задаче, без слов «рабочее место». Без внедренной справки; пояснения - подсказкой «Снизу» стилем
  `ПоясняющийТекст` (128,122,89), надпись - только как исключение.
- Команда перехода: частотное - группа «Важное» ПН; вспомогательное - «См. также».

### std665 Горячие клавиши - [its](https://its.1c.ru/db/v8std/content/665/hdoc)

### std667 Элементы стиля - [its](https://its.1c.ru/db/v8std/content/667/hdoc)
Стандарт; управляемое приложение
- По умолчанию - оформление платформы. Если меняется цвет/шрифт/рамка - только через элемент стиля, не абсолютным
  значением RGB/web/windows.
- Не создавать элементы стиля, дублирующие платформенные умолчания (цвет гиперссылки).
- Один элемент стиля - одна ситуация; для другой ситуации с тем же цветом - отдельный элемент.
- Имя отражает назначение; при одноименных разных видах - суффикс вида в конце: `ПросроченныеДанныеЦвет`,
  `ПросроченныеДанныеШрифт` (не `ЦветПросроченныхДанных`); вид в имени - только фактический.
- Цвета: `ПросроченныеДанные` 178,34,34; `ПояснениеОтсутствующейГиперссылки` 128,128,128; `ТекстЗапрещеннойЯчейки`
  192,192,192; `ИтоговыеПоказателиДокументов` 22,39,121; `ИтогиЖурналаЦвет` 100,100,100; `ФонУправляющегоПоля`
  255,232,179; `ТекстНевыбраннойКартинкиЦвет` 220,220,220; `НегативноеСобытие` 178,34,34; `ПозитивноеСобытие` 0,128,0;
  `НеактуальнаяИнформация` 255,200,200; `Диаграмма` 70,130,180; `Прогноз` 199,21,133; `ПоясняющийТекст` 128,122,89.
- Шрифты (обычный шрифт текста): `ОсновнойЭлементСписка`, `ОсновноеИтоговоеЗначение`, `ИтогиЖурналаШрифт` -
  полужирный; `ТекстНевыбраннойКартинкиШрифт` - размер 12.

## Панель разделов 8.2

### std567 Панель разделов - [its](https://its.1c.ru/db/v8std/content/567/hdoc)
Рекомендация; управляемое приложение (см. 8.3 std712)
- Разделы = области деятельности; задачи одного участка решаются в одном разделе; частотное - в начало ПН/ПД.
- Емкость 8-10 разделов, без прокрутки в типовых сочетаниях ролей (для администратора прокрутка допустима);
  учитывать доступность подсистем по ролям.
- Порядок по приоритету, не по алфавиту; последним - администрирование/настройки/сервис; не называть «Сервис»
  («Сервисные функции», «Прочее»...).

### std568 Названия разделов - [its](https://its.1c.ru/db/v8std/content/568/hdoc)
Рекомендация; управляемое приложение (в 8.3 лимит строже - 35 знаков, std712)
- До ~50 знаков (~150 точек при 96 DPI); максимум 2 строки, слова не переносятся.
- Комбинации: 1-2 средних слова; среднее + короткое; длинное + короткое; два коротких + длинное. Без очень длинных
  слов; близкая ширина; конкретные; только общепринятые аббревиатуры, лучше без них.

### std569 Картинки разделов - [its](https://its.1c.ru/db/v8std/content/569/hdoc)
Рекомендация; управляемое приложение
- 48x48 PNG с переменным альфа-каналом; разные форма и цвет при едином стиле; проверить вид в режиме «только картинки».

### std571 Подсказки для интерфейсных подсистем - [its](https://its.1c.ru/db/v8std/content/571/hdoc)
Рекомендация; управляемое приложение
- Подсказка и справка раздела необязательны - назначение должно быть понятно из названия; подсказка может перечислять

## Панель навигации основного окна 8.2

### std572 Панель навигации основного окна - [its](https://its.1c.ru/db/v8std/content/572/hdoc)
Справочно; управляемое приложение
- ПН - оглавление раздела; по умолчанию 243x589 pt, вмещает 31 обычную команду без групп и прокрутки.

### std573 Названия команд - [its](https://its.1c.ru/db/v8std/content/573/hdoc)
Рекомендация; управляемое приложение
- Укладываться в ширину ПН (234 pt): важные (жирные) ~30 символов, обычные ~38; различаться с первых символов.
- Частотные - вверх, а не алфавитный порядок.

### std574 Группировка команд - [its](https://its.1c.ru/db/v8std/content/574/hdoc)
Рекомендация; управляемое приложение
- В группе 4-9 команд (7±2), при избытке делить подсистему; без прокрутки по умолчанию, редкие - скрывать.
- Избегать групп из одной команды (в т.ч. «вырождающихся» по ролям); вложенность не более 2 (на втором уровне ~36
  символов); помнить, что группы раскрыты по умолчанию; не называть как системные («Создать», «Отчеты», «Сервис»,
  «См. также»).

### std575 Команды, размещаемые в панели навигации - [its](https://its.1c.ru/db/v8std/content/575/hdoc)
Рекомендация; управляемое приложение
- В ПН - рабочие места, списки, обработки-списки («Журнал регистрации», не «Удаление помеченных»); обязательно списки
  «первичных» данных (с оптимизированными под задачу формами).
- Документы: и журналы, и списки, причем списки - невидимы по умолчанию.
- Подчиненные объекты можно не выносить; важный независимый РС - выносить.
- Не размещать в ПН обычные отчеты (открываются во вспомогательном окне); отчет-рабочее место - отдельной
  навигационной командой.

### std601 Группа «См. также» - [its](https://its.1c.ru/db/v8std/content/601/hdoc)
Рекомендация; управляемое приложение
- Необязательна; только полезные команды смежных подсистем (горизонтальные связи), не «на всякий случай».

### std623 Группа команд «Важное» - [its](https://its.1c.ru/db/v8std/content/623/hdoc)
Рекомендация; управляемое приложение
- Жирные команды ПН для прогнозируемо частых переходов; необязательна; не более 5 важных команд.
