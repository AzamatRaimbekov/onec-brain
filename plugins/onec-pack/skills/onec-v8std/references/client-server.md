# Клиент-серверное взаимодействие - стандарты 1С (v8std)

> Пересказ раздела «Клиент-серверное взаимодействие» системы стандартов its.1c.ru/db/v8std, снят 2026-10-07. Это не
> копия: при сомнении открыть первоисточник по ссылке. Нумерация stdNNN совпадает с сайтом.

Содержание:
- std443 Получение предопределенных значений на клиенте
- std459 Использование значений, влияющих на поведение клиентского приложения
- std487 Минимизация количества серверных вызовов и трафика
- std542 Доступ к файловой системе из кода конфигурации
- std629 Минимизация кода, выполняемого на клиенте
- std724 Использование модулей с повторным использованием возвращаемых значений
- std725 Оптимизация использования оперативной памяти
- std748 Таймауты при работе с внешними ресурсами

Область применения всех документов раздела: управляемое, мобильное и обычное приложение (std748 - только управляемое
и обычное).

## Предопределенные и кэшируемые значения

### std443 Получение предопределенных значений на клиенте - [its](https://its.1c.ru/db/v8std/content/443/hdoc)
Стандарт
- На клиенте (тонкий, веб-клиент) менеджеры вида `Справочники.Xxx`, `Перечисления.Xxx` недоступны - ссылки на
  предопределенные элементы справочников, ПВХ, планов счетов, ПВР, значения перечислений, системных перечислений и
  точки маршрута БП получать через `ПредопределенноеЗначение("Вид.Имя.Элемент")`.
- С БСП 2.1.4+ предпочтительнее `ОбщегоНазначения.ПредопределенныйЭлемент` / `ОбщегоНазначенияКлиент.ПредопределенныйЭлемент`:
  для отсутствующего в ИБ элемента вернут `Неопределено`, а не исключение.
- Собственный клиентский кэш предопределенных значений не писать: обе функции ходят на сервер только при первом
  обращении и кэшируют результат сами.

```bsl
ВидЛица = ПредопределенноеЗначение("Перечисление.ЮрФизЛицо.ФизЛицо");
```

### std459 Использование значений, влияющих на поведение клиентского приложения - [its](https://its.1c.ru/db/v8std/content/459/hdoc)
Стандарт
- Если от одних и тех же настроек зависит поведение многих форм или команд - получать их через общий модуль с
  «Повторное использование возвращаемых значений» = «На время сеанса».
- Допустимо, только если устаревание значения в течение сеанса некритично.
- Одна функция такого модуля возвращает сразу все нужные значения (структурой), а не по одному вызову на значение.
- Не злоупотреблять: данные, нужные одной форме, класть в реквизиты формы в `ПриСозданииНаСервере`; кэш-модуль - только
  когда значение влияет на команды или большое число форм.
- Не использовать переменные модуля (управляемого) приложения как средство сократить серверные вызовы.

### std724 Использование модулей с повторным использованием возвращаемых значений - [its](https://its.1c.ru/db/v8std/content/724/hdoc)
Стандарт
- Назначение ПовтИсп-модулей (кэш на время вызова/сеанса): экономия ресурсов сервера и серверных вызовов. Избыточное
  применение раздувает память.
- Запрещено кэшировать то, что вычисляется быстрее чтения из кэша (строковые литералы, «имя пакета» и т.п.).
  Кэшировать имеет смысл данные из БД, внешних источников и результаты тяжелых вычислений; даже константы примитивных
  типов обычно кэшировать не стоит.
- Кэшировать только часто читаемые данные. Значение живет до 20 мин после вычисления или 6 мин после последнего
  обращения (что раньше; цифры зависят от версии платформы), а также сбрасывается при нехватке памяти, рестарте или
  смене рабочего процесса.
- Параметры кэшируемых функций должны иметь узкий диапазон значений (не, например, произвольный контрагент из
  большого справочника - промахи кэша умножаются на число пользователей).
- Не модифицировать возвращенные кэшем значения - кэш отдает ссылку на один и тот же объект. Возвращать неизменяемые
  типы: `ФиксированныйМассив`, `ФиксированнаяСтруктура`, `ФиксированноеСоответствие`.
- Вызовы одной экспортной функции модуля из другой внутри того же модуля не кэшируются - внутри модуля обращаться с
  явным префиксом имени модуля (`МойМодульПовтИсп.Функция()`).
- В модуле «На время сеанса» запрещено возвращать (прямо или внутри коллекций) `МенеджерВременныхТаблиц`, `Запрос`,
  объекты БД (`ДокументОбъект`, `ОтчетОбъект` ...): они валидны только в серверном вызове, где созданы; платформа это
  не проверяет, сбой виден лишь в техжурнале. То же ограничение - для временного хранилища.

```bsl
// модуль ОбменДаннымиПовтИсп
Функция ЭтоАвтономноеРабочееМесто() Экспорт
	Возврат ОбменДаннымиПовтИсп.АвтономнаяРаботаПоддерживается() И ЕстьНастройкаАРМ();
КонецФункции
```

## Серверные вызовы и трафик

### std487 Минимизация количества серверных вызовов и трафика - [its](https://its.1c.ru/db/v8std/content/487/hdoc)
Стандарт

Общее (п.1)
- Контролировать число серверных вызовов из клиентского кода (а для медленного соединения и мобильного клиента - еще и
  объем трафика). Базовое правило: конфигурация не добавляет лишних серверных вызовов на действие пользователя сверх
  платформенных; любое исключение требует обоснования. Допустимое исключение - неявный вызов при первой компиляции
  клиентского общего модуля.
- Отлаживать в режиме имитации задержек серверных вызовов.

Запуск клиента (п.2)
- `ПередНачаломРаботыСистемы`/`ПриНачалеРаботыСистемы` в идеале не обращаются к серверу. Если нужно - не вызывать
  серверные методы напрямую из модуля приложения / управляемого приложения / внешнего соединения; получить все
  параметры запуска одним вызовом.
- Если параметры запуска нужны в разных местах клиента - функция в серверном общем модуле с повторным использованием
  (кэш на клиенте после первого вызова).
- С БСП: серверные параметры добавлять в `ОбщегоНазначенияПереопределяемый.ПриДобавленииПараметровРаботыКлиентаПриЗапуске`
  / `ПриДобавленииПараметровРаботыКлиента`; на клиенте читать `СтандартныеПодсистемыКлиент.ПараметрыРаботыКлиентаПриЗапуске()`
  / `ПараметрыРаботыКлиента()`.

Периодические вызовы (п.3)
- Объединять периодические проверки в один вызов, период - не чаще раза в 20 минут. Вместо опроса сервера с клиента
  предпочитать `МенеджерУведомленийКлиента` (push с сервера).
- С БСП:
  - ожидание длительных операций - `ДлительныеОперацииКлиент.ОжидатьЗавершение`;
  - проверка состояния только для открытой формы без длительных операций - допустимы бесконтекстные вызовы с максимально
    большим периодом; для форм начальной страницы - кнопка «Обновить» вместо опроса, а если опрос нужен - выключен по
    умолчанию и не чаще раза в минуту;
  - серверные оповещения: описание в `ОбщегоНазначенияПереопределяемый.ПриДобавленииСерверныхОповещений`, отправка из
    регламентного задания в `ПриОтправкеСерверногоОповещения`, прием на клиенте в `ПриПолученииСерверногоОповещения`;
  - периодическая отправка данных клиент->сервер: `ОбщегоНазначенияКлиентПереопределяемый.ПередПериодическойОтправкойДанныхКлиентаНаСервер`,
    `ОбщегоНазначенияПереопределяемый.ПриПериодическомПолученииДанныхКлиентаНаСервере`,
    `ОбщегоНазначенияКлиентПереопределяемый.ПослеПериодическогоПолученияДанныхКлиентаНаСервере`.

Открытие формы (п.4)
- Открывать форму одним вызовом `ОткрытьФорму`, параметры - через параметр `Параметры`.
- Запрещено обращаться к серверу в клиентских `ПриОткрытии`/`ПриПовторномОткрытии`. Нужные данные готовить в
  `ПриСозданииНаСервере` в реквизитах формы. Не вычислять серверные данные перед `ОткрытьФорму`, чтобы передать их
  параметром - пусть форма получит их сама в `ПриСозданииНаСервере`.
- Фоновое задание запускать в `ПриСозданииНаСервере`, а в `ПриОткрытии` только начинать проверку готовности.
- Не вызывать ПовтИсп-функции при открытии формы: первый вызов все равно идет на сервер.
- Не подключать несколько `ПодключитьОбработчикОжидания` для разных фоновых заданий - один обработчик за один вызов
  проверяет все и забирает результаты; по возможности объединять и сами задания. С БСП - только через
  `ДлительныеОперации`/`ДлительныеОперацииКлиент` (уже объединяют обработчики).

Команды (п.5-7)
- Локальная команда формы - не более одного серверного вызова. Чисто клиентская команда (открыть форму, отбор, оформление)
  - ноль вызовов: данные заранее в реквизитах формы (например, колонка `ЭтоГруппа` в таблице, заполненная в
  `ПриСозданииНаСервере`). Серверная бизнес-логика - целиком за один вызов.
- Выбор из справочника - только вызов, порождаемый `ОткрытьФорму`; если после выбора нужна серверная логика - еще один.
- Глобальная команда - один серверный вызов; если открывает форму - это и есть вызов `ОткрытьФорму`.
- Команда формирования отчета - ни одного дополнительного вызова; не формировать отчет из `ПриОткрытии`. Правильно:
  открыть отчет с параметром `СформироватьПриОткрытии = Истина` или выставить его в `ПриСозданииНаСервере`.

Подбор (п.8)
- Не передавать потенциально большой список выбранных строк параметром формы подбора (данные коллекции могут
  дочитываться с сервера). Использовать временное хранилище, чтение/запись - на сервере.
- Открытие подбора - не более 2 вызовов (поместить в хранилище + `ОткрытьФорму` с адресом); закрытие - не более 2
  (поместить результат в хранилище + забрать в форме документа).
- Хранилище: либо на время жизни формы (`УникальныйИдентификатор` формы) с удалением после использования, либо один раз
  инициализировать в `ПриСозданииНаСервере` и переиспользовать адрес. Иначе при повторных подборах растет память.

Запись формы (п.9)
- Не делать серверных вызовов в клиентских `ПередЗаписью`/`ПослеЗаписи`; логику класть в `ПередЗаписьюНаСервере`,
  `ПриЗаписиНаСервере`, `ПослеЗаписиНаСервере`, результаты отдавать через `ПараметрыЗаписи` или реквизиты формы.
  Не управлять формой, если она закрывается после записи.

Неявные вызовы (п.10)
- Учитывать клиентские методы/свойства, которые могут ходить на сервер: `ПолучитьИзВременногоХранилища`,
  `УдалитьИзВременногоХранилища`, свойства элементов `Заголовок`, `Доступность`, `Подсказка`, `ТолькоПросмотр`,
  `ПолучитьФункциональнуюОпциюИнтерфейса`, `ПолучитьФункциональнуюОпциюФормы` (полный список - синтакс-помощник).
  Не дергать их многократно - сводить в один серверный вызов.

Передача данных (п.11-12)
- Не передавать на сервер больше нужного: если нужно одно значение - `&НаСервереБезКонтекста` с параметром, а не
  контекстный `&НаСервере`.
- Не возвращать результат через параметры - делать функцию. Параметры серверных методов, вызываемых с клиента
  (экспорт общих модулей «Вызов сервера», `&НаСервере`, `&НаСервереБезКонтекста`, методы формы/команды без директивы),
  объявлять с `Знач` - иначе сложные значения (Структура, Массив) гоняются обратно на клиент.

```bsl
&НаКлиенте
Процедура СписокПриАктивизацииСтроки(Элемент)
	ДанныеПанели = ДанныеКонтактов(Элементы.Список.ТекущаяСтрока);
	ЗаполнитьПанель(ДанныеПанели);
КонецПроцедуры

&НаСервереБезКонтекста
Функция ДанныеКонтактов(Знач Контрагент)
	Возврат КонтактнаяИнформация.ДанныеДляПанели(Контрагент);
КонецФункции
```

### std629 Минимизация кода, выполняемого на клиенте - [its](https://its.1c.ru/db/v8std/content/629/hdoc)
Стандарт
- Минимизировать клиентский код; тяжелые алгоритмы выполнять на сервере за минимальное число вызовов (клиент слабее,
  интерпретатор в веб-клиенте заметно медленнее).
- На клиенте оставлять то, что заведомо быстрее одного серверного вызова - например, пересчет доступности элементов при
  изменении данных.
- Исключение: подсистемы, работающие с ПО клиентского компьютера (торговое оборудование, клиент-банк, офисные программы).
- Если клиентский функционал доступен не во всех режимах - отсекать директивами препроцессора (`#Если ВебКлиент Тогда`).

## Файлы, память, внешние ресурсы

### std542 Доступ к файловой системе из кода конфигурации - [its](https://its.1c.ru/db/v8std/content/542/hdoc)
Стандарт

Временные файлы и каталоги (п.1)
- Имя временного файла - только `ПолучитьИмяВременногоФайла()` (уникальность, права, автоочистка: при рестарте процесса
  и, с 8.3.17, через 20 мин после вызова/сеанса). Временный каталог - тоже по имени из этого метода.
- В веб-клиенте метод недоступен: имя строить из `КаталогВременныхФайлов()` + `Новый УникальныйИдентификатор`; с БСП -
  `ФайловаяСистемаКлиент.СоздатьВременныйКаталог`.
- Удалять временные файлы/каталоги самому, не надеяться на автоочистку; с БСП - `ФайловаяСистема.УдалитьВременныйФайл`,
  `ФайловаяСистема.УдалитьВременныйКаталог`.
- На сервере вся работа с временным файлом - в пределах одного серверного вызова (в кластере следующий вызов может
  пойти на другую машину). Между вызовами сеанса - временное хранилище.
- Передача больших файлов между сеансами (фоновые, веб-сервисы): общее для кластера место, учет в служебном регистре,
  удаление при штатном завершении, регламентная очистка. С БСП - `ФайловаяСистема.ОбщийКаталогВременныхФайлов`.

Двоичные данные (п.2)
- Получать двоичные данные через потоки в памяти (`ПотокВПамяти`, `ЗаписьДанных`, `ЧтениеДанных`), а не через запись во
  временный файл. Файл допустим, только если платформа не дает получить данные в памяти.
- Потоки после чтения закрывать (иначе утечка памяти).

```bsl
Поток = Новый ПотокВПамяти;
Текст = Новый ТекстовыйДокумент;
Текст.УстановитьТекст(Отчет);
Текст.Записать(Поток, КодировкаТекста.UTF8);
Адрес = ПоместитьВоВременноеХранилище(Поток.ЗакрытьИПолучитьДвоичныеДанные(), УникальныйИдентификатор);
```

Клиент <-> сервер (п.3)
- Обмен файлами между клиентом и сервером - только через временное хранилище (разные машины и ФС).
- Загрузка на сервер: `ПоместитьФайлНаСерверАсинх`, `ПоместитьФайлыНаСерверАсинх` (или `НачатьПомещение...`); для жизни
  между вызовами передавать идентификатор формы, при повторной загрузке удалять прежнее значение. С БСП -
  `ФайловаяСистемаКлиент.ЗагрузитьФайл`/`ЗагрузитьФайлы` (`ПараметрыЗагрузки.ИдентификаторФормы`).
- Скачивание на клиент: `ПолучитьФайлССервераАсинх`, `ПолучитьФайлыССервераАсинх` (или `НачатьПолучение...`); с БСП -
  `ФайловаяСистемаКлиент.СохранитьФайл`/`СохранитьФайлы`.

Имена файлов (п.4)
- Автоматически формируемые имена - только латиница и цифры; текстовые файлы - UTF-8 (обмен, выгрузки, ЭД...).
  Исключение - формат задан сторонней системой.
- Если имя вводит пользователь - разрешить кириллицу, но предложить транслитерацию; по умолчанию латинское имя и UTF-8.
  С БСП - `СтроковыеФункцииКлиентСервер.СтрокаЛатиницей`.

Права ОС (п.5)
- Клиентский код работает с правами пользователя ОС клиента; серверный - с правами пользователя службы сервера 1С
  (рабочие процессы могут работать от другого пользователя, см. swpuser.ini), а у файловой базы через веб-сервер - с
  правами пользователя веб-сервера.

Безопасность (п.6)
- Запрещено хранить путь/имя файла в реквизитах формы (подменяемы на клиенте). Служебные реквизиты объекта, которые
  пользователь не правит, проверять при записи на сервере на неизменность.
- Запрещено принимать путь к файлу параметром серверных методов формы и экспортных методов серверных общих модулей
  (вызываемы с клиента сторонними средствами).
- Расширение файла с клиента проверять по белому списку на сервере или через
  `ОбщегоНазначенияКлиентСервер.ЗаменитьНедопустимыеСимволыВИмениФайла`; тот же метод - для путей из данных ИБ.
- Перед работой с файлом на сервере проверять, что он лежит во временном каталоге или ином разрешенном месте.
- Временный файл: вся работа в одной процедуре, путь только из `ПолучитьИмяВременногоФайла` и не меняется, после -
  удаляется.
- Запрещено писать в `КаталогПрограммы()` (только чтение/запуск).
- Администраторам - ограничивать ФС профилями безопасности.

	Возврат СтрНачинаетсяС(Файл.ПолноеИмя, КаталогВременныхФайлов());

### std725 Оптимизация использования оперативной памяти - [its](https://its.1c.ru/db/v8std/content/725/hdoc)
Методическая рекомендация
- Не рассчитывать на неограниченную память; неограниченный объем данных обрабатывать порциями, сохраняя результаты в
  БД/файлы.
- Потенциально неограниченные выборки из ИБ: `Выгрузить()` и даже `Выбрать()` по запросу сначала читают весь результат
  в память. Правильно: цикл запросов `ВЫБРАТЬ ПЕРВЫЕ N ... ГДЕ <еще не обработано>` до `РезультатЗапроса.Пустой()`, либо
  объектная выборка `Справочники.X.Выбрать(...)` (платформа читает порциями). Динамические списки ограничены платформой.
- Большие файлы не грузить целиком (`ТекстовыйДокумент`, `ДокументDOM`, `ДокументHTML`, XDTO-пакет всего файла) -
  читать/писать последовательно: `ЧтениеXML`, `ЧтениеТекста`, `ЗаписьXML`, `ЗаписьТекста`. Исключение - нужен
  произвольный доступ к части файла. В XDTO не делать `ФабрикаXDTO.ПрочитатьXML` на весь файл - идти `ЧтениеXML` и
  десериализовать отдельные фрагменты.
- Избегать циклических ссылок (утечки); разрывать их, обнуляя ссылку, когда объект не нужен. Искать утечки - элемент
  `<leaks>` в logcfg.xml.
- Не злоупотреблять ПовтИсп-модулями (см. std724).

```bsl
Пока Истина Цикл
	Запрос = Новый Запрос("ВЫБРАТЬ ПЕРВЫЕ 1000 ... ГДЕ НЕ Т.Обработан");
	Результат = Запрос.Выполнить();
	Если Результат.Пустой() Тогда
		Прервать;
	КонецЕсли;
	ОбработатьПорцию(Результат.Выбрать());
КонецЦикла;
```

### std748 Таймауты при работе с внешними ресурсами - [its](https://its.1c.ru/db/v8std/content/748/hdoc)
Стандарт; управляемое и обычное приложение
- Для `WSОпределения`, `WSПрокси`, `HTTPСоединение`, `FTPСоединение`, `ИнтернетПочтовыйПрофиль` всегда задавать таймаут -
  иначе зависание интерфейса или регламентного функционала.
- Таймаут подбирать под операцию (покрывает DNS, Connect, Send, Wait, Receive, Cache Read): быстрые операции - малый;
  в общем случае не больше 3 минут; передача больших объемов - по оценке объема, но не больше 12 часов (43200 с).
- Для веб-сервисов с таймаутом операций > ~20 с: добавить операцию `Ping`, сначала вызывать ее через прокси с коротким
  таймаутом (~7 с), затем создавать рабочий прокси. С БСП - `ОбщегоНазначения.WSПрокси(...)` (умеет Ping), для
  HTTP(S)/FTP(S) - подсистема «Получение файлов через Интернет».
- Не веб-сервисы: аналог Ping - тестовый REST-запрос (код 200), пробная отправка пустого файла на FTP/WebDAV.
- Если операция объективно долго выполняется на удаленной стороне (этап Wait) - асинхронная схема: старт фонового
  задания, операции «готово?» и «получить результат»; вызывающая сторона опрашивает через регламентное задание или
  обработчик ожидания, а не блокирующим циклом.
- Рекомендуемые таймауты (сек): описание веб-сервиса - 7; быстрые проверки/менеджер сервиса - 10-20; один контрагент,
  сообщения, SMS, удаленное администрирование - 60-120 (после Ping); сообщения обмена и файлы до 1 МБ - 120-180 (после
  Ping); файлы > 1 МБ - размер_МБ * 128 (64 кбит/с), иначе предел загрузки, но не более 43200.

```bsl
Проверка = Новый WSПрокси(Определение, URIСервиса, ИмяСервиса, ИмяТочки, , 7);
Проверка.Ping();
Сервис = Новый WSПрокси(Определение, URIСервиса, ИмяСервиса, ИмяТочки, , 60);
Ответ = Сервис.Pong(Параметр);
```
