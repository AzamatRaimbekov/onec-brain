## Конструкции встроенного языка

### std441 Общие требования к построению конструкций встроенного языка - [its](https://its.1c.ru/db/v8std/content/441/hdoc)
Стандарт
- Ключевые слова писать канонически, как в Синтакс-помощнике: `КонецЕсли`, не `конецЕсли`/`КОНЕЦЕСЛИ`.
- Подряд идущие присваивания можно выравнивать по `=`, но только локально (соседние строки), не по всему модулю.
- Длинные условия в `Если` переносить по std444.
- Не сравнивать булевы значения с литералами: `Если ЭтоНовый() Тогда`, а не `... = Истина`.
- Результат сложного выражения (например, ответ `Вопрос(...)`) сначала положить в переменную, потом сравнивать.
- Использовать системные наборы значений: `Символы.ПС` вместо `Символ(10)` и т.п.

### std444 Перенос выражений - [its](https://its.1c.ru/db/v8std/content/444/hdoc)
Стандарт
- Строки длиннее 120 символов переносить (кроме случаев, когда перенос невозможен).
- Арифметика: в строке может быть несколько операндов; знак операции - в начале новой строки; продолжение - со
  стандартным отступом или выравнивание по первому операнду.
- Длинные строковые константы переносить через `|` (многострочный литерал). Текст для `СообщениеПользователю` не
  переносить.
- Конкатенация: `+` обычно в начале новой строки; для длинных многострочных литералов (тексты запросов) `+` можно
  ставить в конце строки, чтобы не ломать форматирование.
- Параметры вызова: выравнивать по первому параметру или стандартным отступом; `)` и `;` - на строке последнего
  параметра; допустим и вариант автоформатирования конфигуратора.
- Условия `Если/ИначеЕсли`: при превышении 120 символов каждое элементарное условие - с новой строки; `И`/`ИЛИ` - в
  начале строки; отступ стандартный или выравнивание по первому условию (для выравнивания - пробелы).
- Для форматирования выделенного блока - меню «Текст - Блок - Форматировать».

```bsl
Если ВидОперации = Перечисления.ВидыОпераций.Возврат
	ИЛИ ВидОперации = Перечисления.ВидыОпераций.ВозвратКомиссионеру Тогда
	Сумма = СуммаБезСкидки
		+ СуммаРучнойСкидки
		+ СуммаАвтоматическойСкидки;
КонецЕсли;
```

### std442 Определение типа значения переменной - [its](https://its.1c.ru/db/v8std/content/442/hdoc)
Стандарт
- Тип проверять только сравнением типов: `ТипЗнч(Ссылка) = Тип("ДокументСсылка.Реализация")`. Не через
  `Ссылка.Метаданные().Имя = "..."` и иные косвенные способы.

### std445 Получение метаданных объектов - [its](https://its.1c.ru/db/v8std/content/445/hdoc)
Стандарт
- Если вид объекта известен, брать метаданные методом самого объекта/ссылки: `Объект.Метаданные()`,
  `Ссылка.Метаданные()`. Не `Метаданные.Справочники[Имя]` и не `Метаданные.НайтиПоПолномуИмени(...)` - это заметно
  медленнее.
- Если тип заранее неизвестен - `Метаданные.НайтиПоТипу(ТипЗнч(Ссылка))` (например, для `.ПолноеИмя()`).

### std439 Использование директив компиляции и инструкций препроцессора - [its](https://its.1c.ru/db/v8std/content/439/hdoc)
Стандарт
- Директивы `&НаКлиенте`, `&НаСервере`, `&НаСервереБезКонтекста` - только в модулях управляемых форм и модулях
  команд. В остальных модулях - инструкции препроцессора. В серверных/клиентских общих модулях директивы бессмысленны,
  в клиент-серверных - запутывают.
- В клиент-серверных общих модулях НЕ ветвить код через `#Если Сервер`, `#Если Клиент`, `#Если НЕ ТонкийКлиент ...` -
  контекст надежно не определяется. Разное поведение на клиенте и сервере - две одноименные функции в модулях
  `...Клиент` и `...Сервер`; общую часть (и только ее) оставить в `...КлиентСервер` и вызывать из обеих.
- Допустимо ветвление по режиму клиентского приложения (`#Если ВебКлиент`), как и в обычных клиентских модулях.
- Не разрывать инструкциями препроцессора и `#Область` выражения, блоки `Если/Цикл`, объявления процедур и списки
  параметров вызова (EDT ловит это автоматически).

### std440 Использование дублирующего кода - [its](https://its.1c.ru/db/v8std/content/440/hdoc)
Стандарт
- Не копировать код, который по логике должен работать одинаково: копируются ошибки, исправления теряются.
- Основной способ - рефакторинг: выносить повторно используемые алгоритмы из модулей форм/объектов в общие модули.
- Дублирование оправданно, только если варианты кода в будущем могут сильно разойтись.
- Типовой прием для клиент-серверных функций: клиентская и серверная обертки + общая служебная реализация в
  `...СлужебныйКлиентСервер` (см. std439), а не `#Если` внутри одной функции.

### std494 Предварительная инициализация локальных переменных - [its](https://its.1c.ru/db/v8std/content/494/hdoc)
Рекомендация
- Если переменная вычисляется в ветвях `Если/ИначеЕсли/Иначе`, присвоить ей значение по умолчанию до блока - иначе
  в непредусмотренной ветке она останется `Неопределено`. Актуально для больших ветвлений.

```bsl
СтавкаНДС = 0;
Если ЭтоЭкспорт Тогда
	СтавкаНДС = 0;
ИначеЕсли ЭтоЛьгота Тогда
	СтавкаНДС = 10;
КонецЕсли;
```

### std547 Ограничение на использование оператора Перейти - [its](https://its.1c.ru/db/v8std/content/547/hdoc)
П. 1 - рекомендация; п. 2 - стандарт (управляемое и обычное приложение)
- Не использовать `Перейти` - запутывает поток исполнения; заменять вызовом процедуры или структурными конструкциями.
- Запрещено использовать `Перейти` в общих модулях с признаком «Клиент (управляемое приложение)», в модулях команд и
  в клиентском коде управляемых форм - не поддерживается веб-клиентом.

### std639 Использование переменных в программных модулях - [its](https://its.1c.ru/db/v8std/content/639/hdoc)
Стандарт
- Переменные модулей - источник трудновоспроизводимых ошибок; по умолчанию использовать другие средства платформы.
- Модули объектов (справочники, документы, наборы записей, обработки, отчеты):
  - Передавать параметры в обработчики событий объекта и между подписками через `ДополнительныеСвойства`, а не через
    экспортные переменные модуля (`Перем Флаг Экспорт;` - неправильно).
  - Для передачи внутреннего состояния между собственными обработчиками объекта (например, значение реквизита до
    записи из `ПередЗаписью` в `ПриЗаписи`) допустимы НЕэкспортные переменные модуля.
  - Коды возврата/ошибок - строковые константы (`"ОшибкаЗаписиОбъекта"`), а не переменные-«перечисления» с числами.
  - Кэш долгих и частых вычислений - общие модули с повторным использованием значений (на время вызова). Исключение:
    если по соображениям безопасности результат нельзя отдавать из экспортной функции - локальная переменная модуля.
- Модули форм:
  - Кэш - модули с повторным использованием. Не кэшировать статичное и легко вычисляемое; предопределенные элементы
    и значения перечислений на клиенте получать через `ПредопределенноеЗначение`, а не хранить в переменных формы.
  - Промежуточные результаты: в пределах одного вызова - параметрами методов; между вызовами с клиента - реквизитами
    формы (серверные переменные формы между вызовами не сохраняются).
  - Исключение: клиентские переменные формы допустимы для состояния в обработчиках ожидания, внешних событий и
    клиентских обработчиках событий элементов (например, счетчик сканированных изображений).
- Переменные модуля управляемого/обычного приложения - для «клиентских параметров сеанса» (см. стандарт про
  параметры сеанса).

```bsl
// Вызывающий код
ФайлОбъект.ДополнительныеСвойства.Вставить("КонвертацияФайлов", Истина);
ФайлОбъект.Записать();

// Модуль объекта
Процедура ПередЗаписью(Отказ)
	Если ДополнительныеСвойства.Свойство("КонвертацияФайлов") Тогда
		// ...
	КонецЕсли;
КонецПроцедуры
```

### std492 Обработчики событий модуля формы, подключаемые из кода - [its](https://its.1c.ru/db/v8std/content/492/hdoc)
Стандарт
- Обработчикам, назначаемым через `УстановитьДействие`, давать префикс `Подключаемый_` (англ. `Attachable_`):
  `Подключаемый_КонтактнаяИнформацияНачалоВыбора`.
- Зачем: если подключение делается вне модуля формы (например, в общем модуле), проверка «Поиск неиспользуемых
  процедур и функций» выдаст ложную ошибку - префикс позволяет отсеять ее.

### std499 Перехват исключений в коде - [its](https://its.1c.ru/db/v8std/content/499/hdoc)
Стандарт; п. 3 - управляемое и обычное приложение
- По умолчанию исключения НЕ перехватывать: платформа сама покажет сообщение пользователю (с категорией и
  рекомендацией), запишет в журнал регистрации и при необходимости отправит в сервис регистрации ошибок.
- Перехват с пробросом допустим, когда технический текст надо дополнить понятным пользователю пояснением: внешние
  ресурсы и каналы связи, внешние сервисы, некорректные входные данные/настройки (почта, веб-сервисы, принтеры,
  криптопровайдеры). Пробрасывать без потери исходной ошибки (передавать `ИнформацияОбОшибке` в `ВызватьИсключение`).
- `Попытка` - локально, вокруг конкретного проблемного вызова, а не вокруг большого блока (чтобы не ловить чужие
  ошибки соседнего кода).
- Проверять вывод исключений запуском без отладки и без режима технического специалиста.
- Собственная обработка без проброса (особые случаи, например обработчики обновления ИБ) обязана:
  - фильтровать ошибки кода и отправлять их в сервис регистрации ошибок (`ИнформацияОбОшибке.ЯвляетсяОшибкойКатегории`,
    `ОтчетОбОшибке.Отправить`);
  - писать причину в журнал регистрации;
  - в журнал - `ОбработкаОшибок.ПодробноеПредставлениеОшибки`, пользователю - `ОбработкаОшибок.СообщениеОбОшибкеДляПользователя`.
- Не использовать `ОписаниеОшибки()` вместо `ПодробноеПредставлениеОшибки` (нет стека) и `КраткоеПредставлениеОшибки`
  вместо `СообщениеОбОшибкеДляПользователя` (теряет уточнения, добавленные при пробросе).
- Не разбирать текст исключения для определения причины (текст зависит от локализации и версий) - показывать как
  есть, при необходимости дополнив описанием операции и возможными причинами. С БСП - через
  `ОбщегоНазначенияКлиентСервер.УточнениеИсключения`.
- Недопустим пустой `Исключение КонецПопытки` - «проглатывание» любых ошибок без следа. Если перехват всех ошибок
  действительно нужен - пояснить комментарием и записать `ЗаписьЖурналаРегистрации(..., Ошибка, ...)` с подробным
  представлением.
- Исключения в транзакциях - см. стандарт «Транзакции: правила использования».

```bsl
Попытка
	ЗагрузитьКлассификатор(АдресФайла);
Исключение
	ИнформацияОбОшибке = ИнформацияОбОшибке();
	Уточнение = ОбщегоНазначенияКлиентСервер.УточнениеИсключения(ИнформацияОбОшибке,
		НСтр("ru = 'Не удалось загрузить классификатор:'"));
	ВызватьИсключение(Уточнение.Текст, Уточнение.Категория, , , ИнформацияОбОшибке);
КонецПопытки;
```

### std790 Вызов исключений в коде - [its](https://its.1c.ru/db/v8std/content/790/hdoc)
Стандарт
- Обычно самим вызывать исключения не нужно - ошибки кода порождает и обрабатывает платформа.
- Исключение бизнес-логики, предназначенное пользователю, - без категории (по умолчанию
  `ИсключениеВызванноеИзВстроенногоЯзыка`). Прочие - с подходящей `КатегорияОшибки` (`ОшибкаРаботыСПринтером`,
  `ОшибкаСети`, `НарушениеПравДоступа`...) - тогда пользователь получит и типовые рекомендации.
- Права: как правило вызывать `ВыполнитьПроверкуПравДоступа`. Если проверяется роль вручную через `РольДоступна` -
  `ВызватьИсключение(Текст, КатегорияОшибки.НарушениеПравДоступа, , ДляАдминистратора)`, где в 4-м параметре -
  подробности для журнала (например, какой роли нет).
- Ошибки программиста (неверный тип параметра, неправильно встроенная подсистема) - категория
  `КатегорияОшибки.ОшибкаКонфигурации`.
- Если вызывающему коду нужно различать виды ошибок, выбрать одно из:
  1. не бросать исключение, а возвращать строковый код ошибки (числовые коды запрещены - нечитаемы);
  2. анализировать категорию исключения платформы (`ИнформацияОбОшибке().ЯвляетсяОшибкойКатегории(...)`);
  3. бросать исключение со строковым кодом в 3-м параметре `ВызватьИсключение` (когда вернуть код трудно: в
     `ПередЗаписью`, `ПриЗаписи`, глубокий стек). Код делать уникальным с префиксом подсистемы
     (`"Подсистема.Механизм.ВидОшибки"`); проверять `ИнформацияОбОшибке().Код`, с БСП -
     `ОбщегоНазначенияКлиентСервер.ЭтоИсключениеСКодомОшибки` (ищет и во вложенных причинах).
- В `ОбработкаПроверкиЗаполнения`, `ОбработкаПроведения`, `ПередЗаписью`, `ПриЗаписи`, `ПередУдалением` и т.п. для
  ошибок, которые пользователь может исправить, не бросать исключение, а ставить `Отказ = Истина` и выводить
  сообщения - пользователь увидит все причины сразу. Исключение - когда пользователь не может исправить ситуацию в
  рамках операции или ошибка делает остальные проверки бессмысленными.

```bsl
Если ТипЗнч(Количество) <> Тип("Число") Тогда
	ВызватьИсключение(НСтр("ru = 'Недопустимое значение параметра Количество'"),
		КатегорияОшибки.ОшибкаКонфигурации);
КонецЕсли;
```

### std498 Использование журнала регистрации - [its](https://its.1c.ru/db/v8std/content/498/hdoc)
Стандарт; управляемое и обычное приложение
- Писать в журнал из кода, когда администратору нужна диагностика событий, которые платформа сама не пишет
  (интерактивная бизнес-логика, фоновые и регламентные задания). Одна запись = одно событие.
- Имя события - групповое: `"Группа.Событие"` (`"Обмен данными.Выгрузка"`), без конкретных данных (номеров
  документов, ФИО, карт). Данные - в параметры `Метаданные` и `Данные` метода `ЗаписьЖурналаРегистрации`.
- Имя события локализуемо через `НСтр(..., КодОсновногоЯзыка)` - всегда на основном языке конфигурации.
- Уровни: `Ошибка` - критичное (ошибки бизнес-логики, сбои); `Предупреждение` - потенциальные/нефатальные проблемы;
  `Информация` - успешное завершение операций; допустимо `Примечание`.
- Комментарий - информация для расследования; не склеивать в одну запись лог нескольких событий; не писать данные
  непредсказуемого размера (файлы, ответы веб-сервисов) - ориентир не более 10 Кб. Текст локализуем.
- Сведения об исключении - `ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())`.
- Не использовать выборку из журнала там, где важна скорость (она деградирует с ростом журнала) - заводить отдельный
  регистр для протокола или использовать спецобъекты (например, `МенеджерФоновыхЗаданий` для истории фоновых заданий).
  Учитывать это и в отчетах по журналу.

```bsl
ЗаписьЖурналаРегистрации(НСтр("ru = 'Интеграция.Отправка заказа'", КодОсновногоЯзыка),
	УровеньЖурналаРегистрации.Ошибка, Метаданные.Документы.ЗаказКлиента, Заказ,
	ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
```

## Прикладные объекты и коллекции значений

### std486 Использование модуля объекта, модуля менеджера объекта и общих модулей - [its](https://its.1c.ru/db/v8std/content/486/hdoc)
Рекомендация
- Модуль объекта - поведение одного экземпляра (`ЭтотОбъект`, в т.ч. незаписанного): обработчики событий объекта,
  заполнение экземпляра. Помнить: вызов экспорта модуля объекта извне требует `ПолучитьОбъект()` - загрузка объекта
  целиком с ТЧ, дорого.
- Модуль менеджера - «статическая» логика объекта метаданных, не требующая экземпляра: операции над множеством
  объектов (печать списка, общие сведения, обновление ИБ), а также работа по ссылке на записанный объект (печатная
  форма по ссылке, движения по ссылке).
- Логика, не относящаяся однозначно к одному объекту метаданных, - в общий модуль.

### std544 Ограничения на использование экспортных процедур и функций - [its](https://its.1c.ru/db/v8std/content/544/hdoc)
Стандарт
- Не объявлять `Экспорт` в модулях команд и общих команд - их невозможно вызвать извне.

### std451 Программное создание прикладных объектов - [its](https://its.1c.ru/db/v8std/content/451/hdoc)
Стандарт
- Создавать объекты только через менеджеры: `СоздатьЭлемент()`, `СоздатьДокумент()`, `СоздатьНаборЗаписей()` и т.д.
  Конструктор `Новый("ДокументОбъект.Х")` для объектов, у которых есть менеджер, запрещен.
- После создания явно вызывать `Заполнить(ДанныеЗаполнения)`, при отсутствии данных - `Заполнить(Неопределено)`:
  отработают «Значение заполнения» реквизитов, `ОбработкаЗаполнения` и подписки, как при интерактивном создании.
- Исключение: объект полностью загружается из источника (обмен данными, восстановление из XML).

```bsl
Папка = Справочники.ПапкиФайлов.СоздатьЭлемент();
Папка.Заполнить(Неопределено);
Папка.Наименование = ИмяПапки;
Папка.Записать();
```

### std450 Порядок записи движений документов - [its](https://its.1c.ru/db/v8std/content/450/hdoc)
Стандарт
- В `ОбработкаПроведения` не вызывать `Движения.<Регистр>.Записать()` явно - система запишет наборы сама по
  завершении проведения. Явная запись при параллельной работе ведет к взаимоблокировкам.
- Исключение: записанные движения нужны последующим алгоритмам до выхода из процедуры проведения.

### std447 Использование объекта РегистрСведенийМенеджерЗаписи - [its](https://its.1c.ru/db/v8std/content/447/hdoc)
Стандарт
- Чтение регистра сведений без последующего изменения - только запросом.
- `РегистрСведенийМенеджерЗаписи` - только когда операция требует отбора сразу по всем измерениям. (Внутри он
  использует два набора записей, поэтому события набора записей вызываются и при записи через менеджер.)
- В остальных случаях - `РегистрСведенийНаборЗаписей`: установить отбор, добавить строки, один `Записать()`. Не
  создавать менеджер записи в цикле на каждую строку.

```bsl
Набор = РегистрыСведений.ЦеныНоменклатуры.СоздатьНаборЗаписей();
Набор.Отбор.ВидЦены.Установить(ВидЦены);
Для Каждого Строка Из ТаблицаЦен Цикл
	ЗаполнитьЗначенияСвойств(Набор.Добавить(), Строка);
КонецЦикла;
Набор.Записать();
```

### std409 Использование РеквизитФормыВЗначение и ДанныеФормыВЗначение - [its](https://its.1c.ru/db/v8std/content/409/hdoc)
Рекомендация
- В модулях форм предпочитать `РеквизитФормыВЗначение("ИмяРеквизита")` вместо
  `ДанныеФормыВЗначение(Реквизит, Тип(...))` - проще синтаксис, не нужен тип. По эффективности они одинаковы.

### std411 Установка параметров выбора и связей параметров выбора для объектов метаданных - [its](https://its.1c.ru/db/v8std/content/411/hdoc)
Стандарт
- Параметры выбора и связи параметров выбора задавать в свойствах реквизитов объектов метаданных (справочников,
  документов, измерений), а не в каждой форме: ограничения бизнес-логики должны быть одинаковыми во всех формах.
- Если ограничение зависит от сценария (например, от функциональной опции), уточнять его в конкретной форме: связи из
  метаданных и из поля формы работают одновременно (можно добавить реквизит формы как ведущий).
- Задавать параметры выбора и для неинтерактивно редактируемых объектов (например, измерений регистров) - они
  применяются в отборах отчетов и динамических списков.
- Не ставить в связи параметров выбора «Режим изменения связанного значения» = `Очищать`. Вместо этого писать код
  условной очистки: оставить текущее значение, если оно допустимо; подставить единственное подходящее; иначе
  очистить. Безусловная очистка теряет значение при повторном выборе того же ведущего значения и когда зависимое
  значение подходит нескольким ведущим.
- `Очищать` допустимо, только если повторный выбор ведущего значения без изменения невозможен (например, поле
  флажка) И каждому зависимому значению соответствует не более одного ведущего.
- Для заполнения нового объекта, создаваемого из поля/формы выбора с отборами, задавать параметры выбора с
  префиксом `Отбор.` - они попадут в `ДанныеЗаполнения` обработчика `ОбработкаЗаполнения`.
- Примечание: в корпусе у п. 4 пропущены иллюстрации «Неправильно/Правильно» (скриншоты), текст правила полный.

### std407 Применение параметров отчета в СКД - [its](https://its.1c.ru/db/v8std/content/407/hdoc)
Стандарт; управляемое и обычное приложение
- Не заводить параметр отчета, если хватает обычного элемента отбора: вместо `ГДЕ Организация = &Организация` дать
  пользователю отбор по полю `Организация`.
- Избегать обязательных параметров (иначе отключение параметра пользователем дает ошибку «Не задан параметр
  отчета»): условия с параметрами писать в фигурных скобках расширения СКД, например
  `{ГДЕ Т.Период >= &ДатаНачала, Т.Период <= &ДатаОкончания}` - тогда параметры необязательны и отключаются вместе с
  частью условия.

### std449 Получение представлений для ссылочных значений в табличном документе - [its](https://its.1c.ru/db/v8std/content/449/hdoc)
Рекомендация
- В параметры ячеек макета (тип заполнения «Параметр») не передавать ссылки - при выводе будет по обращению к базе
  на каждое представление. Передавать готовые представления.
- Исключение: если получение представлений само потребует таких же многократных обращений. Учитывать, что
  `Представление`/`ПРЕДСТАВЛЕНИЕ()` в запросе добавляет неявные соединения (для составного типа - по одному на каждый
  тип; при многих типах можно упереться в лимит 256 таблиц MS SQL Server 2005). Выбор способа - по замерам.

### std693 Использование объектов типа Структура - [its](https://its.1c.ru/db/v8std/content/693/hdoc)
Стандарт
- В конструктор `Новый Структура("...", ...)` не передавать больше 3 значений свойств; остальное - через
  `Вставить` или присваивание свойств.
- Не создавать внутри конструктора структуры другие объекты с параметрами (в т.ч. вложенные `Новый Структура(...)`
  со значениями).
- Не вызывать в конструкторе структуры функции с более чем 3 параметрами - вычислить заранее и присвоить.
- Не добавлять свойства «по месту» в разных частях кода с последующей проверкой `Свойство(...)`. Создавать
  структуру сразу со всеми свойствами и значениями по умолчанию (функцией-конструктором, см. std641).
- Исключение - структуры нефиксированного формата: данные внешних источников (ответ HTTP, сканер штрихкодов, ТСД),
  системные параметры формы, параметры выбора в параметрах формы. Пользовательские параметры формы объявлять явно
  на закладке «Параметры» редактора формы.

```bsl
// Неправильно: Если Параметры.Свойство("Идентификатор") Тогда ...
Функция НовыеПараметрыВыполнения()
	Результат = Новый Структура;
	Результат.Вставить("Идентификатор", Неопределено);
	Результат.Вставить("ВФоне", Ложь);
	Возврат Результат;
КонецФункции
```

### std448 Копирование строк между таблицами значений произвольной структуры - [its](https://its.1c.ru/db/v8std/content/448/hdoc)
Стандарт
- Для копирования строк между таблицами/табличными частями со схожим составом колонок использовать
  `ЗаполнитьЗначенияСвойств(Приемник, Источник)`, а не перебор колонок с поиском по имени - намного быстрее.

### std452 Поиск в коллекциях значений - [its](https://its.1c.ru/db/v8std/content/452/hdoc)
Стандарт
- Таблицу значений с большим числом строк (ориентир от 1000; или маленькую, но с многократным поиском, например
  100 строк x 100 поисков) при двух и более поисках индексировать - но только по колонкам с хорошей селективностью.
  Ради одного поиска не индексировать.
- `Найти` использует индекс только по одному полю: не применять `Найти` для поиска по нескольким колонкам в больших
  таблицах - будет полный перебор.
- `НайтиСтроки`: индекс используется, только если набор его полей точно совпадает с набором ключей структуры отбора
  (порядок не важен). Индексы по `Колонка1` и `Колонка2` по отдельности не помогут отбору по обеим; составной индекс
  `"Колонка1,Колонка2"` не поможет отбору по одной колонке. То же для `Скопировать(ПараметрыОтбора)`.
- Сортировка по ссылочным колонкам - см. std781.
- Поиск в большом `Массив` (ориентир от 1000 элементов, или меньше при поиске в цикле): заменить на `Соответствие`
  (порядок не важен) или индексированную `ТаблицаЗначений` (порядок важен).
- Уникальность элементов большого массива - один раз в конце: `СвернутьМассив` или
  `ДополнитьМассив(..., ТолькоУникальныеЗначения = Истина)` (общий модуль ОбщегоНазначения в БСП), а не проверка при каждом добавлении.
- `ДеревоЗначений` не индексируется (поиск перебором) - для частого поиска заменять индексированной таблицей.

```bsl
Остатки.Индексы.Добавить("Номенклатура, Склад");
Отбор = Новый Структура("Номенклатура, Склад", Товар, Склад);
Строки = Остатки.НайтиСтроки(Отбор); // индекс используется
```

### std781 Особенности сортировки в таблице значений - [its](https://its.1c.ru/db/v8std/content/781/hdoc)
Стандарт
- Сортировка по колонкам со ссылками обращается к базе за представлением каждой ссылки в каждой строке.
- Если нужна сортировка по наименованию - при заполнении добавить колонку с представлением и сортировать по ней
  (если это не порождает тех же обращений к базе).
- Иначе сортировать по ссылке: `Таблица.Сортировать("Дата, Ссылка", Новый СравнениеЗначений)`.
- Особенно важно для таблиц в сотни-тысячи строк в критичных по времени алгоритмах.

### std782 Массовая конкатенация строк - [its](https://its.1c.ru/db/v8std/content/782/hdoc)
Стандарт
- При массовой конкатенации (ориентир от 1000 операций, меньше - для длинных строк; особенно в циклах и универсальных
  механизмах) собирать части в массив и склеивать `СтрСоединить` (разбирать - `СтрРазделить`): быстрее и меньше
  памяти. В остальных случаях обычный `+` предпочтительнее для читаемости.

```bsl
Части = Новый Массив;
Для Каждого Строка Из Таблица Цикл
	Части.Добавить(Строка.Текст);
КонецЦикла;
Результат = СтрСоединить(Части, Символы.ПС);
```
